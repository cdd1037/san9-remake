# BEH-IMPORT-0002：剧本宝物记录解析

- 状态：已确认
- 负责人：项目开发者
- 最后更新：2026-08-16
- 关联证据：[RE-SAN9PK-0006](../../research/findings/RE-SAN9PK-0006.md)
- 关联决策：[DEC-DATA-0001](../decisions/DEC-DATA-0001-content-pipeline.md)

## 适用范围

本规格只约束繁中 PK 1.0.1.0 正式剧本 `item` chunk 的记录边界、已确认字段和引用校验。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不定义宝物名称文本、13 个类别的显示名称、状态码 0 的玩家可见含义、地点编号到地图实体的映射或重制版宝物平衡。

## 原作基线

`item` chunk 包含 120 项，每项由 11 个小端 `u16` 组成，共 22 字节：

| 偏移 | 字段 | 已确认约束 |
| --- | --- | --- |
| `0x00` | serialized id | 等于记录序号 |
| `0x02` | resource id 1 | 等于记录序号；具体资源用途未指定 |
| `0x04` | resource id 2 | 等于记录序号；具体资源用途未指定 |
| `0x06` | image id | 0–99 |
| `0x08` | category id | 0–12；类别名称未在本规格定义 |
| `0x0A` | loyalty change | 赏赐与没收使用的忠诚变化量 |
| `0x0C` | ability bonus | 与类别共同决定的能力加成量 |
| `0x0E` | tactic code | 0–40；`0xFFFF` 表示无兵法 |
| `0x10` | holder person code | 0–849；`0xFFFF` 表示无持有者 |
| `0x12` | discovery state code | 正式剧本中只出现 0、1、2；1/2 分别对应未出土/已出土，0 的含义未指定 |
| `0x14` | discovery location code | 0–249；`0xFFFF` 表示无地点 |

原程序加载时以记录位置作为运行时宝物 ID，不信任文件中的首个 ID 字段；仍要求正式输入中的三个编号字段与记录序号一致。持有者、兵法和地点字段经过范围检查后才转换为运行时引用或编号。

前 100 项是内置宝物；后 20 项是额外槽位。后 20 项不通过内置宝物文本路径加载名称，其独立文本来源不属于本规格。

## 重制行为

导入器必须无损保留 11 个原始字段，并为兵法、持有者和发现地点提供显式的可空解析结果。`0xFFFF` 必须映射为空值，不得转换为有效实体 ID。

任何编号不一致、图像/类别越界、无效兵法、无效持有者、未知状态码或无效地点必须拒绝整个 `item` chunk，不产生部分宝物列表。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整剧本流，位置在文件起点。
- 状态变化：无；只生成 120 项只读记录。
- 始终成立的不变量：返回顺序等于原文件顺序；每项保留完整 22 字节语义值。
- 失败或无效输入行为：抛出格式错误，不猜测未知编号或截断引用。

## 示例与边界

- `tactic code = 3`：解析为兵法 ID 3。
- `tactic code = 0xFFFF`：解析为空。
- `holder person code = 326`：解析为武将 ID 326。
- 第 1 项的 serialized id 被改为 99：拒绝整个列表。
- category id 为 13：拒绝整个列表。
