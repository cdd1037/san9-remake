# 电脑 AI 实现规划

- 状态：草案（实现规划，不表示 G11 已启动或验收）
- 更新：2026-09-24
- 范围：G11 自主 AI；G12 承接全地图长期对局；军团可选委任方针适配在自主 AI 完工后另行设计
- 设计性质：重制版自主设计；原作 AI 的算法、工作表、阈值和补偿不构成约束
- 现有边界：[BEH-AI-0001](behavior/BEH-AI-0001-planning-boundary.md)、[DEC-AI-0001](decisions/DEC-AI-0001-deterministic-planning-boundary.md)、[整体路线图](roadmap.md)

## 目标与非目标

电脑应能独立经营一个势力：维持收支与人员稳定，识别需要防守或值得进攻的方向，准备和投送足够兵力，处理外交和事件，执行战争并在局势变化后调整。先完成自主 AI，再根据实际能力设计军团可选委任方针及其适配，不预定必须对应原作选项，也不将该适配列为 G11 完成条件。

首个完整版本追求可解释、能持续行动、有基本战略连贯性的对手。验收看具体局面中的决策与结果，不以模块数量、采用某种算法或单一胜率作为完成标准。困难主要来自多旬资源安排与行动协调，不应首先投入全局博弈树搜索。

按完整势力的决策闭环组织能力，不按算法名词逐项建立模块，也不把某几个困难操作当作架构中心。优先实现能同时改善经营、人事、军事、外交和委任的共享分析与分配机制；复杂能力只有在明确局面中带来可测收益时才深化。

本轮规划不实施代码，不设计新菜单，不新增战争迷雾玩法，不复刻原作 AI，不承诺日历工期。机器学习、在线大模型、全地图蒙特卡洛搜索和复杂人格系统不纳入首版；后续有明确对照收益再考虑。

## 决策结构

采用“获准观察 → 局势与可行性分析 → 势力目标和行动方案 → 统一分配 → 公共命令 → 结果反馈”的决策闭环，局部使用整数效用评分和有界方案比较。方案需求与可用资源相互约束：先估算可行范围，再生成和分配方案；分配不足时缩小或更换目标，不先选定不可完成的目标再强行凑人凑兵。

1. **观察。** 读取当前行动边界的获准信息、命令权限和正在执行的任务。
2. **分析。** 形成经济预测、可用人员与兵力、前线威胁、路线和到达时间等派生结果。
3. **目标。** 选择保全、恢复、发展、夺取据点等少量主要目标，给现有行动明确继续、调整或中止的判断。
4. **分配。** 为目标安排军团、据点、人员和资源；经营、人事、外交与军事竞争同一份可用额度，组合收益和跨行动依赖一起比较。
5. **执行。** 校验完整方案的可行性，生成下一条可执行命令，经过公共验证和提交；成功后更新观察，修复受影响的安排，保留仍然有效的承诺。
6. **收尾。** 无有益合法行动或预算耗尽时结束控制；记录原因及下一次需要检查的条件。

保全与紧急约束先筛选，剩余方案再比较收益、实现概率、到达时间、损失与机会成本。不能让一次高额经济收益简单抵消主城即将失守的风险。评分先用可解释的规则与统一量纲，不把不同领域任意常数直接相加；权重在公开局面中标定。

### 共享分析与方案选择

首版完整 AI 就需要时间、威胁、投送、后勤和目标价值的基本分析，让各领域基于同一局势做决定；后续增强预测精度和搜索深度，不先固化各自为政的局部策略再补分析模块。

- **时间与可达性。** 根据实际移动、任务和结算规则估计到达、完成及可再次使用的时间。覆盖调动、救援、运输、集结和使者任务，不用直线距离统一代替。
- **压力与保障。** 比较不同时间窗口下敌我能形成的有效力量，结合账户收支、粮耗和在途支援判断持续行动能力。先围绕据点、部队和候选路线计算，不要求为全地图每格建立多张图；不增加玩法没有的补给线机制。
- **价值与机会。** 评价目标的经济、交通、支援和后续行动价值，扣除获取及维持成本；区分长期值得争取与当前存在可利用窗口。用少量合理的敌方反应检验方案，如固守、增援或反击，不预测唯一确定的未来。
- **方向与预备。** 按相互关联的攻防方向协调力量，保留能在需要时响应的资源。分析分区不必等同于行政军团；同一批兵将不能重复计入多个方向的可用力量，预备比例随风险与响应时间变化。

行动方案声明目标、参与对象、资源需求、时间窗口、前置条件、预期收益和失败后的处理。公共规则中的确定性效果尽量提取为共享只读计算；随机效果用期望与风险估计，不复制一套会逐渐偏离正式结算的 AI 公式，也不读取正式随机流的未来结果。

统一分配先满足紧急和关键需求，再用确定性启发式生成可行安排，通过替换、交换和少量组合搜索改善。比较的是方案对全局的净收益，计入对象原岗位价值、行动占用、行程和转向成本。具有互补收益或必须共同到位的行动作为组合比较，不能假设所有收益都可逐人、逐命令相加。

候选生成保留不同优势的方案，避免按单项能力或固定编号截断后永久排除关键组合。随预算增加扩大覆盖与局部搜索；首版不求全局最优，但必须能识别资源冲突、关键岗位被抽空及多个方向同时透支等明显问题。

### 观察与信息权限

观察至少覆盖本方账户、据点、人员、部队、任务与预计归期、控制权限、委任方针，以及获准读取的地理、外交、敌方情报和可用内容定义。通用字段使用领域语义，不携带源格式槽位和容量限制。

G11a 先逐项列出“公开信息、本方完整信息、受限信息”矩阵，按现有查询与可见性规则构造观察；不能因为内部快照含有数据就全部交给规划器。未知值与零值分开。若现有玩法允许公开敌军信息就正常使用，若未定义则先在规格明确，不擅自增加迷雾或情报记忆系统。

规划器不持有 `GameSession`、`SimulationEngine` 或可返回完整世界的回调。命令意见、路径分析等查询同样经过视角审查；隐藏状态导致的验证拒绝只能终止或放弃对应动作，不作为反复探测隐藏兵力和位置的接口。

观察中的信息权限与行动权限分别表达：看到本方对象不代表可以调动它。势力层可以分析获准情报，但只有已授权控制的对象和账户进入可分配集合；玩家直属部分不能因处于同一势力而被自动预留。

### 状态所有权与持久性

| 数据 | 所有者与生命周期 |
| --- | --- |
| 资源、行动占用、部队命令、外交任务、控制模式 | Core 权威领域状态；AI 不能直接写入 |
| 势力长期目标、行动分配、阶段、上次有效进展、必要的失败冷却 | Application 会话拥有的 AI 持久状态；凡影响后续选择，必须进入保存、精确恢复和录像一致性校验 |
| 威胁、路线估计、方案评分、当前批次预留 | 根据获准观察派生，可丢弃重建；不得成为第二份权威资源账本 |
| 诊断文本、候选解释、性能统计 | 非权威输出；不改变决策、随机消费或工作预算 |

策略记忆只存不能从当前世界可靠重建的决策承诺，不复制城市兵力与资源。保存和录像格式按仓库版本约定更新，旧格式不以默认为空策略悄悄兼容；明确扩展会话一致性校验范围，不把策略记忆塞进不属于它的 Core 世界哈希。

现有 `IAiPlanner.Plan(AiPlanningContext)` 尚不包含策略记忆和配置输入。G11a 将完整决策输入明确为获准观察、不可变策略记忆、策略版本与配置、用途和预算；输出候选与拟更新的记忆，由 Application 在提交结果确定后共同发布，不在规划器内部隐藏可变单例。不能把“同观察同计划”继续用于忽略记忆或难度配置的比较。相关 Application 类型不得反向进入 Core；需要扩充或调整现有协议时统一迁移消费者，不为保留旧接口维护第二条决策路径。

会话快照与状态哈希纳入策略记忆和影响行为的版本化配置，录像初始状态及终态校验使用同一范围。精确恢复保留这些输入；玩家读档按现有约定更换运行种子，但不抹掉战役承诺。仅可重建的分析缓存不保存，随机样本、预算游标等若跨稳定边界影响选择，也须成为显式状态或在该边界确定性重建。

控制切回玩家时撤销自动规划承诺和未提交预留，已签发任务按公共规则继续；接管电脑时从当前世界建立目标。势力灭亡、据点易主、人员转属和委任变更均清理失效引用。会话操作失败时策略记忆与候选世界一起回滚。

清理按受影响控制范围执行：收回一个子军团不删除其他军团仍有效的计划。动态创建势力或军团时初始化对应策略状态，解散或合并时撤销失效承诺，不能依赖开局对象列表。跨旬承诺重新经过可行性检查，不把旧预留视为对玩家或领域规则的锁定。

### 规划时机、冲突与工作预算

维持现有势力行动顺序：即时命令提交后影响同阶段后续决策，有耗时的工作走共同日级推进。不引入全势力同时规划和统一延后结算。旬行动边界负责战略规划；日内选择在已有任务决策边界响应，部队逐日行动继续由现有军事规则推进，不给电脑额外的随时下令权。

2026-09-24 时序范围确认：先沿用当前重制版的顺序，新局玩家势力在前，其余势力按 ID 排列；不另行复刻原作信望排序，不新增顺序轮换或同步下令。后行动者可以基于其获准观察到的当前变化规划，仍不得读取未获准的对方内部命令。当前接受这一顺序玩法，不把消除先后手差异作为 G11 前置或验收条件；同步计划及联机公平性待未来明确联机需求时再评估。依据与既有选择见[时序决策](decisions/DEC-SIM-0001-determinism-and-saves.md)和[原作顺序研究](../research/findings/RE-SAN9PK-0123.md#命令生效时机复核2026-09-06)。

每次成功提交后刷新受影响观察和派生分析，下一条命令使用最新序号。人员、资金、粮食和兵力在方案内部预留，提交时以当前权威状态为准。预留只防止重复分配，不提前扣资源，也不能用势力总资金替代实际军团账户。

多命令方案不等于领域原子事务：例如第一队已出发、第二队命令被拒绝时，第一条成功结果保留，后续调整须走合法命令。只有外层会话操作整体被拒绝或失败时，才按已有会话事务同时回滚候选世界与策略记忆。分配阶段估计整体可行性，不能保证未来命令必定成功，也不能为补偿方案失败凭空退资源或撤销行程。

失败按原因处理：资源或权限变化触发重新分配；目标失效撤销方案；路线不可达暂缓同一路线并比较替代方案。一次拒绝不重试无限次，重规划消耗同一轮剩余预算，不能通过刷新上下文获得新预算。命令 ID 由提交层分配，拒绝不消耗正式序号。

预算覆盖候选构造、路线搜索、方案求值、可选模拟和提交尝试，并划定有界子额度；搜索内部展开也必须计量，不能只计算外层调用次数。额度可按获准观察中的本方规模确定性增长，不固定只让前几个编号对象行动。紧急行动优先，普通任务在效用相近时按等待时间防止长期饥饿，再用稳定身份消除平局。

墙钟时间只记录性能，不决定权威结果。预算耗尽可以结束本轮，但必须区分“没有可行动作”和“尚有动作但预算耗尽”，让后续调优有据可查。

以上结束规则只适用于可选行动。必须响应的日内选择使用独立、有界且预留的响应额度；额度不足以比较全部方案时仍须从合法选项中按明确的确定性规则完成选择，不得因战略预算耗尽把电脑留在等待状态。只有玩家负责的选择才向 UI 暂停；连续电脑选择的续行不得重置为无限预算，按实际任务进展和有界选项求值推进。

缓存不能改变可搜索工作量：按逻辑求值计费，命中缓存仍扣同等逻辑额度；缓存键包含实际依赖的观察、规则和配置，相关状态变化时失效。缓存仅减少物理耗时，冷缓存、热缓存及恢复后的空缓存必须产生相同候选和结果。遍历与并行归并若采用并发，顺序也不能由完成时间决定；首版无需为并发预建接口。

## 各项能力的实现范围

### 经营与人事

先预测到下一次可靠收入或补给前的资金、粮食与消耗，再决定修复、治安、征兵、训练、开发、买卖粮和调运。征兵受可持续供养与实际军事需求约束，不能各城盲目堆兵。紧急缺粮时比较购粮、输送、缩减出征和撤回等合法方案。

人物按岗位需求和时间价值分配：作战指挥、内政、外交与登用共同竞争可用人物；调动考虑原岗位缺口、行程和任务归期，不能平均分人或反复派人填补已有在途支援的岗位。内政先比较工作价值，再按新增人员的实际增益与机会成本决定投入规模，存在组合效果时比较小规模组合，不默认用满人数。

封官与任免根据实际规则收益、岗位需求和成本安排；褒美根据忠诚风险、人员价值和资金选择；宝物分配考虑实际效果及其他持有者的损失。探索、登用、俘虏处理与调动服务于人员供给及战略需求，不从内容中固化最优人物名单，不为微小评分变化反复任免、移交和调动。所有操作经公共命令执行。

形成公共命令能力清单：对每类命令注明自主选择、响应式处理或暂不主动采用的理由。不是要求电脑每旬使用所有命令，但不能默默漏掉收支、人员补充、维持忠诚等生存闭环。

### 军事与后勤

先建立按路线和时间估算的压力，不用直线距离或当前兵数单独判断安全。对于每个候选目标，比较敌方可达兵力、本方可调兵力、在途支援、到达时间、地形、阵型、士气、据点耐久、粮耗及撤回成本；未知情报使用明确保守估计，不读取隐藏真值。

行动方案有准备、集结、推进、交战、巩固和撤回等必要阶段，持有目标、分配力量和中止条件。每支部队只能承担一个主要任务；多个出发地按到达时间协调，不把分批送入战场当作集结完成。留守需求由威胁推导，避免所有城统一保留固定兵数。

首版完成救援、防守、夺取据点、补给与撤退，并具备与任务匹配的编队、阵型和兵法选择。按任务共同比较人员、兵力、阵型和合法兵法配置，以有界组合搜索及局部替换保留几种有竞争力的方案；基于正式规则快速估计接敌、输出、承伤、攻城效果与持续能力。多部队作为战役的一部分分配，不能让第一支部队拿走所有优秀人员。设施建设同样比较实际用途、费用与时间，不因存在合法建设点就建造。

出征必须具备可达路线、可供养兵力和可接受的本土风险。目标变化后重新评估，不对已占领、受外交保护或长期不可达目标机械下令。更深入的交战模拟用于提高选择质量，不作为首版具备基本战役判断的前提。

目标持续性来自转向成本和承诺：非紧急情况下，新目标必须明显优于继续现目标才切换。无进展按实际距离、集结缺口、补给到位等阶段指标判断，长距离正常行军不能误判为卡住。超期、损失过大或条件失效时收缩、改道或放弃；记录具体原因。

### 外交、计略与事件选择

外交服务于战略目标：减少多线作战、争取协同、取回关键人员或在有利条件下劝降；礼物、交换代价和使者占用进入统一预算，考虑谈判时机与在途任务，避免重复请求和无目的送礼。计略比较任务时间、意见或成功预期、目标价值与其他行动机会成本，不因为合法就必定执行。关系和保护条件变化及时反馈给军事目标与部署。

清点推进过程中的所有电脑决策分支，包括外交谈判、事件接受与拒绝、俘虏、人事和继任等。对已有自动处理保留经过确认的规则，对需要策略选择的分支接入共同决策能力。电脑必须能续行，不等待玩家 UI；玩家选择不能被 AI 代答。不以“全部接受”或“全部拒绝”作为通用完成条件。

G11a 先清点响应入口并贯通一个代表性电脑选择：Core 负责产生合法选项、验证响应和结算，Application 在稳定决策边界选择后继续推进。迁移涉及响应授权、待决状态不变量和暂停续行，不可把电脑伪装成玩家，也不能让 Core 在可变结算中回调持有会话的规划器。其余策略选择在 G11e 接入同一路径；已明确为强制领域结果的分支保留为规则，不无条件改造成可选择项。

### 军团权限与后续委任适配

当前自主 AI 按既有控制范围裁剪可支配账户和命令权限。势力层决定战略优先级和合法跨军团协调，军团层在分配额度内执行；不允许两个层级同时花同一份资源或重复调动同一人物。玩家可选委任方针如何映射到这些能力，待自主 AI 完工后再设计。

协调只通过现有合法任免、辖区调整、调动及资源命令实现。当前控制权限不能完成的跨军团分配视为不可行，不能让“统一分配”越过验证器；若确需新增通用治理命令，先明确玩家同样可用的行为与验收，再补领域规则。军团改变时重新计算账户归属及承诺，保留总量守恒。

本次仅调整工作顺序，不删除或放宽已有方针数据、命令资格和目标清理规则；旧有行为按现有规格保留回归，不将其扩展解释为新 AI 的方针设计。自主规划与既有控制限制有冲突时服从限制，不以通用策略绕过。后续再决定提供哪些选项、如何表达目标和优先级、允许多大自主空间，并同步行为规格和界面验收。自动军团划分根据战线、行程、管理需求和现有合法治理命令决定，不预设必须模仿原作城市阈值或比例分组。

## 工程拆分与实施顺序

规划逻辑先在 `San9.Application` 内按职责组织，Core 只补通用规则、查询和命令缺口；不为 AI 建第二套战斗或经济结算。Content 仅在需要作者配置语义数据时扩展，Importer 不保存规划算法。Godot 不参与规划，Headless 与客户端使用同一会话入口。

以下阶段按共享能力依赖排序，每阶段交付可运行行为。基础分析先有够用版本，经营、人事、军事和外交随后共同消费；不按名词建立空模块。全部完成才可声明 G11 完成。

| 阶段 | 可交付行为与主要改动 | 退出条件 |
| --- | --- | --- |
| G11a 观察与会话闭环 | 信息及权限矩阵、按已接入能力扩充的只读观察、统一自动入口、预算计量、显式记忆与配置、版本化保存；贯通代表性电脑响应 | 最小公开势力完成真实经营及一次日内选择；恢复续跑、回滚、冷暖缓存、诊断开关和受限信息差分测试通过，无重复调度 |
| G11b 基础态势与可行性 | 到达时间、压力、投送、账户预测、后勤和目标价值的够用版本；接入实际救援或补给决策 | 对比可及时到达／来不及、可持续／断粮、可调兵／会暴露后方的局面，行动产生相应差异；不只输出分析数值 |
| G11c 统一分配与势力经营 | 方案需求与冲突处理，经营、人事、任免褒美、登用、调动、基础防守与预备安排 | 生存与人员供给闭环；多城和多方向不重复使用资源，不抽空关键岗位，不侵占玩家直属资源 |
| G11d 战役执行与局部方案搜索 | 多城集结、编成和阵型兵法选择、增援补给、攻占巩固与撤回，简单对手反应和目标持续 | 经营→补员→集结→出征→占城闭环；错峰到达、反击、目标易主和长期无进展均有有效处理 |
| G11e 外交、事件与治理整合 | 外交计略与军事经营共同分配，自动选择分支核对，军团管理与控制权限整合；不含可选委任方针适配 | 外交行动有明确目标及成本约束；电脑无需 UI 续行，控制权限不越界，控制切换及失效引用清理正确 |
| G11f 能力对照与阶段收口 | 汇总场景和早期自动对局，预算梯度及模块对照，全入口审计、难度配置、190 年阶段集成 | 满足下列验收；昂贵能力以测得收益决定是否保留，登记性能基线、剩余局限和 G12 输入 |

先有工作预算与启发式方案，再决定是否引入局部前瞻。仅在难以取舍的候选上，用隔离状态和独立分析随机评估有限方案；若无法基于获准观察构建合法预测，则使用明确的估算，不复制完整隐藏世界做“假装不知道”的模拟。前瞻不能改变正式结算随机，收益须通过去掉该模块的对照实验验证。

首版完整 AI 包含上述基本分析、统一分配、全领域行动与战役闭环。更精细的敌方意图推断、多批次路线优化、更深搜索和随机推演属于按收益追加的增强项；训练属于游戏基本完工后的远期研究。这些边界区分能力精度，不允许把威胁、投送和战役规划本身推迟到首版以后。

G11a 建立命令与响应覆盖清单，此后每阶段随能力更新，G11e 完成核对；观察也随真实消费者扩充，不能在第一阶段为全部未来能力预建字段。迁移时逐项替换旧入口，同一控制范围和同类行为只保留一个生产执行者，未迁移行为显式列明，最终删除退出生产的阶段策略。G11b 的救援或补给以小规模公开局面验证基础分析，G11c 再扩展多目标分配，不要求前一阶段暗中先完成后一阶段全部能力。

## 验收与难度

每个公开场景在实现对应能力前登记起始状态、固定种子集、可行目标、时间窗口、资源约束及失败条件，参数由地图行程和领域规则推导。不得在看到新 AI 结果后移动通过阈值。对照旧策略时只用其已具备能力的场景；新能力另设简单确定性基线，不要求旧策略完成从未支持的功能。

| 场景组 | 必须观察的结果 |
| --- | --- |
| 内政生存 | 可解缺粮局面避免断粮；发展不破坏军费与粮食储备；人员和资源使用合法 |
| 统一分配与治理 | 竞争同一人员或账户的行动不重复占用；调动考虑在途供给；任免、褒美和宝物选择体现实际收益、忠诚风险与成本，不反复无效调整 |
| 威胁响应 | 支援能在场景规定窗口到达；留守风险受控；注定无法守住时有撤回或减损行为 |
| 进攻组织 | 足够力量在窗口内形成合力；完成占领并留有可继续行动的后勤，不以无意义损失换事件数量 |
| 失效恢复 | 易主、结盟、将领离队、道路不可达、援军延误后有界重规划，不无限重试和来回改令 |
| 外交与控制权限 | 目标、预算、权限和外交保护一致；玩家直属行为不被接管；已有委任限制保持回归，新方针设计与适配另行验收 |
| 自动选择 | 所有支持的电脑选择可继续推进；拒绝与失败分支不造成会话悬挂 |
| 确定性与隔离 | 同观察、记忆、配置、种子及预算同计划；恢复续跑及冷暖缓存一致；诊断和未选用分析不影响正式结果；相同获准观察下改变隐藏状态不影响计划，实际提交仍按权威规则复验 |
| 提交与生命周期 | 方案中途拒绝可恢复；外层操作失败时世界与记忆共同回滚；动态势力、军团变更及局部控制切换不残留引用、不清除无关计划 |
| 必选响应与预算 | 战略预算耗尽仍能合法回答电脑待决选择；连续响应有实际进展，不能抢答玩家；同范围没有旧新调度重复执行 |
| 规则平等 | 同条件交换控制者后资格、成本、耗时和效果一致；已声明玩法例外单独列明 |

从最小可运行闭环起执行短程自动对局，配合固定脚本和不同策略对手发现停滞、资源失衡和相互利用的盲点；这不等于机器学习训练，也不替代 G12 长期验证。评估新增搜索或分析时保留其他条件一致的对照，并用未参与调参的场景与种子复核，避免只适应自己的对手和验收地图。

预算梯度实验分别扩大候选覆盖、局部搜索或模拟样本，记录能力指标与成本变化。启发式提供优先级而非不可推翻的选择，评估与候选策略可以独立改进；若更多计算没有收益，先检查评估偏差、候选遗漏和重复工作，不把更高预算本身当作更高难度验收。

报告同时记录任务完成时间、损失、资源消耗、控制地区、无效命令和原因、目标切换、无进展旬数、预算耗尽及各类工作量。墙钟耗时记录全局与单势力的分布，并注明机器和内容规模；测量后登记性能门槛再执行验收，不能只看平均值或只提高预算。

先做一个稳定的标准策略，再用同一场景集定义较低和较高档：调整前瞻、候选覆盖、协调质量和风险策略，信息权限与领域数值保持不变。低档仍保留生存约束；高档不保证每个种子都赢，但应在明确能力指标上有可重复改善。人格偏好以后独立于难度设计。

相关 C# 改动运行受影响测试；共享观察、会话、保存与跨层契约改动运行 `dotnet test San9Remake.slnx`。阶段内使用公开夹具做针对性验证；G11 收口集中做 190 年完整内容、独立 CLI、保存恢复与录像验证，生成报告写入 `local/generated/verification/`。G12 再做固定种子集十年或合法提前终局的全地图压力验收，不把 G11 小局面通过等同于长期平衡或最终画面验收。

## 通用搜索与远期训练

辩证吸收《The Bitter Lesson》中关于利用计算扩展能力的思想：领域规则负责定义合法环境，人工启发式提供初始评估与搜索优先级，不把经验阈值当作不可突破的策略限制。增加确定性预算应能扩大候选覆盖、组合搜索、前瞻或抽样，并通过不同预算的对照验证实际收益；不承诺算力增加必然改善结果。当前以可解释的启发式和有界搜索交付可玩 AI，不为未来训练预建空接口。

待游戏基本完工、规则与模拟器稳定后，再研究借鉴 AlphaGo Master／AlphaGo Zero 所启发的自我对弈、策略与价值学习及搜索结合方向。此处只登记研究意向，不声称两者训练流程相同，也不承诺直接移植算法或获得超人水平；不纳入 G11／G12 的交付门槛。

届时先评估模拟吞吐、动作空间、多势力互动、长周期回报和信息权限，再决定从现有策略数据学习、局部任务训练还是更广泛自我对弈起步。训练策略与固定基线、历史策略及不同对手交叉评估，在未参与训练的剧本、种子和条件中检查泛化；区分合法新策略、模拟器缺陷和奖励设计漏洞。模型、训练配置与评测版本须可追溯，推理与保存重放的一致性届时单独设计。

研究价值可以来自比较搜索与学习的收益、发现人工策略盲点、识别平衡问题和形成可复现实验，不以单纯击败玩家作为科学贡献。研究中的最强策略与产品默认对手分别评估：产品还需兼顾挑战、可理解性、风格与玩家成长空间；强策略可以作为可选挑战或评测对手，不自动替换普通难度。具体科研贡献取决于问题、基线与实验结果，不能由采用某个训练名称保证。

## 旧文档的处理与实施前规格收口

原作研究记录保留为证据，不作为此规划的待办清单。已存在的重制规则仍有约束力：资源守恒、行动资格、控制权、四种委任意图、即时与日级结算时机不能借重新设计 AI 绕开。

实施各子项时同步更新对应 BEH 和必要 DEC；本规划保持草案身份，不用一个新链接隐式改写已确认规格。已识别的收口项如下：

- [治理规格](behavior/BEH-GOVERNANCE-0002-delegation-control-and-automatic-scheduling.md)：移除尚未实现的 `AutomaticWorkProfile`／`CommandPlan` 类型预承诺、固定工作表顺序、原作城市阈值及资金按人数／兵粮按兵数比例分组要求，改写为目标、权限、实际需求与资源守恒；原作基线段仍可保留史料说明。
- [自动外交规格](behavior/BEH-DIPLOMACY-0003-automatic-diplomacy-planning.md)：区分公共外交规则、既有有限策略与新策略，避免继承工作码、编号顺序和旧候选截断。
- [AI 行为规格](behavior/BEH-AI-0001-planning-boundary.md)及[AI 决策](decisions/DEC-AI-0001-deterministic-planning-boundary.md)：补全实际观察权限、持久策略状态、预算计量、批次提交和失效恢复；统一分析种子文字为当前运行种子，保持现有实现语义。
- [保存与录像规格](behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md)：明确策略记忆、策略配置版本、原子发布及一致性校验；沿用精确恢复与玩家读档的随机差异约定。
- [时间推进规格](behavior/BEH-SIMULATION-0001-time-progression-and-state-visibility.md)及涉及的事件、外交和人事规格：按实际迁移范围补充电脑待决状态、响应授权和稳定续行；保留强制规则与玩家选择，不把当前玩家专属响应直接开放给任意控制者。

首个实施切入点为 G11a。先让一个真实经营决策完整经过新观察、规划、提交、保存恢复链路，再逐步扩充能力，避免先搭一批空模块后才发现权限和状态归属不成立。
