## 当前目标与复刻口径

先得到一套有原作证据、覆盖完整控制周期、可独立运行及对照的规则型 AI。保留原版的决策先后、状态转换、候选过滤、排序、阈值、投入数量和受限随机，形成稳定可玩的参考基线；之后再决定恢复何种增强。复刻完成不要求击败老玩家，也不以比当前原型多出征或更快统一作为通过条件。

范围涵盖全局策略准备、军团控制轮转、战略模式与目标、工作批次及尝试门、经营与买卖、人事与配置、计略与外交、军事与建设、输送和撤退、每日部队公共响应，以及所有支持的待决选择。普通电脑、玩家委任、异民族和支持场景分别记录覆盖；项目已明确排除的教学／挑战及小兵培养不因原版存在入口而回归主线。

复刻对象是决策语义。现代集合、类型化引用、公共命令、权限和事务继续保留；源槽位、内存布局、虚表、对象编号上限不进入产品。规则中的最多五人或单次调动十人若确属策略选择，可以作为命名策略参数；不能因此限制人物身份或世界总量。

**当前采用边界：**恢复原版策略顺序、候选排序和有证据的策略门；继续遵守已采用的公共规则、信息权限、独立分析随机与资源守恒。确有冲突的原作读信息、隐式写回或作弊补偿逐项列入差异表，不能静默混成“完整原版一致”。严格同程序随机轨迹和全局逐帧一致不属于本次目标；相同语义输入及注入的规划随机下，已采用的原版规则应得到同一分支和动作。

## 研究依赖

原作事实、争议裁决、研究状态与AI-R01～AI-R14的状态与证据边界只在[原版AI权威研究](../../research/ai.md)维护。2026-10-16已完成决策基线静态研究收口；逐工作覆盖与共享边界复核见该页AI-R13／R14。实现阶段必须链接相应结论，不在本计划另抄研究清单；原作动态对照与重制验收仍须分别记实。

## 实现结构与状态所有权

沿用Application唯一自动控制入口，内部改为“准备当前军团→选择有序工作→在真实执行反馈后继续”的状态机。不要把原作工作顺序映射成现有全局效用分数，也不要让现有SharedAllocator在后台重新排序原版动作。

| 职责 | 建议落点 | 约束 |
| --- | --- | --- |
| 控制轮转、待决恢复、命令身份、外层原子发布 | 既有GameSession、AutomaticTurnRunner、AutomaticResponseRunner | Godot与Headless共用；只改必要接线 |
| 原版工作调度及协议 | Application/AI中的OriginalAiTurnRunner等实际所需实现 | 类型化工作和结束原因，研究码不充当领域ID |
| 内部战略模式与目标 | Application会话持有的显式策略状态 | 与外部CorpsDelegation分开；目标类型安全、失效原子清理 |
| 人员配额、候选及路径分析 | 单个军团／工作单元生命周期 | 可派生数据重建，不把源元数据打包位写进Core |
| 策略门、排序、分配和选项选择 | 无引擎依赖的纯策略函数 | 只消费获准输入、配置、显式规划随机；产生语义意图 |
| 资格、成本、效果、部队自主响应 | Core公共规则 | 玩家／电脑共用；禁止AI私改世界 |
| 工作表、模式参数及人物偏好 | 独立内容可表达的策略定义；确需通用契约时由Content定义 | 原版映射留Importer，Mod不维护EXE地址或偏移 |
| 诊断 | 原有有界诊断入口按新策略调整 | 不保存无用候选，不反馈隐藏信息，不影响选择或随机 |

具体类名是施工建议，不预建空接口。先复用明确符合边界的查询与命令；旧战役观察、粗格路线预测、兵棋估值、训练链和长期承诺不因已存在而自动成为原版规划依赖。原作路径查询的参数和判定用途先恢复，再选择当前共享路径能力；替用近似路线必须登记会改变什么判断并对照，不能默认复用暂停原型的预测。

持久状态仅保存会影响后续决策而无法从当前世界重建的内容：策略版本与实际参数、战略模式／目标、已证实跨旬标志或抽样决定。原版策略准备中跨旬保留的分组标志不能仅按“缓存”删掉。稳定边界若不允许中途保存，批次游标不进存档；事务内仍要保证挂起／续行不重复执行。公共已签发任务以Core为准，不另存一套原版部队真相。

独立分析随机保留原版分支的调用范围、短路和顺序，使用当前项目稳定随机协议；它不要求与原版共享全局随机状态。诊断不得额外投骰。候选自然有穷、元数据尝试数与安全工作上限分开计量：先按已确认的规则完成正常工作，不沿用65536搜索预算任意截断基础工作表；异常规模的保护限额要显式报告未完成，不能当作无候选。限额具体值在代表规模测试后登记。

## 阶段顺序与交付出口

每阶段都是“补研究→无地址行为规格→独立实现→对应验证”的闭环。已有证据能支撑的单元先实现；不先把全部RE重新写一遍，也不先交一个所有模块待机的框架。

| 阶段 | 依赖 | 可运行交付 | 必须通过的出口 |
| --- | --- | --- | --- |
| OAI-00 证据与决策清单 | 本轮盘点 | AI-R01～AI-R13有明确状态、完整工作／提示清单；现有冲突有处置位置 | 39项分支与表外准备均有去向；公共规则与策略分开，影响首个闭环的未知项闭合；已确认异常的产品取舍在对应阶段接入前明确 |
| OAI-01 调度及经营纵向闭环 | 对应调度、战略和经营证据 | 独立内容的小局面运行战略准备、工作门、0–5/61/63，提交公共命令并结束控制 | 顺序与当前反馈、交易、无候选、重复／失败、保存恢复、玩家委任权限通过；生产接管范围唯一 |
| OAI-02 人事与组织配置 | OAI-01；对应人事证据 | 军师、官职、宝物、奖惩、调动、搜索、24/56登用、军团管理及55处置 | 配额→盈缺→调动闭环；执行后后项看到新状态；两条登用与处置全部分支独立验证，无越权／跨账户透支 |
| OAI-03 军事全链 | OAI-02必要人员与策略能力；对应军事证据 | 57撤退、58部署、51输送／后备、9攻击与建设、59部署；查清10/60调用并实现支持路径 | 三组目标、主将／相性成员、兵力、队列、兵法、陆水阵形、建设和失败回退；真实小局面完成经营→补兵→出征→占领，无旧战役搜索代选 |
| OAI-04 计略、外交及全部响应 | 已有公共命令；对应计略外交与响应证据 | 25–36完整策略及所有当前支持提示；接齐每日公共响应 | 外层优先、军师与策略随机符合采纳规则；电脑不悬挂、玩家准确暂停；日内扫描无重复，无界面也能完成 |
| OAI-05 唯一生产入口与协议切换 | OAI-01～04 | 电脑、玩家委任及受支持特殊势力全部切换；原型退出生产；新策略状态、内容及版本接线 | 工作／命令／提示覆盖闭合，删除退出路径的无消费者状态；默认解决方案及独立Headless通过，连续／恢复／日志／录像一致 |
| OAI-06 完整内容与原作基线验收 | OAI-05 | 190年完整内容、代表势力规模、原版决策对照、长期全图报告 | 固定种子十年或合法提前终局，无权限／资源／引用错误；分支符合性、差异表、冷暖性能及最慢军团有记录；G11/G12按实际出口判定 |

顺序允许在一个阶段内穿插已具备证据的策略，但生产切换必须按“控制范围×行为类别”登记唯一执行者。开发中可以用测试宿主调用新策略、在测试侧保留旧原型对照；未迁移行为仍归原执行者，不能让旧共同分配器再次为已接管范围生成同类命令。OAI-05完成后产品不保留长期双调度、自动回退或复刻开关。

OAI-01只证明骨架和经营可运行，不代表原版AI完成；OAI-03只证明军事闭环；全部策略、响应、内容、协议和长期对局闭合才交付完整参考基线。当前OAI-00的静态规则研究已收口，尚未接管生产实现；新确认的原作异常及隐式状态修改必须在对应阶段实施前明确采用方式，不能静默复制或修正后宣称原作一致。

## 现有代码的具体处置

| 现有实现 | 处置 |
| --- | --- |
| AutomaticTurnRunner、GameSession事务、自动／玩家控制划分 | 保留入口职责，核对军团轮转和批前准备，逐步换内部执行者 |
| AutomaticResponseRunner、公共待决命令、Core结算 | 保留公共协议；逐类核对策略答复，不能原样保留“更合理”的经验选择冒充原作 |
| DomesticPlanner及公共资格查询 | 保留仍有脚本消费者的部分；复刻经营按原作候选、人数、阈值实现，不直接认定可复用算法 |
| AllocationTurnRunner、SharedAllocator、AllocationObservations | 最终退出原版生产调度；只复用独立、确有用途的公共投影，不给新工作表套共同评分 |
| CampaignObservation/Planning/Crews/Formations/Equipment/CombatForecast、FieldOperations、TrainingPlans | 自主增强原型；有独有价值的验证留测试侧，产品消费者归零后随迁移删除，避免无关大清理 |
| EconomicPlanning、OpportunityPlanning、PersonnelConfiguration | 区分公共查询与原型策略；买卖、外交、宝物及官职的原版策略重新按证据接入 |
| AiSessionState中的FoodSecurity/Campaigns/Opportunities和domains-v1 | 不机械映射为原版记忆；替换为确需状态，同步保存、摘要、日志／录像协议，明确拒绝旧版而非兼容 |
| AiPlanningTests等原型质量夹具 | 保留仍约束公共安全、确定性和权限的测试；与新目标冲突的能力断言转为暂停路线对照，替代前记录独有覆盖 |
| CampaignRoutePlanner及导航诊断 | 是否复用由原版距离／时间／阻塞契约决定；不默认继承近似误差，也不另造第二套实际行军 |

## 原版与重制差异的明确处理

| 主题 | 原作证据 | 当前处置与接入要求 |
| --- | --- | --- |
| 工作顺序、尝试数、开局等待和编号周期 | [工作调度](../../research/ai.md#schedule) | 作为策略门恢复；公共玩家命令仍保持已采用规则。周期原作按记录身份错峰，重制需定义稳定身份派生的调度键，禁止限定身份范围 |
| 电脑专属褒美门、攻击请求跳过、劝降抑制 | RE-0112/0120/0174 | 按策略恢复并验证，在新行为规格声明采用规则与差异，旧AI规格冻结；不修改双方公共成本／效果 |
| 内部战略模式及分组标志 | [战略状态](../../research/ai.md#strategy) | 采用类型化状态与完整更新，不等同CorpsDelegation、不使用固定槽数组；历史人物偏好转换为显式内容标签／引用 |
| 敌方目标／准备状态、真实接受阈值 | RE-0080/0120/0174 | 逐读取点核对现有信息权限；若原版读取超出许可，明确登记差异并用获准查询映射。缺口不能以隐藏真相或任意估值悄悄补上；严格一致场景限于可提供等价输入的范围 |
| 开局资源倍率、难度加兵、电脑强度伤害修正 | RE-0071/0174 | 属于规则／场景配置，保持现有已采用边界，复刻AI本身不打开；原作对照须归一化或单列输入，不能混作策略能力 |
| 整编禁用及当前公开资格修复 | BEH-AI、公共命令规格 | 保留；原作有调用则明确无该产品能力，不添加AI专用绕过；不恢复原作少付钱等漏洞 |
| 固定人数、兵力阈值、区域分组 | RE-0079/0123等 | 已确认的策略常量可保留并具名；原版固定记录数量、编号判断改为语义内容和可扩展集合 |
| 全局随机、身份并列、路径与时间 | 原作静态关系及既有随机／导航约定 | 保留分支与分布，采用稳定独立规划随机；显式并列和路径差异记录，不能声称二进制级同轨迹 |

此表给出本次复刻的边界和实施时规格修订方向，当前运行行为尚未改变。不能只新建计划就宣称BEH/DEC中旧策略要求已完成迁移。新行为在本目录独立规格中定义；必要公共治理、外交、保存／录像和内容契约在实际接入时同步；重制公共安全不随原版启发式退回。

## 验收、诊断与成本

详细标准见[原版基线验收](acceptance.md#原版-ai-参考基线验收)。每次失败定位到“未到工作门、无候选、排序／评分、随机未通过、提交失效、已执行、未完成”，同时记录军团、工作、输入版本和对应研究规则；不把无动作一概算作AI卡住。

先用自制小场景覆盖全部分支、等号、并列、输入顺序、低资源、无路、无将及候选被前项消耗。含随机的策略用可注入的规划序列检查阈值和调用顺序；不靠统计碰撞验证单分支。军事再通过真实Core推进检查来源扣兵、实际抵达、战斗／占领及撤回，不把生成合法命令当作完成战役。

原作对照由可重复的局面、原版版本、控制方、难度、日期、人物／资源和目标约束登记；比较工作门、排序、投入和分支，列出公共规则差异。原作使用不同随机流时比较可控抽样与分支条件，不强求长期相同最终哈希。

性能沿用标准运行时、顺序单独测试，区分首轮与预热；登记整旬平均／P95／最大值、最慢军团、分配量、路径查询和各工作成本，同时报告行为轨迹差异。先在OAI-01与OAI-03代表规模测量，OAI-05前冻结具体门槛，再用未调参场景验证；不预填未经测量的毫秒数。暂停版本的503～610ms短测及v112历史基线只能作背景。

文档／研究交付检查引用、工作目录、IDA实际写入和回读。局部策略实现按影响运行Application等相关测试；共享契约／跨层改动运行 `dotnet test San9Remake.slnx`；保存、日志、录像及CLI接线另运行 `dotnet test tests/San9.Headless.Tests/San9.Headless.Tests.csproj`。不为纯计划改动运行产品测试或重转包。
