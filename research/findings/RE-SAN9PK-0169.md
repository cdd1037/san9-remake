## 容器覆盖（事实，高置信度）

私有数据目录的 52 个 `G_*` 档案包含 7,858 张索引图和 3 张 24-bit BMP。本轮按档案记录核对来源范围；产品转换不按当前剧本、可见武将或已接入窗口筛选。当前产品采用单份头像／宝物大图，不导出未确认映射，详见下文重制选择。源图可能本身是一张动画长条；记录数不等于动画帧数。

顺序容器先记录总长度，再按 `size/stride/width/height` 四个 DWORD 和索引像素顺序存储；组合容器先保存 `4 + paletteCount × 1064` 字节调色板区，再接上述顺序容器。`G_Common` 实为 67 套调色板、491 张图；`G_Main` 为 21 套、98 张。原版长条可超过 4096 像素宽，例如标题图宽 4576，旧的解码上限不适用于完整档案。

`0x4225D0` 先读取记录数及 DWORD 偏移表，按绝对文件偏移定位同样的 16 字节图像头。独立文件扫描确认以下四个档案严格匹配，所有记录闭合到文件尾：

| 档案 | 图像数 | 外置调色板数 |
| --- | ---: | ---: |
| G_DynEff | 112 | 28 |
| G_Ikki | 80 | 19 |
| G_Gaikou | 51 | 3 |
| G_ZoomIn | 145 | 102 |

三张 Radar BMP 分别为 52²、84²、164²，24-bit BGR、从底至顶，像素区后有额外 2 字节；不能把像素区长度必须等于文件长度当成 BMP 不变量。

## 静态注册表（事实，高置信度）

`0x421890` 的每项为资源 ID、全局调色板槽两个 DWORD；资源 ID 的低 16 位标识资源。加载函数给出各档案的资源起点及调色板起点，二者与注册表联用确定对应关系。

| 注册入口／表地址 | 文件偏移／数量 | 档案组 |
| --- | --- | --- |
| 4218D0 / 650290 | 24EA90 / 1425 | Common、Flag、Name、Jinkei、MMap、Marker、EditPK、LocCPK |
| 533680 / 6619D0 | 2601D0 / 1145 | UnitS、Effect、LBuild、LBAdd、Main、LocalM |
| 51C990 / 65E7D0 | 25CFD0 / 1070 | LLand、LHashi、LCloud、LMask、MapMkr、MASK、MESH、MapCov |
| 54FF30 / 665E98 | 264698 / 51 | Ending |
| 561970 / 668D50 | 267550 / 447 | Start、LocSPK、StrtPK、Start2、BGGAL |
| 563770 / 66A168 | 268968 / 4 | TitlPK |

档案加载实参分别见 `0x423270`、`0x5336A0`、`0x51B940`、`0x54FF50`、`0x561990/5619E0/561A00`、`0x563790`。转换器保存源定位与注册起点，不把反编译实现移入产品。

`G_LocMPK` 的 `0x5B2100` 及 `0x5B21C0/5B21E0/5B3370` 调用明确：前 64 张为 32 组双图，交替使用调色板 0/1；64..67 使用调色板 2..5。`G_Still/G_StilPK` 的 `0x423840` 加载链按相同图像／调色板索引读取，保留全部 283+14 张。六个头像档案完整保留 786+50 组大、中、小三种尺寸和两套原始调色板；导出两套 RGB 变体不表示当前游戏应切换到第二套。

## 动态档案映射（事实，高置信度）

- **DynEff**：`0x546F80` 使用 `0x546F70` 返回的 12 字节表项。表 `0x665440`（文件 `0x263C40`）有 28 项，依次为起始图号、图数、动作元数据；每套调色板绑定连续 4 图，覆盖 0..111。第三字段不是调色板号。
- **Ikki**：`0x548050` 的图像加载段在主库存在部分误分类，读取原始指令而非依赖失败的反编译。`0x547640` 返回背景号 0..8；`0x5480D2..5480E7` 把同一个结果传作图号和调色板号。`0x548143..54814E` 将 `P_Ikki[9..18]` 加载到槽 116..125，`0x548153..548161` 将图 9..59 加载到资源 30006..30056。结合表 `0x665590`（文件 `0x263D90`）得到逐图调色板。`0x5476E0` 将 60..69、70..79 替换到两组相同资源槽，因此分别使用调色板 17、18。`0x422780/4227F0` 的区间加载行为经指令／调用交叉核对。
- **Gaikou**：`0x54BD90` 的所有标志分支、`0x54D170` 的三段文字背景和 `0x54D520` 的背景合成共同覆盖全部 51 图。图 0..24 使用调色板 0，25..47 使用 1，48..50 使用 2。纹理颜色与具体控件的混合方式是两个不同事实。
- **ZoomIn**：`0x543310/5434C0/543620/542E60` 生成的布局将 0..55 的图号和调色板号设为相同值；`0x545D10` 明确补充 56/57。表 `0x664DB8`（文件 `0x2635B8`）的 23 个 52 字节记录经 `0x542F00/542F20/543D80` 给出 58..119 的绑定，类型 9 还有 `0x664DB0` 额外项。`0x543E90/545940` 补充 120..144，对应调色板 77..101。最终 145 张图全部有映射。

## PK 主程序未加载的来源档案与未决语义

以下676张的原始像素和调色板仍可在私有源档案中读取，当前转换包不收录。2026-09-12 对主库补做了完整文件名字节搜索、加载函数交叉引用闭合和调用实参复核：它们不是“已确认消费者但尚未转换”的纹理，而是当前繁中 PK 1.0.1.0 主程序没有加载的来源档案。来源文件存在仍不能证明其运行时用途、调色板绑定或混合语义。

- `G_LNMASK`：640 张，无内置调色板；320 张为 64×32，160 张为 64×42，160 张为 64×22，索引值只覆盖 0..25。`load_map_visual_resources(0x51B940)` 的穷尽清单不含它，EXE 映像中也不存在文件名字节。低值像素分布支持“非普通彩色图”的候选解释，但它是否为标量遮罩、如何解释数值仍未确认。
- `G_LNUKI`：32 张，无内置调色板；来源尺寸为 64×20/32/44 和 96×64/88。`P_NUKI` 确实包含三套调色板，但两者的文件名字节和加载链均不存在于主样本；不能仅由并存关系推定逐图绑定。前16张主要使用索引0/255，后16张覆盖约30个索引值，这也不能代替消费者证据。
- `G_Title`：4 张基础版标题图、4 套内置调色板。`CTitleView` 的 `0x563770/0x563790` 明确注册4项并只检查、加载 `G_TitlPK.s9`；表 `0x66A168` 将资源3000..3003依次绑定调色板0..3。EXE 映像没有 `G_Title.s9` 字节或加载路径，因此这4张可确认为当前 PK 样本不消费的基础版替代资源，而不是待猜测的 PK 标题绑定。两档案虽图数和尺寸相同，前三张索引像素不同，不能互换。

调用边界如下：通用归档入口 `0x422170` 只有 `0x423020`、`0x4230A0` 和 `0x51B940` 三处代码引用；`0x4230A0` 的六个调用点均传入已知固定文件名，地图入口 `0x51B940` 则显式列出 `G_LHashi/G_LLand/G_LCloud/G_LMask/G_MapMkr/G_MASK/G_MESH/G_MapCov/G_MpMkPK` 及其调色板。偏移表归档入口 `0x4225D0` 的六个调用点只覆盖 ZoomIn、DynEff 和 Gaikou。这个闭合集合排除了通过现有通用图像加载器动态拼出上述三个文件名的可能；不能外推到其他版本 EXE 或安装目录外工具。

`F_Font/P_Font` 属于独立字形、字号和文字样式管线，不是本次 52 个 `G_*` 图像档案覆盖声明的一部分；当前客户端继续使用现代字体。档案语义未决不等于像素丢失，也不等于未来玩法已实现。

## 重制选择与验证

2026-09-12 重制选择更新：独立纹理包替代剧本附带资源库；不再保留索引 PNG 与原始调色板字节。头像、插图、CPU地形按明确的不透明用途处理，其余目录默认提供透明键 RGBA；具体调色板 Alpha 和加色解释仍以消费者证据为准。该目录默认规则是重制选择，不是对每个原版调用的混合语义结论。最终逻辑图统一做透明 RGB 扩边后入图集，以免绿色键色在缩放／合成时渗入。

使用确定性最大空闲矩形装箱，保留 2 像素扩边、不旋转、不裁剪；源长条超出 2048 页尺寸时独立保存。运行时旗帜按旗杆、16 色段、32 字形段及季节组合分组，以减少单动画小页。资源库不参与首屏预加载。

独立核对脚本：[verify_texture_library.py](../scripts/verify_texture_library.py)。`verify-client` 校验所有物理 PNG 的指纹、格式和区域；脚本逐项与原版索引像素及调色板颜色比较，也可与先前显示图片基线比较。实际游戏画面由用户验收。
