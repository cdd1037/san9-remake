## 调查范围

调查 `item` chunk 的 22 字节记录如何被目标程序反序列化，以及电子书所述宝物字段能否与目标样本、20 个正式剧本和运行时引用规则闭合。

样本来自私有目录 `private/游戏文件/`，只读检查，不写入仓库。

## 目标程序证据

`deserialize_item_record`（`0x447ED0`）由剧本总加载器固定调用 120 次。函数每次恰好调用 11 次 16 位小端游标读取器，完整消费 22 字节：

| 文件偏移 | 运行时处理 |
| --- | --- |
| `0x00` | 读取但不作为运行时 ID；运行时 ID取调用方记录序号 |
| `0x02` | 保存到运行时 `+0x30` |
| `0x04` | 保存到运行时 `+0x34` |
| `0x06` | 保存到运行时 `+0x3C` |
| `0x08` | 保存到运行时 `+0x38` |
| `0x0A` | 保存到运行时 `+0x40` |
| `0x0C` | 保存到运行时 `+0x44` |
| `0x0E` | 小于 41 时保存兵法编号，否则转为 `-1`；运行时 `+0x48` |
| `0x10` | 通过 `get_person_record` 转为武将指针；运行时 `+0x54` |
| `0x12` | 保存到运行时 `+0x4C` |
| `0x14` | 小于 250 时保存地点编号，否则转为 `-1`；运行时 `+0x50` |

目标中存在 120 项、步长 `0x58` 的运行时表和完整边界访问器。访问器非法索引返回空指针。

## 文档与数据交叉验证

电子书把相同 11 个字段描述为三个顺序/资源编号、图像、类别、忠诚变化、能力增加、兵法、持有武将、出土状态和发现地点，并给出第二项宝物的完整 22 字节示例。其偏移、宽度、兵法空值、武将编号及地点字段与目标函数完全一致。

对 `D_Sce001.S9` 至 `D_Sce020.S9` 的 2,400 项记录逐项只读检查：

- 三个编号字段在全部文件中都等于 0–119 的记录序号。
- 兵法字段始终为 `0xFFFF` 或小于 41。
- 持有者字段始终为 `0xFFFF` 或小于 850。
- 状态字段只出现 0、1、2。
- 地点字段始终为 `0xFFFF` 或小于 250。
- 图像编号均小于 100，类别编号均小于 13。

190 年剧本中前三个编号字段都等于记录序号；图像字段在前 100 项为 0–99，后 20 项均为 0。目标代码也只为运行时 ID 小于 100 的项目走内置名称和说明文本路径，支持“100 个内置宝物＋20 个额外槽位”的边界。

## 事实、推断与保留项

- 事实：记录数量、大小、11 个字段宽度、加载顺序、运行时偏移、兵法/武将/地点范围处理和 20 个剧本的数据不变量。
- 多来源支持的业务语义：图像、类别、忠诚变化、能力加成、兵法、持有者、出土状态和发现地点。
- 保留项：`0x02`、`0x04` 的具体资源用途，13 个类别的显示名称，状态码 0 的含义，以及地点编号到 Zone/City 的映射。

### SCN-02 消费者补证

- `item +0x0A` / 运行时 `+0x40` 进入授予和没收的忠诚路径；授予使用原值，没收惩罚使用 `3/2` 倍。该字段还用于赠与阈值的宝物加成，不能概括为只用于忠诚，见[RE-0117补证](RE-SAN9PK-0117.md#2026-09-17-赠与宝物公式输入补证)。
- `item +0x0C` / 运行时 `+0x44` 是独立能力加成，不从忠诚字段乘系数得到。
- 类别 2、1、5/9、3/4/6 分别映射统率、武力、智力、政治；其他类别不进入四维加成。
- 人物持有多件作用于同一能力的宝物时只取最大 `ability_bonus`，不同能力分别计算；随后再独立叠加人物 `shak` 官职能力加成。

## IDA 标注

- `0x453190` 经 dry-run 后命名为 `get_item_record`。
- `0x12565A0` 经 dry-run 后命名为 `san9_item_records`。
- 两项写入均未覆盖人工名称；访问器的 120 项边界和 `0x58` 步长在完整函数体中保持不变。
- 建立 `San9ItemRecord` 运行时类型骨架，总大小 `0x58`。已知成员严格落在反序列化写入偏移；对象头中未解释的 `0x08..0x0F` 保持为 `unknown_008`。
- 为全局表应用 `San9ItemRecord[120]`，并为访问器和反序列化函数应用明确签名。
- 重新反编译后，11 个读取顺序、范围判断和控制流不变；伪代码现在直接显示 `image_id`、`category_id`、`tactic_id`、`holder_person` 等已确认成员。
- `deserialize_item_record`、访问器和运行时表加入本记录引用及序列化/运行时大小说明。
- 未修改程序字节、函数边界或未经确认的业务字段类型。

## 独立实现

`San9ScenarioItemArchive` 依据已确认规格独立读取 120 项记录，保留全部原始值并校验编号、图像、类别和三类引用范围。实现没有复制反编译伪代码或电子书中的工具代码。
