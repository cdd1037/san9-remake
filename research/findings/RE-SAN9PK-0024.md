# RE-SAN9PK-0024：`squa` 未命名地图字段的样本收窄

- 状态：部分闭合；`+0x02` 收窄为地图块/占用描述候选，其余未知字段暂缓命名
- 日期：2026-08-16
- 结论类型：样本事实、黑盒显示对照、低至中置信度推断、待验证项
- 置信度：高（跨样本不变量、数值分布、特殊值集合）；中（地图块/边缘编码候选）；低（具体 bit 义和玩法效果）
- 关联来源：[RE-SAN9PK-0019](RE-SAN9PK-0019.md)、`SRC-SAN9PK-TC-101`、`SRC-SAN9PKHARD`、`private/s9数据文件/`、`private/剧本编辑器截图/square.png`
- 关联规格：[BEH-IMPORT-0014](../../specs/behavior/BEH-IMPORT-0014-scenario-square-records.md)

## 1. 黑盒显示不是文件记录的逐项布局

`square.png` 中第 0 格原始记录为：

```text
00 00 C6 03 76 00 FF 00 04 02 00 02 00 00
```

编辑器未知栏显示 `0002=966、0004=255、0006=512、0008=0`。这与以下**显示层组合**相符：

```text
0002 = u16(file + 0x02)                 = 0x03C6 = 966
0004 = u16(file + 0x06)                 = 0x00FF = 255
0006 = u16(file + 0x0A)                 = 0x0200 = 512
0008 = u16(file + 0x0C)                 = 0x0000 = 0
```

这只是编辑器把相邻原始字节合并显示的证据，不能覆盖 IDA 反序列化器对 `+0x06..+0x0D` 逐字节读取的事实。导入器仍按 8 个 byte 保存。

## 2. 跨样本边界

对正式 `D_Sce001.S9`–`D_Sce020.S9` 和教学 `D_Ttrl00.S9`–`D_Ttrl05.S9` 的 `squa` 数据区逐字节比较，26 个文件完全相同。因而 `squa` 在这两个家族中是共享地图模板，不携带每个正式剧本的城市、势力或部队初始差异。挑战剧本具有另一份地图数据，本结论不把挑战格式纳入 MVP。

正式地图中 `+0x0C` 的分布为 `0` 共 39,928 格、`1` 共 72 格；所有 `+0x0C=1` 的格同时满足 `terrain_code=11`、`offset_code=1`。但 `terrain_code=11` 共 144 格，其中只有 72 格的 `+0x0C` 为 1。因此它不是“地形 11/桥”的简单布尔镜像，更像桥地形的子类型、叠加层或方向/连接标记；这是推断，不是已确认业务名。

`+0x0D` 在正式地图中有 52 个取值，`0` 占 30,333 格，其余 9,667 格集中出现在地形边界、浅滩/水域交界和地图对象周边。高频值包含 `0x11、0x22、0x33、0x44、0x66、0x88、0x99、0xCC` 等重复半字节模式。该空间分布支持“边缘、连接或地图图形选择码”候选，但没有证明某个 bit 对应某个方向。

## 3. `+0x02` 的地图块描述候选

`+0x02` 在正式地图中有 209 个取值，并非随机自由整数。几个空间对照很稳定：

- 50 个城市坐标处均为 `0x4201`；
- 固定建筑坐标处通常为 `0x4201`，固定建筑类别 2 和 3 的代表值分别为 `0x6201`、`0x5201`；
- 普通地图中大量出现 `0x0200、0x03FE` 及其局部变体，且随地图边缘和对象 footprint 改变。

结合 IDA 证据，文件 `+0x02` 写入运行时 `CSquareData +0x34`，通用 getter `0x45CFC0` 可以直接返回该槽位。因此最稳妥的当前名称是“地图块/占用描述候选”，不能进一步命名为城市、道路、地形或通行 bit 集。它是 MVP 地图拓扑闭环仍需确认的最高优先级 `squa` 字段。

## 4. 其余字段的排除结果

- `+0x06/+0x07`：合并显示为 16 位值时有 453 个组合，不能由地形或偏移代码一一决定；IDA 仍证明它们分别进入运行时 `+0x18` 和 `+0x24`。
- `+0x0A/+0x0B`：合并后有 47 个组合；`+0x0A` 低字节为 `0..14`、`+0x0B` 高字节为 `0..5`，但与 `ZoneCode → city.AreaCode` 的逐格对照不成立，不能命名为州域/区域编号。
- `+0x0C`：当前正式样本只有 `0/1`，且与地形 11 有强关联；仍不能确定是玩法通行、桥梁连接还是图层标志。
- `+0x0D`：加载到运行时 `+0x36`，当前通用 `CSquareData` getter 没有覆盖该偏移。`San9PKHard` 中对 `0x45D070` 的调用证明路径/地图块逻辑会消费地图对象，但现有源码没有把该 helper 的读取落点闭合到 `+0x36`，所以不能据此宣称它“无效”。

## 5. 当前处理决策

| 字段 | 当前结论 | 优先级/动作 |
| --- | --- | --- |
| `+0x02` | 地图块/占用描述候选；有通用 getter | P0：保留原值，后续只做 editor 单变量差分或明确消费者追踪 |
| `+0x06/+0x07` | 两个运行时 byte；显示层会合并 | P1：保留原始字节，暂不导出玩法属性 |
| `+0x0A/+0x0B` | 地图局部编码候选；已排除直接 AreaCode 等价 | P1：保留原始字节，暂不命名 |
| `+0x0C` | 桥地形子集/叠加标志候选 | P1：保留原值；不当作通用桥标志 |
| `+0x0D` | 边缘/连接/图形选择码候选；直接 getter 未发现 | P1：保留原值；当前暂缓 |

本轮未找到足以把这些字段写成重制玩法规则的证据。实现只需无损导入；MVP 可以先以已确认的地形、偏移、Zone 引用和城市/据点坐标建立地图骨架，不能在缺证据时把候选 bit 直接变成通行规则。

## 6. 下一步最小实验

若继续处理 `squa`，收益最高的是在编辑器中只修改一个未知显示项后比较 `squa` 的差分，并同步观察城市/据点坐标附近的 `+0x02` footprint；其次是用 IDA 追踪 `0x45D070` 的被调函数读取的具体 `CSquareData` 偏移。没有这两类新证据时，继续对现有库存样本做频数统计不会可靠地产生业务名称。
