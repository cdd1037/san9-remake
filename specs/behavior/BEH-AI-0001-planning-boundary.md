# BEH-AI-0001：AI 观察、规划与命令提交边界

- 状态：已确认
- 负责人：项目开发者
- 最后更新：2026-10-12
- 关联证据：不适用（原创新增）
- 关联决策：[DEC-AI-0001](../decisions/DEC-AI-0001-deterministic-planning-boundary.md)、[DEC-SIM-0001](../decisions/DEC-SIM-0001-determinism-and-saves.md)
- 继承方式：原创新增

## 适用范围

适用于 AI 势力在稳定规划边界读取观察、执行分析、生成候选命令并提交选择的公共生命周期，以及规则平等和难度表达的约束。系统设计、能力范围、实施步骤和阶段验收统一见[游戏 AI 系统设计](../ai-system-design.md)。本文当前基础协议及已通过条目不代表完整自主 AI 已实现；AI-01～AI-04 已接入经营目标、共同分配、战役闭环、配置和成功执行反馈，全领域能力按后续阶段扩展。

## 原作基线

不适用。本规格定义重制版为确定性测试、长期模拟和现代 AI 扩展建立的系统边界，不声称描述原作内部结构或决策算法。

## 重制行为

Application 在稳定规划边界从已提交的世界快照构造势力视角观察。观察只包含该势力获准读取的信息、权威日期和独立分析种子，不暴露可变世界对象或正式随机状态。规划器读取观察、命名规划用途、确定性预算和诊断级别，返回保持偏好顺序的候选命令、整数评分、理由和可选诊断。

每个候选先经过公共命令验证；只有被选择且验证成功的候选进入公共命令执行入口。验证失败不写世界状态、不占用命令 ID，也不阻止调用者检查下一候选。分析使用由本次运行种子、势力、权威日期和用途派生的独立稳定随机流；重新创建同一上下文会从同一分析种子开始，不改变正式结算随机序列。玩家读档更换运行种子可以改变分析抽样，精确恢复及录像不变，见[随机约定](../../docs/randomness.md)。

诊断只解释已经产生的分析与候选。关闭、摘要或详细诊断级别不能改变分析预算、随机消费、候选集合、评分、顺序或提交结果。

玩家与AI默认遵循相同资源、资格、耗时、信息权限和效果规则。同等世界条件下仅交换控制者，不改变公共命令结果；明确采用的辅助或模式例外须由对应规格声明。难度优先改变规划质量、确定性工作预算和决策策略，不隐式改变资源、战斗数值、命令成功率或开放隐藏信息。具体取舍见[规则平等与能力驱动的难度](../decisions/DEC-AI-0001-deterministic-planning-boundary.md#规则平等与能力驱动的难度2026-09-21)。

整编指令全局禁用，AI（含委任军团）不得生成、评分或模拟整编候选；公共命令入口也拒绝执行。该重制新增指令的状态见[整编规格](BEH-WAR-0001-movement-and-command-lifecycle.md#g07-显式整编与水陆入口)。

褒美不继承原作电脑专属的开局等待与编号周期窗口。双方共享人物每旬次数、资金和人物资格；AI根据当前忠诚风险、预算和机会成本生成候选。此项为已采用的重制选择，自动规划尚待G11实现，不表示原作没有时间限制。

## 状态与不变量

### 当前经营接线

经营规划使用 `DomesticObservation`，按当前控制范围投影有效据点、实际账户及未行动且未被任务占用的本方人物。权限查询与 Core 最终授权共用同一地点归属判断。`DomesticPlanner.Plan` 不接收世界、会话、引擎或验证回调；工作预算计入据点、活动和人员组合访问，返回意图及预算耗尽状态。会话侧绑定身份和序号，再经公共验证选择并执行。`EconomicObservation` 进一步投影账户到下次可靠收获前的粮耗及本方合法购粮报价；粮耗由 `FoodSupplyInput` 的明确账户输入通过共享纯规则 `FoodSupplyForecast.Evaluate` 计算，表现层经济预测复用同一计算，`EconomicPlanner` 只消费该不可变观察与获准的缺粮记忆。购粮优先供养缺口，禁止跨账户支付；每条接受后重建临时账本和可用人物，失败内政候选按确定性工作额度继续检查。缺粮且没有可用购粮方案时保留资金，只允许不收费的训练。购粮、内政、人事、救援由 SharedAllocator 共同分配；征兵受未来粮食保障约束，投送与在途到账计入账户粮耗时间线。战役已接入 AI-04，其余领域观察仍按唯一 AI 计划后续接入。

`AutomaticTurnRunner` 统一结束控制与推进入口的自动工作。电脑势力的根军团及直属范围由势力批次处理，不再重复作为委任根军团运行；玩家委任范围继续使用其自身控制者授权。电脑直属经营和委任经营每批最多选择配置允许的购粮次数及一条合法内政；已购粮的人物与使用过的交易地点不能重复占用。AI-01 的 `AiSessionState` 保存 `campaign-v1` 配置实际值和首次建立日期的账户供养目标；目标只在缺口满足或权限失效时清除。状态随世界分叉计算，成功外层操作才一起发布，拒绝或重复请求不留下目标、记录或水位变化。工作计量覆盖投影、比较、生成及候选检查，额度耗尽仍能记录真实供养目标。Headless 验证只向玩家席位签发脚本命令，自主席位由会话生成自动命令并在录像重放时再生。

### AI-03 共同分配

`AllocationTurnRunner` 在同一势力批次汇集自动控制范围，共用配置工作额度（标准 65536），逐条经公共入口执行并刷新实际状态。紧急救援按共享到达窗口、公开敌方力量与源城留守生成候选，计入准备、调将、在途援军、运输粮耗和武将离队后的防御；合法人事候选与经营争用可行动人物。钱粮保持账户所有权，未来运粮不能支付当前或到达前的消耗。战役、外交及计略进入同一预算和候选比较，外交与计略的机会观察已在 AI-05 迁移。

共享路线输入不含完整世界或敌方隐藏命令；预测区分已知到达、等待、不可达和未完成。批次缓存覆盖输入依赖，仅复用确定结果，命中仍计查询工作。独立有界诊断记录预测与运输实际结果，在事务发布后更新，不保存、不改变权威摘要或决策。有限威胁假设及证据见[AI-03 已实现行为](../ai-system-design.md#ai-03-已实现行为与证据)。

### AI-04 战役闭环

生产军事使用 `CampaignObservationCapture` 与纯 `CampaignPlanner`，不再调用旧脚本进攻策略。候选比较出征后的留守、真实到达窗口、普通战损与耐久、多城会师、实际账户的整体供养和占领后的反击；缺将、士气、兵力或粮食时先提交有用且可负担的前置行动。公开敌情采用明示联合假设，未知敌方统率使用基础估计，不读取敌令、可行动状态或预抽结果。目标机动价值来自公共运输路线，不增加独立补给线。

跨旬目标保存准备、集结、进攻、巩固、退出与冷却阶段，只记录实际成功签发的部队及必要源城；行动失败不建立虚假在途承诺。每个下令边界重新检查归属、保护关系、路线、力量和供养；正常行程保持目标，真实停滞或失效经公共军令撤回。缺粮不阻止合法的减耗撤回；有效返程不反复改令。占领后巡察、修复、训练及接收未到场力量，守备与巩固满足后完成目标。冷却随公开条件变化失效，不永久封禁有效目标。未完成观察或比较保留承诺，不视为不可行。

有限算法、参数与证据见 [AI-04 已实现行为](../ai-system-design.md#ai-04-已实现行为与证据)。当前 `domains-v1` 配置和战役目标与世界原子发布，参与保存、会话摘要及录像；旧结构不增加兼容路径。

### AI-05 全领域贯通

外交、计略、搜索、登用与人事配置进入共同分配。纯机会规划消费合法行动及公开军师意见，按公共准确性解释可靠程度，再比较收益、金钱、行程与人物机会成本；不读取正式骰子。任务反馈保存必要的在途身份与短期条件冷却，按行动目标关联，过期或权限失效清理。人事配置分别比较当前咨询价值及恢复后的长期装备／官职收益，临时军师更替不绑定剥离装备。

自动响应扩展至普通招募、求仕、联盟、外交反要约、拥立、国号和战斗继任，Core 统一产生待决，Application 按实际合法控制者回答。玩家选择保持暂停，强制规则及玩家直辖特殊搜索、修习资格独立保留。逐项命令采用／排除及有限策略边界见 [AI-05 已实现行为与证据](../ai-system-design.md#ai-05-已实现行为与证据)。

### 通用协议

经营观察按显式剩余额度在调用前计费账户预测、据点分析与购粮报价；观察不完整时保留未观察账户的缺粮目标，不能视为缺口已解决。购粮候选包含单人及最多五人的组合，满足同等缺口时优先少占人物；购粮成功即可按真实效果清理完成目标，无额外不计费收尾观察。基础权限投影与公共查询内部扫描不计作搜索节点，当前逻辑工作预算不等于全世界逐对象计算上限。

- 输入与前置条件：稳定世界快照、有效观察势力、非空命名用途、至少一项为正的节点或 rollout 预算、有效诊断级别。
- 状态变化：观察、上下文、计划和诊断均不修改世界；只有公共 `Execute` 接受的命令提交即时效果或持续任务。
- 始终成立的不变量：规划无可变世界引用；分析随机与结算随机隔离；工作预算确定；诊断不影响行为；玩家与 AI 共享最终验证和结算。
- 失败或无效输入行为：空用途、零或负预算、无效诊断级别及无效候选被明确拒绝，不使用默认无限预算、墙钟超时或宽松 AI 专用提交路径继续。

## 示例与边界

- 同一运行种子、势力、日期、用途和预算及观察数据重复规划，候选及顺序相同。
- 同一上下文分别关闭和开启详细诊断，候选完全相同，只有诊断集合不同。
- 分析运行任意允许数量的 rollout 后推进一旬，结果与未运行分析时相同。
- 候选命令使用负序号时，验证和提交返回同一拒绝原因，旬事件中不存在该命令的结算事件。
- 未来战争迷雾只改变观察生成策略；规划器不存在读取完整世界的后门。

## 验收标准

- [x] 不可变观察不暴露 `WorldState` 或正式随机状态。
- [x] 同一观察、用途和预算产生同一分析种子及计划。
- [x] 分析随机消费不改变正式旬结算结果。
- [x] 诊断级别不改变候选命令。
- [x] 零预算、负预算、空用途和无效枚举被拒绝。
- [x] AI 候选通过公共验证和提交入口，拒绝时无部分写回。
- [x] 测试夹具不依赖原版文件、私有样本或研究工具。
- [x] AI-01 覆盖真实多旬购粮、目标完成、配置保存、精确恢复／录像、自动动作后外层回滚、隐藏外方信息隔离、多账户／共账户、权限撤销、低预算与入口去重。
- [x] AI-03 覆盖及时救援、主将离队后留守、准备迟到、人员瓶颈、购粮竞争、跨账户调粮、在途去重、预测结果对照、隐藏敌方输入隔离、工作有界及恢复／录像确定性。
- [x] AI-04 覆盖真实准备到占领与巩固、整体多城费用、迟到会师、供养与反击约束、易主撤回、停滞冷却、交替佯攻及真实威胁对照、预算不足保留目标和恢复／录像确定性。
- [ ] G11覆盖同条件交换控制者的规则一致性，并逐项列明实际采用的非对称例外。
- [ ] G11覆盖开局等待未满／原作周期窗口之外的合法褒美候选，以及资金不足、人物不合格和本旬重复褒美的公共拒绝；不要求AI每次都选择褒美。
- [ ] G11在固定场景和种子集合下，对照基线规划器验证威胁响应、投送时机、留守与补给及失效恢复，记录任务完成、损失、资源消耗和规划工作量；阈值随具体场景确定，不能只用胜率或算法名称验收。

## 未决问题

无。

分析种子派生不读取全世界状态哈希，也不消费正式随机流；同日可重复使用同一分析随机起点，实际候选与评分仍由获准观察数据决定。新增观察字段不要求为整份观察再建立指纹。
