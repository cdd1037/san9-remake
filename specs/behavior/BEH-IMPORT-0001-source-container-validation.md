## 适用范围

本规格只约束 `Importer.San9PkTc101` 对已登记繁中 PK 1.0.1.0 安装中剧本和头像容器的识别与边界校验。导入流程必须先通过 `San9PK.exe` 的大小和 SHA-256 身份门槛。

本规格不定义剧本实体字段语义、头像颜色通道、透明度、图像行方向、剧本显示名称或重制内容模型。

## 原作基线

### 正式剧本

`D_Sce001.S9` 至 `D_Sce020.S9` 是 `RIFF` 容器，form type 为 `S9SC`。RIFF 声明大小加 8 必须等于文件长度。容器依次包含以下 chunk，大小以字节计：

| Chunk | 大小 |
| --- | ---: |
| `head` | 82 |
| `area` | 90 |
| `ciki` | 102 |
| `fbld` | 476 |
| `hiho` | 1,558 |
| `kans` | 126 |
| `shak` | 1,386 |
| `skrk` | 70 |
| `kkgu` | 240 |
| `jnki` | 896 |
| `squa` | 560,000 |
| `bldg` | 5,600 |
| `city` | 2,800 |
| `forc` | 4,300 |
| `item` | 2,640 |
| `unit` | 32,000 |
| `prsn` | 107,200 |

`head` 按小端顺序包含：一个 32 位格式版本、四个尚未解释的 32 位值、16 位剧本编号、16 位组合标志、16 位起始日期编码、16 位联盟持续时间（单位为旬）、16 位地图宽度、16 位地图高度以及 50 字节的编码后城市势力分布向量。该向量只作为原始导入数据保留；城市初始势力归属以 `city +0x1C` 为规范来源，二者的编码域不同。四个 32 位值、组合标志的未确认位义及向量的完整转换表不在本规格中定义。

起始日期采用以 130 年为纪元、每年 360 天、每月 30 天的编码。编码 `21600` 解码为 190 年 1 月 1 日。目标安装中的 `D_Sce002.S9` 必须满足剧本编号 1、起始日期 190 年 1 月 1 日和地图大小 200 × 200，才能作为首个 190 年内容输入。剧本显示名称不由本字段推断。

### 头像图像

头像图像文件以一个 32 位小端文件总长度开始，其后重复保存图像记录。每项由四个 32 位小端整数和紧随其后的 8 位索引像素组成：记录总大小、行步长、宽度和高度。必须满足：

- 声明文件长度等于实际长度。
- 每项记录头一致。
- `记录大小 = 16 + 行步长 × 高度`。
- 行步长等于宽度，文件末尾没有不完整记录。

已确认的文件布局如下：

| 文件 | 数量 | 宽 × 高 |
| --- | ---: | ---: |
| `G_FaceL.s9` | 786 | 240 × 240 |
| `G_FaceS.s9` | 786 | 64 × 80 |
| `G_FaceT.s9` | 786 | 32 × 40 |
| `G_FacLPK.s9` | 50 | 240 × 240 |
| `G_FacSPK.s9` | 50 | 64 × 80 |
| `G_FacTPK.s9` | 50 | 32 × 40 |

### 头像调色板

`P_Face.s9` 以 32 位小端记录数开始。目标文件必须包含两项记录；每项由 40 字节记录头和 `256 × 4` 字节调色板数据组成，文件末尾不得存在未解析数据。

## 重制行为

导入器必须独立解析上述容器并返回只读布局信息。格式不匹配、长度越界、记录元数据不一致或存在尾随数据时必须明确拒绝，不得猜测、截断、补齐或尝试兼容未知格式。

容器解析与像素解码、字段语义转换保持分离。后续解码器只能消费已经通过本规格校验的区段。

## 状态与不变量

- 输入与前置条件：可读、可定位且从文件起点开始的流；安装身份已通过目标 EXE 指纹门槛。
- 状态变化：无；解析器只读取输入并返回布局或头信息。
- 始终成立的不变量：任何返回的区段和图像数据范围都完全位于输入文件内。
- 失败或无效输入行为：抛出明确的格式错误；不产生部分转换结果。

## 示例与边界

- `D_Sce002.S9`：剧本编号 1，日期编码 21600，解码为 190-01-01。
- 被截断 1 字节的 RIFF：因声明长度与实际长度不符而拒绝。
- `item` 大小由 2640 改为 2642：因已确认 chunk 布局不符而拒绝。
- 头像第二项记录的宽度与第一项不同：拒绝整个文件。
- 调色板记录数大于文件可能容纳的数量：在分配记录列表前拒绝。
