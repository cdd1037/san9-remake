# SQUARE 地图方格完整说明

本文独立介绍《三国志 IX 威力加强版》的 SQUARE 地图方格数据，包括存储布局、编辑器栏位、标志位、地形过渡、桥与疆界、寻路以及建筑占地关系。无需配合其他文档阅读。

适用范围为繁体中文版 PK 1.0.1.0 正式剧本中的 `squa` 数据区块。本文依据截至 2026 年 9 月整理的项目研究结果；已确认的程序行为、样本观察和仍未确认的用途分别说明。这里的“完整”指完整覆盖记录结构与当前已知用途，不表示所有原作内部语义都已破解。

证据入口：记录布局见 [RE-0019](../research/findings/RE-SAN9PK-0019.md)，通行与标志消费者见 [RE-0032](../research/findings/RE-SAN9PK-0032.md)、[RE-0034](../research/findings/RE-SAN9PK-0034.md)，地貌过渡与静态渲染见 [RE-0051](../research/findings/RE-SAN9PK-0051.md)、[RE-0053](../research/findings/RE-SAN9PK-0053.md)，占地实例与建筑资源见 [RE-0052](../research/findings/RE-SAN9PK-0052.md)、[RE-0055](../research/findings/RE-SAN9PK-0055.md)，水面动画见 [RE-0054](../research/findings/RE-SAN9PK-0054.md)。

## 1. SQUARE 是什么

SQUARE 是地图的逻辑方格数据。每格描述该位置的地形、偏移、所属地域、建设模板标志、地形衔接形状以及桥和疆界的绘制参数。

它不是地图图片，也不是建筑或部队对象表。原程序结合这些方格数据、地图资源和运行时对象，生成画面并执行部分地图规则。

通常口头说的“square 文件”，在这里具体指剧本文件中的 `squa` 区块或从中提取的方格记录数据。不能将完整剧本的文件偏移直接用于提取后的独立数据文件。

正式地图的逻辑尺寸为 **200×200**，共 **40,000 格**。每格记录 **14 字节，即 0x0E 字节**，记录数据合计 **560,000 字节**。已研究的正式剧本中，`squa` 区块位于文件偏移 `0x1406`；解析时仍应识别剧本容器与区块边界，不把这个样本位置当成所有文件的通用起点。

正式与教学样本中的方格区块逐字节相同，表明这些样本使用同一份共享地图模板。当前势力归属、部队和动态建筑状态并不因此相同。

## 2. 坐标与排列顺序

记录按行排列，X 先增加，随后 Y 增加：

```text
记录序号 = y × 200 + x
x = 记录序号 % 200
y = 记录序号 / 200 的整数部分

x、y 的范围均为 0～199。
某条记录相对于第一条记录的字节位置 = 记录序号 × 14。
```

例如，第 0 条是 `(0,0)`，第 199 条是 `(199,0)`，第 200 条是 `(0,1)`。

文件中的原始序号字段并不是运行时坐标的依据。原程序读取后丢弃该字段，使用记录在数组中的位置确定方格身份。

逻辑方格在画面上投影为 **64×32 像素的等距菱形**。200×200 表示逻辑网格，不表示屏幕上排列了 200×200 个普通矩形。下文的北、东、南、西均指逻辑网格方向：

| 方向 | 邻格坐标 |
| --- | --- |
| 北 | `(x, y-1)` |
| 东 | `(x+1, y)` |
| 南 | `(x, y+1)` |
| 西 | `(x-1, y)` |

## 3. 一条记录的完整布局

所有偏移均相对于当前记录起点，用十六进制表示。`u16` 是小端无符号 16 位整数，读取方式为“第一个字节 + 第二个字节 × 256”；`u8` 是单个无符号字节。

| 文件偏移 | 宽度 | 名称 | 用途概述 |
| --- | --- | --- | --- |
| `+0x00～01` | u16 | 原始序号 | 文件保存的序号；原程序不用于运行时身份 |
| `+0x02～03` | u16 | 方格复合标志 | 阻塞、设施模板、覆盖资格、核心区等位标志 |
| `+0x04～05` | u16 | 地域编码 | 关联城市或据点地域对象 |
| `+0x06` | u8 | 水面辅助值 | 已知分布集中于直接水面地形，专用用途未确认 |
| `+0x07` | u8 | 地形过渡掩码 | 八方向地形／高度融合的边缘展开 |
| `+0x08` | u8 | 偏移代码 | 参与地貌高度关系、图块选择与位置计算 |
| `+0x09` | u8 | 地形代码 | 地形类别及后续地形族转换的输入 |
| `+0x0A` | u8 | 高差过渡掩码 | 当前格四角与更高邻格的衔接形状 |
| `+0x0B` | u8 | 地表纹理变体 | 底图资源变体及图集排序的输入 |
| `+0x0C` | u8 | 桥方向代码 | 桥覆盖图片的朝向选择 |
| `+0x0D` | u8 | 疆界边掩码 | 地域线与都市线的两组四方向资格 |

结构上是 **3 个 u16 + 8 个 u8**。尤其 `+0x06～0x0D` 必须按八个独立字节理解。

## 4. 编辑器的 02、04、06、08 栏

编辑器的栏名和文件偏移不是同一套编号。常见的“未知 02、04、06、08”对应如下：

| 编辑器栏 | 文件位置 | 低字节内容 | 高字节内容 |
| --- | --- | --- | --- |
| `02` | `+0x02～03` | 方格标志低八位 | 方格标志高八位 |
| `04` | `+0x06～07` | 水面辅助值 | 地形过渡掩码 |
| `06` | `+0x0A～0B` | 高差过渡掩码 | 地表纹理变体 |
| `08` | `+0x0C～0D` | 桥方向代码 | 疆界边掩码 |

`02` 本身确实是一个 16 位字段。其余三栏只是把相邻两个独立字段组合成一个 16 位数显示：

```text
显示值 = 低字节 + 高字节 × 256
低字节 = 显示值 & 0xFF
高字节 = (显示值 >> 8) & 0xFF
```

例如编辑器 `08` 显示 `0x2101`，应拆成桥方向 `0x01` 和疆界掩码 `0x21`；不能把 `0x2101` 整体当成某种桥类型。

如果说的是实际文件偏移，则 `+0x04` 是地域编码的起点，`+0x06` 是水面辅助值，`+0x08` 是偏移代码，与同名编辑器栏不同。

## 5. 方格复合标志：+0x02～03

这是一个 16 位位集合。本文从最低位开始编号，最低位是 bit0，最高位是 bit15。多个标志可以同时存在。

| 位 | 十六进制掩码 | 当前已知含义 |
| --- | --- | --- |
| bit0 | `0x0001` | 工作物建设模板格 |
| bit1～8 | `0x01FE` | 已确认方格图寻路使用的阻塞位段 |
| bit9 | `0x0200` | 通用地图覆盖资格 |
| bit10 | `0x0400` | 排除于地域对象方格计数 |
| bit11 | `0x0800` | 运行时临时标记 |
| bit12 | `0x1000` | 相应 3×1 设施的建设资格 |
| bit13 | `0x2000` | 相应 1×3 设施的建设资格 |
| bit14 | `0x4000` | 对象核心区标志 |
| bit15 | `0x8000` | 城市路径相关的运行时覆盖范围标记 |

### 5.1 bit0：工作物模板格

该位表明方格属于可供相关工作物使用的地图模板，不能直接解释为“这里现在有建筑”。已存在对象和预留的空建设点都可能置位。

玩家建设阵、砦、箭楼、城塞时，程序以候选中心生成 3×3 占地；九格必须同属一个地域对象，并且九格全部具有 bit0。是否已经被占用，另由地域对象的动态状态判断。因此只有中心格置位并不足以满足这一模板条件，这一模板条件本身也不代表全部建设条件都已满足。

### 5.2 bit1～8：整体阻塞

已确认的判断为：

```text
阻塞位段 = 方格标志 & 0x01FE
不可通行 = 阻塞位段 != 0
```

这些位曾被描述为八方向阻塞形态，但当前已审计的消费者只判断整个位段是否非零，没有逐方向选择其中一位。因此可以确认“任意一位置位即使该格在这条寻路链中阻塞”，不能据此实现八个方向各自独立的通行规则。

这只覆盖已确认的方格图寻路路径，不能自动外推为所有移动类型、所有特殊路径入口的完整规则。

### 5.3 bit9：覆盖资格

该位被通用地图覆盖逻辑使用。洛阳 5×5 占地和带方港 3×3 占地的所有格都置有这一位，说明它不是桥专用标志。

在桥覆盖链中，只有地形代码为 `11` 时，该位才用作桥覆盖锚点资格。单独置 bit9，不足以把普通陆地变成桥。

### 5.4 bit10：计数排除

该位使方格不计入相应地域对象的方格计数，但不会删除其地域编码。已确认的疆界绘制函数也不读取这一位，因此不能将它当作“无所属地域”或“隐藏疆界”。

### 5.5 bit12、bit13：方向化设施资格

玩家建设路径中，bit12 对应设施代码 `11/13/15` 的 3×1 形状，bit13 对应设施代码 `10/12/14` 的 1×3 形状。这里的尺寸依次为逻辑 X、Y 方向的格数。

自动设施候选过滤对设施代码 `16` 可接受这两位中的任一位；但代码 `16` 的玩家选格模式使用 3×3 的 bit0 条件。不能把自动候选过滤条件直接替代玩家建设条件。

### 5.6 bit14：核心区

该位表示对象核心区，不保证每个对象只置一格。洛阳内部 3×3 九格置位，带方港只有正中心一格置位。

典型值 `0x4201` 可分解为：

```text
0x4201 = 0x4000 + 0x0200 + 0x0001
       = 核心区 + 覆盖资格 + 工作物模板格
```

### 5.7 文件初值与运行时变化

文件中的标志加载到运行时方格对象的 `+0x34` 位置。它是可变复合状态，不能假定游戏全过程都与文件字节一致。

bit11 会被运行时流程设置和整图清除；bit15 会被城市路径相关列表设置。目前将二者保守解释为运行时临时标记，不把它们设计成地图作者必须预先填写的静态玩法字段。

## 6. 地域编码：+0x04～05

这是小端 u16，原版编码规则如下：

| 值 | 对应对象 |
| --- | --- |
| `0～49` | 城市记录，城市编号等于此值 |
| `50～249` | `bldg` 据点记录，记录编号等于此值减 50 |
| `0xFFFF` | 无所属地域 |

例如值 `118` 指向 `bldg[68]`，值 `50` 指向 `bldg[0]`。

地域编码表达方格关联哪个地域对象，不直接表达属于哪个势力。势力归属应继续查询对应城市或据点的当前状态。它也不等于对象的占地矩形：一个地域可包含占地之外的方格，实际建筑几何由对象定义决定。

这些编号区间是原版文件格式规则，不应成为重制或自定义地图对象数量的固有限制。

## 7. 水面辅助值：+0x06

样本中的非 `0xFF` 值为 `0～7`，且只分布于地形代码 `9/10/15/16` 的直接水面格。

该字节被加载到运行时对象的 `+0x18` 位置，通用属性读取与格式化接口可以访问它。不过目前没有找到专门使用它的玩法或绘制消费者。

因此，“水面辅助值”是依据分布取的保守名称。尚不能确定它表示流向、水深、波纹方向或某种水域分类。原作水面动画创建链不读取它，不能把水面动画归因于这个字段。

`0xFF` 与其他值应原样保留；不能因为用途未明就统一改成零。

## 8. 地形过渡掩码：+0x07

该字节决定八方向地形／高度融合的边缘记录如何展开，属于绘制参数。

| 位 | 掩码 | 方向 |
| --- | --- | --- |
| bit7 | `0x80` | 北 |
| bit6 | `0x40` | 南 |
| bit5 | `0x20` | 西 |
| bit4 | `0x10` | 东 |
| bit3 | `0x08` | 西南 |
| bit2 | `0x04` | 东南 |
| bit1 | `0x02` | 东北 |
| bit0 | `0x01` | 西北 |

它不是简单的“邻格地形不同就置位”。原程序使用包含地形、偏移、纹理变体和高差形状的完整图集排序键：

1. 对北、南、西、东四个邻格，邻格排序键大于当前格时，置对应方向位。
2. 对四个对角邻格，除了排序键大于当前格，还必须严格大于该角两侧的正交邻格，才置对应方向位。

例如西北角的判断涉及当前格、西北格、北格和西格，不能只比较当前格与西北格。

这一掩码参与边缘展开，不是八方向通行开关，也不是直接的贴图文件编号。桥、水岸和陆地的过渡可以由同一套排序规则生成，不需要仅因桥地形就额外猜测一种掩码规则。

## 9. 偏移与地形：+0x08、+0x09

### 9.1 偏移代码

`+0x08` 参与地貌的垂直步进、底图选择、邻格高差比较和疆界片段位置。讨论高差时，比较的就是这些偏移代码的大小。

它不是记录在文件中的地址偏移，也不宜直接解释成以米计的现实海拔。`0xFF` 在已采用的派生视图中表示空值，原始字节仍保留。

### 9.2 地形代码

`+0x09` 表示地形编号。原程序进一步将编号转换为地形族，再参与底图资源、概览地图颜色及部分寻路代价计算。

本文可明确列出的相关代码用途为：

| 代码 | 本文所涉及的已确认用途 |
| --- | --- |
| `9/10/15/16` | 直接水面，参与水面动画创建 |
| `11` | 桥地形，结合标志 bit9 判断桥覆盖锚点 |
| `12` | 仅在邻近合格的地形 11 桥锚点时参与已确认水面动画链 |
| `0xFF` | 派生视图中的空地形值 |

这不是所有地形编号的中文名称表。未在这里列出的编号仍是字段可保存的数据，不应据此删除或归并。地形编号也不是图片编号，两者之间存在资源选择与地形族转换。

## 10. 高差过渡掩码：+0x0A

该字段描述当前格四角如何衔接更高的邻格。已确认规则使用低四位，位序并非普通顺时针编号：

| 角 | 位 | 掩码 | 参与比较的邻格 |
| --- | --- | --- | --- |
| 西北 | bit0 | `0x01` | 北、西、西北 |
| 东北 | bit3 | `0x08` | 北、东、东北 |
| 东南 | bit1 | `0x02` | 南、东、东南 |
| 西南 | bit2 | `0x04` | 南、西、西南 |

某角对应的三个邻格中，只要任意一个的偏移代码高于当前格，该角的位就置为 1。越界邻格按偏移 `-1` 处理。

例如当前格偏移为 2，北格为 3，其余七个邻格均为 2，则西北角和东北角都置位，得到 `0x01 | 0x08 = 0x09`。

它表示衔接形状，不是当前格自身高度。它会参与：

- 底图图集索引与资源选择；
- MESH/COV 覆盖资源选择；
- 疆界片段形状；
- 地形边缘锚点的垂直位置。

MESH/COV 是否出现由运行时覆盖网格的状态另行决定。不能因为存在这个字段，就在所有方格上绘制覆盖网格。

地形过渡掩码和高差过渡掩码均已实现确定性重建；已有研究在 20 个剧本共 800,000 格上，对这两个字段得到逐字节一致的结果。这说明它们可以由基础地图数据生成，不必要求地图作者手工维护每一个位。

## 11. 地表纹理变体：+0x0B

该字节与地形、偏移、高差过渡一起参与底图索引和资源选择。

已确认的一条资源变体映射为：

| 字段值 | 选用的资源变体 |
| --- | --- |
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| 3 | 3 |
| 4 | 2 |
| 5 | 1 |

直接水面地形 `9/10/15/16` 在图集排序中还使用专门的重排表，不能把上表当成全部图集索引计算公式。

黑盒观察中，这个字段表现为同种地形的颜色浓淡或纹理变化。但程序是选择资源变体，不是拿该值直接乘颜色。因此“值越大越深”并不是通用规律，更不能将其当作线性亮度或透明度。

## 12. 桥方向：+0x0C

在已确认的桥覆盖链中，资源选择为 `10004 + 桥方向值`。正式地图使用：

| 值 | 逻辑方向 | 资源编号 |
| --- | --- | --- |
| 0 | 南北 | 10004 |
| 1 | 东西 | 10005 |

桥的绘制还要求当前格为地形 `11`，且方格复合标志的 bit9 置位。

因此桥方向是“在满足桥覆盖条件后选择哪张图”，不是独立的造桥开关。原始值 `0xFF` 在已观察路径中有归一到 0 的行为，但无损读取仍须保留原始 `0xFF`。

## 13. 疆界边掩码：+0x0D

一个字节包含两组四方向掩码。低四位控制淡黄白地域线，高四位控制红白都市线。

| 方向 | 地域线掩码 | 都市线掩码 |
| --- | --- | --- |
| 北 | `0x01` | `0x10` |
| 东 | `0x02` | `0x20` |
| 南 | `0x04` | `0x40` |
| 西 | `0x08` | `0x80` |

例如 `0x21` 表示北侧具有地域线资格、东侧具有都市线资格。

这里存的是方向资格，不是一条完整线段，也不是最终画面的直接开关。原程序绘制时还会：

1. 查询邻格及其地域编码指向的城市或据点对象，筛选候选边。
2. 检查当前格两组方向位。
3. 结合当前格偏移和高差掩码确定片段位置及形态。
4. 选择 `G_MapMkr.s9` 中 `10794～10805` 的资源变体并生成视觉片段。

同一方向两种线重合时，都市线资源优先。每个方向还根据相关的两个高差位选择平面、主侧抬高或次侧抬高形态；两侧同时抬高时回到平面形态。

这个字段不参与前述寻路阻塞判断；看到疆界线不能据此推断该边不可通行。

## 14. 从方格数据到地图画面

理解各字段的关系，可以按下面的绘制过程串起来：

1. 使用地形、偏移、高差形状和纹理变体，计算底图资源与子资源。
2. 使用地形过渡掩码展开相邻方向和对角方向的边缘记录。
3. 读取地图资源像素与遮罩，合成方格及其过渡边缘。
4. 处理特殊标记、桥覆盖和地图边缘装饰。
5. 刷新地域线与都市线。
6. 根据运行时选区或覆盖状态绘制 MESH/COV。
7. 绘制更高层的地图对象。

原作当前格的 G_MASK 路径按每行首尾非零点连续复制源图横段；八方向边缘路径才按 P_MASK 权重逐像素混合。地图资源的循环取样使用全图等距坐标，而不是移动视口后的局部坐标。

原作画面写入 RGB555 颜色；重制版可以使用更高精度颜色目标。这是渲染精度选择，不改变 SQUARE 的字段布局和已确认的资源选择关系。

### 14.1 准备哪些输入

要画出原作地貌，仅有 SQUARE 数据还不够。至少需要方格数组、地貌图像、遮罩、季节调色板，以及资源选择和位置修正表。建筑、疆界动态资格与选区还需要当前世界对象和界面状态。

| 输入 | 绘制用途 |
| --- | --- |
| `G_LLand` | 地貌源纹理，资源编号从 10006 开始 |
| `P_Land_S/N/A/W` | 四季地貌调色板，按当前季节选择 |
| `G_MASK` 与 `P_MASK` | 形状覆盖范围及边缘混合权重 |
| `G_LHashi` | 桥图像 10004、10005 |
| `P_LndAdd[0]` | 桥使用的调色板 |
| `G_LMask` | 水面动画图像 10000～10003 |
| `G_MapMkr` | 疆界片段 10794～10805 |
| `G_MESH` 与 `P_MESH` | 运行时选区等方格覆盖 |
| 建筑组合与对应图片 | 在地形之上绘制城市、港口和设施 |

这些名称描述原作资源来源。重制客户端可以直接使用提前解码的图像和绘制描述，不必在运行时读取原版资源文件。

地貌图像的调色板由“资源编号→调色板槽位”关系决定，不是把地形编号作为调色板下标。例如水域基准资源 10315、10319、10323、10327 对应活动地貌调色板记录 4，其纹理变体使用记录 5～7。固定选择某一季节的调色板，会让其他季节的地图色调不正确。

### 14.2 把方格投影到画布

原作 200×200 地图的全图像素坐标为：

```text
centerX = 32 × (x + 200 - y)
centerY = 16 × (x + y + 1)
anchorX = centerX - 32
anchorY = centerY - 16
```

`center` 是基础菱形中心，`anchor` 是该菱形 64×32 包围盒左上角。这里尚未应用具体图块的高差和方向修正。

例如方格 `(89,64)` 的中心为 `(7200,2464)`，基础锚点为 `(7168,2448)`。向逻辑东走一格，画面位置增加 `(32,16)`；向逻辑南走一格，增加 `(-32,16)`。

绘制局部窗口时，只从目标坐标减去窗口的全图原点：

```text
localX = worldX - viewportOriginX
localY = worldY - viewportOriginY
```

源纹理的取样相位继续使用全图坐标。若同时把源纹理取样改成局部坐标，镜头移动时纹理会跟着滑动，相邻分块也可能出现接缝。

高差地貌不能只用这一张平面菱形。底图和边缘图块还须按高差形状、方向类型查位置表；原作包含 16×9 的图块位置组合及 16 项高度修正。不要给所有图块统一加一个猜测的高度偏移来替代这些关系。

### 14.3 一格展开为多条绘制记录

一格通常不只画一次。每格先根据 `+0x07` 生成命中的边缘记录，再追加当前格记录：

| 掩码 | 对应邻格 | 边缘类型 |
| --- | --- | --- |
| `0x80` | 北 | 1 |
| `0x40` | 南 | 4 |
| `0x20` | 西 | 2 |
| `0x10` | 东 | 3 |
| `0x01` | 西北 | 5 |
| `0x02` | 东北 | 6 |
| `0x04` | 东南 | 8 |
| `0x08` | 西南 | 7 |
| 无条件追加 | 当前格 | 9 |

边缘记录使邻格地貌按该方向的形状覆盖到过渡区域，不是简单把邻格整张菱形重画一遍。记录需要携带资源选择所用的地形、偏移、高差、纹理变体，目标位置、源取样位置、类型和排序键。

记录构造时还会根据当前格地形、邻格地形及邻格偏移生成边缘专用标志，供平面情况下的特殊遮罩选择使用。这个标志不是直接取地形编号的低两位。

### 14.4 选择纹理和遮罩

纹理选择与排序索引是两次不同计算：

- 资源选择用地形、偏移、高差和纹理变体确定真正读取的图片及子图。
- 图集排序索引决定不同地貌片段的覆盖顺序，不能直接将排序索引当作图片编号。

纹理变体首先遵循 `0→0、1→1、2→2、3→3、4→2、5→1` 的资源变体映射。例如地形 9、偏移 1 时，六个值依次选择资源 `10315、10316、10317、10318、10317、10316`。

不同地形有各自合法偏移范围和资源步长。例如地形 6 的合法偏移只有 1，基址为 10523，纹理变体步长为 1。原作选择器遇到非法偏移时保留该地形资源基址，不能擅自把偏移钳制到范围下限并称为原作行为。

遮罩按高差形状和边缘类型选择：

1. 普通高差组合使用 16 个形状组，每组 9 个当前格／边缘子图。
2. 高差为零时，还会根据边缘专用标志选择 10950～10958 或 10959～10967 两组特殊遮罩。
3. 从选择的组内按类型取得对应子图，并使用匹配的位置修正。

因此“所有地形共用一张 64×32 菱形遮罩”只能得到粗略示意图，无法画出原作的山壁和水陆融合。

### 14.5 先确定全图顺序，再裁剪

全图按 Y、X 顺序生成记录。每条记录的排序键为：

```text
key = x + mapWidth × (y + atlasIndex × mapHeight)
```

原作地图宽高均为 200。`atlasIndex` 是完整地貌排序索引，不是单独的地形编号。

最终键按升序排列，但相同键的顺序也影响半透明边缘叠加。原作逐条插入时，比较新键与当前首尾键的整数中点：

- 新键小于中点：从头寻找第一个大于等于新键的位置，插在它前面，同键前插。
- 否则：从尾寻找最后一个小于等于新键的位置，插在它后面，同键后插。

实现可以用每个键对应的双端队列保存前插／后插结果，不必复刻原版链表。普通稳定排序不能保证相同结果。

应先得到全图确定的记录顺序，再按图块实际包围盒筛选视口或分块。先裁掉方格再排序，会改变同键插入历史。筛选时也不能只判断方格中心是否在窗口内，因为高差和边缘图块可能从窗口外伸入。

### 14.6 合成当前格与边缘像素

需要区分两个输入：覆盖图决定像素是否参与绘制，权重图决定边缘怎样混合。黑色权重不等于不绘制。

**当前格，类型 9：** 对遮罩每一行，寻找覆盖图中第一个和最后一个非零位置，连续复制两者之间的整段源纹理。该区间内部不再逐像素判断覆盖图，也不执行边缘混合。

**边缘格，类型 1～8：** 只处理覆盖图非零的像素。对 RGB 各通道分别执行：

```text
result = (source × (256 - weight) + target × weight) >> 8
```

这里 `weight` 为解码后的遮罩红通道权重，范围 0～255；`target` 是已经画在目标上的颜色。权重 0 表示完全使用源色，权重 255 表示主要保留目标色。分母是 256，不是 255，不能直接把该值当成普通源 Alpha。

例如源色某通道为 200、目标为 100、权重为 64，则结果为 `(200×192 + 100×64) / 256 = 175`。

纹理循环也有具体边界。设源纹理宽高为 `W、H`，遮罩坐标为 `(mx,my)`，记录提供全图相位 `sourceX、sourceY`：

```text
run = 当前格本行的第一个覆盖位置；边缘记录则为 0
startX = positiveMod(sourceX + run, W - 64) - run
sampleX = startX + mx
sampleY = positiveMod(sourceY + my, H)
```

`positiveMod` 返回非负余数，地貌源纹理宽度须大于 64。横向取模只在扫描线起点进行，连续复制期间不对每个像素重新取模。裁剪目标窗口也不能改变这个起点，否则分块结果会与整图不同。

RGB888 实现可直接对八位通道执行上述公式。需要复现原作 RGB555 写回结果时，应另外明确量化步骤；提升目标颜色精度不会改变遮罩权重的方向和分母。

### 14.7 添加桥、建筑、疆界与覆盖

地貌完成后，再生成相应视觉对象。原程序的创建／刷新调用顺序不等于所有对象最后的遮挡顺序；动态地图还要由显示层组织对象深度。

| 对象 | 位置与选择规则 |
| --- | --- |
| 桥 | 地形 11 且 bit9 置位；图片 10004 或 10005；从基础锚点再向左移 64 像素 |
| 建筑 | 从方格中心出发，纵向加 `-10×(offset-1)`，再叠加建筑组合记录的偏移 |
| 疆界 | 按两组方向资格筛边，结合高差选择片段并修正位置；同方向都市线优先 |
| MESH | 先由运行时决定需要覆盖哪些格及状态，再按高差选择该状态组内图片 |

建筑组合内部按表顺序画，不应自行按组合记录的 `z_offset` 重排。建筑与部队等不同对象之间的遮挡则属于场景对象排序，不能从 SQUARE 的地貌排序键直接推导。

MESH 有 6 个状态组，状态 0～5 的资源基址依次为 `10972、11004、11036、11020、10988、11052`，资源号为基址加高差掩码。图像尺寸为 64×44；位置为 `(centerX-32, centerY-10×offset)`。各状态不透明比例依次为 `50%、25%、20%、22%、20%、20%`，原作先计算 `floor(percent×256/100)` 再传入混合器。这些百分数不是图片缩放比例。

`G_MapCov` 的四张 1024×768 图片不属于上述 96 张 MESH 子图。当前已确认的方格选区链不通过这些大图绘制，不能因名称相似就合并两类资源。

前景云可覆盖地图边缘建筑，但名称、兵力和状态条等信息界面应在其上方。地图外缘还应根据真实高差边界裁剪，不能仅用一个固定几何菱形截断所有山地。

### 14.8 水面动画

水面动画是静态水域底图之上的独立动态覆盖，不能只靠静态方格纹理表现完整水面。

原作以如下公式选择四种位置奇偶资源：

```text
资源编号 = 10000 + (x & 1) + 2 × (y & 1)
```

每项资源为 384×32 像素，横向切成六个 64×32 帧，每帧 200 毫秒，标称循环周期为 1.2 秒。地形 `9/10/15/16` 直接参与，地形 `12` 在邻近合格桥锚点时参与。这条创建链不使用 `+0x06` 水面辅助值。

### 14.9 可落实的绘制流程

下面是重制实现的流程示意；其中资源选择和位置表是输入数据，不是靠 SQUARE 字节即可推导出来的图片内容：

```text
准备阶段：
    读取方格数组，解析视觉资源及调色板绑定
    若基础地形已编辑，先重建高差掩码，再重建地形过渡掩码
    按全图 Y、X 顺序遍历方格：
        根据过渡位构造边缘记录
        追加当前格记录
        为记录计算排序键、资源、遮罩、目标位置与全图取样相位
    得到符合原作同键插入规则的全图记录序列
    按图块包围盒建立空间索引，桶内保留全图顺序

绘制静态地貌：
    申请目标视口或分块像素缓冲
    依次取出与目标相交的记录
    类型 9 按扫描线连续复制
    类型 1～8 按覆盖图和 256 权重公式混合
    处理地图外缘底云
    缓存结果

每帧显示：
    显示当前镜头所需的地貌缓存
    按动画时间选择水面帧
    提交桥、建筑、疆界及其他场景对象
    根据当前交互状态提交 MESH 等覆盖
    按显示层与对象深度合成，再绘制信息界面
```

纹理资源、季节、方格基础数据或过渡掩码改变时，相关地貌缓存失效。仅水面动画换帧或选区变化时，不必重新合成全部静态地貌。分块尺寸属于实现选择，不改变记录顺序、世界取样相位和像素混合规则。

本文给出了绘制流程和关键公式，但没有将原作全部资源注册表、17 类地形选择表及 16×9 位置表逐项抄成资源包。精确复现仍需要这些已解码的视觉数据；缺少时可画逻辑地形示意图，不能据此声称已经复现原作画面。

### 14.10 如何检查绘制是否正确

至少选择平地、山顶／山壁、水陆交界、桥、带疆界的高差格，以及地图外缘各做一次局部对照。重点检查：

- 改变裁剪原点或跨分块移动后，同一世界位置的地貌像素是否一致。
- 边缘是否出现硬直角、黑边或透明裂缝；这通常涉及掩码、调色板或位置修正。
- 山地覆盖是否正确；只按方格 Y、X 绘制可能破坏地貌排序。
- 切换季节后，资源使用的调色板槽位是否仍然匹配。
- 普通陆地是否因方向值为零而误画桥。
- 未选中任何范围时是否误把 MESH 铺满地图。
- 水面帧是否按 200 毫秒推进，静态底图是否保持不动。

整图与分块像素比较可以验证排序、裁剪和取样一致性；画面截图对照才能验证最终外观。编译成功或资源编号合法，不能替代这两类检查。

## 15. SQUARE 与寻路

已确认的方格图寻路只展开北、东、南、西四个邻格，不直接展开斜向邻格。

初始化移动代价时：

| 条件 | 结果 |
| --- | --- |
| `flags & 0x01FE != 0` | 代价设为 `0xFF`，搜索跳过该格 |
| 无阻塞位，地形族不是 4 | 基础代价 10 |
| 无阻塞位，地形族为 4 | 基础代价 12 |

注意这里的“地形族 4”不等于原始地形代码必然为 4；原始地形代码先经过转换。

城市、据点、部队和距离因素还会继续调整代价。因此 SQUARE 给出了部分静态条件，不能单靠一条方格记录还原游戏所有最终路径选择。

## 16. SQUARE 与建筑占地

应区分三个概念：地域编码描述关联地域对象，bit0/bit14 描述模板与核心区，建筑占地则描述实际对象的几何范围。三者有关联，但不能互相替代。

原作从固定建筑定义读取 X、Y 尺寸，以对象坐标为中心构造矩形，再按每格 5 个地图坐标单位量化为方格范围。已研究的 17 类固定建筑使用 5×5、3×3、1×3、3×1、1×5、5×1 六种尺寸，没有发现旋转或不规则占地分支。

两个具体样本为：

| 对象 | 中心方格 | 占地方格 | 地域编码 | 核心区 |
| --- | --- | --- | --- | --- |
| 洛阳 `city[15]` | `(89,64)` | `x=87～91, y=62～66`，共 25 格 | 25 格均为 15 | 内部 3×3 的标志为 `0x4201` |
| 带方港 `bldg[0]` | `(184,26)` | `x=183～185, y=25～27`，共 9 格 | 9 格均为 50 | 中心一格的标志为 `0x4201` |

还有设施代码 4 的实例：运行时实际占地是 1×5，但静态模板只有中间三格置 bit0。由此不能通过统计 bit0 连续格数来推导实际建筑尺寸。

## 17. 完整字节示例

正式样本的第 0 条记录为：

```text
00 00 C6 03 76 00 FF 00 04 02 00 02 00 00
```

逐字段解释：

| 偏移 | 原始字节 | 解释 |
| --- | --- | --- |
| `00～01` | `00 00` | 原始序号 0 |
| `02～03` | `C6 03` | 方格标志 `0x03C6`，十进制 966 |
| `04～05` | `76 00` | 地域编码 118，关联 `bldg[68]` |
| `06` | `FF` | 水面辅助值原始值 255 |
| `07` | `00` | 地形过渡掩码无方向位置位 |
| `08` | `04` | 偏移代码 4 |
| `09` | `02` | 地形代码 2 |
| `0A` | `00` | 高差过渡掩码无角位置位 |
| `0B` | `02` | 地表纹理变体 2 |
| `0C` | `00` | 桥方向字段为 0；当前格不是桥地形，不能据此认定有桥 |
| `0D` | `00` | 两组疆界方向位均未置位 |

其阻塞判断为 `0x03C6 & 0x01FE = 0x01C6`，结果非零，所以该格在已确认的方格图寻路中阻塞。

如果编辑器将未知栏显示为十进制，则对应数值为：

| 栏 | 组合值 | 十进制 |
| --- | --- | --- |
| `02` | `0x03C6` | 966 |
| `04` | `0x00FF` | 255 |
| `06` | `0x0200` | 512 |
| `08` | `0x0000` | 0 |

## 18. 读取、修改与保存时的边界

无损读取首先应保留三个 u16 和八个 u8 的全部原始值。空值、归一值和业务解释应作为额外视图，不覆盖原始数据。

| 字段 | 已采用或观察到的特殊处理 | 原始保存要求 |
| --- | --- | --- |
| 地域编码 | `0xFFFF` 派生为空 | 保留 `0xFFFF` |
| 偏移、地形、高差掩码、纹理变体 | 派生视图可将 `0xFF` 视为空 | 保留 `0xFF` |
| 桥方向 | 已观察路径将 `0xFF` 归一到 0 | 保留 `0xFF` |
| 水面辅助值 | `0xFF` 常见，专用语义未闭合 | 保留原值 |

某些目标汇编里存在单字节读取后与 `0xFFFF` 比较的不可达条件，不能因此把相应字段扩大为 16 位。

修改基础地形、偏移或纹理变体时，应考虑重新生成受影响格及邻域的高差和地形过渡掩码。只改基础字段而留下旧掩码，可能让视觉过渡与新地形不一致。本文给出字段关系，不保证某一外部编辑器保存时会自动重算这些值。

读取正式格式时，应验证 40,000 条记录各消耗 14 字节、记录区总长正确、没有截断，并检查地域引用与城市／据点坐标关系。不要把未确认字段的数值外观当作删除数据的理由。

## 19. 已知结论与仍未知的部分

记录宽度、大小端、坐标排列、地域编码关系、标志的上述消费者、地形与高差过渡、桥方向、疆界方向以及所述绘制和寻路链，均已有程序分析或样本核对支持。

仍应保留以下限制：

- `+0x06` 的专用用途未确认；“水流方向”等名称没有足够依据。
- 标志 bit1～8 的逐位历史含义未确认；当前消费者支持整体阻塞判断。
- bit11/bit15 有运行时写入证据，但不足以给出覆盖所有场景的完整业务名称。
- 纹理变体的“颜色浓淡”是视觉观察，不是线性色彩公式。
- 已确认的一条寻路链不等于全部原作移动规则。
- 外部编辑器的自动重算和保存行为需要单独验证。

对重制或自定义地图而言，原版二进制布局是导入格式。运行时应分别表达地形、地域引用、对象占地和动态覆盖状态；不要让原版的固定编号区间或复用位字段限制新的对象模型。
