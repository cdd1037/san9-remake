## 1. 目的与证据边界

本记录只确认 M1 数据转换需要的地图索引和对象引用关系，不为 `squa +0x02` 或其他未知字节建立通行、道路、图层或战斗规则。

既有 IDA 调查已确认：正式布局的 `squa` 是 40,000 条、每条 14 字节的记录；`+0x04` 被加载为运行时方格的地域槽位，`+0x02` 被加载并可由通用 getter 返回。详见 [RE-SAN9PK-0019](RE-SAN9PK-0019.md) 和 [RE-SAN9PK-0024](RE-SAN9PK-0024.md)。

## 2. 地图线性索引

20 个正式剧本的 `squa` 区块均满足：

- 40,000 条记录的 `SerializedId` 依次为 `0..39,999`；
- 城市和据点坐标处的方格记录序号均等于 `y × 200 + x`；
- 因此 M1 导入使用记录顺序 `Id` 建立行优先地图索引，派生 `x = Id % 200`、`y = Id / 200`。

城市坐标交叉检查覆盖 20 个剧本的 1,000 个城市记录；有坐标的据点交叉检查覆盖 20 个剧本中每个剧本的 137 条记录，共 2,740 条记录。没有发现坐标越界或线性索引不一致。

## 3. `ZoneCode` 的对象编码

在上述坐标交叉检查中，方格 `+0x04` 的编码稳定满足：

```text
城市：ZoneCode = city record id
据点：ZoneCode = 50 + bldg record id
空值：ZoneCode = 0xFFFF
```

20 个正式剧本中：

- 全部 1,000 个城市坐标均映射到对应城市 ID；
- 全部 2,740 个有坐标据点均映射到 `50 + bldg` 记录 ID；
- 城市和有坐标据点没有发生坐标重叠；
- 方格非空 `ZoneCode` 的观测最大值为 `186`，没有出现超出 0..249 编码域的值。

因此产品导入层可以提供两个不改变原始值的派生视图：

- `CityId`：`ZoneCode < 50` 时为城市 ID；
- `ZoneRecordId`：`50 <= ZoneCode < 250` 时为 `ZoneCode - 50`。

这两个视图只描述已确认的输入引用关系，不表示重制版必须沿用原作的内部区域对象设计。

## 4. 实现边界

已进入 `San9ScenarioSquareArchive` 的 M1 行为：

- 200×200 维度常量和 `Id <-> (x,y)` 行优先转换；
- `ZoneCode` 的城市/据点派生引用；
- 非空 `ZoneCode >= 250` 的输入拒绝；
- 跨表校验城市/据点坐标与方格区域编码的一致性，以及对象坐标不重叠。

仍只做无损保留的字段：`+0x02`、`+0x06`、`+0x07`、`+0x0A`、`+0x0B`、`+0x0C`、`+0x0D`。它们的玩法语义需要新的 IDA 消费者证据或编辑器单变量差分，不属于本次 M1 实现。
