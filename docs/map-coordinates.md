# 地图坐标与人事计时

## 坐标单位

`MapCell`表示地形方格；`WorldPosition`表示精细位置。两者都不表示屏幕像素。共享的`MapCoordinates`定义每格5个精细单位，保留已核实原作尺度；地图尺寸不写死为200或1000。

格中心转换为`(5*x+2, 5*y+2)`；从非负精细位置取所在格为`(x/5, y/5)`的整数商。例：格(184,26)中心是(922,132)，格(199,199)中心是(997,997)；精细位置不必恰好在格中心。

据点内容现有X/Y明确保留为地图格锚点，通过类型化Cell/Position访问器取得格和精细中心；不再复制一份可独立漂移的据点坐标。Importer先验证剧本坐标及无效槽，再将未建设地域转换为PersonPlace.Position，将活动部队转换为UnitState.Position。人物旅行规则只接收PersonPlace中的WorldPosition，不能传入裸格坐标。

UnitState自有存档保存精细位置；部队情报和战略全图通过Cell读取所在格，避免地图标记放大五倍。当前没有实现格内行军插值。原作存档导入不在支持范围内，不增加读取入口或兼容分支。

源版本的200×200范围和无效哨兵由TC101 Importer负责；Core只校验位置非负及计算溢出。每格5单位是明确的运行时尺度，不是对象数量或地图尺寸限制。

## 人事倒计时

令两处精细中心之差为dx/dy：

1. `D = floor(sqrt(dx*dx + dy*dy))`。
2. 基础天数`T = (D+29)/30`（非负整数除法）。普通登用和调动/召回使用T。
3. 搜索天数`max(10, 10*((T+9)/10))`，即向上凑成10的倍数、至少10天。不是按历法旬边界对齐。

距离使用宽整数与整数平方根，不把浮点平方根的舍入边界带入确定性规则。先截断平方根再对30向上取整：精细差(30,1)的D为30、基础天数为1，不能直接对浮点距离除30取天花板得到2。

基础距离为0时保留0天；按已有G01日推进顺序，于下次执行每日命令阶段在当前游戏日结算，不在提交调用中立即兑现，也不自行增加一天。探索允许来源和目的为同一对象，不同对象也可以共用坐标，均遵循探索最少10天。零天归队在当轮日期推进后的单位/建筑阶段收尾，不延迟到下一旬执行阶段；正距离地域仍须按实际距离返程。

每日命令前先递减行程倒计时，再判定到期，之后才推进日期。因此提交倒计时N对应的结算日期偏移是`max(0,N-1)`。`JourneyDays`返回倒计时，`ResolutionDayOffset`返回日期偏移；任务Due与查询采用后者，不能把两种天数混用。例：1月1日提交10天搜索，1月10日结算；11天登用在1月11日结算。0和1都在首次每日命令阶段处理。此日内顺序已由RE-0112核实；正常/取消返程的剩余倒计时公式见BEH-PERSON-0003。
