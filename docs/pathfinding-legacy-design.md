# 旧粗格 A* 寻路的设计思考与关键行为

状态：历史设计备忘，2026-10-17整理。记录被本轮原作式粗细两级导航替代的实现，不作为当前行为要求，也不要求保留兼容执行分支。当前设计见[导航设计](../specs/navigation-redesign.md)，新旧测量见[性能记录](pathfinding-verification.md)。

基线为提交 `c92204c49db595e56a652ec957f71ac815e42ca3`（规则 v139）。以下实现事实来自该提交的代码和当时的导航规格；“取舍”部分是对设计的分析，不是原作行为结论。

## 设计出发点

旧实现选择“缩小全局搜索图，但保留细坐标执行”。地形按粗格定义，部队位置、矩形占地和射程仍按细单位计算；全局只搜索四邻粗格中心，起终点通过有界细格搜索接入。因此不必把所有领域位置改成整格跳行，也不必维护全图细格导航、区域图或复杂的路径缓存。

当时200×200粗格地图对应1000×1000细位置，全局工作区从百万级节点缩到4万个；端点窗口为3×3粗格，即最多15×15个细节点。这里减少的是搜索容量，不代表耗时或总内存同比减少。

这是有意限制能力的模型：接受粗格中心路线漏掉细空间窄通路，不提供全图细格兜底、扩窗重试或特定地点例外。它也不是一般化的“全局粗图加局部避障”。不能把后来替换的原因概括成旧实现拥有过多全图兜底。

## 关键行为

### 全局路线、端点与确定性

- 全局四向 A*；实际移动模式的一条粗边包含5个细步，每个细步检查完整部队占地、地形和硬对象。粗路线存在不能只凭中心点地形判断。
- 非中心起点在周围3×3粗格窗口搜索可连接的粗格中心；目标附近使用同样有界的窗口接入精确位置或到达范围。窗口不能自由扩大。
- A* 以累计费用加启发下界为主序，同价依次参考起终点连线偏差、剩余下界及节点编号；邻接访问顺序固定。没有导航随机，不会为了模拟原作而随机替换同价方向。
- 贴近直线只是同价选择，不是原作的连线走廊费用折扣。因此较昂贵的路线不会仅因更贴线就被优先选择。

### 占地、碰撞与费用

占地来自有效阵型的固定 Footprint，不随兵力变化；当时原版转换包的28种阵型均为3×3细单位。Core接受其他合法尺寸，3×3不是算法硬限制。

Simulation根据身份、外交、方针和设施语义生成完整占用快照，搜索器只处理硬阻挡与软费用。同方部队允许重叠；敌军是否硬挡受主动迎敌方针等规则决定，不能把所有其他部队一律当成硬障碍。

规划费用由地形成本与非负避让成本组成。以最小通行成本 `minimum` 为基准，友军附加 `max(1, minimum / 2)`，敌军附加 `minimum * 4`，设施附加 `minimum`；每类是否命中用布尔值聚合，同类对象重叠不逐个累加。设施避让按完整地理矩形覆盖的粗格中心判断，部队避让按矩形重叠判断。当前目标去除自身避让成本，接近目标时仍可将目标作为硬对象以防穿入。

实际推进重新检查下一细步，只扣真实通行成本，避让费用不消耗移动预算。不足以支付下一步的预算作为余量保留。地形时间、水陆速度换算与择路偏好分开，这项原则值得继续保留。

### 每日重规划与自动前瞻

每日重新求路，不保存整条路线。持久状态只保留自动前瞻点及对应真实目标几何；玩家途经点、等待日数与自动前瞻分别表达。

路线足够长时从粗节点链选前瞻，普通移动默认取前方最多25格，追击可缩短。旧前瞻只在真实目标几何未变、阶段点和真实目标都仍足够远时复用：阶段点距离大于 `max(25, budget / minimum)`，真实目标距离大于25细单位。接近目标后重新面向真实到达条件。

前瞻受阻且无法推进时，同一次每日调用会放弃阶段点并重算真实目标；这只是重新搜索粗图，不是全图细格兜底。沿阶段路线执行时仍检查真实到达条件，不能越过真实目标后继续追前瞻。

进入导航前若已经满足到达条件，直接返回 Arrived；执行中到达即停止。因此旧导航不会为了普通攻城持续向内部尝试移动。是否能攻击、何时完成命令仍由上层规则决定，不等同于导航 Arrived。

### 无路、等待与工作预算

搜索失败且存在硬对象时，旧实现会再移除硬对象搜索一次：若此时有路，归类为临时 Waiting，否则为 Unreachable。这里移除的是输入硬占用对象，地形阻挡仍保留；该诊断不能证明未来一定能通行，还会增加失败查询的成本。

可选查询有节点展开预算，耗尽报告 Planning／Incomplete，不将查询工作量不足解释为永久无路。真实日推进不由 UI 的查询预算决定是否允许行动。

### 真实移动、路线页与 AI 的分工

| 用途 | 旧实现行为 | 能提供的保证与限制 |
| --- | --- | --- |
| 真实日推进 | 当日规划，逐细步扣费和碰撞检查，保存位置、余量和前瞻 | 当前快照下执行检查精细；粗图仍可能漏路 |
| 路线页 Plan | 冻结外部世界，反复调用每日推进并累积细步；默认最多4096日、10万次展开 | 与每日移动复用规则，可输出到达日；不预测其他部队未来行动，不能保证实战轨迹一致 |
| 精细 ETA | 按日预测，使用同一移动与预算规则 | 较具体但较贵，仍受冻结世界、等待及预测上限限制 |
| AI EstimateTravelCost | 单次战略粗搜；粗边只采样进入格，端点比较两种轴向折线 | 避让只影响选路，返回时间不包含避让费用；不保证完整占地通行或真实到达日期 |

不要把旧 AI 粗估与保留逐步占地检查的 EstimateRouteCost 混为一谈。旧实现已经承认用途不同可以有不同精度，主要代价在于路线页也承担了长时间逐日模拟。

## 性能与状态所有权的思考

线程独占租用可复用搜索工作区，归还时释放地图、回调和占用引用；地形与水陆视图可复用，对象桶每次查询重填，端点通行缓存每个窗口重置。这样避免把过期兵力、位置、外交或通行方式带入下一查询。

不保存完整路线、阻挡快照、失败次数或重试退避，减少了世界状态、存档与缓存失效之间的耦合。代价是每日搜索仍存在，预览和 ETA 会重复放大这项开销。前瞻缩短搜索距离，但同时改变路线选择，不能当成完全等价的纯性能优化。

优点是结果可复现、实际粗边检查严格、状态较少、失败分类明确；缺点是粗中心图不完备、端点接驳增加实现与查询成本、预览过重，以及固定占地和确定性择路不能表达原作的兵力占地与局部随机行为。不能仅凭 A* 就断言其在连续空间全局最短或一定比新实现更不容易卡住。

## 对当前实现仍有价值的原则

1. 保持择路偏好与真实时间成本分离，并明确预览、粗估、精细预测各自承诺什么。
2. 阶段目标服务于真实目标；验证阶段失效和真实目标途中到达，不让内部引导点接管命令语义。
3. 区分永久地形无路、动态拥堵与计算预算耗尽；必要时改进诊断，不用同一个“不可达”掩盖原因。
4. 工作区复用不跨查询保留动态世界引用；需要缓存时先明确输入依赖和失效机制。
5. 分别衡量路径质量、独立导航负载和完整会话，不用更早等待或更少成功结果冒充等价提速。

这些原则不意味着将旧搜索器作为新实现的隐藏兜底。新实现的等待问题应先核查局部窗口、阶段目标、碰撞与到达条件，再根据目标行为作统一选择。
