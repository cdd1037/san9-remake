# 纹理资源与缓存

客户端只读取转换包。逻辑图片、物理文件与运行时驻留分别建模；资源可见性不改变导入范围或世界状态。长期取舍见[DEC-RENDER-0004](../specs/decisions/DEC-RENDER-0004-texture-atlases-and-gpu-cache.md)。

## 内容契约与独立构建

纹理包由 `import-textures` 独立生成，输入只有已登记 EXE、原版数据目录和转换规则，不接受剧本。默认目录为 `local/generated/content/textures-san9pk-tc101`，`textures.json` 为 schema5、转换版本16。包拥有界面定义、地图资源定义、完整已确认图片目录和全部物理 PNG。

剧本包 `content.json` 为 schema141，只保存来源、共享纹理目录和数据文件相对路径。`map.json`、`scenario.json`、`text.json`、`messages/*.json`、`illustrations.json` 分别保存地图实例、剧本初始状态、静态词条、统一消息和插图角色映射。地图实例保存地形、建筑位置、水面位置等，不保存图片文件或图集定义。`ClientContentFiles` 解析依赖后在内存装配显示内容；客户端图片路径相对纹理包根目录。重新导入剧本不会生成或修改共享纹理。旧包重新转换，不提供兼容读取。

头像通过独立 `portraits` 目录引用统一ID0..835，每项只含一张正常色大图和归一化裁剪锚点；图片按统一头像ID命名为 `images/portraits/{id}.png`（0..835），不导出中图、小图或调色板1变体。同一头像可被多个武将和剧本共享。小地图底图根据当前方格和共享的八类地形颜色在客户端生成，GPU 对象随控件释放，不再导出某个剧本专用的 PNG。

`ImageAsset` 保存稳定逻辑 ID、原始宽高、区域和 `ImageFile`；后者保存相对路径、物理尺寸和通道数。全局纹理统一导出，剧本只引用逻辑 ID。不同原版资源即使像素相同，也保留各自身份；不做像素去重。多个消费者对同一源档案、图片编号、调色板及转换方式的引用在导入时解析到同一资源，图集只对确定的资源按类别装箱。裁帧、透明解释和合成图有各自明确的转换身份。

图片按 `images/interface`、`images/portraits`、`images/illustrations`、`images/scenes`、`images/effects`、`images/map` 分子目录。图集文件按类别内的稳定遍历顺序编号为 `atlas-{number}.png`，普通独立图为 `image-{number}.png`。宝物图按已确认的 G_Still 图号172..271分类至 `images/illustrations/treasures/{imageId}.png`（图片编号0..99），不按剧本中当前使用的宝物筛选。只保留这100张240×240大图，原版72..171的120×120宝物小图不导出，小尺寸显示直接缩放大图。头像、插图、CPU 源图及超大图片独立保存。图集使用确定性最大空闲矩形装箱，最大2048×2048、每侧扩边2像素、不旋转、不裁剪透明边界、不生成 mipmap；页收缩到实际占用尺寸。地图水面和守兵按类共页；旗杆共页，旗面按16色、字形按每种样式32个分段，再按季节分组。这些分组参数不是实测最优值。

纹理清单、物理图片、源文件追踪和归档均不生成、保存或使用 SHA-256；剧本也不保存纹理清单哈希。增量复用依据契约／转换版本以及输入文件名、大小和 UTC 修改时间，并检查 PNG 格式、CRC 和尺寸。修改源文件时必须更新修改时间；保留大小和时间的改写不能由这些元数据识别。中间源图片只用于构建，清单成功发布后清理中间文件、失效 PNG 和空目录。纹理像素更新且逻辑 ID、契约不变时，剧本无需重新导入；本次契约升级的旧包须重新转换。原版 EXE 的版本身份校验属于导入器入口，保持独立。

解析修正与遗漏资源补齐使用显式 `--rebuild`，按光标、皮肤、地图、头像或单个图库档案更新；无需等待源文件变化，也不保存哈希或持久中间缓存。未选单元继续引用正式包，所选单元使用独立目录重打图集，避免覆盖仍被其他单元引用的旧资源。参数、范围与版本边界见[定向重转入口](client-content.md#转换与运行)。


## 完整原版资源库

头像完整覆盖786+50张大图及两张锚点表；原始中／小图由同一母图的96×120相对区域分别缩放呈现。另有43个已确认非头像 `G_*` 档案、4,577个颜色变体（包括三张BMP），涵盖去除宝物小图后的183+14张插图及界面、地图、开场、结局、外交、单挑、动态特效。文件来源只用于追踪，产品分类不按基础版／PK分两套。

头像裁剪详见[单份头像规格](../specs/behavior/BEH-RENDER-0004-shared-portrait-views.md)。完整、160×180和96×120三类视图按实际母图尺寸换算，同源GPU纹理按需建立区域视图，64×80和32×40共用96×120取景。死亡控件通过shader从正常色生成灰度，不新增物理纹理、CPU像素副本或调色板变体。

运行包不保留原始索引 PNG 或调色板字节。IDA 已确认当前繁中 PK 1.0.1.0 主程序不加载 `G_LNMASK` 640张和 `G_LNUKI` 32张；基础版 `G_Title` 4张由显式加载的 `G_TitlPK` 替代。它们不是已确认消费者下的转换遗漏，转换器不伪造最终纹理；来源结构、调用闭合证据和仍未确认的跨版本语义见 [RE-0169](../research/findings/RE-SAN9PK-0169.md)。`F_Font/P_Font` 属于独立字体管线。转换覆盖不等于所有场景和玩法都已接入。

## 透明度不变量

头像、插图、CPU 地形和 BMP 保持明确的不透明解释；其他索引显示资源导出透明键 RGBA，透明键比较完整调色板四字节，不按“看起来是绿色”猜测。已确认使用调色板 Alpha 的界面、建筑、云等仍由具体编译器显式选择，Alpha 使用既定0..128到0..255转换，不把所有源 Alpha 一律套用。

最终逻辑图片在打图集之前统一扩展透明边缘：只给 Alpha=0 的像素填邻近可见 RGB，保持所有 Alpha 与可见颜色，全透明图清零。派生／合成图片也经过此步骤，避免漏掉只在合成或双线性缩放时出现的绿边。扩边在每张逻辑图上完成，不能对整页跨区域扩散。PNG 与 GPU 使用非预乘 Alpha，运行时继续默认 source-over；水面仍按既有加色语义绘制。

## 所有权与预算

`TextureScope.Assets`只提供资源元数据，枚举不会加载纹理；`Request`／`RequestPrefixes`显式申请，索引器只读取已申请的纹理视图，未申请时直接报错。申请不代表加载完成，就绪状态由`IsReady`／`TryGetReady`查询；`BindingCount`表示绑定数量。页面装配声明皮肤资源族，动态资源在内容绑定时申请，绘制回调不发起申请；图标先按元数据选尺寸，再申请对应角色。自定义绘制通过`Get(role, canvas)`读取已申请纹理并登记实际绘制节点，资源就绪或失败后只通知登记的节点重绘，不从创建作用域的HUD递归推断消费者。接收整组裸纹理的滚动条通过`BindRedraw`登记轨道与滑块节点；节点离开场景树或作用域释放时解除登记。

`Main` 装配会话级 `TextureService`。`TextureScope` 是显示资源租约与逻辑区域视图，使用 `Texture2D` 接口；多个角色和窗口共享同一物理 GPU 纹理。窗口只申请实际使用的角色。窗口关闭或重建时移除旧控件并释放作用域；旧绘制引用经过两帧退役后解绑、释放，避免仍在使用的原生绘制命令引用已释放纹理。

| 资源 | 生命周期 |
| --- | --- |
| 共用 UI 皮肤（HUD、按钮、文字图标、目录、详情、信息窗口、全图装饰） | 启动时统一加载并等待就绪，战略场景常驻 |
| 武将／宝物头像 | 仅当前选择持有独立纹理，切换后旧请求释放 |
| 地图对象／动画 | 保护已呈现及待提交视野所需资源，预取外围一圈 |
| CPU 地形源图／遮罩／底云 | 保留合成所需像素，季节切换后替换季节源图 |
| 512×512 合成地形块 | 主地图与预览共用 `TerrainChunkCache`，按合成器代际及块坐标复用；各视图保护显示／待提交及缓冲区域，闲置块 LRU |

`Main` 的启动作用域持有`InterfaceSkin.RequiredUiAssets`声明的非头像资源，直到退出；各窗口仍按实际使用申请共享租约，关闭不影响启动作用域的常驻引用。加载失败走现有启动错误提示，不进入缺少皮肤的战略界面。此选择以增加启动加载量和固定显存占用，换取首次打开各窗口时无需冷加载这些共用皮肤；未列入启动集合的布阵等附加资源仍按页面申请并在就绪后重绘。不批量预载头像或地图，也不增加窗口就绪切换机制。

非地形 GPU 目标预算为 256 MiB，地形块为 256 MiB；两者复用 `ResourceBudget` 的引用保护与按字节 LRU。正在使用的资源不得淘汰，固定资源超出目标时允许超额。计数按宽×高×通道估算，不是驱动实测显存，不含纹理对象、对齐、驱动开销及两帧退役中的对象。

图片最多两个后台解码工作线程，完成后连续领取下一项，不等待下一帧上传；请求按显示优先和显式顺序排队，取消的排队项不执行。入队前为解码结果预留字节，排队、执行及待上传预留目标上限 32 MiB；单个独立图片大于上限时，只允许它独占解码队列以保证进展。文件纹理与生成地形共用每帧 2 ms 上传目标，单次上传不能抢占并记录超时；地形生成另有两个连续工作的后台线程，排队、执行和待上传结果独立限制在32 MiB。换季只逐块生成和上传目标首屏，不保留整屏已合成 CPU 图片。

预取优先级低于显示请求，每个物理资源就绪后立即释放预取租约；预算不足时跳过预取，真实显示请求仍可申请。没有引用的未完成任务取消，有其他消费者的共享任务继续。失败只结束本次请求，重新请求才重试；退出后不安装迟到结果。

## 像素副本与异步显示

客户端的文件纹理与 CPU 地形源图统一由 `ClientImageFiles` 调用 Godot `Image.Load` 解码，不使用 Content 的简化 PNG 解码器。加载时校验清单尺寸，再转换为清单声明的 L8／RGB8／RGBA8 像素布局，保持合成器与缓存预算一致；声明 RGB 的图片不保留替换文件的 Alpha。常规 PNG 的附加信息块与行过滤由 Godot 处理；替换文件须保持清单路径与尺寸，修改扩展名须同步清单。离线转换与校验工具仍使用自身的 PNG 编解码契约。

头像解码后释放 Godot `Image`，上传后释放解码数组；GPU 缓存项不持有图片像素。淘汰后再次需要时重新解码。未就绪头像显示固定尺寸占位，错误显示错误占位。当前选择通过 `ResourceSelection` 独占请求，旧请求完成不回填新选择，关闭页面后不再持有头像。

窗口图片未就绪时仅保留逻辑区域尺寸，区域视图不绑定底图、不绘制像素；就绪后绑定真实底图并通知所属控件树重绘。不得使用引擎的 `PlaceholderTexture2D` 作为加载画面，该类型[不适合实际渲染](https://docs.godotengine.org/en/stable/classes/class_placeholdertexture2d.html)。头像仍由控件显式绘制灰色／错误占位。全图隐藏时销毁其按钮并释放窗口作用域；重开时重新取得租约。HUD 和地图标注共享物理资源。透明拾取只保存必要的位掩码：HUD 与全图按钮用非零 Alpha，建筑用 Alpha≥128；不为拾取保留整张 RGBA。

悬停高亮由每个对象的 shader 执行原有颜色／Alpha 变换，保持桥、疆界、建筑、动画、云和选择标记顺序。滚动条直接从三段纹理绘制，不从 GPU 回读合成新纹理。区域平铺使用显式区域绘制，不依赖图集整页重复。

视野提交只等待当前镜头内地形、相交的静态对象与动画的当前季节完整帧集；可见建筑悬停旗帜需要的秋季第 2 帧也预先申请。对象是否进入镜头按图片矩形判断，不按建筑或动画锚点判断。外围对象纹理仅低优先级预取，未完成或失败不影响当前镜头提交；资源随后进入镜头时提升同一物理请求的优先级并等待就绪。换季及跳转失败保留已呈现画面。小地图边框、拾取和标注继续读取已呈现视野。

## 验证与画面验收

自动测试覆盖装箱后像素还原、扩边、分页、同像素不同资源保留身份、跨组独立资源、区域校验、请求合并、取消、失败重试、解码背压、预算保护／淘汰、预取预算、迟到结果、最新选择与完整视野提交。离线工具可比较原版解码后的 Alpha 和可见颜色，透明像素的隐藏 RGB 按上述扩边约定处理；不把资源覆盖与已接入玩法混为一谈。

F3 显示非地形固定／闲置 GPU 字节估算、地形 GPU 估算、CPU 合成源字节、待上传预留字节、命中／缺失／淘汰、累计解码／上传时间和单次上传超时数。截图自检等待活动纹理与视野连续两帧就绪后采集。

本次不启动 Godot 游戏。头像占位、图集接缝、三段背景、透明命中、动画加色与顺序、悬停高亮、换季画面由用户验收；编译与状态测试不等同于画面验收。预算是工程默认值，不据此声称实测性能提升。

## 多地图视图的地形资源

`MapWorld` 持有会话级地形缓存，主地图与详情预览通过 `MapSceneView` 申请独立租约；远处预览不移动主镜头、不替换主地图的可见集合。`TerrainChunkKey` 中不可变合成器的实例身份区分地图与季节代际，同一代际的重叠请求共用一次合成和上传。无消费者的旧代际块被清理，避免缓存键长期保留旧季节源像素。

地形合成最多两路并行，工作完成后连续领取排队项，待上传结果不占执行名额；排队、执行与待上传合计预留不超过32 MiB。已取消但尚未结束的任务仍占执行名额，上传遵守 `TextureService` 的帧预算。完成上传后释放任务结果引用；没有消费者的任务结果不上传。合成地形目标预算仍为256 MiB，涵盖主地图、预览及换季过渡；所有在用资源都保护，必要时允许暂时超额，预取不优先于可见请求。旧帧的租约经过两帧退役后释放。

`MapFrameTransition` 保留完整旧帧直到目标镜头内地形和对象均就绪，失败或被取代的请求不能提交。主地图外围缓冲地形和对象预取均不阻塞提交；移动进入缓冲区域前仍检查目标镜头内每块地形、实际相交的静态图片及完整动画帧集已就绪。对象绑定在同一缓冲区域内增量复用，探测已准备镜头只绑定GPU缓存命中的图片，不发起新的必需加载。绘制只读取已经绑定就绪的纹理，不能隐式申请外围图片；新增绑定就绪后按资源版本刷新对象和水面绘制。镜头内缺块优先于外围块入队，显式请求序号避免字典空位复用改变顺序。每个视图独立提交季节／世界版本，因此准备期间允许短暂显示不同的完整版本，不允许同一视图拼接新旧建筑与标注。预览首次加载显示提示，有旧帧时继续显示旧帧。此机制不改变领域状态、内容包或存档契约。


## 透明模式接入核对

透明色、调色板Alpha、不透明和固定权重加色是不同的消费方式。通用图库默认的透明色解释不能替代界面皮肤或地图组成定义指定的逐色Alpha；不得因为像素为黑色、调色板有低覆盖度或通道全零而自动选择透明模式。HUD装饰框、轨道／滑块、菜单合成框／三段按钮、情报操作三段按钮及情报地图图标均已按原版消费者明确接入逐色Alpha，转换版本18原位重建。证据及全局检查范围见[RE-0158](../research/findings/RE-SAN9PK-0158.md#已接入界面透明模式复核2026-09-26)与[RE-0161](../research/findings/RE-SAN9PK-0161.md#已接入界面透明模式复核2026-09-26)。

新增显示角色时，先确认具体消费者的混合语义，再选择对应转换出口；核验源透明色、源覆盖度、转换PNG的Alpha和可见RGB，以及装箱后的逻辑区域。`IndexedImageArchiveTests.PaletteAlphaUsesOriginalScaleAndCompleteTransparentKey`覆盖完整透明色、非透明色项的零／半覆盖和两种模式差异；仅有解码器单元测试不能证明每个角色接线正确，接入仍需消费者证据与像素核对。

## 异步重绘的引擎回归
