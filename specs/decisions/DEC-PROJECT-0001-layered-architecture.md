# DEC-PROJECT-0001：Godot 表现层与纯 C# 模拟核心分离

- 状态：已确认
- 日期：2026-08-15
- 决策者：项目所有者
- 关联行为：待建立
- 替代或被替代：无

## 背景

项目需要跨平台桌面表现、确定性策略模拟、无头测试、AI 长时间运行和未来内容工具复用。把领域状态放进 Godot 场景树会增加测试、序列化和确定性控制成本。

## 决策

采用 Godot 4.7.1 Mono 与 .NET 10。`Core` 不引用 Godot；`Content` 定义内容结构；`Application` 组织用例；Godot 客户端只能提交命令和读取快照。导入器不成为游戏运行时依赖。

运行时定义由 Application 的 `ScenarioSessionDefinition` 持有，`ScenarioRules` 在剧本会话建立时统一编译规则，模拟、AI、查询、草稿、消息上下文和结局投影复用这些规则；世界快照和预览只替换状态，不重新构建规则。

## 备选方案

- Godot 节点驱动规则：初期直接，但长期难以无头验证和复用。
- 全面 ECS：规模能力强，但当前领域和规模尚不足以抵消复杂度。

## 影响

- 玩家可见影响：无直接影响；有利于稳定暂停、存档和跨平台一致性。
- 数据/存档影响：世界状态必须由 Core 类型完整表达。
- 测试影响：绝大多数规则测试无需启动 Godot。
- 风险与代价：需要维护清晰的命令、事件和快照边界。
- 回退方式：无；这是基础架构约束。

## 验收条件

- [x] Core 工程不引用 Godot。
- [x] 客户端通过 Application 进入模拟。
- [x] 无头测试可推进旬并比较结果。
