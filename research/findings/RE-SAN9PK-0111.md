## 对象、状态、输入、输出与不变量

对象是交互/自动登用行动、24 号命令记录、每日命令事件任务、执行者、目标人物、执行势力与目标当前所属势力/据点。输入包括既有公式 2 的登用阈值、执行者与目标、目标实时身份/归属/位置、提交时保存的随机载荷、军师判断阈值以及各势力忠诚数组；输出包括人物身份、势力、位置、任务位、势力忠诚、势力关系和执行者政治成长尝试。

不变量：交互与自动生产者必须汇合到同一 24 号命令；提交时只固定随机载荷，不固定成功阈值；最终判定必须读取阶段到达时的实时人物状态；失败不得改变目标身份、所属势力或位置；成功必须以共享身份转换初始化身份 3、目的地和势力忠诚；命令完成后执行者行动占用必须进入公共释放路径。

## 已确认事实

### 交互、自动候选与共同命令

交互工厂 code 24 构造 `interactive_recruit_action_ctor@0x4C7170`，RTTI 为 `COrderTouyouDlg`。`validate_and_populate_interactive_recruit_action@0x4C7390` 复用公共上下文门，拒绝场景标志字 2 等于 9、据点状态码 6、据点虚函数 `+0x90` 为真、没有目标或没有可用执行者。执行者来自当前据点并排除 `person_flags & 0x1000`；目标经过共享 `is_recruit_target_eligible_for_force@0x472E40`。其在职分支排除异民族归属、同根势力、联盟成员／盟主配对、攻击请求配对及君主；俘虏和在野另走地点资格分支，详见下文2026-09-25补证。

自动工厂 code 24 构造 `automatic_recruit_action_ctor@0x4B6F10`。公共资格成立后，一个仍保持中性名称的势力谓词为真时另有 50% 跳过门。随后建立三类输入：

1. 可用来源对象由自动行动公共来源扫描产生；
2. 执行者来自本方城市人物集合，身份掩码为 `0x0F`（原始码 0–3），排除 `0x1000` 已行动者，再保留当前政治 `person+0x60` 位于闭区间 `35..115`，按该政治值排序；
3. 目标先以身份掩码 `0x30` 限定为原始码 4/5，再用共同资格谓词过滤：码 4 目标必须处于本方可登用的扣押关系，码 5 目标必须没有冲突的现属势力/位置；最后按人物 `+0x50/+0x58/+0x60/+0x68` 四个有效能力槽的最大值排序。

任一必要集合为空便不产生命令。共享选择器确定来源、执行者与目标后，交互和自动两侧都调用 `recruit_command_ctor@0x494F10`。自动评分探针会构造真实命令：军师结果 1 映射为 100、结果 3 映射为 0，其余情况使用真实登用阈值并套入配置区间；这不改变最终命令的随机判定。

### 提交、军师意见与阶段状态

`dispatch_recruit_command@0x495150` 先通过公共参与者准备路径给执行者设置 `0x1000` 行动位，再以执行者、目标和日期生成稳定种子（日期开关并非命令域，见[RE-0171](RE-SAN9PK-0171.md)），保存 `rnd(100, kind=0, seed)` 的 `0..99` 载荷到类型 24 事件记录。行程使用基础欧氏距离天数函数，不执行探索命令的10天倍数取整（2026-09-12纠错见RE-0110，旧“最大轴距离”解释撤回）；来源任务随后被标为活动。

`recruit_command_event_task_ctor@0x4950A0` 从事件记录恢复目标，初始化：

- `task+0x44 = 0`：成功标志；
- `task+0x48 = 0`：后续保存阈值；
- `task+0x4C = 1000`：阶段。

`process_recruit_command_event_task@0x4955A0` 的主阶段为：1000 到达/推进、1001 表现对象、1002 判定、1003 最终写回。阶段 1002 重新调用 `compute_recruit_success_threshold`，把阈值保存到 `+0x48`，读取命令提交时保存的随机载荷，并严格比较 `random < threshold`；成功才写 `+0x44=1`。所以同批多条命令只固定各自随机数，阈值会受先完成命令的实时写回影响。

`evaluate_recruit_advisor_result@0x495480` 不是最终骰。它用同一个执行者—目标稳定种子分别计算 `rnd(recruit_threshold)` 和 `rnd(advisor_threshold)`：两者布尔结果相同返回 1/消息 7305，不同返回 3/消息 7309。军师输出因此描述判断与真实阈值结果是否一致，不直接承诺成功或失败。

### 成功、负责人带动与竞争顺序

普通成功路径调用共享归属转换，将目标写为原始身份码 3，关联执行势力与目的对象，清理旧任务/战法间隔和相关人物标志。对执行势力的忠诚初始化为：

`L_new = 75 + trunc_toward_zero((50 - affinity(target, new_leader)) / 2)`

若目标原有势力有效，则其对旧势力忠诚写为 45。目标原有势力关系在普通成功时减少 `3 + rnd(3)`。执行者最终总会尝试一次政治成长 `try_increase_person_base_ability(actor, 3, 0)`，任务阶段回到完成态 2，再由公共任务链释放行动占用。

目标若同时满足“当前对象负责人”位 `person_flags bit 2`、旧势力/对象有效且对象未被排除，则进入负责人带动分支。该分支先实时枚举对象内其他人物；每人以 `sub_44F320` 计算的跟随阈值进行一次全局流判定，成功者加入归顺名单，失败者走脱离/重新安置路径。归顺名单中的每个人都执行同一个身份 3、目的对象、新势力忠诚公式和旧势力忠诚 45 写回；对象本身随后转交新势力并触发旧势力/区域清账。该分支的旧势力关系减少 `5 + rnd(3)`。

这里的“阶段竞争”是明确的顺序依赖：候选在下令时选择，随机载荷也在下令时保存，但阈值、目标现属势力、当前位置、负责人位及带动名单都在 1002/1003 读取实时值。先完成的登用或对象归属变化会改变后完成命令的阈值与终局分支；实现不能把候选快照当成最终可写回授权。

### 失败不变量与每势力忠诚

code 24 失败不改变目标身份、所属势力或位置，也不调用成功归属转换。非俘虏且旧势力有效时，旧势力关系减少 `1 + rnd(3)`；俘虏身份码 4 跳过这项关系下降。

事实（2026-09-06 复核）：失败先以 `75 - affinity(target, recruitingLeader)` 为阈值调用全局流概率门，命中则给目标对招募势力的忠诚加 1，上限为 255。这里的 `recruitingLeader` 是招募方君主，不是执行登用的武将：`0x495789 → sub_485E80 → get_object_force_leader@0x45E0D0` 得到君主，`0x495791` 保存，`0x495EA6..0x495EAE` 将其用于相性比较。旧记录的 `affinity(target, actor)` 因混淆反编译局部变量而写错。相性环距封顶 50，因此该概率阈值范围为 25..75；精确概率契约见 [RE-SANCALC-0001](RE-SANCALC-0001.md)。

事实：之后独立检查旧势力有效、目标身份为 1/2/3、目标与旧君主相性距离大于 0、义理 `person+0x70 < 15`；全部成立时，以阶段 1002 保存的登用阈值再次调用全局流概率门，命中后对同一个招募势力忠诚项减 1，下限为 0。两次忠诚调用 `0x495ED4/0x495F32` 都传入 `ebp`（`0x495787` 保存的招募势力），不是 `ebx`（旧势力）。减法门不依赖前面的加法门命中，故不能只描述为“抵消”：普通未饱和值可净增 1、不变或净减 1。

事实：加法链为 `increase_person_loyalty_for_force@0x44DD60 → sub_44CA10 → limadd(value,1,255)`；减法链为 `adjust_person_loyalty_for_force@0x44DDB0 → sub_44CA60 → limsub(value,1)`。二者均解析显式势力编号，读写 `get_person_force_loyalty@0x44C9D0 / set_person_force_loyalty@0x44C9F0` 对应的 `person+0xB6[forceId]` 字节。必须按先加后减顺序保留饱和边界：例如原值 255 且两门均命中，最终为 254，而不是用净增量 0 保持 255。旧势力个人忠诚项不由这两个失败反馈分支修改；势力间友好度下降是另一个对象域，不能当作个人忠诚下降。

事实：普通成功路径的 `0x495E4B` 尝试执行者政治成长；失败尾部 `0x495F37..0x495F3E` 直接设置完成态并跳往返回，跳过该成长调用。因此旧版“无论成功失败都尝试政治成长”的结论也予以撤回。此处只讨论 code 24 普通行程登用，不覆盖下节探索人物即时登用的独立执行器。

### 对“应扣原势力忠诚”的再次复核（2026-09-06）

用户指出：旧君主相性距离为 0 或义理为 15 时免于扣减，从设计上更像保护对现任君主的忠诚。该解释与手册意图相容，但不能替代机器实参。再次只读核对发现：

- `get_selected_actor_force@0x485EE0` 从当前命令执行人物取所属势力，`0x495787` 将其保存为 `ebp`；目标人物的所属势力由 `0x4957AB` 的虚调用取得，`0x4957B3` 保存为 `ebx`。
- 失败路径经 `0x4958F5 → 0x495923 → 0x495E6E`，没有把 `ebp` 改为旧势力。加法调用前的 `0x495ED1` 和减法调用前的 `0x495F2F` 都明确传 `ebp`；资格检查取得旧君主时则明确使用 `ebx`。条件读取与最终写入的势力确实不同。
- `0x44DDB0` 优先使用传入的有效势力，只有该参数无效才回退到目标人物当前势力；正常有效招募势力不会触发该回退。随后按传入势力的根编号索引忠诚表，未把编号替换为目标现属势力。
- 重新读取磁盘 EXE，大小与 SHA-256 均匹配登记样本；`0x495787`、加法传参段和 `0x495F2C` 起的减法传参段逐字节与 IDB 一致。减法传势力的指令位于文件偏移 `0x9532F`，确认为 `push ebp`，不是表示旧势力的 `push ebx`。因此该现象并非本次 IDA 注释或反编译命名产生的假象。

裁决：当前样本实际扣招募势力忠诚；传错对象仍为未确认推断，Steam 构建差异待验证。重制已另行批准改扣所属势力，见 [DEC-PERSON-0001](../../specs/decisions/DEC-PERSON-0001-recruit-failure-affiliation-loyalty.md)，不改变本记录的原作事实。

### 俘虏登用的额外分支（2026-09-06）

身份 4 的普通登用差异：关押地点须属于招募方；阈值加 30、不受原忠诚大于 99 的拒绝门限制，仍要求招募势力忠诚至少 50。失败只可能增加招募势力忠诚，不扣外交关系、不进入在职减法，也不改变身份或位置。

成功时使用俘虏专属消息，玩家表现路径还置世界标志 `0x2000`（只确认写入，不命名其最终玩法用途）；公共归属转换 `0x44F640 → 0x44D5F0` 根据身份 4 走 `0x45E4B0`，从原驻留对象的俘虏列表移除，然后转通常在职身份、清原军团缓存 `+0xEC`、重置官职/兵法间隔并加入目的对象。不是失败后自动释放。

独立的监禁旬扣减公式与证据统一见 [RE-SAN9PK-0112](RE-SAN9PK-0112.md)，不属于登用失败反馈。

### 探索人物事件的即时登用执行器

`execute_recruit_command@0x494580` 是探索人物事件的即时登用，不是 24 号行程任务。它共享公式 2，却使用新的全局流概率调用而非命令记录中的固定 `0..99` 载荷。判定前先把目标对执行势力忠诚增加：

`10 + trunc_toward_zero((50 - affinity(target, new_leader)) / 5)`

成功时同样转为身份 3，并按 `75 + trunc((50-affinity)/2)` 初始化执行势力忠诚。接受交互但登用失败时，`RE-SAN9PK-0110` 已确认目标从隐藏集合转为目标地点的身份 5，本批补充其对执行势力忠诚被直接写为 49。两条路径都尝试执行者政治成长。

## 资料裁决、推断与待验证

电子书 3-8 关于政治、忠诚、信望、义理、相性和俘虏影响登用的方向性主张，由公式 2 与本批真实调用链支持；精确整数式仍以 `RE-SAN9PK-0067` 为准，不能把攻略中的“政治对忠诚”简化语句当公式。

电子书 3-11 所说“失败有助下次登用”和“被登用后对旧势力忠诚 45”分别被修正确认：45 是成功离开旧势力后的明确写回；失败的招募势力忠诚由上述先加后减两个条件分支决定，不保证单调增加，也不扣旧势力个人忠诚。默认忠诚 50 的适用边界和俘虏旬扣减已由 RE-SAN9PK-0112 单独核对；没收宝物仍不在本链已确认范围内。

原始身份码 4/5/3 分别与俘虏、发现后在野、通常在职高度相容；这是跨记录机器行为推断，不替代未来正式领域枚举。负责人带动分支操作的是人物当前关联对象；其精确 UI 名称可能随城市、地域设施等子类变化，机器规格应保留“当前关联对象”而不硬编码单一建筑类别。

## 2026-09-25 登用的异民族资格门

作者：Codex。样本与工具沿用本记录登记的繁中PK 1.0.1.0及项目主库`San9PK-TC-101.i64`；本次健康探针、输入SHA-256、文件大小2,636,800、基址`0x400000`、IDA 9.3及Hex-Rays 9.3.0.260421均与登记一致。方法为完整反编译、关键分支反汇编、虚表原始字节与构造引用交叉核对；没有新增游戏运行实验，也不外推日版地址。

**事实，高置信度：异民族势力的在职武将不能成为普通登用目标。** 共同目标谓词`0x472E40`先调用`0x44BEF0 → 0x44BE70`，以掩码`0x0F`选择身份0至3。在此分支，`0x472E85`调用人物虚槽`+0x48`，非零即在`0x472E8A`跳至拒绝出口。真实人物构造`0x44B7B0`写入虚表`0x606110`，该表首项`0x44B7A0`返回`CPersonData`运行时类，表`+0x48`的原始四字节解码为`0x446920`。后者读取对象所属势力并经`0x43FA20`检查根势力`+0x34`的bit2，闭合为异民族归属。它不是人物种族、姓名、编号或忠诚阈值。命令校验`0x494F50`仍调用同一目标谓词，因此不能绕过候选门靠高政治或降低忠诚登用。
