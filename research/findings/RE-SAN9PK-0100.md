## 对象、状态与不变量

本批对象是一次陆战兵法机会成功写入候选列表后，候选人物怎样取得或丢失这次机会。输入是源部队人物列表、人物当前伤势与发动间隔、九宫格阵位、当前选择兵法、源部队人数、阵形和交战对象；输出是一个人物兵法子任务，或整次机会结束。发动后的间隔重置、联动者间隔、动画、经验和成长属于 `TAC-03`。

不变量：人物当前间隔是候选资格，不是机会产生概率；机会候选按阵位行排序后逐项消费；人数系数使用源部队全部当前成员数，不是过滤后的合格人数；阵形加倍只属于四类武力兵法；候选谓词和任务工厂支持的兵法类别范围并不相同，因此“候选非空”不保证能创建兵法子任务。

## 候选谓词与当前间隔

`process_tactic_opportunity_task_state(0x505EF0)` 先从源对象虚表槽 `+0x7C` 取得人物列表，再以 `is_tactic_opportunity_candidate_person(0x472CB0)` 过滤。该谓词要求：

```text
person.interval_at_0x98 <= 0
person.health_at_0x80   <= 0
(person.flags_at_0xE8 & 0x1000) == 0
selected_tactic is invalid OR selected_tactic.category < 42
```

`+0x80` 已由 [RE-SAN9PK-0009](RE-SAN9PK-0009.md) 闭合为健康/伤势倒计数；故只有值 0 的健康人物进入候选。`+0x98` 在此处只作 `<=0` 资格门，负值同样通过。谓词没有读取兵法记录的基础最小间隔，也没有要求当前选择兵法对象有效；基础值如何在发动后写回人物字段属于 `TAC-03`，电子书所列 6/9/15 数值表仍由 `TAC-04` 对账，不能由本谓词直接确认。

## 阵位顺序与逐项消费

机会主概率成功后，代码以 `get_person_formation_row_sort_key(0x471C10)` 取得 `get_person_unit_formation_row`，再调用 `0x46F610(..., direction=1)`。`sort_list_by_key` 的机器比较表明方向 1 为键值升序，因此候选顺序严格为前锋行 0、中锋行 1、后卫行 2；同一行保持原列表相对顺序。列表随后截到最多 5 人并复制到机会任务。

状态 1004 每次先检查候选数，再由 `pop_front_list_value(0x518210)` 从队首删除并返回当前人物，随后调用 `create_person_tactic_resolution_task(0x5014B0)`。这不是只读首项：人物在子任务建立之前已经从列表移除。受支持子任务的资格函数位于各自虚表槽 `+0x20`；资格概率失败时不进入结算，控制返回仍为状态 1004 的机会任务并消费下一人。列表耗尽时机会任务进入完成状态 2。

## 分配概率与类别

`get_tactic_position_coefficient(0x4FEA10)` 返回阵位行系数 `5,4,3`。`get_tactic_member_count_coefficient(0x4FEA50)` 重新读取源部队全部成员，把人数封顶为 5，并按 `0,20,14,10,9,8` 取系数。四类武力兵法的共同随机式为：

```text
chance = position_coefficient
       * member_count_coefficient
       * formation_coefficient
       * 5 / 8
kakuritsu(chance, RANDOM_KIND_GLOBAL_STREAM, 1)
```

乘法完成后只在末尾除以 8。阵形系数默认为 1，命中下列硬编码集合时为 2：

| 兵法类别 | 当前选择兵法 ID | 有利阵形类别 |
| --- | --- | --- |
| 步兵 | `0..2` | `0,1,15,18,19` |
| 骑兵 | `3..5` | `2,3,16,17` |
| 弓骑 | `6..8` | `2,5,16` |
| 弩兵 | `9..11` | `4,5,8` |

对应资格函数分别是 `check_infantry_cavalry_tactic_allocation(0x503560)`、`check_mounted_archery_tactic_allocation(0x503680)` 和 `check_crossbow_tactic_allocation(0x503730)`。谋略/策略资格函数 `0x504B80`、`0x5057E0`、`0x505890`、`0x506980`、`0x5071B0`、`0x5075F0` 同样使用阵位与人数系数，但没有阵形乘数，普通单位目标的随机式为 `5*position*members/8`；各函数在掷骰前仍有自己的目标、关系和状态门，部分特殊对象分支可直接通过，不能把统一概率当成全部资格条件。

## 类别遮蔽与提前终止

候选谓词允许无有效选择兵法的人物，也允许类别 `0..41`。但人物任务工厂只为 `0..11`、`23`、`24` 和 `25..30` 建立对应子任务；类别 `12..22` 走跳转表默认空返回，`31..41` 和无效兵法同样没有可返回的陆战子任务。状态 1004 对空返回不是“跳过此人”，而是在 `0x50646E` 直接把机会任务置为完成状态 2。

因此 SanIX 所述“锋线人物兵法发不出来时，后四人尚未判断就结束”存在明确静态机制：候选按阵位升序，首个不受陆战工厂支持的人物会遮蔽后续候选并丢失整次机会。该结论不再依赖一次截图观察；但它不是“所有锋线概率失败都会遮蔽后排”，受支持类别的资格概率失败仍可继续消费下一候选。

## 来源校核与候选清账

SanIX 关于健康/间隔候选、前中后 `5/4/3`、人数表、四类有利阵形和末尾 `*5/8` 与当前机器式一致；其“谋略/策略无有利阵形”也得到六个资格函数的独立交叉引用支持。原文没有区分“资格概率失败”和“任务工厂空返回”，本批补上了真正的提前终止边界。电子书对人物 `+0x98` 达到 0 才能再次候选的主张已确认；6/9/15 基础值和每日递减/发动重置尚未在本批闭合。

`TAC-02` 队列共 26 项：11 项人数系数地址命中 `0x4FEA50`；3 项 `0x5030EA` 属已确认的兵法阻击阵形加成而非机会分配；4 项 `0x4B8295/0x4B87EB` 属自动兵法/阵形选择；3 项二次间隔候选实际落在发动后 `0x4FF030` 写回，转交 `TAC-03`；1 项相对偏移 `0x7C` 只佐证运行时兵法记录的间隔字段；其余 4 项为动态地址或配置绑定，不能独立证明原版规则。26 项均有显式处置，未留未决候选。

## 事实、推断、待验证与结论

- 事实：候选要求当前间隔和伤势均 `<=0`，人物标志位未置位；无有效选择兵法也会进入候选。
- 事实：候选按阵位行 `0 -> 1 -> 2` 排序并逐项从队首删除，人数系数取源部队全部成员数。
- 事实：四类武力兵法使用阵位×人数×阵形×5/8；谋略/策略没有阵形加倍。
- 事实：不受工厂支持的首个候选会让整次机会立即完成，形成前排对后排的类别遮蔽。
- 推断：SanIX 截图中的具体人物配置命中了上述空任务类别；图片本身不足以恢复每个人当时的选择兵法 ID。
- 待验证：兵法记录基础最小间隔 6/9/15 的逐项数值、人物字段每日递减、主发动者/联动者写回及水战/设施差异，进入 `TAC-03/04`。
