# BEH-DOMESTIC-0001：四项内政基础增量

- 状态：已确认

## 适用范围

定义巡查、商业、开垦、修筑的基础增量，以及已知加倍判定结果时的最终数量和费用。完整命令、组合判定、账户提交、信望与熟练度副作用由[BEH-ECONOMY-0001](BEH-ECONOMY-0001-domestic-and-economic-cycle.md)定义。

## 原作基线

RE-0095于2026-09-06将实际指令与RE-0067能力生产链交叉核对：巡查使用当前智力，商业和开垦使用当前政治，修筑使用当前统率。原记录的能力对应关系错误，已纠正。

## 重制行为

输入为内政种类、当前值、上限、参与者当前有效能力及执行前实际资源账户资金。不得使用基础能力代替当前能力，也不在本函数重新应用伤势、宝物或官职加成。

令差额 `d = maximum - current`、人数 `n`、对应当前能力总和 `S`：

- `R = floor(sqrt(4*d))`。
- `A = floor(5*(21-n)*R/100)`。
- `T = floor(S*A/1000)`。
- 巡查：`min(d, n + floor(9*T/5))`。
- 商业、开垦：`min(d, n + 3*T)`。
- 修筑：`min(d, funds, n + 3*T)`；资金只限制最终基础增量，不能替换平方根输入的差额。

使用整数平方根及足够宽的整数中间量，保持截断位置；不复刻原版异常输入导致的整数溢出。计算无随机调用、无状态变化。

数量结算必须显式接收已经完成的加倍判定结果；不得自行生成随机数。未加倍时最终增量等于基础增量，加倍时为`min(d,2*基础增量)`。修筑也遵循此式，不能在加倍后再次夹取资金。费用始终为`50*n`，与最终增量无关。数量结算要求资金足以支付费用；否则明确拒绝，不能返回可提交结果。返回基础增量、最终增量和费用，供完整命令在重新校验后原子写回。

## 状态与不变量

- 输入与前置条件：已验证种类；`0 <= current <= maximum`；非负资金和当前能力；1至5名参与者。RE-0095续查已确认四个玩家入口及AI均最多五人。
- 状态变化：无；返回基础增量。
- 始终成立的不变量：结果非负且不超过差额；修筑不超过执行前资金；参与者排列不影响结果；零差额结果为0。
- 失败或无效输入行为：非法种类、空参与者、超过已确认人数范围或非法数值明确拒绝，不夹取输入后继续计算。

## 示例与边界

差额100、单人对应能力100时，`R=20,A=20,T=2`，巡查增加4，其他三项增加7。修筑资金为3时增加3；不能先把差额降为3再求平方根。

差额99、单人能力100时，`R=19,A=19,T=1`，巡查增加2，商业增加4。这与差额100形成截断边界。

## 运行时命令

G03已接入1至5人四项内政及征兵、训练，全部通过同一`DevelopCommand`和控制者上下文提交。`DevelopmentCommand.OfficerIds`保存不同参与者身份；账户由当前据点军团解析，拒绝零副作用，旬更新恢复六项使用状态。单人商业/开垦仍由同一处理器执行，客户端F3保持单人调试入口。

基础公式的无随机契约不变；完整命令需要加倍时消费命名组合随机。当前行为、资源守恒与验证见[经营规格](BEH-ECONOMY-0001-domestic-and-economic-cycle.md)及[G03验收](../../docs/g03-verification.md)。
