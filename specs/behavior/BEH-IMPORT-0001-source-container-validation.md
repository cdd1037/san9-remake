## 适用范围

本规格只约束 `Importer.San9PkTc101` 对已登记繁中 PK 1.0.1.0 安装中剧本和头像容器的识别与边界校验。导入流程必须先通过 `San9PK.exe` 的大小和 SHA-256 身份门槛。

本规格不定义剧本实体字段语义、头像颜色通道、透明度、图像行方向、剧本显示名称或重制内容模型。

## 原作基线

### 正式剧本

`D_Sce001.S9` 至 `D_Sce020.S9` 是 `RIFF` 容器，form type 为 `S9SC`。RIFF 声明大小加 8 必须等于文件长度。容器依次包含以下 chunk，大小以字节计：

| Chunk | 大小 |
| --- | ---: |
| `head` | 82 |
| `area` | 90 |
| `ciki` | 102 |
| `fbld` | 476 |
| `hiho` | 1,558 |
| `kans` | 126 |
| `shak` | 1,386 |
| `skrk` | 70 |
| `kkgu` | 240 |
| `jnki` | 896 |
| `squa` | 560,000 |
| `bldg` | 5,600 |
| `city` | 2,800 |
| `forc` | 4,300 |
| `item` | 2,640 |
| `unit` | 32,000 |
| `prsn` | 107,200 |

`head` 按小端顺序包含：一个 32 位格式版本、四个场景世界标志 `u32`、16 位剧本编号、16 位模式/地图缓存组合值、16 位起始日期编码、16 位联盟持续时间（单位为旬）、16 位地图宽度、16 位地图高度以及 50 字节的城市势力颜色快照。组合值的低字节选择原作 `D_LandNN.s9` 地图绘制缓存；高字节只有低 4 位进入运行时场景模式，正式剧本中模式 0 为普通模式、模式 1 为忽略人物年龄，高字节高 4 位被目标加载器丢弃。导入器同时保留原始 `u16`，不得把被丢弃位解释为模式。

四个 `u32` 直接成为 128 位世界事件状态。正式样本只有第一字非零；载入后的日期初始化还会按固定日期阈值向第一字追加位而不清除文件初值，所以导入值与最终新局状态必须分开。第一字 bit 0 会使当前皇帝解析返回空，但 220 年 10 月 24 日及以后也会由日期初始化置位。

50 字节向量按城市 ID 排列。20 个正式剧本的 1,000 个城市槽中，798 个有效城市均精确等于其 `city +0x1C` 所属 `forc` 记录的 `ColorCode`，202 个空城市均为 `0xFF`。它是冗余的初始显示颜色快照，不是另一套势力 ID；城市初始归属仍以 `city +0x1C` 为规范来源。

起始日期采用以 130 年为纪元、每年 360 天、每月 30 天的编码。编码 `21600` 解码为 190 年 1 月 1 日。`D_Sce002.S9`的编号1、190年1月1日是登记样本事实，不是导入资格门。当前20个正式剧本均按各自头部日期和编号转换，地图尺寸只校验本版本实际支持的200×200源格式；重制契约不继承此尺寸限制。一般／if分类由Importer按源界面编号范围映射到剧本目录定义，客户端不根据编号推断分类。正式剧本标题和长说明不存放在 `head`；加载器按剧本编号分别绑定 `M_MsgPK.s9` 的 `2×ScenarioId` 与 `2×ScenarioId+1`。内容文本仍不得复制进仓库。

### 头像图像

头像图像文件以一个 32 位小端文件总长度开始，其后重复保存图像记录。每项由四个 32 位小端整数和紧随其后的 8 位索引像素组成：记录总大小、行步长、宽度和高度。必须满足：

- 声明文件长度等于实际长度。
- 每项记录头一致。
- `记录大小 = 16 + 行步长 × 高度`。
- 行步长等于宽度，文件末尾没有不完整记录。

已确认的文件布局如下：

| 文件 | 数量 | 宽 × 高 |
| --- | ---: | ---: |
| `G_FaceL.s9` | 786 | 240 × 240 |
| `G_FaceS.s9` | 786 | 64 × 80 |
| `G_FaceT.s9` | 786 | 32 × 40 |
| `G_FacLPK.s9` | 50 | 240 × 240 |
| `G_FacSPK.s9` | 50 | 64 × 80 |
| `G_FacTPK.s9` | 50 | 32 × 40 |

### 头像调色板

`P_Face.s9` 以 32 位小端记录数开始。目标文件必须包含两项记录；每项由 40 字节记录头和 `256 × 4` 字节调色板数据组成，文件末尾不得存在未解析数据。

## 重制行为

导入器必须独立解析上述容器并返回只读布局信息。格式不匹配、长度越界、记录元数据不一致或存在尾随数据时必须明确拒绝，不得猜测、截断、补齐或尝试兼容未知格式。

容器解析与像素解码、字段语义转换保持分离。后续解码器只能消费已经通过本规格校验的区段。

## 状态与不变量

- 输入与前置条件：可读、可定位且从文件起点开始的流；安装身份已通过目标 EXE 指纹门槛。
- 状态变化：无；解析器只读取输入并返回布局或头信息。
- 始终成立的不变量：任何返回的区段和图像数据范围都完全位于输入文件内。
- 失败或无效输入行为：抛出明确的格式错误；不产生部分转换结果。

## 示例与边界

- `D_Sce002.S9`：剧本编号 1，日期编码 21600，解码为 190-01-01。
- 被截断 1 字节的 RIFF：因声明长度与实际长度不符而拒绝。
- `item` 大小由 2640 改为 2642：因已确认 chunk 布局不符而拒绝。
- 头像第二项记录的宽度与第一项不同：拒绝整个文件。
- 调色板记录数大于文件可能容纳的数量：在分配记录列表前拒绝。
