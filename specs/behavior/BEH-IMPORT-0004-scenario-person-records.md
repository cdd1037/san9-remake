## 适用范围

本规格约束繁中 PK 1.0.1.0 剧本 `prsn` chunk 的记录边界、已确认字段和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不定义名称资源到实际文本的解析、姓名读音采用的具体注音体系、身份与爵位显示名称、地点代码的异构对象类型、勇猛、信念、“友/相性武将”、属性或熟练度的玩法范围，也不包含 50 个新武将槽。寿命、健康、旗和身份状态起始年属于本规格。

## 原作基线

`prsn` chunk 包含 800 项，每项 134 字节。导入器必须按以下分组读取：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| `0x00` | `u32` | 人物原始标志字；已确认位定义见下表 |
| `0x04` | `u16` | serialized id |
| `0x06` | `u16` | 姓资源代码 |
| `0x08` | `u16` | 名资源代码 |
| `0x0A` | `u16` | 字（表字）资源代码 |
| `0x0C` | `u16` | 姓名读音资源代码；具体注音体系未定义 |
| `0x0E` | `u16` | 头像资源编号 |
| `0x10` | `u16` | 列传资源编号；列传正文不内嵌在本记录中 |
| `0x12` | `u16` | 登场年编码；显示年为编码加 130；身份 7 达到该年后才可进入身份 6/3 的派生流程 |
| `0x14` | `u16` | 出生年编码；显示年为编码加 130；年龄为当前年加 1 再减该年 |
| `0x16` | `u16` | 当前身份状态起始年编码；解码年为编码加 130。在职时为加入当前势力年/仕官基准年，俘虏时为被俘年；原值 0（解码 130）是未设置哨兵 |
| `0x18` | `u16` | 地点代码；小于 1,100 时为有效运行时引用 |
| `0x1A` | `u16` | 无效/保留字段；目标加载器读取但不写入运行时人物对象 |
| `0x1C` | `u16` | 身份代码；0–9 为目标程序已知值 |
| `0x1E..0x24` | 4×`u16` | 统率、武力、智力、政治 |
| `0x26` | `u16` | 爵位/称号候选代码；0–75 为目标程序已知值 |
| `0x28` | `u16` | 寿命档位；目标程序生成值域为 `0..7` |
| `0x2A` | `u16` | 健康/伤势值：`0` 为良，`1..4` 为轻伤，`5..14` 为重伤；恢复时逐期递减至 0 |
| `0x2C` | `u16` | 血缘根人物编号；小于 1,050 时为有效运行时引用 |
| `0x2E` | `u16` | 父母/亲代人物编号；小于 1,031 时为有效运行时引用 |
| `0x30`、`0x32`、`0x34`、`0x36` | 4×`u16` | 相性、义理、野心、性格；运行时依次落到人物 `+0x6C/+0x70/+0x74/+0x78` |
| `0x38` | 9×`u16` | 九类兵法熟练度 |
| `0x4A` | `u16` | 当前装备兵法代码；0–40 为有效运行时引用，与 `0x00` 标志字相互独立 |
| `0x4C` | `u16` | 旗代码；`0xFFFF` 表示无旗代码 |
| `0x4E` | 50 字节 | 势力忠诚候选值表 |
| `0x80` | 6 字节 | 已习得兵法位集；已确认兵法编号为 0–40 |

`0x00` 标志字的已确认位定义：

| 位 | 规格语义 |
| --- | --- |
| bit 0 | 性别二值标志 |
| bit 2 | 所属对象的主将/负责人标志 |
| bit 3–11 | 九类兵法精通标志 |
| bit 12 | 命令占用/参与标志 |
| bit 13 | 特殊俘虏子状态；只与身份 4 共同解释，精确业务名称未定义 |
| bit 15 | 兵法修行/传授事件进行中标志 |
| bit 16–20 | 九宫格成员位置 `0..8`，9 表示无格位 |

bit 1、bit 14 和 bit 21–31 不定义玩法语义，必须原样保留。bit 14 已知属于会被周期流程清理且参与人物过滤的临时状态，但在精确业务名称确认前不得暴露为“已行动”等确定属性。

## 重制行为

导入器必须完整保留每项 134 字节所表达的全部字段。四个名称资源代码以及头像、列传资源编号、寿命档位、健康/伤势值和旗代码必须作为独立值暴露，不得合并为无语义数组，也不得在缺少资源包时伪造显示文本。列传资源编号与列传正文必须保持分离。血缘根编号与父母/亲代编号必须作为两个独立人物引用暴露，不得合并为通用关系数组，也不得误命名为“友”。未知字段不得丢弃、钳制或移入玩法模型。50 字节表和六字节兵法位集必须以只读值暴露，不返回底层可变数组。

地点、身份、爵位、血缘根、父母/亲代和当前装备兵法代码应同时保留原始 `u16`，并按目标程序边界提供可空派生 ID。性别、负责人、精通、命令占用、特殊俘虏子状态和兵法修行状态查询只能读取上表对应位；成员位置查询只读取掩码 `0x001F0000`，并把 9 解释为无格位；已习得兵法查询只接受编号 0–40。当前装备兵法不得从 `0x00` 推导，已习得兵法也不得与当前装备兵法合并。标志字和位集的其余位仍须原样保留。

`0x16` 必须作为当前身份状态起始年编码暴露，并提供“编码加 130”的派生年份。在职身份下派生加入当前势力年及包含起始年的仕官年数；俘虏身份下派生被俘年及包含起始年的被俘年数。其他身份只保留原始编码，除非后续证据确认其业务显示名称。该槽会随身份转换改写，故不得命名为人物一生不变的首次仕官年，也不得解释为登场年或寿命。健康查询必须按 `0`、`1..4`、`5..14` 分别派生良、轻伤、重伤，同时保留原始 `u16`，不得只保存分类结果。旗代码与姓氏文本必须保持分离；没有资源映射时不得用姓氏首字符伪造旗显示。

`0x12` 与 `0x14` 不得因字段相邻而按界面展示顺序猜测。目标程序明确把 `0x12` 用作登场门，并可令其等于 `0x14 + 14`；自然死亡和年龄显示链读取 `0x14`。导入器必须分别暴露 `EncodedAppearanceYear/AppearanceYear` 与 `EncodedBirthYear/BirthYear`，不得保留早期颠倒命名。

`0x1A` 必须作为原始 `u16` 无损保留，但不得映射到运行时人物领域属性，也不得根据其非零值改变导入结果。它只参与记录边界消费。

原作当前皇帝解析器按 `0x10` 列传资源编号依次查找 `563`、`564`、`565`，并选择首个有效且身份代码不为 `8` 的人物。这里的三个常量不是记录序号、`serialized id` 或通用人物 ID；导入器不得为迎合该规则改写记录顺序或 `0x04` 字段。候选人物的城市由 `0x18` 地点代码在运行时派生，不得在城市记录中伪造皇帝字段。

本阶段不以未经正式剧本复验的数值范围拒绝整个记录。后续加入严格校验前，必须用多份正式剧本或可重复单变量实验确认不变量，并更新本规格。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整剧本流，位置在文件起点。
- 状态变化：无；只生成 800 项只读记录。
- 始终成立的不变量：返回顺序等于文件顺序；每项完整消费 134 字节；整个 `prsn` chunk 恰好消费 107,200 字节。
- 失败行为：容器或记录边界不成立时抛出格式错误。

## 未决问题

- 姓名读音采用的具体注音体系，以及资源包文本解析格式。
- 勇猛的存储位置；不得用当前保留字段猜测填充。
- `0x00` bit 14 的精确业务语义，以及 bit 1、bit 21–31 是否在尚未覆盖的流程中使用。
- 旗代码到显示字符的资源映射。
- 信念及“友/相性武将”属于未纳入本规格的 50 个新武将槽；后续应在对应扩展记录规格中定义。
- 爵位/称号与 50 字节忠诚表的第二来源验证。
- 正式剧本中的编号、能力、属性、熟练度与位集不变量。
