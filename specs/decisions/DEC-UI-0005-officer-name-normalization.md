# DEC-UI-0005：原版文本统一解码与简体显示

- 状态：已接受
- 日期：2026-09-06
- 关联：BEH-UI-0002、RE-SAN9PK-0159
- 授权：用户要求统一原版数据到UTF-8的入口，保留在导入器内，并采用OpenCC。

## 决策

所有原版文本字节由版本导入器的OriginalTextConverter统一处理：CP950及已确认扩展码位解码为正确Unicode源文，再以OpenccNetLib 1.6.2的T2S配置生成简体显示文字。内容序列化层输出UTF-8。姓名、地名与EXE设施后缀共用入口；消息容器仅负责读取字节和校验边界，不另行解码。

依据[RE-0159](../../research/findings/RE-SAN9PK-0159.md)，FA40/41/45按码位直接解码为伷/璝/儁，与所处姓名或正文无关。SourceText保存正确源字，Text保存OpenCC结果，例如朱儁→朱俊、劉璝→刘𪻺。不使用HKSCS投影冒充原字形，不按整姓名补救，不设独立文本项目。未知扩展、图标及脚本控制明确拒绝，不能随意降级成其他字。

此前人物602被猜测为刘繇，已由原字形证据纠正为劉璝；原版字节来源保持不变。字符转换不参与人物ID、归属或玩法。

## 待后续考虑：异体字归一化

用户要求仅记录、暂不实施。后续评估是否在简体显示之外增加异体字归一化，例如“璝→瑰”（显示“刘瑰”）。这是待评估候选，不是已批准的姓名替换规则；需确定可靠依据、姓名适用范围、与OpenCC的处理顺序及罕见字保留原则，再更新行为规格。当前OpenCC T2S行为不变。

补充观察：当前“朱儁”已经显示为“朱俊”，说明所用OpenCC T2S词典已包含部分异体字转换，不能将现状描述为完全未处理异体字。是否沿用词典结果、保留原版姓名字形，或采用其他统一规范，均留待后续考虑；“朱儁／朱俊”与“璝／𪻺／瑰”的最终显示选择尚未决定。本次仅补充记录，不新增或撤销转换规则。
