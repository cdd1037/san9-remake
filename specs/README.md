# 规格索引

`specs/` 保存已采用的产品行为与重要决策，研究记录提供证据，实际实现进度见根目录 [README](../README.md)。

## 规格维护

- 新功能、核心规则和数据语义变化先明确目标行为与验收标准。用户要求或已有约定足够明确时，可在同一任务中更新规格、实现和验证，无需另设文档审批步骤。
- 优先更新已有 BEH；形成独立行为主题时才新增。普通修复、布局调整与重构可直接实施，只在改变长期约定时更新文档。探索性原型可以先验证设计。
- BEH 描述最终行为与验收；DEC 仅记录需要独立解释的重要长期取舍、备选方案与代价，并链接相关 BEH。可在 BEH 内说明的选择、一般视觉差异与未来设想无需另立 DEC。
- 区分原作事实与重制选择；证据未决只限制原作结论的确定性，不阻塞已有明确目标的重制实现。未来规划与已采用行为分别标明。

当前证据纠错、规格边界与待用户集中处理事项见[研究与规格疑点清单](../research/research-open-questions.md)。

## 约束词

- **必须**：不可省略；违反即不符合项目规范。
- **应该**：推荐做法；有实质影响的偏离说明原因，不为无关项补记录。
- **可以**：可选做法，不构成要求。

## 文档状态

| 状态 | 含义 | 是否可作为实现依据 |
| --- | --- | --- |
| 草案 | 正在整理，内容可能变化 | 否 |
| 验证中 | 已有证据，仍需复验或解决矛盾 | 否 |
| 已确认 | 已采用的目标行为或设计决策，边界与验收明确 | 是 |
| 已废弃 | 被新文档取代或结论被否定 | 否 |

表中“实现依据”指正式产品要求；草案与验证中的内容仍可用于探索原型。满足目标、边界与验收要求即可按当前授权更新状态，“已确认”不额外要求一次用户审批。

BEH与DEC在元数据中使用以上状态；旧有“已接受”统一为“已确认”。产品状态表示是否采用，不表示原版事实已获证实。RE中的事实、推断、待验证及置信度单独表达证据质量和样本适用范围；现代设计可以被采用而没有对应原版事实。

## 标识符

| 前缀 | 对象 | 示例 |
| --- | --- | --- |
| `SRC-` | 来源 | `SRC-KAODATA` |
| `EXP-` | 黑盒实验 | `EXP-EDITOR-0001` |
| `RE-` | 逆向记录 | `RE-SAN9PK-0001` |
| `BEH-` | 行为规格 | `BEH-SEARCH-0001` |
| `DEC-` | 改良决策 | `DEC-UI-0001` |

进入共享或发布基线的标识符一经引用不得复用。尚未对外使用的一批新增记录可在整理提交中整体重编号，但必须同步仓库内全部引用；被否定或废弃的既有记录保留原 ID，并链接替代项。
