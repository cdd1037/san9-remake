# BEH-IMPORT-0013：剧本 `skrk` 记录解析

- 状态：已确认（区块边界、记录数量和无损读取；业务用途未确认）
- 负责人：项目开发者
- 最后更新：2026-08-16
- 关联证据：[RE-SAN9PK-0018](../../research/findings/RE-SAN9PK-0018.md)
- 关联决策：[DEC-DATA-0001](../decisions/DEC-DATA-0001-content-pipeline.md)

## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `skrk` chunk 的记录边界、顺序身份和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不把 `skrk` 强行解释为设施、地形、兵种或其他重制领域对象。现有证据只确认目标程序把它加载到运行时表，不能据此证明它是死数据或已知玩法表。

## 原作基线

`skrk` chunk 位于正式剧本数据偏移 `0xF38`，包含 7 项，每项 10 字节，共 70 字节。运行时记录 ID 使用文件顺序 `0..6`。每项由 5 个小端 `u16` 组成：

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| ---: | --- | --- | --- |
| `0x00` | `u16` | `serialized_id` | 原始序号槽位；原程序读取后丢弃，运行时编号使用记录序号 |
| `0x02` | `u16` | `opaque_field_02` | 写入运行时对象；当前未发现独立索引访问器或直接消费者 |
| `0x04` | `u16` | `opaque_field_04` | 写入运行时对象；当前未发现独立索引访问器或直接消费者 |
| `0x06` | `u16` | `opaque_field_06` | 写入运行时对象；当前未发现独立索引访问器或直接消费者 |
| `0x08` | `u16` | `opaque_field_08` | 写入运行时对象；当前未发现独立索引访问器或直接消费者 |

正式样本中出现了分组值，但默认数据分组不是字段命名证据。当前最准确的描述是“已加载到运行时表，直接消费未发现，业务用途未证实”。

## 重制行为

导入器必须生成 7 个按文件顺序排列的 `skrk` 定义，并暴露 `Id`、`SerializedId` 和四个不透明原始字段。所有 5 个 `u16` 必须按小端读取并保留；不得因原程序当前没有发现直接消费者而丢弃整张表或把字段转换成未经确认的规则。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整 `S9SC` 剧本流。
- 状态变化：读取 `skrk` chunk 后产生 7 条记录；导入过程不推导额外领域语义。
- 始终成立的不变量：chunk 大小为 `70` 字节；每项完整消费 10 字节；记录 `Id` 为 `0..6`；四个不透明字段保持 `u16` 宽度。
- 失败或无效输入行为：chunk 大小异常、记录截断或游标不能恰好填满 chunk 时抛出 `InvalidDataException`。

## 示例与边界

正式样本第 0 条的五个 `u16` 为 `0, 0, 1, 1, 3`，第 1–6 条显示出分组值。该观察只说明字段确实承载非随机数据，不足以命名其用途。任何超出当前样本的 `u16` 原始值都必须继续保留。

## 验收标准

- [x] 7×10 字节边界、记录顺序和全部原始字段由自动测试证明。
- [x] 四个不透明字段不会因没有已确认语义而丢失。
- [x] 异常 chunk 大小会被拒绝。
- [x] 测试夹具不依赖原版文件、编辑器或 IDA 数据库。

## 未决问题

- 其他版本是否使用相同的记录布局和运行时表。
