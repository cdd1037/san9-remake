# 随机判定、SL与录像

本约定实现[确定性决策](../specs/decisions/DEC-SIM-0001-determinism-and-saves.md)。验收关注操作顺序、SL与回放行为；算法、种子组合和流划分采用现代实现，不要求原版同种子同结果。

## 两类玩法随机

**固定条件随机**使用不变的本局种子、用途、下令日期、执行者及目标身份计算百分骰。没有共享抽样游标，不依赖命令ID、提交序号或本次运行种子。完全相同的条件得到相同骰子，先提交其他操作、读档或重启进程不会改变它。不同输入可以产生不同骰子，但百分骰只有100种取值，不保证输入改变时数值必变。现有算法使用Ordinal用途名、InvariantCulture数字文本和项目自有SplitMix64。

**运行随机**使用`RunSeed`派生具名流，同一次运行中逐次推进；不同用途互不消耗对方的随机数。同一用途内仍按实际结算顺序抽样。正常玩家读档生成新的64位运行种子，并清空旧流的游标，因此未来抽样可能改变。新局以本局种子作为首个运行种子，便于受控启动；运行中的规则不读取系统时钟或系统随机源。

固定的是骰子，不是最终成败。其他操作改变忠诚、能力、目标可用性或候选集合时，实时阈值与分支可以改变；硬条件不满足也不会因SL而强制成功。

## 保存、加载与回放入口

- 存档保存`InitialSeed`、`RunSeed`、已消费的命名流状态及完整世界和任务。已写入任务的`SuccessRoll`属于已确定状态，任何读档都不重抽；改的是未来抽样。
- `SaveService.Load`为玩家读档：完整验证原文件和状态后，生成不同于原运行种子的系统随机值，建立新会话并清空运行流。保留世界、任务、命令水位、年表及最近记录，不重跑新局或旬准备，不自动继续旧录像。失败加载不会修改原会话。
- `SaveService.Read/Decode`、`GameSession.Restore`为精确恢复：原样保留两个种子和流游标，用于检查点、诊断、事务副本和录像。不得在底层`WorldState.Restore`中自动换种子。
- `BeginRecording`捕获加载后的完整起点；种子及流状态随起点保存。重放从该起点精确恢复，重新执行操作并校验每步世界／事件及最终摘要，不调用玩家读档入口，也不逐骰保存新记录。
- 一次玩家读档形成新录像片段；旧片段不自动回退或追加。多片段管理和流式落盘维持后置。录制开关本身不改变骰子或种子。
- 新增运行种子属于状态契约和规则版本变化，旧规则存档／录像明确拒绝，不默默使用默认种子。

CLI：`run --load PATH`表示玩家读档后执行命令文件；`run --restore PATH`表示精确恢复后执行，二者互斥。`replay --recording PATH`始终精确回放。命令文件本身只描述操作；从不同运行状态执行同一文件可以得到不同结果，独立录像才带完整重放起点。

额外常驻状态是一个64位运行种子；每次玩家读档仅生成一次系统随机值，日常判定仍是少量整数计算。不增加每颗骰子的日志、密码学哈希或系统随机调用；未把这一分析当作性能实测结论。
