# 哈希与指纹用途

哈希用于比较内容或记录证据，不替代领域不变量、版本语义或身份字段。当前没有防作弊、对抗性存档验证或跨机器身份认证需求，不把SHA-256当作所有对象的默认身份。

| 用途 | 保留方式 | 实际消费者 |
| --- | --- | --- |
| 原版程序识别 | 对已登记EXE计算SHA-256 | Importer选择正确版本，防止以错误布局解码 |
| 导入来源与文本证据 | 记录源文件SHA-256，证据与源样本匹配 | 离线溯源、文本位置核对与研究复现；客户端不重新读取原文件 |
| 世界/会话诊断 | 显式调用`WorldDiagnostics.Compare`／`SessionDiagnostics.Compare`比较类型化状态，返回首个字段差异 | 测试、headless显式`verify`；正常运行与录像不生成状态哈希 |
| 命名随机 | 稳定非密码学混合后使用SplitMix64 | 隔离规则/AI分析随机用途；不承担完整性校验 |
| 研究目录、队列和字体产物摘要 | 保留离线来源/快照摘要 | 确認样本、记录处理输入、定位旧证据；不进入游戏运行时 |

内容指纹及其匹配门槛已移除。恢复使用当前内容定义和存档中的实际状态，允许修改初始兵力、年龄、地图成本、规则参数与初始开关；缺失对象引用、未知任务／阵形和不合法状态仍拒绝。存档内的运行开关属于世界状态，不因当前内容初值不同而覆盖或拒绝。槽位预览不核对内容身份，实际兼容性由载入时的状态／引用校验决定。

普通存档允许手工修改，摘要头和正文均不保存或检查完整性哈希；仍检查结构、格式版本、对象引用和状态合法性。存档、日志、槽位、录像与报告均不再包含`hashVersion`。录像格式22只保存起点和操作／事件，不保存最终哈希；旧格式明确拒绝。

世界与会话快照不提供`StateHash`属性。诊断API使用System.Text.Json源生成元数据，显式捕获权威状态与不持久化的待答／任务步骤，排除本地提交次数`Revision`，规范化无序集合，保留有序记录。按字段分块比较，相同不可变快照／集合以及相等的记录直接通过，只有不能直接证明相等的分块才规范化并序列化。会话复用世界比较，不重复序列化共享世界。`SessionDiagnostics.Compare(GameSession, GameSession)`可比较已发布的待答状态，不要求达到保存边界；存档捕获仍只接受稳定状态。`AreEqual`只判断相等；`Compare`失败时返回首个字段路径及期望／实际值；需要导出时才调用`ToDiagnosticJson`。只读查询与界面检查可直接比较`Revision`。这套诊断不参与身份生成、保存合法性或正常播放。

默认运行和录像录制／播放不计算状态SHA-256，不逐步核对旧事件。调试调用可用`verifyEvents: true`核对实际事件；headless的`verify`还显式比较连续、恢复和重放的完整会话状态。普通报告只记录运行结果，不序列化诊断快照。录像使用直接恢复入口；内容加载不生成玩法内容指纹。

本地命令绑定当前会话，序号决定处理顺序；会话请求ID直接编码身份类别和操作序号，自动命令与准备查询ID直接编码身份类别、势力和Core命令序号。三类内部ID使用不同类别，互不混用；单机会话内的对象身份不依赖种子或跨机器认证。派生任务ID由Core世界的`NextTaskIdentity`单调分配，随事务提交、回滚及存档恢复；命令入口拒绝占用派生任务身份类别，恢复拒绝现存派生任务超出分配水位。不哈希命令载荷、日期或原因对象。JSONL只在头部比较格式、种子和会话配置，规则版本不同仅警告，不给每条操作附加派生流指纹。AI分析由初始种子、势力、日期和用途派生，不依赖全世界哈希。

AI机会与战役冷却保存类型化的公开条件，按业务值比较，不保存条件哈希。无消费者的分配诊断意图哈希已删除。待答状态与步骤直接比较，一次接受的自动答复必须推进待答状态；不维护交互指纹集合。界面消息与播放线索直接使用既有的事件键，不将其哈希为GUID。

录像不保存或核对整文件完整性哈希。结构、版本、对象引用、操作序号和操作接受结果保证正常重放；逐步事件及终态内容比较只用于显式调试验证，不新增防篡改或安全认证。读取录像只解析一次JSON。

Importer组合流程复用已读源字节和来源摘要，地图编译不再自行重复读取、哈希同一份EXE/剧本。版本识别与研究导出仍可独立运行，保留各自必需的样本核验。纹理增量更新继续使用已有转换版本、文件大小和时间戳，没有新增全资源指纹链。

世界引用、数值范围、稳定边界、任务占用及未知格式版本仍按各自契约校验；这些是保证状态有效的规则，不因移除重复哈希而省略。具体存档和录像入口见[G02使用与验收](g02-verification.md)。

玩家录像的正式交付目标包括全程回放、跳转和接手新分支。以上事件／状态核对描述显式验证模式，正常播放不必强制逐事件比较；玩家模式的一致性检查与差异处理在交付前明确，见[后续要求](../specs/behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md#面向玩家交付前的后续要求)。
