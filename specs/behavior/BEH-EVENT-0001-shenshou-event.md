# BEH-EVENT-0001：神兽事件的战斗判定

- 状态：已确认
- 负责人：项目开发者

- 关联证据：[RE-SAN9PK-0027](../../research/findings/RE-SAN9PK-0027.md)、[RE-SANCALC-0001](../../research/findings/RE-SANCALC-0001.md)、[RE-SAN9PK-0130](../../research/findings/RE-SAN9PK-0130.md)
- 关联决策：[DEC-EVENT-0001](../decisions/DEC-EVENT-0001-shenshou-probability.md)、[DEC-SIM-0001](../decisions/DEC-SIM-0001-determinism-and-saves.md)
- 继承方式：参数调整

## 适用范围

适用于重制版探索后触发的神兽事件。地点、奖励、消息表现和人物属性字段沿用神兽事件的既有设计；本规格只明确战斗成功判定的前置条件和武力参数。

## 原作基线

原作在有“奋斗”或“鼓舞”时读取人物当前有效武力 `effective_wu`，并计算：

```text
effective_wu < 10 ? 10 : floor(effective_wu / 5)
```

再将该参数传入整数概率判定。两种兵法都没有时，阈值为 `0`，因此战斗成功不可达。原作概率服务生成 `0..99` 整数并严格比较 `roll < chance_argument`；不会再缩放、反转或夹制阈值。

## 重制行为

重制版保留无“奋斗”和“鼓舞”时阈值为 0、必败的规则；至少拥有其中一种兵法时，使用 `DEC-EVENT-0001` 指定的连续参数：

```text
chance_argument = max(10, floor(effective_wu / 5))
```

战斗选择统一从命名的事件概率稳定随机流取得一个 `0..99` 整数，严格按 `roll < chance_argument` 判定；缺少两种兵法时仍消费该骰但阈值为 0。不得使用原作的 `effective_wu < 10 ? 10 : floor(effective_wu / 5)` 分段函数；随机状态按 `DEC-SIM-0001` 进入存档和状态哈希。

## 状态与不变量

- 输入与前置条件：有效人物、当前有效武力 `effective_wu`、奋斗/鼓舞拥有状态和命名事件概率随机上下文。
- 状态变化：成功率参数由上述公式产生并消费一次命名事件概率随机；本规格不改变成功奖励、失败伤势或逃走分支。
- 始终成立的不变量：没有“奋斗”和“鼓舞”时，战斗不会成功；拥有更多有效武力时，成功率参数不会下降。
- 失败或无效输入行为：缺少两种兵法时消费一次战斗概率随机并以阈值 0 判定失败；有效武力按重制版人物属性不变量处理。
