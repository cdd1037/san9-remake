# BEH-IMPORT-0011：剧本国号记录解析

- 状态：已确认（边界、三份序号、名称资源、势力关联、君主/州域引用和州域反向链接）
- 负责人：项目开发者
- 最后更新：2026-08-31
- 关联证据：[RE-SAN9PK-0016](../../research/findings/RE-SAN9PK-0016.md)
- 关联决策：[DEC-DATA-0001](../decisions/DEC-DATA-0001-content-pipeline.md)

## 适用范围

本规格约束繁中 PK 1.0.1.0 正式布局剧本 `kkgu` chunk 的记录边界、运行时身份、君主/州域代码和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不把 20 条国号定义与 50 条 `forc` 势力/军团记录合并成一个领域表。根势力通过可空国号 ID 引用定义；子军团读取根势力的同一引用。

原作还为 `kkgu` 提供按 ID 的访问器，并在载入后把两个有效州域引用反向链接到对应 `area` 记录；这属于运行时关系，不改变导入器对原始代码的无损保留。

## 原作基线

`kkgu` chunk 位于正式剧本数据的 `0xF86`，包含 20 项，每项 12 字节，共 240 字节。运行时国号 ID 使用记录序号 `0..19`。

| 偏移 | 类型 | 规格字段 | 已确认语义 |
|---:|---|---|---|
| `0x00` | `u16` | `serialized_id` | 原始序号槽位；原程序读出后丢弃 |
| `0x02` | `u16` | `serialized_id_copy_02` | 第二份序号；原程序写入对象但没有业务读取 |
| `0x04` | `u16` | `serialized_id_copy_04` | 第三份序号；原程序写入对象但没有业务读取 |
| `0x06` | `u16` | `ruler_person_code` | 君主人物代码；原程序运行时只接受 `<1050` |
| `0x08` | `u16` | `area_1_code` | 州1代码；原程序运行时只接受 `<15` |
| `0x0A` | `u16` | `area_2_code` | 州2代码；原程序运行时只接受 `<15` |

## 重制行为

导入器必须生成 20 个按文件顺序排列的国号定义，并暴露：

- `Id`：记录序号 `0..19`；
- `SerializedId`、`SerializedIdCopy02`、`SerializedIdCopy04` 的原始值；
- `RulerPersonCode`、`Area1Code`、`Area2Code` 的原始代码；
- `RulerPersonId`：仅在代码 `<1050` 时提供派生值，否则为空；
- `Area1Id`、`Area2Id`：仅在代码 `<15` 时提供派生值，否则为空。

繁中 PK 名称资源以记录序号绑定，而不读取三份序号槽位的值：名称消息号为 `5315 + 2×Id`，读音消息号为 `5316 + 2×Id`。导入器必须提供这两个派生消息号，并拒绝 `0..19` 之外的国号 ID。库存 `M_MsgPK.s9` 的 20 个原文名称依次为魏、蜀、吳、成、倭、烏丸、羌、山越、南蠻、黃巾、燕、趙、齊、宋、楚、涼、越、秦、韓、晉；对应读音项均为空。显示文本属于外部消息目录，不复制进剧本记录。

原作把 `forc +0x10` 的有效代码载入根势力运行时 `+0x10`，子军团通过根势力指针共享该值。授予流程只从可用定义中选取并防止普通国号被有效势力重复持有；手动目录允许 `0..3` 与 `10..18`，异民族 `4..8` 永久保留，黄巾 `9` 与晋 `19` 不进入手动目录。势力记录重置会把关联清为 `-1`；称帝/相关事件提交会写入先前选择的国号。重制版若实现动态授予，必须原子提交国号选择与势力状态，不得让子军团另持一份可分叉状态。

当 `Area1Code` 或 `Area2Code` 小于 15 且对应 `area` 记录有效时，原作会建立 `area` 记录到当前 `kkgu` 记录的运行时反向链接；导入器可将其表达为派生关系，但不得覆盖原始代码。

导入器不得因代码越界而改写原始代码或拒绝整条记录；不得把 20 条国号当成 50 条势力，也不得把两个冗余序号副本解释为颜色、势力或官爵。即使非库存输入破坏三份序号相等关系，也须保留原值而不是静默改写。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整剧本流。
- 状态变化：无；只生成 20 个只读记录。
- 始终成立的不变量：返回顺序等于文件顺序；每项完整消费 12 字节；整个 `kkgu` chunk 恰好消费 240 字节；六个原始 `u16` 无损保留。
- 失败行为：容器或 `kkgu` chunk 尺寸不正确时抛出格式错误。
