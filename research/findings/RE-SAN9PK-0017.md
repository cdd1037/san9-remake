## 结论

`jnki` 位于剧本数据偏移 `0x107E`，大小 `896` 字节。它由 28 条、每条 32 字节的阵型记录组成。目标程序的 `deserialize_jnki_record`（IDA `0x448AF0`）实际读取布局如下：

| 偏移 | 大小 | 当前结论 | 目标程序行为 |
| ---: | ---: | --- | --- |
| `+0x00` | `u16` | 序列化编号；`SerializedId` | 读取后丢弃，运行时编号改用记录顺序 |
| `+0x02` | `u16` | 未确认字段 | 写入运行时 `+0x50`，编辑器数据访问器可读 |
| `+0x04` | `u16` | 未确认字段 | 写入运行时 `+0x54`，编辑器数据访问器可读 |
| `+0x06` | `u16` | 未确认字段 | 写入运行时 `+0x58`，编辑器数据访问器可读 |
| `+0x08` | `u16` | 对部队效果 | 与 `阵型.png` 的“对部队”一致 |
| `+0x0A` | `u16` | 对守兵效果 | 与“对守兵”一致 |
| `+0x0C` | `u16` | 对城壁效果 | 与“对城壁”一致 |
| `+0x0E` | `u16` | 守备力 | 与“守备力”一致 |
| `+0x10` | `u16` | 机动力 | 与“机动力”一致 |
| `+0x12` | `u16` | 视野半径 | 与“视野半径”一致 |
| `+0x14` | `u16` | 视角范围代码 | 截图显示为 `4`，标签附带 `x45°`；暂不把代码直接换算成角度 |
| `+0x16` | `u16` | 出征费用 | 与“出征费用”一致 |
| `+0x18` | `u16` | 未确认的资源枚举字段 | 非零时进入 0–14 的资源表；格式化访问器另返回 `15 - value` |
| `+0x1A` | 5 bytes | 五个出征阵位代码 | 复制到运行时 `+0x80`；访问器按 0–4 返回每个字节 |
| `+0x1F` | 1 byte | 程序跳过的字节 | `0x448AF0` 只递增指针，不写入运行时对象 |

样本 `D_Sce001..020.S9` 与 `D_Ttrl00..05.S9` 的这 896 字节区域哈希一致。`D_Sce001.S9` 的第 0 条为：

```text
u16: 0, 0, 0, 0, 15, 10, 10, 10, 12, 3, 4, 0, 1
slots: 01 03 04 05 07
ignored: 39
```

这与截图中鱼鳞阵的“对部队 15、对守兵 10、对城壁 10、守备力 10、机动力 12、视野半径 3、视角范围 4、出征费用 0”相符。五个阵位代码 `1,3,4,5,7` 对应截图中的“前中、中左、中中、中右、后中”；其余代码暂保留为原始字节，避免把未逐项观察的几何映射写成规格。

## `+0x18` 的使用情况

该字段不能标记为“完全未使用”。`sub_448980` 将其作为 `0..14` 的资源表索引交给 `sub_5681E0`；`sub_448CB0` 的相关分支在非零时返回 `15 - value`。因此当前实现暴露 `OpaqueField18`，并提供仅表达范围的 `ResourceCode` 派生值，不擅自命名其业务含义。样本中的 28 条记录覆盖 `0..14`，说明它不是固定填充。

相反，`+0x1F` 在当前记录加载函数中确实没有运行时消费者；但它是记录布局的一部分，样本均为 `0x39`，所以实现仍保留为 `IgnoredByte`，不把它从输入中吞掉。
