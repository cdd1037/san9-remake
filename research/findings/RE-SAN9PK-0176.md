# RE-SAN9PK-0176：地图书签与上下文键盘事件

- 日期：2026-09-27；分析者：Codex。
- 类型：静态事实；主要映射置信度高，运行体验待验证。本轮未启动原游戏。
- 样本与工具：沿用[RE-0175](RE-SAN9PK-0175.md)及[SRC-SAN9PK-TC-101](../sources/SRC-SAN9PK-TC-101.md)登记的繁中PK 1.0.1.0、x86、基址`0x400000`、IDA/Hex-Rays 9.3；本轮健康检查确认项目主库`research/analysis/San9PK-TC-101.i64`，输入SHA-256回读与登记一致。
- 范围：从F8入口向地图上层、通用对话框、目录及数值输入消息表追踪；没有改重制键位或行为规格。

## 地图松键事件

消息表`0x611258`将WM_KEYUP映射至`0x520A20`。上层`0x5266C0`先调用通用对话框松键处理，再向地图子窗口转发WM_KEYUP。因此不是每个快捷键都在按下时执行，也不是所有窗口共享同一动作。

| 按键 | 静态行为 | 证据与边界 |
| --- | --- | --- |
| Ctrl＋主键盘0–9 | 保存当前地图视图中心到对应位置书签 | `0x520AD4..0x520AF4`；矩形中心函数`0x414F60`计算四边中点；十个点从视图`+0x1A84`开始 |
| 主键盘0–9 | 跳回对应有效书签，并刷新光标位置相关状态 | `0x520A68..0x520AAB`；`0x401B40`要求两坐标非负，移动调用`0x519B60` |
| F8 | 切换边缘卷动模式 | `0x520B1D..0x520B24`，完整模式证据见RE-0175 |
| PageUp / PageDown | 无Ctrl且重复计数不超过1时直接返回，没有地图动作 | 虚拟键`0x21/0x22`，不可将反编译字符`!`、双引号当作字符快捷键 |

数字保存／召回分支要求消息重复计数不超过1；Ctrl状态在松开数字键的处理时读取，实际操作应保持Ctrl直到数字键松开。这里没有小键盘数字`0x60..0x69`映射。书签默认值、跨地图重建或存档持久化未查证，不能宣称能跨局保存。F8之外未在该函数发现其他F键分支；不据此断言全程序不存在其他功能键。

## 对话框与截图

| 按键 | 行为 | 证据 |
| --- | --- | --- |
| Tab / Shift＋Tab | 向后／向前移动控件焦点 | WM_KEYDOWN表`0x6250E0 → 0x5B7BD0`，调用`0x5B77F0/0x5B77B0`；受当前交互状态约束 |
| Enter | 按下建立控件激活状态，松开提交；文本输入控件另走自身完成／焦点路径 | `0x5B7BD0/0x5B7CF0`，不能概括为无条件结束当前回合 |
| Esc | 通用松键处理在允许状态调用窗口取消虚函数 | `0x6250F8 → 0x5B7CF0`；`0x4FB0F0`明确吞掉Esc，目录还有自己的门槛 |
| Pause | 松键进入通用尾处理时导出当前画布为BMP | `0x5B9230`比较19（VK_PAUSE），调用`0x5C8140`；不是暂停模拟 |

截图函数建立模块目录下的`Scene`目录，将全局画布复制到24位表面，以`Scene%03d.bmp`查找可用编号并调用保存路径。`0x5BEA00`虽有旧名`load_bitmap_stream`，实际此链使用文件写入模式和表面保存虚函数，不能被名字误导。未实测目录写权限、键盘Pause消息到达情况及编号耗尽；也不承诺拦截通用尾处理的窗口能截图。

## 目录与数值输入

目录消息表`0x6202E8/0x620300`分别接`0x577880/0x576220`，与[RE-0151](RE-SAN9PK-0151.md)一致：

- 上／下：在目录中移动当前行，到可见区域边缘时滚动；不是地图方向移动。
- Ctrl＋Tab／Ctrl＋Shift＋Tab：正向／反向循环字段页。
- Ctrl＋A：全选命令7505；Ctrl＋Shift＋A：清空命令7506。两者受对应按钮存在／可用状态控制，且清空分支只在全选按钮资格检查未通过时尝试，不能概括为两个始终可用的独立快捷键。
- Esc：目录标志可禁止，某些状态先提示消息7509；按下与松开都有相关处理，不泛化成全局无条件关闭。

数值输入WM_KEYDOWN表`0x5FFCB0 → 0x404350`接受主键盘与小键盘数字；左箭头／小键盘减号减值，右箭头／小键盘加号增值，受上下限约束。长按重复计数与当前数值的十进制整除条件共同放大步长，不能只按固定时间描述加速。其他按键的命令语义已在下方后续调查闭合，包括F1打开帮助。

另在详情／编辑器列表处理器`0x58E3A0/0x595EB0`确认上／下在行控件范围内换焦点或滚动；后者原有符号包含resource，但运行类证明其属于CEditBaseDlg。通用方向键入口`0x420090`存在既有解码／函数边界异常，未修改或以失败反编译补足结论；这是本轮覆盖限制，不影响上述独立入口的直接证据。

2. 反编译`0x520A20`，交叉检查矩形中点、点有效性和地图移动消费者。

### 数值窗口：补齐直接操作

键盘入口`0x404350`、命令处理`0x404100`与数值虚表`0x5FFCF8`形成完整对应：

| 按键 | 行为 | 命令／消费者 |
| --- | --- | --- |
| Home、↓ | 设为允许最小值 | 1013，读取对象DWORD索引1302 |
| End、↑ | 设为允许最大值 | 1014，读取索引1303 |
| Space | 当前不是最大值则取最大，否则取最小 | 1014／1013 |
| Backspace | 删除末位十进制数字 | 1015，整数除10 |
| Delete | 将输入置0 | 1016；不是无条件设成允许最小值 |
| Enter | 确认，要求确认控件可用 | 1017及虚表`+0x84` |
| F1 | 打开该窗口配置对应的帮助主题 | 1019 → 虚表`+0xCC = 0x420340`；帮助键映射有效才打开 |
| Tab | 此数值键盘入口直接返回 | 不沿用通用Tab焦点切换 |

直接数字输入、退格和清零允许出现暂时越界值；`0x403430`按最小／最大范围启停确认按钮。因此“所有编辑操作自动夹取”不成立，只有前述增减键的数值更新做边界限制。F1不是由通用对话框按键入口全局提供，不外推为每个界面均可用。

### 功能／右键／命令菜单

`0x601E80 → 0x4192E0`属于`CMenuDlg`；运行类`0x601E20`及其派生类CFunctionMenuDlg、CRButtonMenuDlg、CCommandMenuDlg证明菜单身份。旧名`navigate_audio_panel_command`和`position_audio_panel`中的audio不能当业务依据。

- ↑／↓：在当前主菜单或子菜单行之间移动焦点；无匹配行焦点时有选择主菜单首／末项的分支。
- →：主菜单当前项有子项时，`0x4190D0`布置子菜单，再聚焦子菜单首项2025。
- ←：从子菜单回到对应主菜单项。
- 以上方向操作受对象当前交互状态约束；未专门处理的键进入既有对话框链。没有发现此菜单处理器以字母或F键直接激活菜单项的分支。

### 情报详情与编辑器

情报`CInfoDlg`运行类`0x6225B8`、消息表`0x6225E8`绑定`0x58E3A0`，共用该基类的城市、建筑、军团、势力、宝物、人物、部队详情可继承此行为。编辑器`CEditBaseDlg`运行类`0x623260`、消息表`0x623290`绑定`0x595EB0`，对应派生建筑、城市、军团、人物编辑窗口。

两处均要求焦点控件ID在2000..2024，↑／↓换列表行；越过当前可见行时尝试调整内嵌滚动条并刷新列表。它控制对象名单，不能说成修改能力数值、详情字段翻页或无条件切换所看对象；详情打开动作还取决于控件激活。其他键转交基类，未发现这两个入口有PageUp/PageDown专用动作。

### 文本编辑控件

`CDialog_on_key_down → 0x5C4EA0 → 0x5C4AE0`先把键盘命令交给当前文本控件；字符输入另走`WM_CHAR → 0x5B7180 → 0x5C4EE0`。

- ←／→：移动插入光标；Backspace／Delete删除前／后字符，相关分支检查双字节字符边界。
- Home：光标回到整个缓冲区起点；End：向文本结尾移动，不应套用现代编辑器“当前行首／尾”的解释。
- ↑／↓：按排版行位置寻找上下行的对应光标位置。
- Enter：只有多行配置允许插入换行；单行输入的完成／换焦点仍由外层对话框控制。
- 此命令处理器没有Ctrl＋C／V／A分支；未据此断言系统输入法或其他路径绝不支持相关操作。

### 幻灯展示与换季动画

`CSlideShowDlg`消息表`0x618860/0x618878`分别将WM_KEYDOWN和左键按下映射至`0x54E2D0`，不区分键值，调用取消虚函数。实际虚表`0x618958 + 0x88 → 0x54E440`要求对象`+0x15C`允许，随后设置结束标记并进入关闭链。普通构造`0x54E260`初始允许；因此这里是“允许跳过的幻灯展示可用任意键或左键结束”，不是所有动画均可跳过。

派生`CSeasonChangeAnimeDlg`消息表`0x618C70/0x618C88`将同样两种消息覆盖为`nullsub_67`，明确阻断上述按键／左键跳过路径。没有把其他消息、定时完成或所有动画类型一并排除。

### Ctrl＋Shift＋变更：批量平移登录武将出生年

后续追踪已闭合此前的不明返回码。`CMakeNewMainDlg`命令处理`0x5567D0`在激活命令1001时同时读取Ctrl和Shift，将返回选择码从1改成8；`0x556DD0 → 0x560AC0`的case 8调用`0x55FBB0`。正常case 1进入`0x55EB50`的单人变更选择器，不是其旧注释所称的选择指导武将。

**入口事实：**新武将登录菜单初始化`0x5569F0`为第二项绑定资源3628及提示8122；现有转换文本的消息8643为“登錄新武將”，8122为“變更登錄武將的內容。”。命令1001就是该变更项，须在激活时保持Ctrl与Shift按下；单独按组合键不会启动此功能。正常菜单还会在没有可变更登录武将时禁用该项。

**用途的独立文本证据：**`0x55FBB0`显示消息8423“將所有登錄武將的出生年／總括變更”，再用8424“選擇作為出生年之標準的武將”打开单人选择器。这与实际批量写回链一致，排除只改所选者或仅调整亲属的解释。文本回读自`local/generated/research/unified-text/messages.json`的`messages.8423/8424`；该文件为现有忽略生成物。

**操作与计算：**先从符合条件的登录武将中选一名基准人物，再在“生年”数值框输入其新出生年；确认后计算`差值 = 新生年 − 基准人物原生年`，对列表中每个有效对象增加同一差值。例如基准人物从180年改到190年，其他人的生年也整体加10，彼此年龄差保持不变。选择器或数值框取消均不进入本函数的写回循环。

**对象与边界：**列表谓词`0x471140`要求已占用人物、运行时槽700..799，且排除列传资源码664和665；这不是历史武将全体，也不是仅亲属集合。`0x44D5B0`确认空槽判定为身份字段等于-1。原作以135／265作为整体生年范围边界，按最早、最晚出生年计算可向前／后平移空间；基准人物数值框最小值为其原生年减前移空间，最大值为其原生年加后移空间。列表为空或两方向空间都为0时不打开调整流程。此处范围算法针对正常合法数据，未验证外部异常生年输入。

**写回事实：**`0x55FDD2..0x55FE55`逐项验证人物及其登录记录，以`0x44C250 → 0x4534D0`取得对应的独立登录记录，同时对当前人物和登录记录调用`set_person_birth_year(0x44BD70)`，设置编辑器已修改标志。未发现此循环直接改登场年、寿命或亲子关系；文件落盘时点未追踪，不把内存同步等同于立即保存到磁盘。函数最后回到菜单状态1010。

这已是静态高置信结论，尚未用原游戏实测按钮文案、操作反馈及保存重启。隐藏入口不自动成为重制功能要求。

本次另向`0x5567D0/0x560AC0/0x55FBB0`追加三条入口、分发及批量生年语义注释，特别纠正旧“关联人物”表述过窄的问题；全文回读一致，三函数强制重新反编译成功，主库保存成功。未改函数名、类型、边界或样本字节。
