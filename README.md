# 三国志 9 重制

本项目旨在从第一性原理重建《三国志 IX》的策略体验。原作行为提供可研究、可比较的设计基线，但不要求逐项照搬；重制版可以采用现代工程技术，也可以有意识地调整或重新设计玩法。玩家可见的重要差异应被清楚记录，不能伪装成原作行为。

## 当前阶段

项目目前处于 M0 工程基线阶段。技术路线已确定为 Godot 4.7.1 Mono、.NET 10、纯 C# 确定性模拟核心、JSON 内容源包和本地编译缓存。

项目采用以下单向信息流：

```text
原始资料/黑盒样本 -> research 研究证据 -> specs 书面规格 -> 独立实现与测试
```

- `research/` 保存来源、实验记录和逆向证据，不是产品需求的权威来源。
- `specs/` 是未来实现的唯一行为依据。
- `private/` 保存项目当前使用的本地私有样本；正式 `.s9` 数据位于 `private/s9数据文件/`，编辑器截图位于 `private/剧本编辑器截图/`，均不提交。
- 未来实现不得运行时依赖原版程序、原版资源、IDA 数据库或研究工具。

这种分层是个人项目中的逻辑洁净室流程，不代表由独立人员完成、也不构成法律意义上的洁净室认证。

## 工程入口

- `San9Remake.slnx`：.NET 解决方案。
- `src/San9.Core/`：不依赖 Godot 的确定性领域核心。
- `src/San9.Content/`：内容清单、剧本定义与校验。
- `src/San9.Application/`：游戏会话与用例入口。
- `src/San9.Importer.San9PkTc101/`：繁中 PK 1.0.1.0 样本识别与后续转换器。
- `src/San9.Client.Godot/`：Godot 客户端。
- `tests/`：无头自动测试。
- `local/generated/`：本地转换数据和缓存，禁止提交。

## 基本原则

1. 研究原作时先记录证据，再形成规格；原创或现代化设计可以直接形成重制规格。
2. 明确区分事实、推断与待验证事项。
3. 不复制反编译代码，不提交原版或未知授权资源。
4. 不用补丁式兼容逻辑掩盖错误模型；发现模型错误时修正模型和规格。
5. 可以使用 IDA Pro（包括本地 MCP）辅助研究，也可以自由采用现代语言、架构、算法与交互模式实现重制版。
6. 提交采用带 scope 的 Conventional Commits；仓库初始化阶段暂不创建提交。
