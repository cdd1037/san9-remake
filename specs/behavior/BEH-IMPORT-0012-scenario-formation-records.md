## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `jnki` chunk 的记录边界、记录身份、已确认字段和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格确认阵位的 3×3 几何、视角扇区的显示含义和说明资源代码，但不据此推造原作没有机器消费者的战斗、索敌或 AI 规则。

## 原作基线

`jnki` chunk 位于正式剧本数据偏移 `0x107E`，包含 28 项，每项 32 字节，共 896 字节。运行时阵型 ID 使用记录序号 `0..27`，不使用文件中的序列化编号。文件按小端顺序包含 13 个 `u16`、5 个阵位字节和 1 个尾部字节：

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| ---: | --- | --- | --- |
| `0x00` | `u16` | `serialized_id` | 原始序号槽位；原程序读取后丢弃，运行时 ID 使用记录序号 |
| `0x02` | `u16` | `catalog_code` | 目录代码；写入运行时对象但当前 EXE 无载入后读取 |
| `0x04` | `u16` | `reserved_field_04` | 保留字段；写入运行时对象但当前 EXE 无载入后读取 |
| `0x06` | `u16` | `reserved_field_06` | 保留字段；写入运行时对象但当前 EXE 无载入后读取 |
| `0x08` | `u16` | `against_units` | 对部队效果；编辑器字段已对照 |
| `0x0A` | `u16` | `against_soldiers` | 对守兵效果；编辑器字段已对照 |
| `0x0C` | `u16` | `against_walls` | 对城壁效果；编辑器字段已对照 |
| `0x0E` | `u16` | `defense_power` | 守备力；编辑器字段已对照 |
| `0x10` | `u16` | `mobility` | 机动力；编辑器字段已对照 |
| `0x12` | `u16` | `vision_radius` | 视野半径；编辑器字段已对照 |
| `0x14` | `u16` | `vision_angle_code` | 视角范围的 45° 扇区数；与朝向共同选择视野扇形视觉 |
| `0x16` | `u16` | `deployment_cost` | 出征费用；编辑器字段已对照 |
| `0x18` | `u16` | `description_resource_code` | 阵形说明资源代码；`0` 为空，`1..14` 选择固定说明文本 |
| `0x1A..0x1E` | 5 字节 | `deployment_slot_codes` | 五个出征阵位代码；`0..8` 为 3×3 行优先位置，`9` 为无阵位 |
| `0x1F` | `byte` | `ignored_byte` | 当前记录加载器跳过但仍属于文件布局的字节；必须保留 |

完整阵位对照为 `0/1/2=前左/前中/前右`、`3/4/5=中左/中中/中右`、`6/7/8=后左/后中/后右`，`9=无阵位`。原作部署界面按 `column=code%3`、`row=code/3` 放置人物，确认这是行优先 3×3 网格。

## 重制行为

导入器必须生成 28 个按文件顺序排列的阵型定义，并暴露所有原始字段。`Id` 使用记录序号；`SerializedId`、三个前置元数据字段、13 个数值字段、5 个阵位字节和 `IgnoredByte` 均不得因当前样本值而丢弃。

`DescriptionId` 仅在原始 `DescriptionResourceCode <= 14` 时存在。`VisionAngleDegrees = VisionAngleCode × 45` 只表示视野扇形显示角度。阵位位置按 `(column=code%3,row=code/3)` 派生；代码大于 8 时位置为空，原始代码仍保留。上述派生均不得在导入阶段改写输入或提前执行战斗规则。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整 `S9SC` 剧本流。
- 状态变化：读取 `jnki` chunk 后产生 28 条阵型记录；导入过程不修改原始字节含义。
- 始终成立的不变量：chunk 大小为 `896` 字节；每项完整消费 32 字节；记录 `Id` 为 `0..27`；`deployment_slot_codes` 始终为 5 字节。
- 失败或无效输入行为：chunk 大小异常、记录截断或游标不能恰好填满 chunk 时抛出 `InvalidDataException`。

## 示例与边界

正式样本第 0 条的 13 个 `u16` 为 `0, 0, 0, 0, 15, 10, 10, 10, 12, 3, 4, 0, 1`，阵位字节为 `01 03 04 05 07`，尾部字节为 `39`。它的视角为 `4×45°=180°`，人员位置为前中、中左、中中、中右、后中，说明代码 1 选择步兵系兵法发动说明。

## 验收标准

- [x] 28×32 字节边界、记录顺序和全部原始字段由自动测试证明。
- [x] 5 个阵位字节与被目标加载器跳过的尾部字节均可逐项回读。
- [x] `DescriptionResourceCode` 的原始值与 `DescriptionId` 派生视图不会互相覆盖。
- [x] 45° 扇区角度、3×3 阵位与无阵位哨兵由测试覆盖。
- [x] 异常 chunk 大小会被拒绝。
- [x] 测试夹具不依赖原版文件、编辑器或 IDA 数据库。

## 非阻塞补证

- 编辑器对非库存阵位/说明代码的保存行为，以及其他版本是否读取 `+0x02/+0x04/+0x06`，统一归入 [`EDITOR-01`](../../research/scenario-field-research-checklist.md#范围外与后续扩展)；当前版本的负面审计保持成立。
