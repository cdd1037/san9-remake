# 三国志 9 重制整体路线图

状态：已确认

## 产品基线

- 完整的 Windows、macOS、Linux 单机重制版，键鼠操作，简体中文首发并预留 i18n。
- 保留旬制同步推进、大地图一体化和部署后自主战斗；优先现代化 AI、规则透明度、信息反馈和工程可维护性。
- 采用选择性继承与现代重组：保留经确认且被规格选用的核心公式关系与变化曲线，参数、边界、领域模型和系统组织可以围绕目标体验重新设计，详见 [DEC-PROJECT-0002](decisions/DEC-PROJECT-0002-selective-inheritance.md)。
- 原版研究是设计输入而非实现清单；逆向按当前设计需要闭合，不以代码量、函数覆盖率或逆向完成率衡量里程碑进度。
- 首个完整内容为 190 年反董卓全地图剧本。
- 最小可玩版本只要求正式剧本范围；`D_Ttrl00.S9`–`D_Ttrl05.S9` 教学剧本和 `D_Trst01.S9`–`D_Trst28.S9` 挑战剧本不属于实现与验收范围，详见 [DEC-SCOPE-0001](decisions/DEC-SCOPE-0001-scenario-scope.md)。
- 原版研究基线为繁中 PK 1.0.1.0、x86 PE、大小 2,636,800 字节、SHA-256 `D20794AEFF67301EC2BF8C3BECB1E9944C68C6C0588FBFD4BF04E8597F0E5028`。
- 原版转换数据与资源仅供本地开发，不入库；v1 不含多人、原版存档导入、公开模组 API、作者 GUI 编辑器或公众导入流程。

## 里程碑

| 里程碑 | 交付结果 | 退出条件 |
| --- | --- | --- |
| M0 工程基线 | Godot/.NET 分层、确定性旬推进样例、测试、版本锁定和架构决策 | Core 可独立测试；Godot 只经 Application 调用；构建和测试通过 |
| M1 数据转换 | 指定构建识别、190 年所需数据和资源转换、JSON 内容包与校验 | 未知哈希被拒绝；重复转换一致；引用、范围和地图拓扑有效 |
| M2 垂直切片 | 自制小地图上的内政、旬推进、编队、出征、自主战斗、占领与存档闭环 | 全流程可连续完成；同种子和命令得到相同结果 |
| M3 全地图 Alpha | 190 年完整地图、多势力、内政、人才、外交、计略、战争、事件、AI 和正式 headless runner | 十年无人值守模拟无崩溃或世界状态违规，并输出状态哈希、终局、性能和决策分布报告 |
| M4 内容体验 Beta | 本地原版内容接入、现代 UI、规则说明、i18n、设置与武将编辑 | 主要流程完整；经研究确认的玩家编辑范围可用；回归通过 |
| M5 本地完整版本 | 三桌面平台、难度、结局、性能和完整回归 | 三平台构建验证通过；190 年剧本达到发布候选质量；不以教学/挑战剧本作为硬门槛 |
| M6 后续扩展 | 教学/挑战剧本、其他剧本、作者编辑器及单独评估的公开分发/模组/旧存档项目 | 每项扩展独立决策，不污染 v1 核心接口 |

## 系统推进顺序

1. 内容身份、地图拓扑、游戏时钟、命令队列和存档骨架。
2. 城市与武将分配、基础内政、征兵训练和旬结算。
3. 编队、路线、行军、普通战斗、伤亡、撤退和占领。
4. 阵型、兵法、设施、攻城、后勤、俘虏与伤兵。
5. 人才、忠诚、外交、计略、事件、胜负与结局。
6. 分层 AI：以势力视角观察、确定性预算和公共命令验证为边界，逐步实现战略规划、资源预算、人才、外交和军事执行。
7. 规则解释、批量操作、信息图层、战报、教程和体验优化。

## 阶段门槛

后续显示规范待议：评估姓名异体字归一化（如“璝→瑰”），用户于2026-09-06要求先记录、暂不实施。详见[DEC-UI-0005待议项](decisions/DEC-UI-0005-officer-name-normalization.md#待后续考虑异体字归一化)。

- 每个阶段必须同时具备功能闭环、相关规格、自动测试和已知限制记录。
- 玩法里程碑按重制规格、体验不变量和代表性模拟场景验收，不要求对原版程序进行逐函数或全输入复刻。
- AI 与玩家通过同一命令验证入口；难度加成必须透明且可关闭。
- M0–M2 保证 Core/Application 可由测试和模拟夹具无 GUI 驱动；正式 CLI 不属于 M2 退出条件，但必须在 M3 长期无人值守验收前提供。
- M3 headless runner 只依赖 Application、Content 和 Core；以内容包、场景、种子、控制器和最大旬数为输入，以机器可读终局、状态哈希、事件摘要和分类失败码为输出。
- 存档格式升级只允许显式迁移；不做静默兼容。
- Godot 负责表现和输入，Core 负责规则；原版地址和内部结构不得进入产品接口。
- M2 完成前不给后续里程碑承诺日历工期，之后依据实测速度更新规划。
