## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `unit` chunk 的记录边界、字段读取、运行时引用视图、兵力上限视图和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格定义已确认的 `unit_status` 状态域、四项运行时策略位、主目标对象编码和运行时目标类型映射；不定义完整命令枚举、当前目标状态的序列化来源、目标代码的条件域或两个不透明字段的业务语义，也不把剧本文件记录直接当作 850 项运行时部队对象布局。

## 原作基线

`unit` chunk 位于正式剧本数据偏移 `0x8DB9A`，包含 800 项，每项 40 字节，共 32,000 字节。运行时部队表容量为 850、对象步长为 `0x104`，但剧本加载器只从本区块加载前 800 项。字段布局如下：

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| ---: | --- | --- | --- |
| `0x00` | `u32` | `soldier_count` | 原始士兵数；运行时加载视图上限为 60,000，原始值必须保留 |
| `0x04` | `u32` | `wounded_soldier_count` | 原始伤兵数；运行时加载视图上限为 50,000，原始值必须保留 |
| `0x08` | `u32` | `encoded_target_object` | 原样写入 `CUnitData +0x50` 的主目标对象编码；高 16 位为类型、低 16 位为序号；有效教学记录满足 `0x00050000 \| (area_code + 1)`，低位 `+1` 规则待确认 |
| `0x0C` | `u32` | `runtime_flags_0C` | 原始旗标字；详见下文 |
| `0x10` | `u16` | `serialized_id` | 记录内序列化编号；正式样本通常与记录下标相等，但不替代导入记录 `Id` |
| `0x12` | `u16` | `unit_status` | 写入运行时 `CUnitData +0x24`；状态文本资源表接受 `0..8`，对应 `unit_status` 用词表 |
| `0x14` | `u16` | `opaque_field_14` | 写入运行时 `CUnitData +0x28`；upstream 标为异常持续天数，编辑器源字段显示为未知 `0014`，业务名待验证 |
| `0x16` | `u16` | `morale` | 写入运行时士气字段；样本和编辑器对照值为 `100` |
| `0x18` | `u16` | `command_code` | 命令代码；`0..70` 由加载器规范化到运行时命令域，`0xFFFF` 为 `-1` 哨兵；不是目标代码 |
| `0x1A` | `u16` | `opaque_field_1A` | 20,800 条现有正式布局样本均为 `0`；`0x460FF0` 读取后丢弃，业务语义未确认 |
| `0x1C` | `u16` | `opaque_field_1C` | 20,800 条现有正式布局样本均为 `0`；`0x460FF0` 读取后丢弃，业务语义未确认 |
| `0x1E` | `u16` | `area_code` | 地域代码；`0..249` 提供有效地域视图，其中 `0..49` 为城市、`50..249` 为州域候选 |
| `0x20` | `u16` | `force_code` | 所属势力代码；`0..49` 为有效引用，其他值为空引用 |
| `0x22` | `u16` | `array_code` | 原作运行时 `Array` 编号；由 `jnki` 按记录顺序载入，正常布局下与 `jnki` 记录序号同值；`0..27` 为有效引用，界面显示为阵形 |
| `0x24` | `u16` | `coordinate_x` | X 坐标，0..199有效；`0xFFFF` 派生为空坐标，原始值不变 |
| `0x26` | `u16` | `coordinate_y` | Y 坐标；0..199有效；`0xFFFF` 派生为空坐标，原始值不变 |

`unit_status` 的显示域为 `0..8`：`0=无效`、`1=正常(一般)`、`2=正常(交战)`、`3=陷阱`、`4=伪装`、`5=无阵`、`6=混乱`、`7=溃败`、`8=高昂`。这是运行时 `+0x24` 的状态码域；状态 2 不等同于 `runtime_flags_0C` 的某一个 bit。

### 运行时标志详解

文件 `unit +0x0C` 会原样复制到运行时 `CUnitData +0x20`。导入器必须保留完整的 `u32`，不得因为当前只确认了部分位而截断或重编码。

先区分两个容易混淆的概念：

- `unit_status`：文件 `+0x12` → 运行时 `+0x24` 的独立状态码，`0..8` 为有效文本域；`2=正常(交战)` 不是 `+0x20` 的某一个 bit。
- `runtime_flags_0C`：文件 `+0x0C` → 运行时 `+0x20` 的位集合；四项方针和若干内部状态共用这个字。

已确认、可在规格中使用的位：

| 位 | 掩码 | 原作语义 | 导入器处理 |
| ---: | ---: | --- | --- |
| bit 2 | `0x00000004` | 主动交战位 | 保留原始位；可提供交战诊断视图 |
| bit 3 | `0x00000008` | 已出征位 | 保留原始位；可提供状态诊断视图 |
| bit 12 | `0x00001000` | 敌接近时攻击 | 保留原始位；提供方针查询 |
| bit 13 | `0x00002000` | 自主撤退许可 | 保留原始位；提供方针查询 |
| bit 14 | `0x00004000` | 追击许可 | 保留原始位；提供方针查询 |
| bit 15 | `0x00008000` | 事后攻击 | 保留原始位；提供方针查询 |
| bit 22 | `0x00400000` | 被动交战位 | 保留原始位；可提供交战诊断视图 |

bit 2 与 bit 22 组成交战组合 `0x00400004`。它们可以作为主动/被动交战的运行时诊断视图，但不能把该组合替换成 `unit_status=2`。

以下是当前研究中观察到、但尚不自动转化为重制版产品枚举的位。这里保留 upstream 的行为语义，避免把“研究已知”误读成“导入器可以重算或改写”：

| 位/组合 | 当前线索 | 规格处理 |
| --- | --- | --- |
| bit 0 | 都市内嵌/内部部队分类；影响距离起点、战法间隔、伤兵上限和俘虏等特殊路径 | 仅保留原始位；不重算内嵌部队规则 |
| bit 1 | 单人部队分类；普通目标、护卫/援护和外部部队筛选会排除它 | 仅保留原始位；不把它解释为士兵数等于 1 |
| bit 19 | 建设部队上下文中的“正在建设”标志；会影响中继点和出征日期处理 | 仅保留原始位；不对所有部队无条件派生“建设中”状态 |
| bit 20 | 建设图标标志 | 仅保留原始位；不由导入器生成图标状态 |
| bit 21 | 运输标志 | 仅保留原始位；不由导入器生成运输状态 |
| bit 23 | 行动处理前后设置/恢复，疑似瞬时处理或重入保护位 | 仅保留原始位，不作为稳定状态导出 |
| bit 16–18、bit 24 | 存在设置、清除或门控读取，但独立业务名称未闭合 | 仅保留原始位，禁止强语义命名 |
| bit 4–11、bit 25–31 | 当前没有足够的直接消费者证据；不能据此断言未使用 | 仅保留原始位，禁止视为“未使用” |

upstream 还使用了两个有助于理解的组合掩码：`0x00400004` 表示 bit 2/22 的主动/被动交战组合；`0x00700006` 同时覆盖 bit 1、2、20、21、22；`0x0000000B` 同时测试 bit 0、1、3，用于筛选非内嵌、非单人、未出征部队。`unit +0x22` 的字节掩码是同一 `runtime_flags_0C` 的 bit 16–23 别名，不是另一个字段。

上述研究线索只用于后续逆向和调试，不改变导入字段的原始值，也不自动生成领域枚举。完整证据见 [RE-SAN9PK-0029](../../research/findings/RE-SAN9PK-0029.md)。

## 重制行为

导入器必须生成 800 个按文件顺序排列的部队定义，并保留全部 16 个序列化字段及记录下标 `Id`。原始值和派生视图分开：

- `AreaId`、`ForceId` 和 `ArrayId` 只在目标访问器边界内返回有效代码，否则为空；`CommandCode` 提供 `0..70`/`0xFFFF` 的加载视图。
- `encoded_target_object` 保留主目标对象的原始 `u32`，并可按高 16 位类型提供 `3=部队`、`4=据点/Zone`、`5=都市` 的解释；不从 `unit` chunk 派生另一组当前目标 `+0x54/+0x56`。
- `XCoordinate` 和 `YCoordinate` 将 `0xFFFF` 派生为空，但保留原始坐标值。
- `LoadedSoldierCount` 和 `LoadedWoundedSoldierCount` 分别按 60,000 和 50,000 上限提供运行时加载视图，不覆盖原始 `u32`。
- `HasRuntimeFlagBit(0..31)` 查询原始旗标；越界参数必须拒绝。

导入层不把 `encoded_target_object` 擅自转换为当前目标状态；其主目标类型/序号可按运行时 `+0x50` 编码规则解释，但低位 `+1` 规则仍需确认。`unit_status` 按原始 `u16` 保留，并可按 `0..8` 词汇提供状态视图；策略位名称只作为已确认的原作语义说明，原始 `runtime_flags_0C` 仍完整保留，未确认的其它运行时状态位不被重新命名。`unit_command` 词汇绑定到 `unit +0x18 → CUnitData +0x58`，但不把运行时当前目标 `+0x54/+0x56` 反推为 `unit +0x1A/+0x1C`；这两个字段只作为可无损保留字段读取。

### 运行时目标类型

主目标类型已经存在于 `unit +0x08` 的编码目标对象中；另一组当前目标状态仍属于运行时状态：

| 运行时位置 | 语义 | 已确认类型 |
| --- | --- | --- |
| `CUnitData +0x50` | 主目标对象编码；低 16 位为序号，高 16 位为类型；由 `unit +0x08` 直接写入 | `3=部队`、`4=据点/Zone`、`5=都市` |
| `CUnitData +0x52` | 主目标类型字节 | 类型分派由 IDA `0x4537C0` 闭合 |
| `CUnitData +0x54/+0x56` | 当前目标序号/当前目标类型 | upstream 直接消费，序列化来源未确认 |

`unit +0x18` 是命令代码，不是目标代码；`unit +0x1A/+0x1C` 在当前加载器中读取后丢弃。因此导入器不得根据这两个槽位生成另一组当前目标类型或目标对象。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整 `S9SC` 剧本流。
- 状态变化：读取 `unit` chunk 后产生 800 条部队记录；引用和加载上限视图不覆盖原始字段。
- 始终成立的不变量：chunk 大小为 `32,000` 字节；每项完整消费 40 字节；记录 `Id` 为 `0..799`；记录由 4 个 `u32` 和 12 个 `u16` 组成。
- 引用派生边界：命令 `0..70`、地域 `<250`、势力 `<50`、Array `<28` 才提供有效视图；命令的 `0xFFFF` 映射为 `-1`，坐标仅把 `0xFFFF` 视为空。
- 失败或无效输入行为：chunk 大小、记录边界异常或游标不能恰好填满 chunk 时抛出 `InvalidDataException`；旗标位查询超出 `0..31` 时抛出 `ArgumentOutOfRangeException`。

## 示例与边界

正式样本和编辑器对照支持 `unit_status` 状态域、`morale=100`、有效命令/阵形代码和坐标字段。`D_Sce002.S9` 默认旗标字为 `0xF000`，其中 bit 12–15 分别对应四个策略项，且 `0x8000`、`0x1000` 和 `0` 的教学记录证明策略集合可部分设置。教学有效部队还显示 `encoded_target_object` 的类型 5 编码与 `area_code + 1` 的低位关系。

测试使用原始士兵数 `60,001`、伤兵数 `50,001` 验证：原始值保持不变，而加载视图分别为 `60,000` 和 `50,000`。`0xFFFF` 命令、势力、地域、Array 代码和坐标同样只产生空视图或 `-1` 哨兵，不修改原始代码。

## 未决问题

- `encoded_target_object` 低 16 位的 `+1` 编码规则，以及主目标对象在不同命令/状态下的业务角色。
- `unit_status` 各状态值的产生条件，尤其是状态 2 与运行时 bit 2/22 交战组合的界面显示关系。
- 当前目标 `CUnitData +0x54/+0x56` 的序列化来源，以及 `unit +0x1A/+0x1C` 是否在编辑器或存档专用链路中承载另一组目标信息。
- `command_code` 的完整枚举和各命令对目标类型/目标代码的条件域。
- `opaque_field_1A`、`opaque_field_1C` 是否存在非零样本或仅用于编辑器/兼容保存；当前不阻塞 MVP。
- `area_code` 的完整玩家语义，以及 `Array` 术语在重制领域模型中的最终命名。
