## 调查问题与领域模型

本批闭合皇帝身份、势力官爵、武将官职、君主身份和势力存续之间的边界。领域对象不是一张统一“身份表”，而是四套独立状态：

1. 皇帝人物：由固定列传资源候选、人物死亡状态和世界状态位动态解析；
2. 势力官爵：根势力记录持有的 `kans` ID `0..8`；
3. 武将官职：人物持有的 `shak` ID，命令类型 14 修改该状态；
4. 君主与势力存续：根军团、直属君主、被俘君主状态、可用据点/人物和跨对象引用。

输入是场景初值、周期晋升门、事件选择、俘虏/死亡转移及军团资产变化；输出是官爵、忠诚、君主、根军团和引用图的确定性写回。核心不变量是：子军团不拥有独立势力官爵；被俘君主仍可保持君主身份；人物死亡或势力灭亡后不得留下悬挂的君主、军团、外交、联盟、目标或宝物引用。

## 三套身份体系不可合并

### 皇帝人物

`get_current_emperor_person(0x458540)` 在世界状态 bit 0 置位时直接返回空；否则按列传资源 563、564、565 查找灵帝、少帝、献帝，返回第一名身份不为 8 的人物。身份 4 的俘虏仍可被解析为皇帝，皇帝所在城市则从其当前人物位置动态取得。

因此“当前皇帝”不是某势力官爵为 0，也不是 `kkgu` 国号记录的君主字段。世界状态 bit 0 与人物身份 8 是皇帝解析的两个明确失效条件；它的完整剧情名称不影响该机器契约。

### 势力官爵 `kans`

`forc +0x1A` 载入到运行时势力 `+0x30`，有效范围为 `0..8`。所有读写先把子军团归一到根势力，因此一个势力的全部军团共享同一官爵。重置可复用势力记录时，记录 ID 失效、根指针回到自身、官爵回到最低的 8；这里的“势力失效”由记录有效性决定，不以官爵 `-1` 表示。

晋升资格执行以下顺序：官爵无效或已为 0 时拒绝；ID 8 至少需要完整控制一州（2026-09-20续核纠正，见文末）；ID 1..7 则要求当前信望达到相邻更高一级（`id - 1`）的 `kans` 所需信望。提交总是写入 `id - 1`、增加 10 点基础信望，并把新官爵 `+0x0A` 的数值逐名加到非君主武将对当前势力的忠诚。

世界状态 bit 0 置位、即没有当前皇帝解析时，周期入口可把所有合格根势力各晋升一级，包括从 ID 1 到 ID 0。bit 0 清除时走皇帝在位的册授分支，候选额外排除 ID 1，所以该路径不会授予皇帝级；提交带当前皇帝演出和事件日志 `0x44`。山阳公等事件还可显式写入 ID 0。`set_root_force_peerage_rank_id` 的全部四个运行时调用者均属于这些周期或内置事件提交；势力官爵没有对应的玩家命令类型。

### 武将官职 `shak`

命令类型 14 的执行器处理人物列表和 77 项 `shak` 官职：写入新官职，并按新旧官职俸禄值差的一半调整忠诚。它不读取或修改势力 `kans`。此前把该命令称为“武将爵位”会把人物官职和势力官爵混为一谈；文档、路线图及 IDA 中交互生产、命令构造、校验和执行的 6 个 `peerage_assignment_*` 旧名现均已更正为 `office_assignment_*`。

同时，`kans +0x0A` 过去因误读、误转录编辑器截图中的“忠诚上升”而被记作“能力上升”。重新核图与当前 EXE 的周期晋升、皇帝册授和山阳公授爵三类消费者一致：它们都把该值传给逐势力忠诚增加器，且跳过身份 0 的君主；没有人物四维写回。故 [BEH-IMPORT-0005](../../specs/behavior/BEH-IMPORT-0005-scenario-rank-records.md) 和导入模型已改为 `promotion_loyalty_bonus`。

### 宝物、官职与官爵的能力/忠诚字段

三类记录不共用一个“收益值”，也不通过系数把忠诚换算成能力：

- 宝物 `item +0x0A` 是授予/没收消费的忠诚变化，`+0x0C` 是独立能力加成；没收只对忠诚字段应用 `3/2` 惩罚系数。
- 宝物 `+0x08` 类别映射能力：2 为统率、1 为武力、5/9 为智力、3/4/6 为政治，其余类别不提供四维加成。同一能力持有多件宝物时取 `+0x0C` 最大值，不累加。
- 人物 `shak +0x0C` 是俸禄，原版官职忠诚影响由其一半派生；`+0x0E` 能力掩码和 `+0x10` 能力加成是另外两个字段。
- 根势力 `kans +0x0A` 只在晋升/授爵时作为忠诚增加值；当前能力重算链不读取 `kans`。

`recompute_person_current_abilities(0x44EF70)` 的顺序是：先生成伤势修正后的四项基础值，再加入逐能力的宝物最大值，最后按人物 `shak` 掩码加入共享官职能力值。

## 俘虏、死亡与继任

`capture_person` 捕获身份 0 的君主时写入身份 4，并设置人物标志 `0x2000`。`force_requires_ruler_successor(0x440110)` 明确把带该标志的身份 4 人物视为仍然有效的被俘君主；所以被俘本身不换君，也不让皇帝解析失效。

`kill_person` 先快照原势力、军团、关联对象和宝物接收候选，再写身份 8。原身份 0 或带 bit13 的被俘君主进入同一势力后续分支：若势力已缺少存续所需的据点或人物，则执行终端灭亡；否则调用 `select_force_successor`。这使正常君主死亡与被俘君主后续死亡在写入身份 8 后汇合。

继任候选来自势力人物集合。玩家势力先显示排序后的单人选择器；取消时回退到自动选择。自动路径复制候选并按旧君主关系、血缘／年龄、特定人物优先值及四项当前能力和组合出的机器键排序，提交第一项。子项解释以文末G09复核为准；玩家列表的身份／官职排序不能混入自动继任排序。

提交继任时，新君主身份改为 0、人物官职清空，并成为其当前军团直属君主；原直属负责人若既非旧君主也非继任者则降为普通身份。若继任者来自子军团，不是把旧根记录的君主指针简单替换，而是把旧根军团合并进继任者所在军团，使后者成为存续记录。随后按新君主亲和差为其他武将扣减忠诚并刷新相关引用。

## 势力灭亡与引用清理

普通子军团撤销仍合并回根势力；根记录有可用子军团时可通过合并保留。只有缺少存续资产的终端分支调用 `eliminate_force_and_cleanup_assets(0x441EC0)`：它迁移或清理人物、部队、建筑和目标，清除外交关系、联盟/战争目标及跨势力引用，最后以 `reset_force_record_state` 将槽位恢复为可复用的无效记录。

死亡宝物也遵循最终引用：存在有效继任或其他接收人时整体转交，否则清空持有人。本批只确认灭亡前后的对象与引用守恒；后续 [RE-SAN9PK-0142](RE-SAN9PK-0142.md) 已解释势力消亡写入的胜负状态位和旬任务路由。

### 独立的季度收尾政治表

`47F750`是第五个周期选择器生产入口：开局经过日数至少30，使用`66CCAC`的四项表`20,21,22,23`。其唯一静态调用者`483140`受父任务季度标记`this+13`控制；父状态机`484EE0`在状态1010进入该收尾，位于季度世界更新和可选年度登场之后。它不是季度前置`24,25`，也不是季度主表`26,12,13,8,11,10,-1`。之前RE-0145列举四张表没有覆盖该收尾生产器，不能据此认为官爵对象只有工厂、没有运行入口。

顺序为：有皇帝制度分支的称帝／禅让20、制度终止分支的称帝21、册授晋爵22、无皇帝制度晋爵23。两个称帝候选都要求当前信望至少1000及官爵1；前者另需当前皇帝所在城市属于候选根势力。普通晋爵不是玩家任官命令，也没有是否接受的玩法选项。称帝排在普通晋爵前，不能将23提前而抢先把符合称帝条件的官爵1改成0，导致国号选择路径被跳过。

### 最低官爵门的纠正

`589130`对官爵8调用`4425A0`。后者先取得全部州对象，再遍历城市，凡不属当前根势力，就从结果中移除该城市所属州。因此要求至少一个**完整控制的州**，不是拥有一座城市，也不是把已占城市的州编号去重后非空。城市虚表`605938+0xD0`指向`43A750`，读取`City+0x1EC`；其州引用载入证据见[RE-0008](RE-SAN9PK-0008.md)。正文“一处地域”的旧概括已更正。独立创作内容实施时须以实际非空城市分组判断，不让没有任何城市的空州满足条件。

数据链核对发现低层`San9ScenarioRankArchive`完整读取9条，但`ScenarioContentCompiler`只发布前8条，且将势力官爵8和官职所需官爵8改成null。这会丢失有效最低等级，并使空城起兵错误地选到已发布的次低等级。本批修复三个转换点：完整发布9条、保留势力有效引用、保留官职有效要求；源解析器仍负责把真正无效引用转为null。没有改变原始身份、指挥上限、信望要求或忠诚奖励，也没有把源编号上限带入Core。
