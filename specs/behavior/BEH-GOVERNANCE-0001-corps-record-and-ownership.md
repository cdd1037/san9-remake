# BEH-GOVERNANCE-0001：军团记录与对象归属

- 状态：已确认

- 关联证据：[RE-SAN9PK-0121](../../research/findings/RE-SAN9PK-0121.md)、[RE-SAN9PK-0122](../../research/findings/RE-SAN9PK-0122.md)

## 适用范围

适用于玩家势力的君主直属军团和普通委任军团，以及新设、变更、解散时的负责人、辖区、对象归属和资源迁移。不规定委任 AI 如何选择工作，也不规定低忠诚人物的跨势力叛离。

## 原作基线

势力根记录同时是君主直属军团；普通军团引用同一根记录并保存自己的直属都督、辖区、委任字段、资金和兵粮。新设、变更、解散分别使用模式 0、1、2。

默认都督在执行时从所选城市所属地域建筑中的同根在职人物重新产生；君主当前服务建筑整体不进入候选。排序按在职身份、武官官职顺序和当前统率。变更都督时，旧都督恢复普通在职身份，新都督取得都督身份。

城市迁移必须同步地域建筑和按服务据点关联的合格部队；不能按单位地图当前位置推定迁移范围。人物的有效军团通过驻留对象解析。普通军团解散时，其人物、城市、建筑、部队、资金和兵粮合并回君主军团，残留引用清除后源记录才可复用。正常军团管理不能把君主军团作为普通子军团删除。

## 重制行为

重制版保留根军团/子军团关系、直属都督与势力君主的语义区分、对象归属同步和撤销合并不变量。领域模型使用独立 `ForceState`、`CorpsState`、据点/部队的军团引用和对象所有权关系，不复刻原作让一类记录同时承担势力和军团的存储技巧。

军团使用可扩展身份集合，不继承原作固定记录槽位或以源表容量限制新设数量。资金与兵粮采用完整转移，不能按原作合并封顶静默损失差额；不可表示的溢出在写回前拒绝。上述属于重制工程选择。

都督离任后先根据剩余人员及辖区决定保留或合并，再维护有效都督引用，不能无条件注销军团。设施负责人重选与军团都督接替分别表达候选和排序，不能只清离任者标志。相关机器边界见RE-0122的放逐后自动治理修复复核；人事出行的驻地与实际附着差异须与返程生命周期一并处理。

HUD金钱和兵粮读取玩家当前君主军团本账户，不读取势力汇总；势力情报、结局与经济预测按各军团账户汇总一次。君主继承转移根军团身份时，把旧根账户资源转入新根并注销旧根，保存／恢复／重放保持一致。原作栏位依据见[RE-SAN9PK-0158](../../research/findings/RE-SAN9PK-0158.md)。

## 状态与不变量

- 输入与前置条件：有效君主军团、模式、目标军团、非空城市集合、可实时选任的都督、委任字段及资源分配。
- 状态变化：建立或修改军团，迁移辖区对象，更新负责人和资源；解散时合并并注销源军团。
- 始终成立的不变量：每个普通军团恰有一个势力根；城市、地域建筑和驻留部队的归属一致；目标与来源资源总量守恒；人物有效军团可由驻留关系唯一解析；活动对象不得引用已注销军团。
- 失败或无效输入行为：空辖区、无有效都督、划出君主所在城市、君主军团不留城市、目标跨势力或目标为君主军团时拒绝且不写回。

## 示例与边界

- 从君主军团划出两城建立普通军团：两城、所属地域建筑和驻留部队一同迁移，君主军团至少保留一城。
- 把一城从普通军团收回：该城对象回到君主军团，两个军团资金和兵粮只按新分配值平衡差额。
- 解散普通军团：都督降为普通在职身份，全部对象和资源合并，源军团注销后无残留引用。
- 对君主军团执行普通解散：请求无效；势力消灭属于独立的终止状态机。

## 验收标准

- [x] 新设、变更、解散三种模式分别有自动测试。
- [x] 城市、地域建筑、驻留部队和人物有效军团在迁移后保持一致。
- [x] 都督执行时重选、排序、身份切换及君主服务建筑排除由确定性夹具覆盖。
- [x] 部队服务据点与当前位置分离，覆盖身处其他城市但服务于划拨据点的单位，以及人事/战争活动的迁移边界。
- [x] 资金和兵粮在新设、变更与解散后守恒。
- [x] 主军团保护、根至少保留一城、跨势力目标和资源溢出均由失败测试覆盖。
- [x] 注销军团后不存在对象或辅助字段残留引用。
- [x] 都督离任覆盖仍有人员及城市、无人、无城市但存在其他同根军团的分支；设施负责人替换保持唯一引用。
- [x] 大额资源合并不静默截断；新建军团保存恢复不受初始身份集合或源记录池容量限制。
- [x] 测试夹具不依赖原版文件或研究地址。

单位保存独立可空服务地点引用；内容与恢复验证其存在于据点或有效未建设地域中。单位当前位置、军团归属和服务地点分别保存，服务地点易主后不凭空改写为最近己方城市。

### 单位跟随服务地点的资格

分别保存内嵌单位、人事单位两个分类属性、已分配命令类别和当前异常状态。状态为伪装或溃退时，有效命令按军事返回处理，但不覆盖保存的原命令类别；其他状态读取原类别。新设或变更的共同候选是服务于被划拨地点的人事单位或有效军事命令单位，新设额外排除内嵌单位。解散仍整体迁移所属单位，不套用城市局部划拨的候选规则。

当前类别仅表达治理需要的无命令、非军事、军事三类，不承诺已支持这些命令的执行、战斗或完整异常状态演进；具体单位任务随G05/G06接入。Importer负责原作编号与分类位的转换，Core不读取源位掩码。

## G04运行契约

`CreateCorpsCommand`、`ChangeCorpsCommand`、`DissolveCorpsCommand`均已接入。所有军团均保存必填`CorpsTreasury`，以必填`IsRoot`标识君主军团；`ForceState`不保存金钱或兵粮。每个未灭亡势力（含休眠势力）恰有一个根军团，军团编号不等于势力编号也必须正常路由。资源事件统一引用实际军团账户ID；身份集合可增删，不受初始集合约束。每势力最多8军团是独立玩法上限，不能由源表长度或ID范围替代。

新设与变更命令必填委任方针，与辖区、都督和钱粮在同一事务内校验并发布；目标非法时整体拒绝。变更命令提供完整新辖区及目标金粮值，按差额与根账户平衡；新设划拨全值，解散回收全值。选择现场可用都督，排除人事出行者；旧都督降职、新都督任职，军师引用必要时清空。任免、离任和出发/归队的负责人变化由统一选任维护阶段处理，业务命令不逐条调用据点修复。离任军团没有在职人员或没有城市则合并，反之按剩余候选接替。派生军团从服务据点解析；归队任务签发者是历史记录，解散不使任务失去有效性。

新设默认自动控制，可通过公共命令切换；来源控制与自动调度见[BEH-GOVERNANCE-0002](BEH-GOVERNANCE-0002-delegation-control-and-automatic-scheduling.md)。公开夹具覆盖资格与资源边界，190年一年新设/变更/解散、委任及保存重放见[G04验收](../../docs/g04-verification.md)。

## 2026-09-13：据点大将与部队主将统一维护

**重制选择，2026-09-19用户确认，替代此前按候选遍历顺序破同分的选择。** 两者共用身份、官职带兵量、适用官职优先级、有效统率的选任规则，最后以人物ID升序打破同分。成员归属由人物UnitId表达，主将身份与阵位独立保存，不维护成员排序状态；换任不移动阵位。初始任命不因建立列表而重选。军团都督接替保留其独立业务规则。

人员驻地、所属部队、归属、身份、官职、基础统率、伤势、宝物持有/可用状态及人事旅行资格变化，由领域事务自动识别；有相关变化才统一重选全部当前据点和部队，无关行动标志、兵法冷却、经济数值和普通移动不触发。人员资格和现有领导身份的业务变化先完成，批量命令提交前执行一次维护；旬内任务完成及军事规则步骤之间完成维护，保证后续战斗读取新的大将。事务失败不发布维护结果或事件。读取大将不触发现场选优，冷却或伤势导致无法发动时不临时替换其他武将。

已有初始态及精确恢复保留保存的大将身份；后续相关变化触发重选，不在每次恢复时重新排名。据点最终换任产生`CommanderChangedEvent`，保留供后续界面汇总，当前不接UI。原作授官后全对象重选和读取既有负责人的证据见[RE-0122](../../research/findings/RE-SAN9PK-0122.md)及[RE-0101](../../research/findings/RE-SAN9PK-0101.md)。本轮明确采用相关输入变化触发，不声称完整复刻原版全部调度时机。

验收：批量授官跨据点换任、部队成员升官接任且阵位不变、宝物及伤势改变有效统率、无关操作不重新选任、现任大将不能发动时不选择次将、保存恢复和录像重放一致。本批包含交战关系维护，规则版本统一更新为`san9-core-g08-v6`，旧规则存档/录像明确拒绝，内容包及文件结构不变。
