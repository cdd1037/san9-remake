## 阶段实施输入

开始阶段时，在相关BEH及验收记录中明确以下内容，不另建重复的权威清单：

1. **完整范围。** 按路线图、已采用规格和支持内容集合列出当前行为及明确推迟项。代表性场景是验收入口，不是可省略其余行为的范围清单；发现此前未列出的范围内依赖，同阶段补齐。
2. **行为依赖。** 核对入口资格、输入生产者、账户或状态所有者、公式与随机、日内及周期时机、成功/失败副效果、后续写回、取消及失效清理。涉及原作规则时沿调用者与消费者核对，不能只读取主公式。
3. **证据与选择。** 复用已有RE；补齐缺失或冲突证据。重制差异须有产品理由、明确目标和验收，不能用“尚未研究”作为简化依据。只将与当前结果无关、明确归属其他阶段的疑点留待以后。
4. **实现和验证。** 先以公开夹具验证明确规则预期及边界，再执行所需190年集成；覆盖成功、拒绝、竞争、对象失效、跨域清理与任务中恢复。公式预期不得由被测生产函数生成，确定性验证不替代行为覆盖。
5. **完成结论。** 对照支持集合和行为依赖检查正式实现与实际验收。当前范围仍有未决规则或缺失实现时保留未完成状态；已完成阶段发现遗漏时修正结论并补齐。实际运行结果、原作静态证据和未做的动态/视觉验收分别报告。

## 使用 IDA MCP 定位原版行为

当当前阶段缺少可执行规则输入、已有证据矛盾，或行为时机与写回边界不清时，可直接使用 IDA Pro 与本地 MCP 定向调查。执行遵循[逆向规范](reverse-engineering.md)和[研究规范](research-method.md)；常规只读调查及有证据的解释性标注已有授权，无需逐项确认。

1. 先把问题限定为当前阶段所需的行为，例如“持续任务何时释放人物占用”或“某笔费用从哪个军团账户扣除”。查对应 BEH、RE 和符号记录，优先复用已有结论；将事实、推断与待验证项分开。
2. 发现并连接当前可用的 IDA MCP 工具，核对连接的样本与项目主库身份；默认使用 `San9PK-TC-101.i64`，引用已有样本登记。只有问题涉及 DLL 内部契约时才进入对应 DLL 数据库，不能跨版本套用地址。
3. 从已有符号、字符串或交叉引用定位入口，沿调用者、被调用者和字段读写追踪前置校验、输入生产、调度条件、随机消费、最终写回及清理分支。反编译用于导航，关键整数截断、符号性、条件跳转及调用顺序须结合实际指令和数据流核对。
4. 对静态证据无法判定的分支，记录最小动态实验的初态、操作、观察量与预期区别；实际运行前遵守当前任务的不启动游戏约定。MCP不可用或证据不足时明确记录缺口，继续不依赖它的工作；影响当前行为的缺口解决前不计为完成；重制选择须说明产品理由及其与未决证据的关系，不因工具不可用而临时简化规则，也不把猜测写成原作事实。
5. 将结论、来源、适用范围及限制写回对应RE。需要更名、注释或类型修正时，先完成只读查证，再同步样本主库并记录实际变更与回读验证；批量操作先审阅dry-run。原版地址与存储偏移留在RE，产品只消费规范化语义。
6. 依据证据更新对应BEH的输入、效果、不变量与验收，再独立实现规则。原作动态实验与重制测试分别报告；不将反编译代码、汇编转写或第三方补丁实现复制到产品代码。
