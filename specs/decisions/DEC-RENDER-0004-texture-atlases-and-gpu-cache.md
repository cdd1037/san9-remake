# DEC-RENDER-0004：静态纹理图集与 GPU 缓存

- 状态：已确认
- 日期：2026-09-11
- 决策者：项目所有者（本次会话批准实施计划）
- 关联行为：[地图完整呈现](../behavior/BEH-RENDER-0002-interactive-static-map.md)、[情报浏览](../behavior/BEH-UI-0004-information-browser.md)

采用转换时生成的静态 PNG 图集与逻辑区域索引；按共同使用和释放关系分页，头像独立保存。客户端以物理纹理为 GPU 缓存单位，显式租约保护在用资源，闲置资源按字节预算 LRU 淘汰。头像等纯显示资源上传后不保留 CPU 图片副本，CPU 合成源图及紧凑命中掩码按实际用途保留。

常驻、按需加载、缓存淘汰和 CPU／GPU 存储是独立维度。HUD 在场景期间常驻，窗口和头像按需加载，地图视野保护完整动画集。异步加载采用尺寸稳定的占位，旧请求不能覆盖新选择；地图在完整资源就绪后统一提交，失败保留旧视野。

本决策替代此前界面和地图显示图片全量解码／上传、悬停派生图片常驻的实现。它扩展此前地图分块缓存约定，不改变 [DEC-RENDER-0002](DEC-RENDER-0002-seasonal-textures-and-standard-alpha.md) 的透明混合与四季地形规则，也不引入 Godot 专用磁盘资源或运行时全包 SHA-256 扫描。

不采用单个全局大图集，因为它会把独立生命周期绑定到同一显存分配；不采用动态图集，因为当前资源来自确定的离线转换包，无需运行时搬移区域。接受头像首次使用需读取／解码、页内空隙及边缘扩展占用空间、软预算允许在用资源暂时超额等代价。

接口、预算、诊断与验收详见[纹理资源文档](../../docs/texture-resources.md)。这是重制实现选择，不是原作缓存算法的研究结论。

2026-09-12 用户明确资源所有权：纹理独立于剧本构建，剧本只引用共享资源；此选择替代按剧本导出图片再附加资源库和事后去重的流程。所有最终图片在同一次打包中按像素、透明语义和生命周期处理。运行包不保留原始索引图与调色板，未确认项留在研究记录；接受后续补充未确认语义时重新转换的成本。

透明显示资源必须输出透明键 RGBA，不能用不透明颜色展开图替代。最终逻辑图（包括派生合成图）在入图集之前统一做透明 RGB 扩边；保留既定非预乘 PNG 和默认 source-over，不把绿色背景或缩放渗色留给客户端补救。
