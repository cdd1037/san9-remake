- 继承方式：关系保留；未交付兵力返还与士气权重重新设计

## 适用范围

适用于以部队为目标的伪报、扰乱、激励与救援，包括持续状态、士气、兵力和伤兵边界。公共提交与随机规则由 `BEH-STRATEGY-0001` 规定。

## 原作基线

伪报、扰乱、激励分别在成功时设置各自状态，并写入由对应公式产生的持续日数；每日模拟更新把正值持续日数减一。激励还把兵法间隔清零。

高昂仅在本次每日更新把正剩余日数减到 0，且部队当前命令事件类型属于 `38..52` 时，执行一次士气下降 30；正常正士气写回下限为 1，随后状态恢复为基准状态。此扣减对玩家和 AI 部队同样生效，消息显示另受所属势力对玩家可见性控制。不满足命令类型门槛，或进入更新前日数已不大于 0 时，只恢复基准状态，不扣士气。治疗在到期前清除高昂后，也不再触发这次下降。原版对扣减后非正士气另有部队终止分支，见关联研究；正常正士气不会由本次扣减进入该分支。

救援提交时从执行者所在来源据点立即扣除固定 3000 兵，保存来源当时的士气和判定骰，建立到目标的命令行程；到期后才复验并结算目标效果。成功请求补兵 3000，失败仍有缩减补兵，均按执行时目标带兵上限截断；已扣成本不返还，超额不回流来源，也不转成伤兵。两条分支均混合目标原兵力/士气与来源提交时士气/请求补兵量，不保证成功必升士气、失败必降；截断后士气权重仍使用请求补兵量。成功清除异常状态，但保留基准状态与激励状态。时序复核见[RE-0114](../../research/findings/RE-SAN9PK-0114.md#2026-09-13救援扣兵等待与超额复核)。

## 重制行为

保留三类状态的成功写入、按日递减、激励间隔清零、高昂到期士气惩罚，以及救援“先付固定成本、失败仍有部分效果、伤兵不变、兵力夹取、选择性清状态”的关系。

救援等待生效时序与原作对齐：提交时按来源与目标的领域细坐标中心计算整数欧氏距离 D = floor(sqrt(dx² + dy²))，初始倒计时 N = ceil(D / 30)，不按十天倍数取整。每日命令前将正倒计时饱和减一，到期后在当次每日命令阶段复验并结算。因此第 max(1, N) 次每日处理生效，对应下令日期偏移 max(0, N - 1)；零天也不能在提交调用中立即补兵。领域坐标与命令时序由 Core 保存，不依赖动画或原版内存字段。

**重制选择（2026-09-13）：未交付兵力随执行武将返还，明确不同于原版。** 本选择替代此前重制行为中“失败与超额不返还”的约定；上方原作基线仍保留原版事实。提交立即从来源扣除 3000，并转为救援任务持有的在途兵力，等待与结算不再扣兵。成功请求 3000，失败请求缩减兵力；实际交付量取请求量、当前目标空余容量与在途兵力三者最小值，目标失效或满员时为零。剩余 `3000 − 实际交付量` 随执行武将返程，到达有效己方据点后才入库。失败本身不造成死亡或伤兵，其代价是补兵不足、兵力往返占用与武将时间。

目标士气按实际交付人数与来源提交时士气混合；零交付不改变目标士气。此权重也明确不同于原版按请求量计算的行为。未交付士兵保持来源提交时士气，归队入库时按实际接收人数混合驻军士气。返城容量不足沿用现有部队入城的超额遣散回人口规则，不直接删除兵员。

返程复用[现有人物返程规则](BEH-PERSON-0003-recall-movement-and-action-reservation.md#状态与不变量)，新增随行兵力的保存、转移与归队入库。兵力由任务持有并随返程迁移，不作为武将个人财产随改属自动转给新势力。取消、武将被俘或改属、无己方据点等终止路径必须明确处置剩余兵员并记账，禁止直接删除有兵力的任务或瞬时退款；异常兵员去向在 G08 实现前细化。

去程、交付、返程、入库须保持兵员单一归属；保存任务中的兵力、士气、时序和判定骰，存读档与重放不提前兑现、不重复扣兵或返还。本规格为 G08 实现依据，救援尚未接入运行时。

状态使用明确枚举和独立剩余日数字段，不继承原作数值编码。高昂到期沿用上述日数和命令类型门槛，正常正士气按固定 30 扣减并钳制到 1；救援成本与具体公式常量由相应公式规格提供；若调整固定 3000、到期惩罚或清除集合，须明确目标行为与验收，是否新增 DEC 按[文档规则](../README.md)判断。

## 状态与不变量

- 输入与前置条件：来源据点与目标部队、双方领域细坐标中心、命令剩余倒计时、来源提交时士气、单名执行者、实时能力与阈值、来源兵力、目标容量、状态及持续日数。
- 状态变化：状态/日数、兵法间隔、来源和目标兵力、目标士气、执行者成功能力成长及全员策略熟练度。
- 始终成立的不变量：持续日数不低于零；目标兵力不超过容量；正常正士气的高昂到期恢复基准状态且士气写回不低于 1；救援不直接改变伤兵；提交成本只扣一次；失败不触发执行者基础能力成长。
- 失败或无效输入行为：来源不足固定成本时不得提交；目标失效或无容量时执行复验拒绝效果。

## 示例与边界

- 持续日数为 1 的状态在下一次每日更新后到 0。
- 救援成功时目标上限 10000、执行前有 9000 兵，只补 1000；来源已扣 3000，余下 2000 随武将返回，归队前不计入城内兵力。容量按执行时查询。
- 救援失败请求 1500、目标只剩 500 容量时，交付 500，返程携带 2500；目标失效或满员时携带全部 3000 返回。
- 救援失败仍走缩减补兵和士气失败分支，不能简化为无效果。
- 成功救援保留激励状态，不把所有非基准状态无差别清空。
- 士气 100 的部队被激励成功后，满足命令类型门槛的高昂到期将士气降至 70 并恢复基准状态，而不是回到激励前的数值。
- 高昂期间被治疗命中时先恢复基准状态，这次到期不再触发士气下降；救援命中则保留高昂。
- 高昂到期的士气写回有下限，单次到期扣减本身不会把部队士气扣成 0。

## 验收标准

- [ ] 三类状态成功、失败和逐日到期分别有测试。
- [ ] 高昂到期覆盖命令类型 37/38/52/53、日数从 1 减到 0 与进入更新前已为 0 的边界；仅满足门槛时扣减 30，并验证正士气下限 1、玩家/AI 一致及治疗提前清除。
- [ ] 激励成功清零兵法间隔。
- [ ] 救援提交立即扣 3000，不应用目标效果；覆盖初始倒计时 0/1 均首次每日命令阶段生效，2/10 分别第二/第十次生效，以及细坐标距离 0/1/30/31 的天数取整。
- [ ] 等待中存读档与重放保持剩余时序、来源士气和判定骰，不重复扣兵、不提前兑现。
- [ ] 成功/失败均按执行时容量交付，未交付部分随武将返程；覆盖失败请求 1500 而只容纳 500、目标失效/满员全额返回，不增加伤兵。
- [ ] 来源立即扣兵，目标交付和归队入库各一次；去返程存读档、取消与目的地改道不丢失或复制兵员，归队前不提前退款。
- [ ] 士气按实际交付人数混合，零交付不改目标士气；返城满员沿用超额遣散规则。
- [ ] 救援前后伤兵相等，成功清状态集合精确测试。
- [ ] 成功能力成长和成功/失败全员熟练度分别测试。
- [ ] 测试夹具不依赖原版文件或研究地址。
