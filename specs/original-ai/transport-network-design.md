# 据点交通网络设计

日期：2026-11-05。状态：已确认，开局常驻参考网、工作9范围及路线摘要接线已实现（v248）；扩大相同条件公共查询结果的复用暂缓。

当前实现：`SettlementTransitField` 提供有界同来源多目标粗格地形搜索，`SettlementTransitNetwork` 在新游戏／恢复时完成所有物理来源的参考关系，持有统一端点、参考行程、水陆代价及候选途经设施，并建立出边、入边及点对索引。参考行动力50、陆上5×5／水上4×4、等速水陆成本、范围60日。几何变化整体重建并随会话事务发布；归属和部队移动不重建参考网。参考端点使用设施占地覆盖的粗格，实际攻击接近和出发位置仍由公共导航负责；粗格途经关联不证明整队能够实际穿过设施。

工作9严格从当前来源的直接出边发现目标，未入网或无边的设施不进入候选，不补查网外关系，不用多跳扩展范围。来源预估及选阵前上下文直接消费参考摘要；只在参考路径被中间敌设施阻断、或基础编成没有其所需船型时，对已有网内目标查询替代路线。最终编成仍保留公共连通性、出发位置与粗格行程检查，无逐日预演。公共费用缓存的结构、生命周期及失效逻辑保持现状；反向费用场、走廊引导、局部依赖失效及距离场增量修复尚未实现。

每条边补充 `TransitRouteSummary`：地形ID集合、按首次经过顺序的地域与实际相交中间设施，以及参考接近费用的起终位置和水陆分量。中心线为来源坐标、粗格中心序列和目标坐标依次连接的轴向折线；每段先水平再垂直，按细坐标检查设施占地；首次进入目标占地即停止采集摘要，不记录目标后方的设施、地形或地域。费用只计离开来源占地后的步进，进入目标占地的最后一步不计；起点为首次离开前的位置，终点为首次进入前的位置。源、目标内部费用不混入普通攻击接近估计，原始参考行程仍定义60日候选边界。零行程、宽占地与同粗格情形保持明确，摘要不证明实际队伍净空。

敌我资格、设施工程类别与施工状态不写入静态摘要。AI按当前世界解释途经对象；仅速度变化用 `Reweight` 和实际预算换算同一路线，不追求按编成重新求最短时间。原作先求路、再读标记选阵的依据及其静态限制见[权威研究](../../research/topics/ai/military.md#re-0082-事实来源兵力与选人)。

用于支撑[白马港方案](local-attack-proposal.md)及旧军事邻接的退出。用户提供的既有讨论作为本次设计起点：

> 后续将以都市、港口、关隘等设施为统一节点，维护一定时间阈值内可达的其他设施及参考行军时间、水陆代价，保留途经其他设施的关系，并在建设、拆除时按依赖更新。

本次沿用统一节点、参考投送及途经关系的方向；当前采用首次AI交通查询时完整构建、几何变化在下次查询时整体重建，是否进一步局部维护仍待比较，不因上述旧讨论就预先确定局部增量更新。

## 1. 网络表示什么

网络表达给定移动条件下，实际据点之间的参考投送关系。节点包括当前存在的城市、港口、关隘及其他有物理占地的设施，使用统一据点身份；不按原版槽位、属城或数量区间限定。尚不存在的建设地点不是据点节点，建设规划可按坐标单独查询。施工中的物理对象按公共规则作为端点或障碍，不能仅因不能驻将就从几何中删除。

网络分为参考交通和当前通行查询两层：

| 层次 | 输入与结果 | 不承担的职责 |
| --- | --- | --- |
| 参考交通 | 地形、据点占地、参考移动条件、查询时间范围；返回有向路线、时间、水陆代价和途经对象 | 不判断敌我、战略价值、留兵或是否应出征 |
| 当前通行查询 | 在网内参考候选上加入当前归属、外交、行动通行条件及粗格路线检查 | 不把普通进攻的60日门推广为救援、输送或其他工作的共同规则 |
| 工作策略视图 | 消费交通结果和兵力／人员索引，形成进攻来源、救援候选、输送排序等 | 不另维护一张城市军事邻接表否决真实通路 |

参考网络不是世界的可变领域状态，不持久化，不要求作者维护连线。参考边也不是公共命令的通行许可证。

## 2. 节点、移动条件与边

| 数据 | 必须表达的内容 |
| --- | --- |
| `TransitNode` | 据点身份、实际占地、地域引用、几何修订；节点身份不随归属变化 |
| `TransitProfile` | 陆／水移动规则、占地、速度比例及地形规则版本；按移动语义共享，不能只用“陆路／水路”两个标签 |
| `TransitRoute` | 起点、终点、参考行程、分开的水陆代价、路线／走廊、水陆转换及按经过顺序记录的其他设施 |
| 参考覆盖范围 | 固定参考条件、60日范围、全部有效端点和几何版本；发布时所有来源已完成，无边表示不属于普通进攻候选 |
| 缓存输入标识 | 来源与目标几何、移动条件、端点语义和版本；若选择局部失效，再维护保守影响范围等额外依赖 |

关系有方向，`A → B` 的结果不能直接倒过来充当 `B → A`。港口是统一节点中的一种，不把所有港口之间视为天然水路连接；船型和实际岸线决定通行。水陆代价分别按对应移动率换算同一参考路线的行程，不乘单一速度系数。仅速度变化不要求重选路线；参考路线不保证实际时间最短，船型通行能力及实际占地检查保持独立。

当前参考搜索从来源中心格出发，进入目标占地覆盖的任一粗格即到达；正反向分别选路，去程的到达点不必是回程的出城点。因此端点附近的路线差异也可能使一向在60日内、反向超时，不能据此推断地形只能单向通行。天水／武威及柴桑／寿春的实测均为60／62日，中心到中心对照则均为64／64日；费用、端点及旧邻接集合差异见[新旧城市关系对照](transport-network-performance.md#新旧城市关系对照与单向边)。这描述当前实现的边界，尚未改变端点或时间阈值；其他消费者现按下文静态范围迁移。

参考移动条件由模型定义，不依赖可选阵形编号或当前人物装备。候选发现使用固定参考占地；具体队伍按真实兵量占地和所选阵形／船型重核出发位置与粗格行程。参考边和粗格可达均不证明全部细步通行，不在出兵前逐日预演来提供该保证。

当前会话参考网的 `ReferenceHorizonDays` 为60，行动力50；普通进攻实际行程上限 `MaximumAttackTravelDays` 独立为60。两者当前同值但语义独立：调整实际出兵上限不改变候选集合，调整建表范围才改变候选覆盖。请求、救援、输送及周边估值同样只取直接静态关系，不补表外候选，不使用多跳扩展。各工作保留自己的实际时间规则；普通进攻上限不推广为所有军事命令的统一限制。

## 3. 建图与查询

所有有效节点统一索引；每个来源执行一次固定参考条件下的60日有界搜索，在会话发布前完成全网。不会逐阵形建立全图，也不在AI查询时按需补来源。

1. 参考搜索从设施参考位置出发，目标使用设施占地覆盖的粗格。实际出发位置与攻击接近条件由网内公共查询处理，不能把参考中心点当成真实出发位置。
2. 同来源一次搜索全部其他端点，按60日累计地形费用停止，完成后仅将范围内可达关系写入图。
3. 采用共享有界单源场生成参考关系。实验分支 `MilitaryTransportNetwork/BattlefieldTravelField` 仅作为算法参考，不整体移植其策略和状态。
4. 单源场只用于其明确支持的粗格参考语义。公共导航的选路偏好和实际地形时间分别计算；不能把避让加价当作行军时间，也不能把最短参考时间冒充公共行军一定采用的路线。尚不能证明同语义的结果只作候选，再由公共查询复核。
5. 常驻保存完整的紧凑端点关系、参考路径和摘要，不按32个来源淘汰。构建时的整图工作数组不逐来源常驻，工作数组复用尚未优化。普通进攻不再为选阵前摘要重新寻路；最终队伍与不适用参考路径的网内候选仍可能执行公共查询。

结果至少区分：

| 状态 | 含义 |
| --- | --- |
| `ReferenceReachable` | 在标明的参考条件下已找到范围内的路线，仍需当前通行及实际编成检查 |
| `BeyondHorizon` | 本次时间范围内没有合格路线，不能推断更大范围也不可达 |
| `Unreachable` | 本次条件下搜索已穷尽，确认没有参考通路 |
| `Incomplete` | 计算尚未完成，不能据此消除候选或写入不可达缓存 |
| 未查询 | 单源搜索过程可存在尚未完成的端点；已发布会话网不存在待AI补查的来源或端点 |

上述状态由单源构建表达；会话网只在全部来源完成后发布并保存可达边。无边对普通进攻就是范围外，不是待补查询。时间阈值与展开预算是不同参数；预算耗尽不能被当作完整网发布。耗时只用于诊断，不决定军事选择。

## 4. 途经设施与实际通行

必须分别保存“穿过设施占地”和“经过其所在地域”。经过官渡地域不自动表示必须攻打官渡，实际路线、占地和公共障碍规则才决定是否受阻。

例如参考路线 `白马 → 官渡 → 濮阳`：

- 官渡为己方且允许通过时，保留白马到濮阳的参考关系及其经过官渡的事实。
- 官渡为敌方且实际阻断这条路线时，该参考关系不能直接授权攻击濮阳；官渡作为统一节点，可以独立成为白马的攻击目标。
- 若有可能绕行，按当前通行条件查找替代路线；不能因为一条缓存路线被挡就把整对据点判为不可达。替代路线也检查自己的时间范围，不能沿用被挡路线的时间。

参考网络可以记录同一对端点经过不同设施的有限候选，但首版不穷举全部路径。缓存路径是存在性证据，缺少其他路径不是不存在的证据。必经点只有经额外核对才能标为必经，不根据一条路线推断。

把多条据点边串起来也不自动获得一条可执行行军路线：中间设施可能只允许到达、需要先攻占，或需要另发命令。实际长途投送仍查询完整起终点；本次不设计自动中继、换队或多跳运输任务。

野外部队和建设坐标不作为不断变动的永久网络节点。由兵力／空间索引找候选，使用共享公共导航从实际位置查询；不能把最近城市作为其当前位置。

## 5. 建设、拆除与其他失效

| 变化 | 更新 |
| --- | --- |
| 新建设施／施工障碍形成 | 加入节点与物理障碍；失效受影响来源场和路线，补查新增端点 |
| 拆除／损毁、位置或占地改变 | 更新节点和障碍；失效可能因新捷径而变化的来源场，不仅失效旧路线经过该设施的边 |
| 易主、外交改变 | 刷新当前通行覆盖及工作目标资格；不重建没有几何变化的参考地形关系 |
| 部队移动、新出征或消失 | 更新兵力／空间／命令索引及动态占位查询；不使全部参考边失效 |
| 人员、兵量、士气、账户改变 | 重评来源资格；实际占地或移动条件变化时选用相应查询条件，不重建无关参考边 |
| 地形、移动或设施占地规则改变 | 按规则／地图版本重建相关参考数据 |

当前几何变化整体构建新的不可变网络，并随对应会话操作一起提交；旧会话及失败事务保留原网。以下是后续维护备选，不表示当前已经采用局部更新。

| 备选维护方式 | 优点与代价 |
| --- | --- |
| 几何版本失效，按需重建所请求的来源／目标查询 | 实现简单，建拆时不主动重算；建拆频繁且热点查询多时可能重复搜索 |
| 按可靠影响范围局部失效，再按需重建 | 保留未受影响缓存；需要维护和验证影响范围及反向引用 |
| 在原距离场上增量修复 | 可能减少大量动态变化下的重算；算法、内存和正确性成本更高，不预设为首版要求 |

当前以整网重建作为测量基线，观察完整旬中的命中、重建及建拆成本，再决定是否局部维护。相关数据见[性能实测](transport-network-performance.md)。

若选择局部失效，已经使用的对象依赖只能覆盖直接变化，还需要保守影响范围发现旧路线以外的新阻断或新捷径。范围从来源完整出入口、时间阈值、最快地形移动下界及占地／接近范围推导，不能拿旧搜索访问格或旧路线包围盒代替。无法可靠证明范围外不受影响时扩大失效范围。

所有更新以当前已发布快照为依据。旧世界产生的查询结果携带输入版本，不能在新世界中直接作为可提交结论。缓存不持久化，保存恢复后按相同输入重建。

## 6. AI决策寻路的数据复用

普通进攻已复用参考路径、水陆代价和静态摘要；公共路线结果缓存扩展继续暂缓。其他旧邻接消费者已迁移静态候选；同目标反向场、走廊引导仍是后续方向，不表示已经实现。

| 可复用数据 | AI怎样使用 | 正确性边界 |
| --- | --- | --- |
| 节点、占地、出入口和端点索引 | 从真实来源出发，批量找到目标，构造公共查询 | 实际出发占位改变时重新选择起点，不能固定使用参考中心 |
| 同来源多目标场 | 一次扩展取得多个设施的参考行程、路线和途经关系 | 按移动条件和端点语义区分；只覆盖本次时间范围，未覆盖不等于不可达 |
| 同目标反向费用场 | 多个来源或部队查询同一目标时复用；在满足条件时引导A*搜索 | 必须在有向移动图上正确反向建场，不能把目标到来源的路线简单倒转 |
| 参考路线／走廊和途经设施 | 快速检查当前阻断，提供候选路线或搜索初始解 | 有效路线可提供当前模型内的可行解／上界；路线时间通常不是最短时间下界，走廊外仍可能有绕路 |
| 分开的地形水陆代价 | 快速重算同一路线在相容移动条件下的行程，减少重复遍历 | 普通工作9按该参考路线换算来源行程门；超时不代表所有替代路线都超时，本轮不按速度比求时间最优路线 |
| 输入完全一致的公共估计或准备结果 | 直接复用，避免重复完成同一查询和资格准备 | 必须绑定对应输入和当前世界依赖，不能只用起终点ID判定命中 |

使用距离场作为A*启发式时，必须证明它在当前搜索代价模型下不高估。可采用忽略动态部队及部分阻挡的放松地图计算下界；参考阵形更小并不自动保证速度、地形通行及端点条件也满足下界要求。障碍拆除后，旧场可能高估新最短路，不能继续拿来剪枝。

实际队伍条件与参考条件不同，优先复用地图、索引、合法下界和候选走廊，再执行必要查询。不能把参考走廊作为唯一搜索区域：走廊受阻时允许扩展或全域查询，否则会把合法绕行误判为不可达。若使用路径上界剪枝，比较值须与搜索目标使用同一代价模型，不能混用行军时间与含避让加价的选路成本。

热点距离场可按需保留，冷字段及工作数组按内存限额回收。单源场、反向场及公共路线缓存按实际调用集中选择，不默认三套全量常驻；跨工作共享不要求跨存档保存。

进一步复用的性能验证须对比不复用、只复用端点结果、复用搜索数据的完整旬成本，统计构建次数、展开节点、命中、失效重建及峰值内存。在相同输入下选择和查询结论一致，才能将收益归因于加速；现有测量与局限见[性能实测](transport-network-performance.md)。

## 7. 与进攻关系及兵力索引的接线

通用交通网不含兵力、人物、目标偏好或出兵门。`OriginalAiAttackView` 在当前军团合法来源上查询交通，再施加战略敌对资格、普通敌设施前沿条件和行程门，得到工作9的有向进攻关系；同一关系提供目标列表和反向来源列表，保证白马不会在目标重建时丢失。

v250修正普通进攻的前置目标优先级：原目标参考路线上的首个满足战略目标资格的途经据点承接该阶段，包含城市及中立据点，不含工程障碍类，不另加前沿门；先检查同一来源到该据点的直接交通边，再按统一关系收集实际来源。普通已占领敌设施独立候选阶段的前沿门保持。按实际目标去重，不重新使用城市军事邻接，也不增加网外目标。沿路施工冲突仅约束本批主路线，不逐一过滤额外参战来源；转建设地域取自主路线，建设来源独立按同城士气及空闲人物资格重选。该顺序修正v249的部分恢复；v251恢复已有兵力分配后尝试完即结束当前城市批次的规则，命令全部为空或被拒绝也不继续后备；来源、路线、强度或零分配阶段的后备行为保持。失败后继续后备可能合理，但本轮暂不采用，不将其混入交通网复用。

反向索引收集已完成的各来源正向结果，不把目标到来源的行军结果反转使用。普通进攻只有已有直接有向边的来源—目标对，不另行补查无边关系。

兵力索引独立维护当前据点、野外部队、兵伤及所属关系，命令索引维护现有输入权限下的目标关联。索引回答“哪里有什么兵”；交通网回答“在何种移动条件下如何到达”；工作策略再判断能否及时投入及是否应出动。

`MilitaryRouteQueryContext` 继续提供公共行军语义和具体部队复核。Application持有会话／控制范围内的交通缓存与工作视图。会话创建和读档不建网，首次AI交通查询完成后随成功操作发布缓存；未使用交通的操作不触发构图，失败操作不把候选缓存写回会话；Core持有路径、地形、占地和时间规则，不复制一套AI专用移动公式。旧军事邻接消费者及其生产字段、生成器已退出。目标周边估值使用自身及入边来源；优待留兵和输送前线看入向威胁，请求与救援看来源到目标的边，输送按直接边参考行程排序。迎敌只接受来源地域及出边端点所在地域，再查询野外队真实位置，不加入途中空地域。具体规则见[B20](behavior.md#b20)。

## 8. 具有区分力的验收

- 同一白马式港口到邻近敌港有参考边、当前进攻关系及真实公共提交，三层分别验证；不补城市军事连线。
- 同一对端点有水陆差异、相反方向或不同兵量占地时，结果按条件区分，不能误用缓存。
- 改变途经设施的归属，只更新当前通行；敌设施阻断后，能发现其作为目标，且合法绕行存在时不误判不可达。
- 拆除一处旧路线未经过的障碍后出现更短路线，无论使用整体失效或局部维护都能发现捷径；新建设施、施工开始及新增目标也能被发现。
- 单源构建区分阈值之外、真正不连通与计算未完成；会话网完成后才发布。普通工作9不扩展网外目标，实际快速阵形也不放宽。
- 冷建、命中、建拆后重建及保存恢复的结果一致；索引与直接扫描一致，不因网络节点增加而重复统计守军。
- 热点反向场、参考走廊及地形代价复用与直接公共查询对照；占地、速度比例、动态阻挡或端点语义变化时，不误用参考结果或过期下界。
- 固定普通与大量设施局面比较完整旬成本，包含构图、缓存、失效及公共复核；先确认工作量，再决定单源场和局部失效的实现粒度。

单源场及摘要不证明真实队伍细步通行，实际行军交由每日导航；出兵前逐日预演已撤除。普通进攻采用完整参考网范围、按参考路径换算的来源行程及最终编成公共检查。反向费用场、走廊引导、公共结果缓存扩展及局部维护仍按上文边界暂缓或待比较。
