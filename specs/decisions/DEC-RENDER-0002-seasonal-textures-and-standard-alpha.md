# DEC-RENDER-0002：MVP 四季彩色纹理与标准透明混合

- 状态：已确认
- 日期：2026-09-05
- 决策者：项目所有者（本次会话）
- 关联行为：BEH-RENDER-0002、BEH-RENDER-0001

MVP 保存四套独立 RGB 地貌 PNG，共用方格、资源 ID 和遮罩；调色板仅参与导入。完整注册表复核后确认全部771项绑定，四季独立输出。先前研究脚本遗漏8个区间末尾资源，其中5项被190年剧本实际使用；经用户授权补查，现已由RE-0053闭合，无需猜测或占位。

建筑、桥、云转换为 RGBA；逐索引 Alpha 用 `round(min(A,128)*255/128)`，不按单幅图的 Alpha 最大值归一化。非 Alpha 路径仅应用透明键色。透明键比较完整调色板四字节，重复键色均透明。

运行时使用标准 source-over 透明混合，接受与原版 128 分母、取整和压暗行为的细微差异；不承诺逐像素差异低于 1%。本决策替代 BEH-RENDER-0001 对 MVP 建筑/云保持整数 Alpha 混合的要求，不修改研究快照基线。地貌仍使用 RGB888、原有排序和 256 权重遮罩关系。

四季按初始月份选择（1–3 春，4–6 夏，7–9 秋，10–12 冬），另提供开发预览选择。日期驱动的换季动画与玩法影响不在此次实现内。

经用户确认，透明边缘处理归入资源转换阶段：普通 RGBA PNG 的完全透明区域填入邻近可见像素的 RGB，Alpha 和所有可见像素保持不变；运行时直接使用 Godot 默认 source-over 材质。颜色按八邻域从所有可见像素同时向外扩散，同距离按行优先种子与固定邻接顺序确定；全透明图 RGB 清零。不按特定绿色识别边缘，不预乘 PNG 或 GPU 纹理。此流程替代此前的运行时预乘实现，避免客户端承担源资源的边缘修复。依据：[Godot 透明边缘导入处理](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html#process-fix-alpha-border)。当前验收覆盖无 mipmap 的双线性缩放；未来引入 mipmap 时另验收缩小质量。

验收使用地貌精确对照、透明层误差统计及实际画面检查。四套纹理增加磁盘空间，以免运行时耦合索引调色板；通常只加载一个季节。
