# DEC-SIM-0001：确定性命令结算与显式存档迁移

- 状态：已确认
- 日期：2026-08-15
- 最后修订：2026-09-06（项目所有者确认暂时维持原作命令生效时机）
- 决策者：项目所有者
- 关联行为：[BEH-GOVERNANCE-0002](../behavior/BEH-GOVERNANCE-0002-delegation-control-and-automatic-scheduling.md)、[BEH-PERSON-0001](../behavior/BEH-PERSON-0001-discovery-recruitment-and-affiliation.md)
- 替代或被替代：无

## 背景

旬制同步推进、AI 调试、长期自动模拟和跨平台存档要求相同输入产生可复现结果。隐式随机源、表现层改状态和静默存档兼容都会破坏这一目标。

## 决策

所有玩家与 AI 行为提交为类型化命令，按显式、稳定的顺序执行。当前保留原作生效时机：即时命令在轮到对应军团、通过执行校验后立即写回；有行程或耗时的命令提交为持续任务，再按日推进并在满足执行条件时写回。双方共用同类命令的执行规则，不要求各方基于同一份旬初快照同时规划。

随机行为只使用显式种子和项目自有稳定随机流。`AdvanceXun()` 返回事件与只读快照，但不是所有命令效果的唯一提交入口。存档记录格式版本、内容指纹、随机状态和世界状态，升级必须使用显式迁移；命令日志保留实际执行顺序，存档包含仍在执行的任务。

2026-09-06 修订替代原先“所有命令在旬边界结算”的统一表述。当前不采用全部命令延后至共同结算的方案；进入联机设计时重新审视生效时机、先后手与同旬命令依赖，再修订本决策。此选择不降低确定性要求。原作时序证据见 [RE-SAN9PK-0123](../../research/findings/RE-SAN9PK-0123.md#命令生效时机复核2026-09-06)。

## 备选方案

- 各系统直接更新节点：实现快但执行顺序不透明。
- 使用平台随机实现：无法承诺跨版本稳定序列。
- 存档尽力兼容：错误可能被静默带入新状态。

## 影响

- 玩家可见影响：规则可解释，暂停和恢复结果稳定。
- 数据/存档影响：新增随机或状态字段必须进入哈希与存档。
- 测试影响：同种子、同命令日志必须得到同一状态哈希和事件序列。
- 风险与代价：并行化必须保持逻辑提交顺序。
- 回退方式：无；非确定性表现只能消费事件，不能参与规则。

## 验收条件

- [x] M0 旬推进样例使用命令队列和只读快照。
- [x] 稳定随机流有固定向量测试。
- [ ] 存档实现后具备往返与迁移测试。
- [x] 玩家与 AI 的同类即时命令无需推进日期即可写回；有耗时的命令在提交时不提前兑现最终结果。
- [ ] 相同初态、命令顺序和随机状态产生相同结果；即时写回与未完成任务均可保存、恢复和重放。
