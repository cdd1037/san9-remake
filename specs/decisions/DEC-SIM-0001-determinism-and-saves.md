# DEC-SIM-0001：确定性命令结算与显式存档迁移

- 状态：已确认
- 日期：2026-08-15
- 最后修订：2026-09-19（交互续行与存档边界分离）
- 决策者：项目所有者
- 关联行为：[BEH-GOVERNANCE-0002](../behavior/BEH-GOVERNANCE-0002-delegation-control-and-automatic-scheduling.md)、[BEH-PERSON-0001](../behavior/BEH-PERSON-0001-discovery-recruitment-and-affiliation.md)
- 替代或被替代：无

## 背景

旬制同步推进、AI 调试、长期自动模拟和跨平台存档要求相同输入产生可复现结果。隐式随机源、表现层改状态和静默存档兼容都会破坏这一目标。

## 决策

所有玩家与 AI 行为提交为类型化命令，按显式、稳定的顺序执行。当前保留原作生效时机：即时命令在轮到对应军团、通过执行校验后立即写回；有行程或耗时的命令提交为持续任务，再按日推进并在满足执行条件时写回。双方共用同类命令的执行规则，不要求各方基于同一份旬初快照同时规划。

随机行为区分固定条件抽样与命名运行流，均使用显式种子和项目自有稳定算法。普通登用、探索发现门按本局种子、日期及参与身份确定，不依赖操作顺序；可重抽判定使用运行种子，玩家读档时换种子，精确恢复和录像重放不换。已经写入任务的骰子不重抽，实时资格和阈值仍参与最终结算。完整分类、入口和后续系统原则见[随机约定](../../docs/randomness.md)。这是项目所有者2026-09-12确认的行为选择，替代所有判定统一消费连续流及所有读档都精确恢复随机状态的旧约定；不复制原作依赖进程剩余随机状态的技术方案。

`AdvanceXun()`返回事件与只读快照，但不是所有命令效果的唯一提交入口。存档记录格式版本、内容指纹、两个种子、流游标和世界状态，升级必须使用显式迁移；命令日志保留实际执行顺序，存档包含仍在执行的任务。录像从完整起点恢复运行种子，不逐骰记录。

2026-09-06 修订替代原先“所有命令在旬边界结算”的统一表述。当前不采用全部命令延后至共同结算的方案；进入联机设计时重新审视生效时机、先后手与同旬命令依赖，再修订本决策。此选择不降低确定性要求。原作时序证据见 [RE-SAN9PK-0123](../../research/findings/RE-SAN9PK-0123.md#命令生效时机复核2026-09-06)。

2026-09-12采用默认玩家存档与显式录像分离：普通存档只含当前状态、水位、最近128条自动内政记录和玩家年表；整局命令/事件另存录像，支持中途起点。此选择替代早期G02把完整操作历史放入每份存档的方案，避免几十年对局中普通存档随操作数线性增长。代价是旧序号只判定已处理，不再逐条核对历史载荷；完整追溯由显式录像承担。协议见[BEH-SAVE-0001](../behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md)。

2026-09-12哈希复核：世界/会话摘要改为录像与诊断按需计算，不写入默认快照或参与普通恢复校验；外部文件只保留一层完整性校验，内容指纹与规则版本分开表达。命令ID由种子/序号直接生成，本地请求不再附加重复的流指纹。

2026-09-19按项目所有者确认收紧保存边界，替代先前把玩家待答点作为存档／录像起点的设计：运行时事务可提交等待选择的状态，保存只接受完整旬结算后的稳定下令状态及完成终局。谈判步骤、季度邀请／报名及继任选择留在内存；跨边界任务与已确定结果继续持久化。录像从稳定起点记录玩家答复以重现过程，不依赖中间状态存档。代价是不能在待答提示中保存或开启录像；未来逐日存档须在完整日结算处扩充，不逐阶段保存。

2026-09-19进一步明确录像的产品定位：正式面向玩家时须支持全程对局回放、时间跳转及在可操作边界接手新分支，不限于战斗展示或调试。当前显式记录事件、逐操作比较与最终状态比较可作为验证实现暂时保留，不作为玩家播放必须执行的流程。该澄清替代“录像仅服务调试”的定位，不要求本阶段立即实现玩家回放，也不改变中间交互不存档的边界。交付前工作与验收方向见[BEH-SAVE-0001](../behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md#面向玩家交付前的后续要求)。

## 备选方案

- 各系统直接更新节点：实现快但执行顺序不透明。
- 使用平台随机实现：无法承诺跨版本稳定序列。
- 存档尽力兼容：错误可能被静默带入新状态。

## 影响

- 玩家可见影响：规则可解释，暂停和恢复结果稳定。
- 数据/存档影响：新增权威状态进入诊断哈希；只有跨保存边界的状态进入存档。
- 测试影响：同种子、同命令日志必须得到同一状态哈希和事件序列。
- 风险与代价：并行化必须保持逻辑提交顺序。
- 回退方式：无；非确定性表现只能消费事件，不能参与规则。

## 验收条件

- [x] M0 旬推进样例使用命令队列和只读快照。
- [x] 稳定随机流有固定向量测试。
- [x] 存档具有磁盘往返与未知版本拒绝测试；目前没有已支持旧版，不提供隐式迁移。
- [x] 玩家与 AI 的同类即时命令无需推进日期即可写回；有耗时的命令在提交时不提前兑现最终结果。
- [x] 相同初态、命令顺序和随机状态产生相同结果；即时写回与未完成任务均可保存、恢复和重放。
