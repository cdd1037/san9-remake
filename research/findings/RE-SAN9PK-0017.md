## 结论

`jnki` 位于剧本数据偏移 `0x107E`，大小 `896` 字节。它由 28 条、每条 32 字节的阵型记录组成。目标程序的 `deserialize_jnki_record`（IDA `0x448AF0`）实际读取布局如下：

| 偏移 | 大小 | 当前结论 | 目标程序行为 |
| ---: | ---: | --- | --- |
| `+0x00` | `u16` | 序列化编号；`SerializedId` | 读取后丢弃，运行时编号改用记录顺序 |
| `+0x02` | `u16` | 目录代码 | 写入运行时 `+0x50`；当前 EXE 无载入后读取 |
| `+0x04` | `u16` | 保留字段 | 写入运行时 `+0x54`；当前 EXE 无载入后读取 |
| `+0x06` | `u16` | 保留字段 | 写入运行时 `+0x58`；当前 EXE 无载入后读取 |
| `+0x08` | `u16` | 对部队效果 | 与 `阵型.png` 的“对部队”一致 |
| `+0x0A` | `u16` | 对守兵效果 | 与“对守兵”一致 |
| `+0x0C` | `u16` | 对城壁效果 | 与“对城壁”一致 |
| `+0x0E` | `u16` | 守备力 | 与“守备力”一致 |
| `+0x10` | `u16` | 机动力 | 与“机动力”一致 |
| `+0x12` | `u16` | 视野半径 | 与“视野半径”一致 |
| `+0x14` | `u16` | 视角范围的 45° 扇区数 | 编辑器标签为 `x45°`；与朝向共同选择视野扇形视觉资源 |
| `+0x16` | `u16` | 出征费用 | 与“出征费用”一致 |
| `+0x18` | `u16` | 阵形说明资源代码 | `0` 返回空文本，`1..14` 选择固定说明文本 |
| `+0x1A` | 5 bytes | 五个出征阵位代码 | `0..8` 是 3×3 行优先格，`9` 是无阵位哨兵 |
| `+0x1F` | 1 byte | 程序跳过的字节 | `0x448AF0` 只递增指针，不写入运行时对象 |

样本 `D_Sce001..020.S9` 与 `D_Ttrl00..05.S9` 的这 896 字节区域哈希一致。`D_Sce001.S9` 的第 0 条为：

```text
u16: 0, 0, 0, 0, 15, 10, 10, 10, 12, 3, 4, 0, 1
slots: 01 03 04 05 07
ignored: 39
```

这与截图中鱼鳞阵的“对部队 15、对守兵 10、对城壁 10、守备力 10、机动力 12、视野半径 3、视角范围 4、出征费用 0”相符。五个阵位代码 `1,3,4,5,7` 对应“前中、中左、中中、中右、后中”。全部库存记录合并后覆盖 `0..9`，部署界面消费者进一步确认完整映射。

## `+0x18` 的说明资源链

`get_formation_description_text(0x448980)` 在代码非零时调用 `get_formation_description_by_code(0x5681E0)`，后者以 `0..14` 为边界索引 15 项文本表。代码 0 对应空文本；1..10 是陆上阵形的兵法发动、俘虏、单挑、异常状态和防御说明，11..14 分别是舰船可发动的“箭雨”“强袭”“箭岚”“强攻/箭岚”说明。`get_formation_property_value(0x448CB0)` 的排序键 16/18 另返回 `15-code`，用于把非空说明按资源代码逆序排列。

因此 `+0x18` 是阵形说明资源代码，不参与伤害、机动、部署费用或资格计算。导入层暴露原始 `DescriptionResourceCode`，并只在 `0..14` 内派生 `DescriptionId`；实际文案仍属于消息资源，不复制进产品数据。

## 阵位代码与几何映射

`get_formation_slot_code(0x4487F0)` 按人员序号 `0..4` 读取文件 `+0x1A..+0x1E`，越界返回 9。`assign_formation_slots_to_unit_people(0x448870)` 把每个代码写入人物 `person_flags & 0x001F0000`；代码大于 8 时停止分配。单位阵形界面 `populate_unit_formation_dialog(0x590AD0)` 回读该人物位并按以下公式放置头像：

```text
column = slot_code % 3
row = slot_code / 3
x = 149 + 144 * column
y = 121 + 88 * row
```

由文件生产者、人物状态和坐标消费者闭合，完整映射为：`0/1/2=前左/前中/前右`、`3/4/5=中左/中中/中右`、`6/7/8=后左/后中/后右`，`9=无阵位`。这里的坐标是原作部署界面像素，不是重制版必须复用的 UI 常量；领域不变量是 3×3 行优先几何与空值哨兵。

## 视角代码

编辑器将 `+0x14` 明示为“视角范围（x45°）”。运行时 `get_unit_vision_arc_visual_key(0x54E990)` 从单位阵形读取该代码，并与单位朝向组成缓存视觉键；`refresh_unit_vision_arc_visual(0x54E9D0)` 用二者取得并刷新视野扇形图像。库存代码覆盖 `0..8`，分别表示 `0°..360°` 的 45° 扇区数；代码 0 不创建扇形视觉，代码 8 是完整圆周。

这条证据确认的是视野扇形的显示几何。当前全程序字段访问审计未发现 `VisionRadius` 或 `VisionAngleCode` 直接参与战斗命中、索敌或 AI 资格计算，因此重制规则不得仅凭字段名推造隐藏视野机制。

## 三个前置槽位的负面审计

`+0x02/+0x04/+0x06` 分别写入运行时 `+0x50/+0x54/+0x58`。对当前 IDB 全部可反编译函数、阵形访问器、战斗公式、部署链和渲染链扫描，未发现任何载入后读取；26 个正式/教学样本中三者均等于记录顺序。第三方编辑器只把首个值显示为“编号”，其余仍在未知区。

产品因此使用 `CatalogCode`、`ReservedField04`、`ReservedField06`，全部无损保留，但不把它们当作身份键、资源代码或玩法参数。后续若其他版本出现消费者，应作为版本补证回并本记录。

`+0x1F` 在当前记录加载函数中没有运行时消费者；但它是记录布局的一部分，样本均为 `0x39`，所以实现仍保留为 `IgnoredByte`。

## 实现与验证

- `San9ScenarioFormationArchive.ReadKnownRecords` 严格检查 `jnki` 大小为 `28 × 32`。
- 所有 13 个 `u16`、5 个阵位字节和被跳过字节均保留；记录 `Id` 使用文件顺序。
- 单元测试覆盖字段顺序、说明资源代码、45° 扇区换算、3×3 阵位解码、无阵位哨兵和错误大小。
