## 对象、状态、输入、输出与不变量

对象是交互 dispatcher code 34/35/36、`COrderYouseiDlg`、`COrderHenkanDlg`、`COrderKankokuDlg`、来源与目标势力、单名使者、第三方地域建筑、请求返还的俘虏、反要约中的俘虏/资金/宝物、命令事件及双边关系。输入包括双方控制权、关系、势力资源、使者政治、目标君主野心、兵力汇总、稳定随机种子和提交时保存的 `0..99`；输出包括攻击目标状态、俘虏释放、资金/兵粮/宝物转移、势力消灭与对象重归属、关系、政治成长、参与占用和任务收尾。

不变量：三个交互 code 分别汇合到内部类型 34、35、36 的独立共享命令；玩家控制的一方在自己负责的接受或反要约阶段显式选择，AI 才走机器判定；反要约在最终接受前不转移；俘虏返还成功必释放被请求人物；劝降成功必进入整势力解体与重归属流程；成功和失败都走公共事件/任务收尾。自动工厂同样有 code 34–36，但其候选与评分属于 `DIP-04`，本批不以交互链替代自动调度调查。

## 已确认事实

### 三个交互生产者与公共提交边界

交互工厂 code 34、35、36 分别构造 `interactive_attack_request_action_task`、`interactive_prisoner_return_action_task`、`interactive_surrender_demand_action_task`。三个任务的确认槽分别构造 `attack_request_command`、`prisoner_return_command`、`surrender_demand_command`，公共基类中的命令类型分别为 34、35、36。RTTI 对话框链与 `Yousei/Henkan/Kankoku` 一致，最终数据流将其业务语义分别限定为攻击请求、俘虏返还和劝降，而不是仅凭罗马字翻译命名。

三类提交都准备单名使者、建立事件、路由到目标君主所在地并设置来源任务活动状态。三者都把稳定种子上的 `rnd(100)` 写入事件，但该字段是否参与结果必须逐类判断：攻击请求和劝降消费它，俘虏返还的已观察谈判/执行链不读取它。

### code 34：攻击请求与反要约

命令同时保存被请求势力和第三方 `CChiikiBuildingData` 目标。有效性要求公共命令门通过、被请求势力与目标建筑仍有效、来源/被请求方/目标持有方满足不同君主与势力标志约束。`can_fulfill_attack_request` 进一步沿被请求势力的地域建筑与都市集合检查目标区域可达性、相关都市守备条件、附近部队过滤和一个至少为 1000 的势力汇总门；未能唯一映射的公共字段保持中性。

提交只保存 `0..99`，不预付报酬。AI 被请求方用同一保存结果依次划分结果：低于免费接受阈值则无条件接受；否则可能要求交换俘虏；再否则选择资金或宝物反要约；没有可行报酬时拒绝。玩家被请求方通过对话框选择反要约。免费接受阈值在可执行性与外交状态门通过后为 `使者当前政治 + 当前关系 - 80`；俘虏反要约阈值在存在可交换俘虏等门通过后主要为 `使者当前政治 + 当前关系`，特定目标君主字段小于 6 时直接返回 100。军师以相同稳定种子模拟免费接受、反要约和拒绝类别，再叠加军师准确度与 50% 分类扰动；意见不是执行骰的明文泄露。

资金或宝物反要约按来源当前资金、使者政治、关系、目标君主字段及可转让宝物选择。随后由请求方决定是否接受：玩家请求方显式选择；AI 对交换俘虏直接接受，对资金检查当前预算上限，对宝物同时检查保存结果和宝物价值字段。只有双方完成谈判后才释放交换俘虏或转移资金/宝物。

成功时关系增加 `max(40-current_relation, 10)`，并给被请求势力写入来源势力、目标建筑字段及剩余19旬，形成后续攻击目标元组；期限消费者已由2026-09-16补证闭合。失败关系固定减少 5。成功还尝试提高使者政治；两条分支最终都处理地域对象人员并收尾。

### code 35：俘虏返还谈判

有效性要求目标势力与目标人物有效、双方不是同一君主、目标人物状态字段为 `4`，且目标人物的归属势力解析回来源势力；这条对象链把 `Henkan` 限定为请求对方返还己方俘虏。提交事件保存一个 `0..99` 字段，但 `get_unit_command_event_roll` 的全库调用点中没有 code 35 函数；反要约、接受和最终执行均不消费该字段。

AI 目标方先决定返还条件：特定外交状态且没有可交换俘虏时可免费返还；否则优先选择一名交换俘虏，再计算资金补偿，资金不满足门时改选可转让宝物，仍不可行则拒绝。补偿基值取目标俘虏当前四能力中最高两项，按机器整数顺序计算 `max(500, ((top1+top2)/2)^2/4 - 8*(使者当前政治+当前关系))`。玩家目标方可显式选择条件。

请求方随后决定是否接受交换俘虏、资金或宝物条件；玩家显式选择，AI 复用当前人物、资金和宝物门。军师只预测“存在可行补偿”这一真假类，再以同种子军师准确度翻转类别；它既不读取也不预测提交事件里的未消费随机字段。

免费返还或请求方接受条件后，目标俘虏被释放；交换条件还释放对方俘虏，或从来源向目标转移资金/宝物。成功不写双边关系，但尝试提高使者政治；失败关系减少 5。两条分支都完成相关人员归属整理和公共收尾。

### code 36：劝降势力

有效性要求目标势力有效、双方不是同一君主、目标虚槽状态允许劝降、双方不同时处于特定特殊势力状态，且不存在对应的既有关系状态。提交保存稳定 `0..99`，不预先转移资源。

AI 接受阈值先排除一个目标君主特殊谓词，再要求一个势力关系谓词成立，并要求整数兵力比 `source_strength / max(20000, target_strength) >= 5`。通过后阈值按机器顺序为：

`S(使者政治) * ((clamp(F_source,0,1000)-clamp(F_target,0,1000))/40 + strength_ratio - 10*target_count - max(0,5*目标君主野心-40) + 10) / 60`

其中 `F_source/F_target` 为双方当前信望，`target_count` 为目标根势力所属城市数（含其军团）；2026-09-06 补证见下文。军师用同一稳定种子分别对该阈值和军师准确度抽样，只报告真假类别是否一致。AI 目标严格以 `stored_roll < live_threshold` 接受；玩家目标进入显式劝降对话框。

成功后目标势力进入完整解体：向来源转移目标势力汇总资金与兵粮的一半；遍历目标人物，以独立全局概率决定加入来源或脱离，并为加入者按与来源君主的相性距离重设忠诚；随后处理目标地域建筑、部队、人物归属、势力记录、通知和界面刷新。成功尝试提高使者政治。失败关系减少 `max(10, current_relation-39)`，因此结果最多为 39 且至少下降 10。

## 资料冲突与边界

“外交采用确定公式、不存在概率”对攻击请求和劝降直接不成立：两者都保存 `rnd(100)` 并在结果链消费，劝降成功后的人员归属还逐人使用全局概率。俘虏返还是重要反例边界：它虽然沿公共提交模板保存随机字段，但当前谈判和执行不读取该字段，不能仅凭事件布局声称结果有概率。SanIX 与电子书的当前样本校核已同步更新；剩余外交关系/联盟与自动调度仍由 `DIP-03/04` 裁决。

### 2026-09-17 俘虏返还报价与严格接受边界补证

样本沿用本记录繁中PK 1.0.1.0登记。健康探针确认当前为项目主库`San9PK-TC-101.i64`、输入`San9PK.exe`、基址`0x400000`，自动分析和Hex-Rays均就绪。本轮使用入口反编译、排序器比较方向、原始表项及只读指令解码交叉核对。以下均为静态事实，不等同于动态谈判竞争实验。
