## 控制与调度

事实：旬行动先按军团轮转，再进入日期模拟。`0x50EC90`在无当前游标时建立军团列表并安排全局策略准备`0x4BDF90 → 0x4BE7E0`；已有游标的恢复路径不重做准备。排序键为`max(0,1000−信望)+(主军团?2000:0)+(直接玩家控制?4000:0)`，稳定降序，同键保持原列表顺序。一般玩家根先于电脑根，根先于普通子军团。

直接控制位决定交互或自动任务；根势力归属查询另行归一化，因此玩家子军团可以属于玩家势力而执行自动工作。自动任务先更新内部战略模式及人员配额，随后按工作表逐项运行。每个非空子任务结束后再继续，后项看到前项即时效果；行程和日期效果不提前结算。日期阶段的自动撤退／追击是玩家和电脑共用规则，不能移到电脑专属规划中。

研究码、公共命令类型、事件类型及交互工厂码是不同编号域；同号不证明同义。AI负责选择和构造公共命令，共享执行器负责成本、资格和写回。前述控制与队列证据身份为RE-0049/0072/0089/0123；这些公共运行时记录继续保存各自非AI事实。

### 当旬轮转列表的修改与恢复

**事实，AI-BOUNDARY-20261016-O。**`0x46AB10 → 0x46F200`复制的是有序引用列表；`0x46AAD0`取当前表头，`0x46AC10`弹出已结束的表头后继续。初始排序不意味着此后列表不可变化：公共军团管理执行器`0x487D20`的新设分支复制当前列表、把新军团追加到尾部，再经`0x46AB10`写回；解散分支则按引用移除待解散军团后写回，再合并／清理其记录。新设分支没有重新按信望插入或等待下一旬的步骤。

因此，**新建军团可以在同旬后续获得控制机会**，这是上述状态机和写回链的静态推论，尚未做原游戏专门对照。它仍须通过该军团的控制资格、准备和工作门，不表示必定出令。直接控制标记决定其交互／自动入口，根势力为玩家并不自动令子军团等待玩家操作。

人员配额的重算也有独立时点：`0x4A9A80`的直接调用只来自批前`0x4BDB40`；工作12新设／解散和工作22收集余缺不调用它。父军团在12之前算出的建筑配额不会因12执行而统一重算；新军团若轮到，则由自己的批前准备计算。后项查询最新归属、钱粮和人物，与读取仍保留的配额可以同时成立，不能概括为“每个工作前重算全部派生状态”。

`0x50EC90`对已有军团游标的恢复不重做全局准备／排序；其恢复标志还跳过普通进入军团时的单位`0x10000`清理。普通进入路径通过`0x473CC0 → 0x46F230`枚举有效单位并清该位；这里只确认位的生命周期，不补造其未闭合的中文业务名。若实际取出的当前军团无效，外层结束该行动阶段；没有通用的“自动重新排序并重试”分支。证据与限制见[边界核查账本](archive/ida-write-records/original-ai-boundary-20261016.json)。

## 工作批次、资格与失败消费

本节规定工作何时被尝试。表中有某工作只表示调度到它；实际命令仍须通过该工作的准备、候选和公共验证。末批 63 执行剩余工作。

<a id="re-0077-事实批次消费方式"></a>
### 批次状态机

- 阶段 `1001` 调用 `select_automatic_force_action_work_batch(0x4BDD00)`，传入递增的批次索引，并取得一个整数数组及长度。
- 阶段 `1002` 按数组顺序取工作码，通过虚槽 `+0x28` 调用 `create_automatic_force_action_subtask(0x4BD030)`；工厂返回非空子任务时入队并等待，返回空时继续扫描下一码。
- 当前批次耗尽且没有活动子任务后，阶段回到 `1001` 请求下一批；选择器返回零时阶段归零结束。
- 因而静态数组中的位置是实际尝试顺序，不只是允许集合；某个子任务是否产生最终命令，仍由该子任务自己的过滤和规划逻辑决定。

取证身份：RE-SAN9PK-0077。

<a id="re-0174-有界自动工作的尝试预算"></a>
### 难度、分组与尝试预算

**事实。** `0x4B02A0` 以元数据第2字节的上限M计算 `clamp(floor((k*M+1)/3),1,M)`：根记录元数据位8未置时，初级k=2、高级k=3；该位已置时，初级k=1、高级k=2。

例如M=3且该位未置：初级最多2次、高级最多3次；该位置位则是1次／2次。M=1两难度相同。这是规划尝试预算，不是命令成功率，也不能概括为所有AI行动次数提高50%。根元数据位8已找到全局策略分组写入者，具体分组语义见本页战略状态；它与难度的独立减量分别成立。本节替代[RE-0123](findings/RE-SAN9PK-0123.md)中“世界+0x24语义未确认”的旧结论。

取证身份：RE-SAN9PK-0174。

<a id="re-0124-委任军团的登用调动与外交权限"></a>
### 主军团与子军团的工作权限

每个自动工作码有 8 字节元数据。`is_automatic_work_permitted_for_force(0x4AF39C)` 读取第 4 字节：位0允许异民族归属（势力虚槽`+0x48 → 0x446920`检查归属势力），位1允许非主记录。码 22 和 24 的元数据均置位 1，所以普通子军团可自动调动、自动登用；正常子军团的首批和二级工作表均不含码 33–36，而主记录首批含这些外交码。该结论来自权限谓词与工作表的交集，不是从菜单标签反推。

公共门还有元数据之外的前置条件：`0x4AF380 → 0x50E990`检查当前军团引用有效，再拒绝该军团虚槽`+0x40`的直接玩家控制。前置调用`0x45DE60`在登记样本中只是恒返回1，不能将它解释为另一个模拟状态限制。`0x43F9F0`读取所传军团自身的控制标记，不归根；根级玩家归属由另一槽`+0x3C`查询。随后才检查日期与元数据权限。军团引用失效时`0x50E990`还清理任务关联引用并失败。军事准备中名为`Win95IsDebuggerPresent`的`0x4B7610`只是`0x47E4C0`资格包装，不读取操作系统调试状态；不能依此名称增加反调试规则。

策略敌对谓词`0x4B0670`按以下顺序执行，调用它的建筑包装为`0x4B0700`：

1. 来源／目标有效、不同根，且目标非异民族，否则拒绝。
2. 来源为联盟成员或盟主时，目标为联盟讨伐对象则**直接通过**；否则目标也为联盟成员／盟主则拒绝。

第二步的直接通过发生在请求配对和关系门之前，不能在现代公共查询中改为“先检查全部保护再放行”。它与普通接近选敌的`0x4453E0`不是同一契约；后者关系门为<2。此处只描述原作资格，不决定重制是否采用差异。

<a id="candidate-order-and-random"></a>
### 列表顺序、重复引用与随机消费

`0x46F430`先按输入列表顺序为每项计算一次键，再稳定插入排序；模式0降序、模式1升序，同键不交换。列表不足两项时直接成功，不调用评分回调。`0x46F330`按输入节点顺序过滤并追加，末参控制是否先清输出；`0x46EF80`只追加，不去重。交集`0x46F670`按第一张表顺序保留第二张表包含的项，不采用第二张表顺序，也不自动删除第一张表的重复引用。来源分配表、成员表与建筑邻接生成器是否去重须分别核对，不能用一个集合替代全部列表。

`select_random_list_value(0x46E900)`总会调用`rnd(列表长度)`，但随机入口调用次数与随机状态推进次数不同：[RE-SANCALC-0001](findings/RE-SANCALC-0001.md#rnd-与-kakuritsu)已用DLL代码及32位探针确认，`rnd(N)`在N<2时不推进全局流；`kakuritsu(p)`仍执行`rnd(100)`，p≤0或p≥100也会推进。因此单候选随机选择不应额外取一个随机数，确定失败／成功的概率调用也不能直接删掉。58不同兵法分支的短路顺序、特殊编队先随机再覆盖仍按对应正文维护。

### 路线与预计行军时间

<a id="re-0080-事实ai-确实求路预测但不逐日演算"></a>
#### 求路与时间换算

`0x468870 → 0x44A680 → 0x44A4C0` 是单位路线预计时间链，不只是界面显示。直接 AI 消费者包括 `0x49E420`、`0x49EAA0`、`0x49F160`、`0x4A2440`、`0x4A2FD0` 和 `0x4A3BB0`；组1选择器 `0x4A2CB0` 自己构造路径后直接调用 `0x44A4C0`。

`0x44A680` 构造粗格图并调用 `solve_square_path_graph(0x478290)` 一次，去掉起终格，以及目标是建筑时完全落在其占地内的尾部格，再统计剩余路线。普通类与 `terrain_family == 4` 类分别计数，预计时间为：

`ceil(10 * n0 / rate0) + ceil(10 * n1 / rate1)`

两移动率来自 `0x464740/0x4647D0` 选择的阵形机动力字段；选择器含特殊状态/阵形分支，不将它们概括成固定的两种速度。公式已逐指令核对 `0x44A4C0`。原先“慢地形”是该谓词的历史命名，不意味着这里简单把每格乘1.2。

这条预测链没有逐日调用 `compute_unit_daily_movement_step`、细步碰撞或前视路点推进。路径选择仍受粗图阻挡、对象软代价和连线偏好影响，详见 [RE-0136](findings/RE-SAN9PK-0136.md)；**选路代价与时间换算分开**，预测不把设施+50、单位+5/+40等搜索惩罚直接当作时间相加。因此是有路线依据的近似预计，不是保证实际抵达日的完整模拟。

#### 空路径、零速率与调用上下文

`0x478290`先清输出，求路失败不填路径；`0x44A680`忽略失败标志，剥除端点后交`0x44A4C0`。正机动力时空表返回0，所以同粗格、剥空的相邻路线和失败路线不能由此ETA区分。`0x44A4C0`两项除法均无零保护，不能编造“零速率返回无限”。机动力来自阵形`+0x5C`／源`jnki+0x10`；有效状态5～7用阵形27，常规慢地形用副船，失效船默认20、失效阵形默认10。登记20正式剧本的28项原始机动力逐项为8～26，均非0；这是原始数据核对，非仅以当前转换包证明。异常Mod／损坏输入的原作除零仍不转成产品要求。

### 下令、出征标志与电脑反应时机

- **事实：下令已创建，尚未进入每日阶段。** 普通出阵执行器`0x48BD20 → 0x485FA0 → 0x465450`立即创建部队、扣除来源兵力并写入目标。初始化通过部队虚表`0x606490 +0x14 → 0x4615E0`清零`+0x20`旗标；普通出阵路径没有置bit3。`0x461E40`写命令事件时设置的是其他旗标，不是bit3。
- **事实：玩家先规划，电脑后规划，然后推进日期。** `0x50EC90`按既有排序逐个等待交互／自动任务完成；正常直接控制主军团先于电脑主军团。`0x507DA0`等待整个军团行动阶段后才启动日期模拟，详见[RE-0123](findings/RE-SAN9PK-0123.md#命令生效时机复核2026-09-06)。

### 主将选定与死亡／读档重选

公共出征执行器对成员稳定排序后确定主将；阵位与主将资格分别处理。以下为登记样本的静态调用与指令证据，未作该组原游戏黑盒对照。

#### 普通出征

`execute_unit_deployment_command(0x48BD20)`先按输入成员对应关系写入各人的兵法与阵位，随后在`0x48BDC6`调用`0x46F610`，比较器为`0x471CA0→0x44DBE0`，模式0。`0x46F430`确认这是降序稳定排序，相等键不交换。然后`0x485FA0→0x465450`接入排序后的成员；`0x463270→0x4631E0`维护身份特殊成员及归属，`0x460A40`清除成员负责人标记并给最终链表首成员置位。因此“排序后首位”不能换成“用户输入首位”，阵位也不等于主将资格。

`0x44DBE0`在正常源数据范围内依次比较：

**目标需求和重复来源项。**`0x4B91C0`对有占用目标取`trunc(现兵×(1000−max(0,200−当前耐久))/1000)`；未占领目标取关联非己方建筑平均驻兵的40%，空建筑取60%，平均先做整数除法、空集合为0。这里使用建筑关联表`0x4AF920`，不是任意几何半径敌军，也不是按最大耐久折算。它和前述防御估值分别服务于分配与选目标。

9和59的分配器不是每个来源只看一次：每轮按**模拟剩兵**重新降序取首，成功后保留该来源在候选表中，增加它的模拟次数；只有容量／兵量不合格才移除，因此输出可含同一建筑的多个引用。容量辅助器`0x4B7B40`收集来源可行动人物，按公共主将键降序取该来源第k名人物的容量，且要求`k<可行动人数−1`，在模拟阶段至少留一人。保留量的缺省缓存由`0x4B7810`取指向该建筑的合格事件38部队现兵总和的三分之二。累计分配必须**严格超过**两倍需求才提前停止；恰好相等会继续。公共计划最多复制前五项（9）／前两项（59），不是保证不同建筑数或最终实际队数。正式生产时还会重新选人、算留兵和容量，不能将模拟分配量冒充最终部队兵量。

`build_automatic_attack_source_plan(0x4B4CD0)`清空旧参与者，经`0x4B3960`按公共都督／主将键稳定降序取首人为主将；余下只检查前`floor(n/2)`人，经`0x473190 → 0x4B3FD0`逐人P(max(0,100−与主将相性距离))加入，全部参与者最多五人。**该函数间接消费随机，不能写成确定性选人**，也不同于59补员的P(武力+统率)。兵力为可派额度与主将容量的较小值。

**最低兵力分阶段核对。**来源分配`0x4B4A20/0x4B9320`确实要求城市≥10000、非城市≥5000；但最终计划器`0x4B4CD0`在主将容量截小后使用`!城市 || 兵≥10000 || 城市 || 兵≥5000`，两次城市判断间无相关变化，因此该最终门恒通过。`0x4B4E50..0x4B4E84`与完整函数原始字节已核对一致；59也有同类冗余。不能把分配门自动当作最终派兵下限，或依据旧IDA“deterministic”注释省掉补员随机。

**动态证据边界。**[E／F／G实验](#experiment-r06)分别以受控容量验证9城市9999、9非城市4999和59城市9999均可实际出阵。正常官职／爵位容量数据不提供该低容量输入，尚无自然触发路径证明；59非城市和成对重复未实测。完整输入、数据域核对与干预记录集中在附录。

#### 关系与概率门

1. `select_probabilistic_adjacent_attack_target(0x4B39A0)` 先枚举相邻建筑并做类型、状态和兵力过滤。未占建筑不进入此分支；城市类阈值为`floor(max(0,89−势力关系值)^2/100)`，其他建筑要求至少50000兵、概率40%。V沿目标虚槽`+0x30`取得所属势力，再调用`get_force_relation_value`，已闭合为关系值；通过者按当前驻兵降序取首。
2. `passes_automatic_attack_strength_gate(0x4B57F0)` 汇总来源兵力 `S`，再扣除目标相关建筑的防守要求：城市基础项为 10000，相邻部队兵力和按 `2/3` 计入，特定势力模式还与关联建筑最大兵力的一半取大。令可派余量U=来源驻兵S−逐来源保留总量，目标强度D由`0x4B54F0`取目标驻兵，加仍未置出发mask8、非守军／非失效且服务建筑为目标的单位兵力；其单位字段`+0x24`须非0。按下表**前项优先**比较，全部使用严格U大于取整阈值：

   | 条件 | 通过门／后续 |
   | --- | --- |
   | 己方联盟成员／盟主，且攻击本联盟目标 | `U>floor(75D/100)`；未过直接失败，无后备随机 |
   | 君主列传3 | `U>D`；未过直接失败 |
   | 己方根元数据bit7 | `U>floor(150D/100)`；未过直接失败 |
   | 其余 | `U>floor(125D/100)`；未过且根bit8为真、S≥70000才执行P(君主野心+5) |

   最后后备门的`get_root_force_metadata_bit_w(0x4AF5F0)`读**bit8**，与上一分支`0x4AF5A0`读bit7不同，不能因旧辅助函数名相似而误判成被return遮蔽。建设优先形状的33%门同样读取bit8。
3. `try_select_alternate_attack_target(0x4B46F0)` 仅在持久路径项数 `N > 2`、起点和中间节点类型满足要求、相关部队/建筑过滤均为空，且下一建筑兵力大于起点兵力一半时调用 `kakuritsu(25*N, RANDOM_KIND_GLOBAL_STREAM, 1)`。成功后把替代目标写为路径中的区域城市建筑。

`RE-SANCALC-0001` 已确认 `kakuritsu(P)` 严格执行 `rnd(100) < P`，不对阈值夹到 0–100。因此第三处在 `N=3` 时是阈值 75；`N>=4` 时阈值至少 100，必定通过。这里不能把“有随机调用”一律解释为永远具有不确定结果。

<a id="siege-formation-selection"></a>
#### 路径障碍与耐久驱动的攻城阵形

**取证AI-FORMATION-20261016-L。**主库已有相关链的解释性标注，本次独立沿工厂、路径生产者和选阵函数回读，再核对关键分支指令与登记EXE字节；六段相关函数共4577字节逐段一致。实际普通分支先按选中人物兵法建立陆阵可用表，再按预算筛选；从可负担候选中检查象兵11、冲车9、发石10等。`0x4B9DA0`先选陆阵，再扣其费用选船阵；异民族及操作10／51另走分支，不概括为所有出征共用。

- **路径障碍分支。**自动攻击的`0x4B50B0`和请求履约的`0x4A09C0`逐格扫描所求路径，遇有效建筑且归并类别7～10时，通过`0x4B7790`按来源建筑记录路径bit1；它与地形族4产生的bit0不同。`0x4B85B0`读bit1为真时，直接进入**象兵→冲车→发石**的可用优先链，不要求先通过耐久概率。冲车必须可用且可负担，并且没有优先的象兵；不是“任意障碍必选冲车”。路径另有敌对建筑阻断资格，仍可能在选阵前淘汰来源。
- **耐久概率分支。**bit1未置位时，若已有符合`0x4B0770`的同目标部队，且其当前陆阵为象兵或冲车，对每个符合项读取目标当前耐久D，执行`P(trunc((500-D)/5))`，最后一次符合项写入的结果决定是否进入上述优先链。当前耐久由目标虚槽`+0x50 → 0x435630`读取，不是最大耐久或耐久百分比。D=500时阈值0、D=300时40、D=100时80，故此分支是耐久越低越容易通过，不能写成“城墙越厚越倾向冲车”。多项结果覆盖，不按任一成功累加。
- **资格与边界。**`0x4B0770`要求有效部队、已出发位、非排除状态、当前事件38、有效建筑／城市目标且与参数目标同一对象；该谓词没有另加同势力或距离限制，不擅称“己方附近攻城队”。没有路径bit1时，地形bit0且目标为港还存在先选长蛇的分支；未通过特殊门则继续后续兵法和后备选阵，不能由特殊链失败推断完全不会选择冲车。完整通用选阵其余分支须沿实际选择器承接，不再用`0x4B38C0`代替。

该分支尚无原游戏动态对照。实际回读、字节摘要和两条主库补注释见[选阵核查账本](archive/ida-write-records/original-ai-siege-selection-20261016.json)。

#### 通用选阵的其他分支

**候选与费用过滤。**`0x4B85B0`的陆阵候选为人物已知兵法支持的0～11，船阵为20～23；所需兵法无有效引用的阵形直接可用。费用表按闭区间`0≤费用≤剩余预算`过滤。陆阵的特殊／兵法判断用费用过滤表，最后通用后备却使用原始可用陆阵表；不能把“预算筛选存在”外推为所有返回分支均只取可负担阵形。

除前述攻城优先链，路径bit1为假、地形bit0为真且目标固定类别为港时，陆阵直接取长蛇6；船阵则在同样的地形／港上下文中按楼船23→斗舰22→艨艟21的可用优先级选择，否则取走舸20。这两个默认返回不通过“在费用过滤表中存在”的同一显式检查，必须与后续公共命令验证分开记录。

未选特殊阵时，按**本计划实际已配置兵法**的类别2（弓骑）／3（弩兵）计数选择：有弓骑且无弩兵时优先井阑8→发石10→锥形2；有弩兵时优先井阑8→发石10→箕形5；均无或优先项都不可用时，按对守兵效果稳定降序取原始可用表首项。这里不是统计人物“会不会”某类兵法，计数器`0x48BB60`遍历五个已配置兵法槽。函数没有给普通陆阵分支另加抽签；耐久概率属于前述独立分支。

`0x4B9DA0`依当前武力降序安排人物阵位，起始阵位索引为`clamp(floor(max(0,85-最高当前武力)/20),0,5-参与人数)`，依次写入阵形对应位置。因此主将的公共选择与阵位上的首名人物不是同一排序。异民族由所属根国号对应陆阵15～19、水阵26；操作10建设取13／24，操作51输送取14／25，不能泛化到普通攻城选阵。另一套`0x4B96C0`按主将熟练度偏好与费用表求交再回退，并调用任务虚槽`+0x38`；9／59的对守兵排序辅助器位于这个协议位置，不能据虚表有此槽断言实际工厂主分支调用了它。

#### 自动部队的四项出征许可

#### 逐人兵法选择

##### 两套累计量与实际优先级

事实：`0x49F450`把B现役兵力记为G，把P现役兵力总和记为S，把上文公式阈值记为T。第一组累计量初始为G；中间组累计量初始为G加“有效建筑目标为B、原始状态1、低两位标志清零且t<10的部队数量”。后一项确实是数量而非兵力：`0x46F280`返回列表长度，`0x49F5A2..0x49F5B1`直接相加写入，未调用求和器。这是机器事实，是否属于原作缺陷未做黑盒裁决。

普通军团每次构造一条命令，依次尝试：

1. 中间组：累计量严格小于T时选首队，累计增加该队`现役兵力+floor(伤兵/2)`；已达到T时清空剩余中间组。
2. 第三组：选首队，不检查兵力预算，也不增加上述任一累计量。
3. 第一组：累计量严格小于`floor(S/2)`时选首队，累计增加同样的现役加半数伤兵；已达到半数时清空剩余第一组。

事实：异民族虚槽`+0x48`成立时，准备阶段走独立`0x49F000`筛选器填中间容器，命令阶段直接取该容器；不能把“异民族也取中间组”解释为它采用普通军团的附近补防条件。2026-10-17为OAI-03沿`0x49F000/0x49EF30/0x4643F0/0x49EC70`补读：先取当前直接军团的共同状态1、非内嵌／人员候选，仅保留事件38。有效建筑目标仍先当前后主目标；有建筑目标时，归根玩家、非城市或驻兵≥10000均排除。没有有效建筑目标时，若主目标解析的部队／内嵌守军仍有效且现兵>0，也排除；其余追加，保持枚举顺序，不使用普通三组的时间门和累计预算。这里只补静态分支，没有新增原游戏动态实验；实际主库注释与回读见[RE-0085](findings/RE-SAN9PK-0085.md)。

### 35：俘虏返还

### 每日执行顺序与调用入口

撤退与追击的 850 项全表扫描不是孤立代码，也不是逐旬入口。旧 IDB 把 `0x50A168..0x50A23F` 错定义成单个数据项，遮蔽了 `process_simulation_stage_task_state(0x50A170)`。恢复代码后可见两个普通相对调用：

- 状态 1001：`0x50A1A6 -> process_unit_autonomous_retreat_updates(0x453B20)`；
- 状态 1002：`0x50A1B2 -> process_unit_pursuit_updates(0x453B50)`；
- 状态 1003/1004：建立并消费后续部队任务。

`vftable_simulation_stage_task(0x610AC4)` 的 `+0x0C` 槽直接保存 `0x50A170`。外层 `process_simulation_state_machine(0x50A760)` 在阶段 1001/1002 创建 `simulation_stage_task`；该任务完成后，外层阶段 1005 调用 `advance_date_and_run_daily_updates(0x50A340)` 将日期推进一天。若新日期不是旬首，外层状态回到 1001，创建下一日的同类任务。因此两次扫描在每个模拟日各执行一次，顺序固定为先撤退、后追击。

### 外交敌对、明确攻击与被攻击反击

**事实，静态调用与连续指令核对：**公共势力敌对谓词 `0x4453E0` 先拒绝无效/同根势力，再排除双方同属联盟成员或盟主、存在攻击请求配对，最后要求关系档小于2，即关系0..39。关系40..100（包括中立）不会单凭接近成为普通外交敌人。`0x445460` 为单位包装，`0x445490` 为建筑包装；这些入口被主库其他函数范围覆盖，不能直接采信对该地址返回的无关大型反编译，故本轮以真实入口连续指令及调用目的地址确认。

野战接近响应 `0x464910` 经回调 `0x474C00` 检查活动/接近条件，经 `0x474500` 排除同势力，再经 `0x474C50` 筛选候选。后者既允许公共敌对谓词 `0x45E180 → 0x45E100 → 0x445460` 成立，也允许候选与自身意图目标或当前目标同属一个根势力。因此“关系40以上或同盟”仅阻止普通自动选敌，不能推翻已有明确攻击命令。响应还受当前命令/状态、接近策略、主将性格、总战力评估比、已有目标等限制；外交敌对不是保证当日自动攻击的充分条件。

普通设施的每日自动目标由 `0x50B1B0 → 0x438750 → 0x474370` 产生，需要有守兵、有效活动单位、`0x435810 → 0x4357C0 → 0x445490 → 0x4453E0` 的敌对资格及设施射程。工作物运行时类型7..10有单独放行分支，不把它们和普通城池/据点混为一谈。故仍同盟时，即使野战交战令关系降至39，附近普通设施也不会仅据低关系自动选中盟友部队。

**反击是另一条规则。**`0x49B460` 状态1005计算被攻击方反击伤害时只通过 `0x465970` 检查反向射程，并在原始状态6（混乱）或7（溃败）时将反击兵损置零。`0x465970 → 0x465860` 的野战分支要求有效目标、反击方兵力为正、相应有效标志及射程；设施分支经 `0x465940` 转附属单位，公共设施射程见 `0x438690`。此处不读取关系档位、联盟或攻击请求身份，也不要求B预先有攻击A的命令。

因此A明确攻击原盟友/友好势力B的部队，B仍可在同一普通攻击结算中还手；超出B射程、B无兵或混乱/溃败等情况不会造成普通反击兵损。高关系但无联盟/请求的双方，交战关系降到39后，还会获得普通自动选敌的外交资格；仍同盟时该资格继续受联盟门阻止，但直接反击与既有明确目标不因此消失。上述为静态规则，不承诺每个兵法/特殊情境均等同普通反击。

取证身份：RE-SAN9PK-0119。

<a id="re-0090-自动撤退没有概率或冷却"></a>
#### 无随机、无冷却与次日重试

`handle_unit_autonomous_retreat_response(0x464E00)`及其每日扫描链不消耗随机。

条件不成立时，处理器不写入“上次判断日”、倒计时或其它冷却状态；下一模拟日会再次扫描同一活动部队。条件成立但 `try_set_unit_return_event(0x4642B0)` 转换失败时，同样没有冷却写回，因此只要部队仍满足入口条件，后续日期仍会重试。成功后则以事件类型和状态位排除重复处理，这属于状态转换，不是时间冷却。

<a id="re-0090-返回事件的精确转换"></a>
#### 返回事件转换的前提与写回

`try_set_unit_return_event(0x4642B0)` 的机器边界是：

1. 当前命令/事件类型必须在闭区间 `38..52`；`-1` 或区间外类型直接返回 0；
2. 部队 `+0x64` 的关联返回对象必须有效；
3. `clear_unit_command(0x462670)` 将当前命令清为 `-1`；
4. `unit_return_event_ctor(0x46BF20)` 构造内部类型 `52`、目标为返回对象的事件；
5. `set_unit_command_event(0x461E40)` 写入事件，随后设置部队标志 `0x40000` 并清理辅助状态。

因此调试中看到的 `-1` 可以只是空命令或清理过程的哨兵；它本身不表示撤退概率失败。如果在调用 `0x4642B0` 前已经是 `-1`，本次转换确定性失败且没有返回状态写回。

这里的内部事件类型 52 与 `RE-SAN9PK-0089` 的交互工厂 code 52 不属于同一编号空间：交互 code 52 最终仍可构造命令类型 39，而本函数明确写入事件记录类型 52。

<a id="re-0150-自动撤退三组优先级改变但与异民族击破撤退无关"></a>
#### 旬级撤回优先级的版本差异

繁中自动撤退命令对普通势力按“中间组达到阈值前 → 第三组 → 第一组达到半阈值前”取部队。日版 `0x4A6270` 改为先取第三组并累计其成本，再尝试中间组，最后才取第一组；准备函数 `0x4A6A80` 仍建立相同三组和目标阈值。势力虚槽 `+0x48` 已由繁中主库独立闭合为异民族标志，而两版的异民族分支都直接取中间组，故普通势力三组排序差分与“异民族消灭敌部队后撤退”无关。三组的正式业务名仍未闭合，不据此设计新的重制规则。

2026-09-23补充：繁中三组完整条件、两套不同目标量及行军时间语义已在[RE-0085](findings/RE-SAN9PK-0085.md)补证。上文“半阈值”具体指有效目标指向该据点的类型38部队现役总兵力的一半，并非中间组补防阈值的一半；异民族虽然使用中间容器，但采用独立候选筛选器。

**修正意图推断，仅供参考：**结合繁中分组条件，日版可能希望先召回远离本据点、未交战且主目标仍为有效野外部队的第三组，再将已决定回撤的兵力纳入后续需求判断，减少额外召回附近部队补防。这是由候选用途和选择顺序差分推导的解释，不是官方明确说明，也不是已验证的日版运行时效果。第三组累计量具体写入哪个字段、怎样影响后续各组预算，仍需日版定向复核；不能据此宣称日版已经消除重复召回。

本节只记录日版差异，不自动改变本页繁中基线或新规格的采用行为。
