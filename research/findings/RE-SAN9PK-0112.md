## 对象、状态、输入、输出与不变量

### 2026-09-06 默认忠诚50的适用范围

事实：`0x44E740` 在人物 `+0xB6` 的50字节表填入50（指令中为重复写入 `0x32323232` 及剩余字节），随后对有效当前势力槽写 `80+rnd(21)`。其直接调用者 `0x453220` 遍历0–699的有效人物；新局确认 `0x45C120` 只在 `scenario_world_state.n8==1` 时调用它。这里已证明特定随机化初始化的生产者—存储—当前势力覆盖链，不把内部模式值直接推广到所有新局。

普通 `prsn` 加载由 `0x44F830` 直接复制50字节；RE-0009 的20剧本剖面既包含大量50，也包含0、110、120、150和255。因此撤销“没有找到50写入”的旧结论，同时否定“所有人物对所有势力都必须初始化为50”的泛化。既有原作默认内容值、随机化初始化和登用成功忠诚重置是三条不同来源。

本轮对 `0x44E740/0x453220` 写入带本记录编号的事实注释，保存后回读并强制反编译成功，详见[疑点复核写入清单](../analysis/ida-write-records/research-questions-audit-2026-09-06.json)。

对象是交互 code 13/15/16/19/21/22、对应即时命令、势力、人物、宝物、军师引用、人物所属对象和按势力忠诚表。输入包括候选人物、目标对象、势力资金、人物义理、当前忠诚、宝物忠诚增量、身份和人物临时标志；输出包括身份、军师引用、资金、宝物持有者、忠诚、位置/所属对象及行动占用。

不变量：交互行动与命令必须按相同类型汇合；执行前必须复验对象有效性和人物占用；`0x1000` 是公共命令参与占用，`0x4000` 是本旬已褒美标志，两者不能合并；军师任命不等于一般官职任免；宝物转移与忠诚增量是两个连续写回；召回和移动必须经过公共参与者准备/释放路径。

### 军师任命与一般官职边界

事实（2026-09-06 复核）：`execute_appoint_strategist_command@0x4872B0` 取得现任军师；若有效，比较双方人物 `+0x58` 的当前有效智力。`0x4872F6` 的比较与 `0x487302` 的有符号 `jge` 共同确认：旧智力大于或等于新智力时，`0x487310` 调用 `rnd(3, RANDOM_KIND_GLOBAL_STREAM, 1)`，随后 `0x48731C` 以旧军师为接收对象、任命势力为目标势力调用 `adjust_person_loyalty_for_force@0x44DDB0`。没有旧军师或新智力严格更高时跳过这次抽样和扣减。当前有效能力层次见 [RE-SAN9PK-0067](RE-SAN9PK-0067.md)，并非基础智力或执行能力。

事实：扣减链为 `0x44DDB0 → 0x43ECE0`（解析根势力编号）及 `0x44CA60 → get_person_force_loyalty@0x44C9D0 → limsub → set_person_force_loyalty@0x44C9F0`；最终写回旧人物 `+0xB6[forceId]`。反汇编核对了旧人物接收指针和参数传递，避免由辅助函数不完整的反编译签名误判对象。[RE-SANCALC-0001](RE-SANCALC-0001.md) 已确认 `rnd(3,11,1)` 推进一次全局流并返回 `0..2`，`limsub` 下限为 0；故结果是 `max(0, oldLoyalty - draw)`。这是实际忠诚扣减，不是仅有表现变化；抽到 0 或旧忠诚已为 0 时仍消费该次随机。

事实：之后 `0x487327/0x487333` 把现任身份 2 改为 3、选定人物身份 3 改为 2，`0x48733E` 更新势力 `+0xC0` 军师引用。身份辅助函数 `0x44D540` 只处理身份和旧军师引用；引用写入器 `0x43E5B0` 不写忠诚。表现门位于这些状态写回之后的 `0x487347`，不会决定是否扣忠诚。`validate_appoint_strategist_command@0x487280` 要求新人物通常在职身份 3、当前有效智力至少 70。

本执行器不写一般人物官职 ID、官职记录或俸禄，但通过明确的辅助调用写忠诚。旧版“不写忠诚”结论遗漏了 `0x44DDB0` 的减法链，现予撤回。官职记录的 `salary` 及其 `salary/2` 忠诚影响仍以 `RE-SAN9PK-0011` 为准；军师替换扣减不属于该官职俸禄规则。

### 褒美、宝物与两个临时标志

code 15 命令要求列表非空、每人有效、当前所属势力忠诚小于 100、未置 `person_flags & 0x4000`，且势力资金至少为 `100 × 人数`。令人物义理为 `G`、当前忠诚为 `L`，单人增量为：

```text
base = min(trunc0(50 * (20-G) / 100), 10)
gain = min(base, max(0, 100-L))
```

执行按稳定列表逐人调用公共忠诚反馈路径，扣 100 资金并置 `0x4000`。`update_persons_for_xun` 每旬对全人物清除此位。因此 `0x4000` 的精确语义是“本旬已褒美”，不是一般已行动。

code 16 同时保存人物和宝物。执行先把宝物从旧持有者移交给目标人物，再以宝物记录 `+0x40` 作为正增量进入公共忠诚反馈路径。宝物特例资源码 79 还会设置一个势力事件/标志；该特例不改变一般持有者和忠诚写回顺序。

需要行动占用的普通命令参与者由公共准备路径置 `0x1000`，并在旬后公共清理中释放。`0x1000` 与 `0x4000` 的生产者、消费者和清理入口均不同。

### 放逐的身份分支

code 19 对列表逐人处理：

- 身份 4（俘虏）：先把其对当前扣押势力的忠诚增加 `trunc0(义理/5)`，再释放或重新安置；
- 非身份 4：先把其对执行放逐势力的忠诚直接写为 45，再脱离当前势力/所属对象，并执行关联势力和对象清账。

所以“叛离后忠诚 45”不是所有放逐对象的通式；它只对应本命令的非俘虏分支。俘虏放逐使用义理增量，且不是把忠诚重置为 45。

放逐执行链及其人物脱离辅助函数没有调用宝物持有者转移函数。人物脱离会移除其当前所属对象成员关系、重置身份/位置相关状态，但不能据此推导“宝物必被没收”。当前样本静态证据不支持“放逐时自动没收”的概括；电子书关于主动没收的记载不能作为放逐自动没收的证据。

### 召回、移动、位置与行动占用

召回命令复制公共参与人物列表，按人物当前关联对象排序和分组；每个原对象形成一组事件记录，再统一调往目的对象。因此它是“多来源、单目的地”的分组调动，不是一次裸指针覆盖。

移动命令同样先准备参与者、创建事件记录，再进入共享调动路径。若来源势力与目的势力不同且首要人物身份为 0，则走君主/势力专用迁移，并重挂相关部队；其他情况进入普通对象调动。两条命令均复验人物有效性、目的对象和 `0x1000` 占用，并在执行后走公共完成/释放链。

### 俘虏忠诚旬周期

事实（2026-09-06 再核对）：`update_persons_for_xun@0x4806E0` 每旬遍历人物，身份 4 才进入此分支。`sub_44C020@0x44C020` 由人物 `+0xEC` 保存的原军团取得其君主；有效时取双方相性环距 `d`，否则 `d=50`。`0x480791` 调用 SanCalc 的 `sqr`，其已确认契约为整数平方根而非平方（见 RE-SANCALC-0001），随后调用：

```text
kakuritsu(15*floor(sqrt(d)) + 10, RANDOM_KIND_GLOBAL_STREAM, 1)
```

命中后 `0x4807B3 → 0x44DE60 → 0x44DDB0 → 0x44CA60 → limsub`，实际为忠诚减 1、下限 0。旧名称 `increase_person_loyalty_for_current_force` 与旧“增加忠诚”结论错误，现更名为 `decrease_person_loyalty_for_current_force`。

被扣对象的归属由人物虚表 `+0x30` 解析：基础人物虚表 `0x606110` 的该槽 `0x606140` 指向 `0x44DE80`，另两份人物派生虚表同槽也指向此函数。身份 4 时它走 `0x44BFF0`，由保存的 `person+0xEC` 原军团解析原根势力；不会使用关押设施的势力。`capture_person@0x450710` 在变更关押位置前保存旧军团到 `+0xEC`，与此读取链互证。因此减的是对原势力忠诚，不是对扣押势力忠诚。

相性距离 0/1/3/4/35/36/49/50 对应阈值 10/25/25/40/85/100/115/115。阈值不钳制，距离至少 36 必过；距离 0 仍有阈值 10。此处没有义理门，也不要求执行过登用命令。若原势力失效，概率门仍执行，但后续忠诚写回被有效性检查拒绝。旧版平方、`d>=3` 必过与 `+1` 三项结论全部撤回。

该周期与 RE-SAN9PK-0111 的登用失败链是独立机制：后者对身份 4 跳过关系下降和在职人物减法，仅保留可能的招募势力忠诚增加；不能用监禁旬扣减解释为失败命令直接扣原势力忠诚。当前样本身份、工具与验证环境同本记录 2026-09-06 军师复核；本次为调用链、虚表、生产者与反汇编核验，未运行游戏内监禁实验。

## 2026-09-06 独立没收命令的旧待办纠正

事实：RE-0121已登记code17，RE-0006/0141已登记忠诚惩罚。本轮重新反编译`0x486B40/0x486BA0/0x486C00/0x4BF180/0x485E80`，确认构造器使用17；执行器先保存原持有者，将宝物交给所选命令对象对应的君主，再对原持有者扣除宝物忠诚增量的3/2（整数截断）。身份相关分支分别调用带反馈或直接忠诚调整路径；宝物ID79另触发势力信望重算。它是主动没收命令，与放逐code19不同。

撤销“没收功能缺乏机器支持、需要用户证明菜单存在”的待办。真正尚需完善的是独立命令进入产品规格时的候选资格、身份边界、执行复验和宝物79特例验收；这些可由开发者沿已找到的链继续补证，不要求用户现在做存在性实验。放逐自动没收仍没有上述链的支持，两者不得混为一谈。本次只读核对，未写入IDA语义标注。

## 2026-09-06 没收候选、复验与特殊物品闭合
