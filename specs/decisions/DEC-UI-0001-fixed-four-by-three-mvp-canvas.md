# DEC-UI-0001：MVP 采用固定 4:3 逻辑画布

- 状态：已确认
- 日期：2026-08-22
- 决策者：项目所有者
- 关联行为：待建立
- 替代或被替代：无

## 背景

原作的逻辑画面为 1024×768。项目工程基线曾以 1280×720 初始化 Godot 视口，但没有形成正式的 16:9 产品决策。MVP 需要优先完成可玩的界面闭环，固定设计尺寸可以降低布局、绘制和回归验证的复杂度；地图同时需要保留独立缩放及未来适配动态长宽比的能力。

## 决策

MVP 的 UI 采用 1024×768 逻辑画布。实际窗口可以改变大小或进入全屏，完整画布始终等比缩放并居中；长宽比不一致的区域留黑，不拉伸也不裁切内容。逻辑尺寸不限制高 DPI 屏幕的实际输出分辨率。

地图世界、地图相机和 UI 分层组织。地图缩放只改变地图相机视野，UI 位于独立画布层，不随地图相机变化。窗口输入先映射到 1024×768 逻辑画布，再经地图画布变换映射到世界坐标；黑边输入不属于游戏画布。

后续动态长宽比需要单独决策和验收：届时通过约束式 UI 布局和扩大地图相机可见区域适配宽屏，不改变地图世界坐标或资产比例。

## 备选方案

- MVP 直接采用动态长宽比：能更早提供宽屏体验，但会同时扩大 UI 设计、交互和视觉回归范围。
- UI 保持 4:3、地图立即延伸到宽屏两侧：能利用额外空间，但会让 MVP 提前承担两套坐标与构图边界。
- 窗口只允许 4:3：实现简单，但不必要地限制窗口化和全屏体验。

## 影响

- 玩家可见影响：宽屏显示器上出现对称黑边，游戏内容保持完整比例。
- 数据/存档影响：无。
- 测试影响：需要覆盖常见窗口比例、黑边命中、逻辑坐标往返及地图相机与 UI 隔离。
- 风险与代价：未来开放动态长宽比时需要重新设计部分 UI 布局，不能依赖散落的固定像素常量。
- 回退方式：以新的 UI 决策替代本决策，并调整逻辑画布和布局策略。

## 验收条件

- [x] 1024×768、1280×720、1920×1080 及纵向剩余空间场景的缩放和居中规则可由自动测试唯一判断。
- [x] 地图世界、地图相机和 UI 使用独立场景层级。
- [x] 地图相机缩放不改变 UI 层的尺寸与位置。
- [x] 重制行为没有被表述为原作事实。
