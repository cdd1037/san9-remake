## 对象、状态、输入、输出与不变量

对象是交互 code 13/15/16/19/21/22、对应即时命令、势力、人物、宝物、军师引用、人物所属对象和按势力忠诚表。输入包括候选人物、目标对象、势力资金、人物义理、当前忠诚、宝物忠诚增量、身份和人物临时标志；输出包括身份、军师引用、资金、宝物持有者、忠诚、位置/所属对象及行动占用。

不变量：交互行动与命令必须按相同类型汇合；执行前必须复验对象有效性和人物占用；`0x1000` 是公共命令参与占用，`0x4000` 是本旬已褒美标志，两者不能合并；军师任命不等于一般官职任免；宝物转移与忠诚增量是两个连续写回；召回和移动必须经过公共参与者准备/释放路径。

## 已确认事实

### 六类交互命令映射

RTTI、虚表创建槽、命令类型和执行槽共同确认：

| code | RTTI | 领域动作 | 命令执行结果 |
| --- | --- | --- | --- |
| 13 | `COrderGunshiDlg` | 任命军师 | 替换身份 2 人物与势力军师引用 |
| 15 | `COrderHoubiDlg` | 褒美 | 每人扣 100 资金、增加忠诚、置本旬已褒美位 |
| 16 | `COrderJuyoDlg` | 授予宝物 | 转移宝物持有者并按宝物记录增加忠诚 |
| 19 | `COrderTsuihouDlg` | 放逐 | 按身份写忠诚后脱离/释放并清账所属对象 |
| 21 | `COrderYobiyoseDlg` | 召回 | 按原所属对象分组，向同一目的对象调动 |
| 22 | `COrderIdouDlg` | 移动 | 向目的对象调动；君主跨势力时走专用迁移分支 |

这些交互虚表均以 `+0x20` 复验、`+0x24` 消息映射、`+0x28` 创建命令；相邻 `+0x30` 已是下一个虚表，不属于同一行动。命令虚表的 `+0x20` 为复验、`+0x30` 为执行。

### 军师任命与一般官职边界

`execute_appoint_strategist_command` 取得现任军师；若有效，先比较现任与新任的当前智力并处理表现/关系分支，再把现任身份 2 改为 3。选定人物从身份 3 改为 2，势力 `+0xC0` 写为新军师。候选要求新人物当前智力至少 70。

本执行器不写人物官职 ID、官职记录、俸禄或忠诚。故 code 13 是军师身份/势力引用替换，不是一般官职任免。官职记录的 `salary` 及其 `salary/2` 忠诚影响仍以 `RE-SAN9PK-0011` 为准；不能把该派生值误写成命令即时忠诚变化。一般官职分配属于另一套治理链，不强行并入本命令族。

### 褒美、宝物与两个临时标志

code 15 命令要求列表非空、每人有效、当前所属势力忠诚小于 100、未置 `person_flags & 0x4000`，且势力资金至少为 `100 × 人数`。令人物义理为 `G`、当前忠诚为 `L`，单人增量为：

```text
base = min(trunc0(50 * (20-G) / 100), 10)
gain = min(base, max(0, 100-L))
```

执行按稳定列表逐人调用公共忠诚反馈路径，扣 100 资金并置 `0x4000`。`update_persons_for_xun` 每旬对全人物清除此位。因此 `0x4000` 的精确语义是“本旬已褒美”，不是一般已行动。

code 16 同时保存人物和宝物。执行先把宝物从旧持有者移交给目标人物，再以宝物记录 `+0x40` 作为正增量进入公共忠诚反馈路径。宝物特例资源码 79 还会设置一个势力事件/标志；该特例不改变一般持有者和忠诚写回顺序。

需要行动占用的普通命令参与者由公共准备路径置 `0x1000`，并在旬后公共清理中释放。`0x1000` 与 `0x4000` 的生产者、消费者和清理入口均不同。

### 放逐的身份分支

code 19 对列表逐人处理：

- 身份 4（俘虏）：先把其对当前扣押势力的忠诚增加 `trunc0(义理/5)`，再释放或重新安置；
- 非身份 4：先把其对执行放逐势力的忠诚直接写为 45，再脱离当前势力/所属对象，并执行关联势力和对象清账。

所以“叛离后忠诚 45”不是所有放逐对象的通式；它只对应本命令的非俘虏分支。俘虏放逐使用义理增量，且不是把忠诚重置为 45。

放逐执行链及其人物脱离辅助函数没有调用宝物持有者转移函数。人物脱离会移除其当前所属对象成员关系、重置身份/位置相关状态，但不能据此推导“宝物必被没收”。当前样本静态证据不支持把电子书的“放逐时没收宝物”写成已确认规则。

### 召回、移动、位置与行动占用

召回命令复制公共参与人物列表，按人物当前关联对象排序和分组；每个原对象形成一组事件记录，再统一调往目的对象。因此它是“多来源、单目的地”的分组调动，不是一次裸指针覆盖。

移动命令同样先准备参与者、创建事件记录，再进入共享调动路径。若来源势力与目的势力不同且首要人物身份为 0，则走君主/势力专用迁移，并重挂相关部队；其他情况进入普通对象调动。两条命令均复验人物有效性、目的对象和 `0x1000` 占用，并在执行后走公共完成/释放链。

### 俘虏忠诚旬周期

`update_persons_for_xun` 每旬遍历人物。身份 4 的人物取得一个关联人物；若有效，令相性环距为 `d`，否则令 `d=50`。随后调用：

```text
kakuritsu(15*d*d + 10, RANDOM_KIND_GLOBAL_STREAM, 1)
```

`kakuritsu(P)` 的已确认契约是严格比较 `rnd(100) < P`，不夹取阈值。所以 `d=0/1/2` 时阈值分别为 10/25/70，`d>=3` 或没有有效关联人物时必定通过；成功只把人物对当前势力的忠诚增加 1。该机制是每旬一次的条件式 `+1`，不是无条件固定恢复，也不是通用人物忠诚自然增长。

## 资料裁决、推断与待验证

电子书 `EBK-PER-03` 的复合主张拆分如下：

- 新仕官忠诚与旧势力 45：由 `RE-SAN9PK-0111` 确认；
- 俘虏忠诚随时间恢复：方向确认，但精确机制修正为上述每旬阈值与成功 `+1`；
- 叛离后忠诚 45：仅由本批确认放逐非俘虏分支，不能泛化到所有脱离；
- 没收宝物：本批命令链不支持，保持待验证，不进入行为规格；
- 通用默认忠诚 50：本批未发现相应初始化写回，保持待验证。

身份 0/2/3/4 分别与君主、军师、通常在职、俘虏高度相容；这些是跨命令机器行为支持的领域映射。code 21/22 的目的对象可有多个运行时子类，正式模型应保留“可驻留对象”而不硬编码为城市。
