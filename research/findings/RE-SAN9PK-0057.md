## 只读证据

### 信息面板对象

MFC 运行时类记录 `0x614C50` 的类名为 `CMapBuildingInfoDIB`，对象大小 `0x368`，基类为 `CMapInfoDIB`。构造函数 `0x523520` 初始化以下子对象：

| 面板偏移 | 子对象 | 用途 |
| --- | --- | --- |
| `+0x30` | 文本 DIB | 士兵数 |
| `+0x84` | 文本 DIB | 建筑显示名 |
| `+0xD8` | 状态条 | 当前/最大耐久 |
| `+0x1F0` | 状态条 | 士气/100 |
| `+0x308` | 图标 DIB | 商人或训练 |
| `+0x338` | 图标 DIB | 皇帝 |

同一组相邻运行时类还包含 `CMapBarrierInfoDIB`（`0x19C`）与 `CMapUnitInfoDIB`（`0x264`）。这说明目标不是建筑地图精灵 `CMapBuildingVO`，而是独立的地图信息面板。

`populate_map_building_info_panel`（`0x524080`）直接完成面板填充：

| `CSan9MapBuildingData` 偏移 | 显示行为 | 结论 |
| --- | --- | --- |
| `+0x10` | 以整数格式写入 `+0x30` 文本 DIB | 士兵数 |
| `+0x14` | 传入第二状态条，最大值固定为 `100`；士兵数不大于 0 时先归零 | 士气 |
| `+0x48` / `+0x4C` | 传入第一状态条的当前值/最大值 | 耐久/最大耐久 |
| 名称访问器 | 经 `get_map_building_display_name` 写入 `+0x84` 文本 DIB | 建筑显示名 |

名称访问器先取建筑基础名称，再由 `0x52E240` 按固定建筑类型码追加 EXE 内静态标签。标签访问器 `0x568160` 从 `0x66A90C` 的 11 项指针表返回繁体文本；追加规则如下：

| 固定建筑类型码 | 追加标签 |
| --- | --- |
| `1` | 港 |
| `6` | 陣 |
| `7` | 砦 |
| `8` | 箭樓 |
| `9` | 城塞 |
| `10/11` | 柵欄 |
| `12/13` | 土砂 |
| `14/15` | 土壘 |
| `16` | 石兵 |

类型 `0` 与 `2..5` 不追加。完整标签表还含“都市”和“關”，但本追加函数不使用这两项；不能仅因它们相邻就给显示名附加对应文字。由此，剧本基础名“孟津”显示为“孟津港”，而类型 `4` 的基础名“虎牢关”保持不变。

### 士兵、士气和耐久的上游字段

建筑快照函数 `0x52E4F0` 先通过源对象虚表 `+0x64` 取得内嵌 `CUserHeishiPersonData` 状态对象，再读取该状态对象虚表：

- `+0x80 -> 0x45E400`，返回状态对象 `+0x30`，写入快照并最终成为面板数据 `+0x10`；
- `+0x84 -> 0x45E410`，返回状态对象 `+0x38`，写入快照并最终成为面板数据 `+0x14`。

城市加载器 `deserialize_city_record` 将剧本城市记录 `+0x0C` 的 `u32` 士兵数限幅到 `500000` 后，写入城市内嵌状态对象 `city +0x58 +0x30`。既有 [RE-SAN9PK-0022](RE-SAN9PK-0022.md) 又证明部队记录 `+0x16` 写入同类运行时字段 `+0x38`，且样本与编辑器的士气值 `100` 闭合。因此面板两项可分别确定为士兵数与士气，而不是仅凭 UI 位置猜测。

耐久通过源建筑对象的两个虚表契约进入快照：

- 虚表 `+0x50` 返回当前耐久；城市实现 `0x435630` 从运行时 `+0x3C` 取低 15 位；
- 虚表 `+0x12C` 返回最大耐久；城市实现 `0x43A4C0` 读取运行时 `+0x1C8`。

快照复制阶段将两者写入面板数据 `+0x48/+0x4C`。因此城市、关隘和其他据点可通过各自虚表实现共享同一面板契约，不要求共享城市的具体运行时偏移。

### 商人、训练和皇帝图标

`populate_map_building_info_panel` 按建筑的地域编号解析城市对象或地区建筑对象本身，再通过该对象的三个虚表条件加载图像资源。该解析不会把港口、关隘等地区建筑转换成其所属城市，因此城市状态图标不向所属地区建筑传播：

| 条件 | 资源 ID | 面板槽位 | 证据 |
| --- | ---: | --- | --- |
| 城市运行时 `+0x1E0` bit 0 | `1245` | `+0x308` | 虚表 `+0xC8 -> 0x43B2B0` 的完整函数体等价于读取该位；[RE-SAN9PK-0008](RE-SAN9PK-0008.md) 已确认该位为常驻商人 |
| 训练类别不为 `-1` | `1244` | `+0x308` | 虚表 `+0x11C -> 0x43B200` 的 ID 分派；与用户观察到的训练图标闭合 |
| 城市等于当前皇帝所在城市 | `1243` | `+0x338` | 虚表 `+0xC4 -> 0x43A6C0` 与全局当前皇帝城市指针比较；与用户观察到的皇帝图标闭合 |

训练类别函数只为九个城市返回 `0..8`：

| 类别 | 城市 ID | 城市 |
| ---: | ---: | --- |
| 0 | 0 | 襄平 |
| 1 | 3 | 南皮 |
| 2 | 8 | 北海 |
| 3 | 14 | 汝南 |
| 4 | 17 | 安定 |
| 5 | 20 | 武威 |
| 6 | 25 | 会稽 |
| 7 | 36 | 西城 |
| 8 | 42 | 建宁 |

城市 ID 与名称由工作区内生成的语义目录 `local/generated/research/catalogs/san9pk-tc-101-semantic.csv` 回读。完整目录含原版批量文本，只保存在被 Git 忽略的 `local/generated/`，不进入提交。其他城市和超出城市范围的 ID 均返回 `-1`。

图标组合存在明确优先级：`+0x308` 先检查商人，只有没有商人时才显示训练；皇帝使用独立的 `+0x338`，可以与商人或训练同时显示。面板宽度按图标需求从 `76` 扩到 `95` 或 `116`，高度固定为 `55`。

资源 `1243..1245` 是传给图像加载器的图像资源 ID，不是 `messages.json` 的文本消息 ID。

### 面板绘制位置、状态条和调色板

面板填充函数在 `0x524169` 以静态格式串 `%7d` 生成士兵数字文本，因此原版固定字格渲染器会把不足 7 位的数字右对齐。面板绘制函数 `0x5236A0` 再以面板左上角为原点，依次把该士兵文本放在 `(16,4)`、耐久条放在 `(0,16)`、士气条放在 `(0,29)`、名称放在 `(0,39)`、商人/训练共享槽放在 `(75,17)`，皇帝槽放在 `(96,17)`。实验渲染器使用现代比例字体，不复制前导空格这一实现手段，而是在从 `x=16` 开始的 56 像素字段内直接执行右对齐，把实际字形包围盒右缘放在 `x=72`。

普通建筑信息对象的创建位置链为 `0x532880 -> 0x522D60 -> 0x51CB20 -> 0x5306E0`：`0x522D60` 用建筑类型码索引 `0x660948` 的 17 项坐标表，`0x51CB20` 把该偏移加到建筑视觉基点，`0x5306E0` 才写入信息对象位置。城市（类型 `0`）为 `(12,-128)`，港口（类型 `1`）为 `(12,-74)`，虎牢关所用类型 `4` 为 `(80,-106)`。因此信息面板既不按自身宽度居中，也不能直接使用建筑基点；不同建筑类型具有独立的向上/横向偏移。

`0x530C90 -> 0x52F170 -> 0x52EF80` 是另一条按建筑数据更新信息对象位置的路径，不能脱离创建路径据此推断最终偏移为零。截图中可见的黑色区域来自状态条图像自身，而不是一块覆盖整个 `76/95/116 × 55` 的矩形底色。

`configure_map_info_bar` 与 `0x523F30` 确认两条状态条的资源和裁剪规则：外框为 `390/391`，士气填充按正常/警告/危急使用 `392/395/394`，耐久填充使用 `393/397/396`；当前值低于最大值的 `40%`、`20%` 时依次进入警告和危急资源。填充宽度在 `0..68` 之间按当前值/最大值计算，填充图放在外框 `(4,4)`。

用户提供的原作乌丸边缘截图进一步确认可见层次：建筑本体和旗帜可被地图前景云遮住，但士兵数字、两条状态条和名称仍清晰显示在云上。因此静态导出顺序必须满足 `建筑本体 < 前景云 < 建筑信息面板`。截图只确认信息面板与云的相对层次，不用于推断疆域线与云的先后；边缘云证据见 [RE-SAN9PK-0148](RE-SAN9PK-0148.md)。

静态资源绑定表进一步闭合了颜色来源：资源 `390..393` 使用全局调色板槽 `251`，资源 `394..397` 使用槽 `252`；`G_Common.s9` 从槽 `200` 开始加载，因此分别对应文件内调色板 `51/52`。图标资源 `1243..1245` 均使用槽 `314`；`G_Marker.s9` 从槽 `311` 开始加载，因此对应文件内调色板 `3`。这些绑定来自资源表项，不是按预览颜色猜测。

## 结论与限制

- 事实：建筑信息面板显示名称文本、士兵数文本、当前/最大耐久条和士气/100 条；无士兵时显示链把士气归零。
- 事实：建筑信息面板绘制在地图前景云之上；前景云仍可遮住建筑本体和旗帜。
- 事实：资源 `1245/1244/1243` 分别受常驻商人、九城训练类别、当前皇帝城市条件控制；常驻商人优先占用训练槽，皇帝为独立槽。流动商人当前在场不触发资源 `1245`，详见 [RE-SAN9PK-0058](RE-SAN9PK-0058.md)。
- 事实：训练类别表固定对应襄平、南皮、北海、汝南、安定、武威、会稽、西城、建宁。
- 推断：这些资源的业务名称由代码条件与用户黑盒观察闭合；本轮未单独解码三张图像的像素内容。
- 待验证：信息面板具体由悬停、选择或其他交互触发的完整状态机；状态条的动态势力色参数和遮蔽规则；九类训练点影响训练候选和结果的完整规则。
- 适用范围：结论仅适用于繁体中文版 1.0.1.0 当前样本；不把图像资源编号或运行时偏移推广到其他版本。
- 当前证据足以形成后续地图建筑信息显示规格，但在产品实现前仍应单独定义可见性触发和雾区信息隐藏规则。

## 2026-08-22 命名纠正

后续回查 `0x52EAB0 -> 0x475AA0 -> 0x454DF0` 的完整调用链确认：地域编号 `0..49` 返回城市对象，`50..249` 返回对应地区建筑对象；函数不会继续查找后者所属城市。原名 `get_map_building_city` 与正文“关联城市”的表述会错误暗示状态传播，现已更名为 `get_map_building_region_object`，并写入 `[RE-SAN9PK-0057][FACT]` 注释。保存项目主数据库后重新反编译回读了新名称；未修改程序字节或函数边界。
