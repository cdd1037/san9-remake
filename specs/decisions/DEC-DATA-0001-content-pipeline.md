# DEC-DATA-0001：JSON 内容源包与本地生成缓存

- 状态：已确认
- 日期：2026-08-15
- 决策者：项目所有者
- 关联行为：`BEH-IMPORT-0001`–`BEH-IMPORT-0017`
- 替代或被替代：无

## 背景

原版数据使用旧编码和固定布局，游戏与未来编辑器需要共享现代、可校验且可迁移的数据模型，同时不得把原版内容提交到仓库。

## 决策

导入器把已识别原版构建转换为版本化 JSON 内容源包，再由内容编译阶段校验并生成运行缓存。完整转换结果写入 `local/generated/`；仓库只提交架构、转换器、校验器和自制测试夹具。

固定地图定义可由多个剧本显式引用，建筑布置仍由各剧本持有；公共地图不保存剧本身份、初始季节或源文件追踪列表，身份与季节从剧本定义取得。转换器校验显式共享的固定数据一致性，不按内容哈希或引用次数推断文件归属。独立包与自定义地图使用同一引用契约，具体布局见[内容管线](../../docs/client-content.md)。

## 备选方案

- SQLite 唯一格式：编辑查询方便，但文本审阅和迁移不直观。
- 运行时直接解析原版：会让产品耦合原版偏移、编码和安装布局。

## 影响

- 玩家可见影响：开发阶段使用本地内容；公众导入体验另行决策。
- 数据/存档影响：存档引用内容包指纹，不嵌入原版资源。
- 测试影响：转换结果必须可重复，未知样本必须拒绝。
- 风险与代价：需要维护格式版本和显式迁移。
- 回退方式：可重新生成缓存，JSON 源包保持权威。
