## 调查问题与领域模型

本批闭合皇帝身份、势力官爵、武将官职、君主身份和势力存续之间的边界。领域对象不是一张统一“身份表”，而是四套独立状态：

1. 皇帝人物：由固定列传资源候选、人物死亡状态和世界状态位动态解析；
2. 势力官爵：根势力记录持有的 `kans` ID `0..8`；
3. 武将官职：人物持有的 `shak` ID，命令类型 14 修改该状态；
4. 君主与势力存续：根军团、直属君主、特殊俘虏状态、可用据点/人物和跨对象引用。

输入是场景初值、周期晋升门、事件选择、俘虏/死亡转移及军团资产变化；输出是官爵、忠诚、君主、根军团和引用图的确定性写回。核心不变量是：子军团不拥有独立势力官爵；被俘君主仍可保持君主身份；人物死亡或势力灭亡后不得留下悬挂的君主、军团、外交、联盟、目标或宝物引用。

## 三套身份体系不可合并

### 皇帝人物

`get_current_emperor_person(0x458540)` 在世界状态 bit 0 置位时直接返回空；否则按列传资源 563、564、565 查找灵帝、少帝、献帝，返回第一名身份不为 8 的人物。身份 4 的俘虏仍可被解析为皇帝，皇帝所在城市则从其当前人物位置动态取得。

因此“当前皇帝”不是某势力官爵为 0，也不是 `kkgu` 国号记录的君主字段。世界状态 bit 0 与人物身份 8 是皇帝解析的两个明确失效条件；它的完整剧情名称不影响该机器契约。

### 势力官爵 `kans`

`forc +0x1A` 载入到运行时势力 `+0x30`，有效范围为 `0..8`。所有读写先把子军团归一到根势力，因此一个势力的全部军团共享同一官爵。重置可复用势力记录时，记录 ID 失效、根指针回到自身、官爵回到最低的 8；这里的“势力失效”由记录有效性决定，不以官爵 `-1` 表示。

晋升资格执行以下顺序：官爵无效或已为 0 时拒绝；ID 8 至少需要一处地域；ID 1..7 则要求当前信望达到相邻更高一级（`id - 1`）的 `kans` 所需信望。提交总是写入 `id - 1`、增加 10 点基础信望，并把新官爵 `+0x0A` 的数值逐名加到非君主武将对当前势力的忠诚。

世界状态 bit 0 置位、即没有当前皇帝解析时，周期入口可把所有合格根势力各晋升一级，包括从 ID 1 到 ID 0。bit 0 清除时走皇帝在位的册授分支，候选额外排除 ID 1，所以该路径不会授予皇帝级；提交带当前皇帝演出和事件日志 `0x44`。山阳公等事件还可显式写入 ID 0，但属于事件族的选择提交，不是通用官爵写命令。

### 武将官职 `shak`

命令类型 14 的执行器处理人物列表和 77 项 `shak` 官职：写入新官职，并按新旧官职俸禄值差的一半调整忠诚。它不读取或修改势力 `kans`。此前把该命令称为“武将爵位”会把人物官职和势力官爵混为一谈，现已在 `RE-SAN9PK-0121` 与路线图中更正。

同时，`kans +0x0A` 过去依据编辑器截图被记作“能力上升”。当前 EXE 的周期晋升、皇帝册授和山阳公授爵三类消费者都把它传给逐势力忠诚增加器，且跳过身份 0 的君主；没有人物四维写回。故 [BEH-IMPORT-0005](../../specs/behavior/BEH-IMPORT-0005-scenario-rank-records.md) 和导入模型已改为 `promotion_loyalty_bonus`。

## 俘虏、死亡与继任

`capture_person` 捕获身份 0 的君主时写入身份 4，并设置人物标志 `0x2000`。`force_requires_ruler_successor(0x440110)` 明确把“身份非 0 但处于特殊俘虏状态”的君主视为仍然有效；所以被俘本身不换君，也不让皇帝解析失效。

`kill_person` 先快照原势力、军团、关联对象和宝物接收候选，再写身份 8。原身份 0 或特殊俘虏状态进入同一势力后续分支：若势力已缺少存续所需的据点或人物，则执行终端灭亡；否则调用 `select_force_successor`。这使正常君主死亡与被俘君主后续死亡在写入身份 8 后汇合。

继任候选来自势力人物集合。玩家势力先显示排序后的单人选择器；取消时回退到自动选择。自动路径复制候选并按旧君主关系、血缘/年龄、身份/官职及人物排序值组合出的机器键排序，提交第一项。本批确认组合与顺序，不为仍未完全命名的子 helper 发明独立玩法标签。

提交继任时，新君主身份改为 0、人物官职清空，并成为其当前军团直属君主；原直属负责人若既非旧君主也非继任者则降为普通身份。若继任者来自子军团，不是把旧根记录的君主指针简单替换，而是把旧根军团合并进继任者所在军团，使后者成为存续记录。随后按新君主亲和差为其他武将增加忠诚并刷新相关引用。

## 势力灭亡与引用清理

普通子军团撤销仍合并回根势力；根记录有可用子军团时可通过合并保留。只有缺少存续资产的终端分支调用 `eliminate_force_and_cleanup_assets(0x441EC0)`：它迁移或清理人物、部队、建筑和目标，清除外交关系、联盟/战争目标及跨势力引用，最后以 `reset_force_record_state` 将槽位恢复为可复用的无效记录。

死亡宝物也遵循最终引用：存在有效继任或其他接收人时整体转交，否则清空持有人。最后一个全局势力被移除后触发的胜负状态位仍由 `SCN-03` 解释；本批只确认灭亡前后的对象与引用守恒。

## 事实、推断与后移项

- 事实：皇帝、势力官爵、武将官职和君主身份是独立状态；官爵归根势力所有；晋升门、授爵忠诚、被俘保留、死亡继任和灭亡清理均来自当前样本控制流与写回。
- 推断：自动继任排序键中的亲和、血缘/年龄、官职与通用人物排序共同表达“优先继承人质量”；在所有子 helper 正式命名前，产品规格不采用更具体的宗法或资历名称。
- 后移：世界 bit 0 的完整剧情命名、两类周期事件的正式 UI 标题、最后势力消失后的胜负路由进入 `SCN-03/04`；它们不阻塞本批身份和存续状态机。

## 实现边界

重制领域模型应分别表示 `EmperorState`、根势力 `PeerageRank`、人物 `OfficeRank` 与 `RulerSuccession`。官爵晋升必须以相邻等级定义和显式世界状态为输入；俘虏君主不能因人物状态不再为 0 就自动换君；继任提交与灭亡清理必须是事务式状态转换，验收时检查所有反向引用。当前样本地址、对象池索引和事件消息码只留在研究层。
