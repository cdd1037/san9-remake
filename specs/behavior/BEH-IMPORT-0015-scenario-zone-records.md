## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `bldg` chunk 的记录边界、运行时引用、已确认字段和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。本规格中的运行时 `Zone` 对应编辑器的“据点”记录。

本规格定义名称资源代码到消息 ID 的绑定公式，但不把原版批量文本复制为产品数据；也不定义重制版据点平衡或要求导入器复现原版运行时对象布局。

## 原作基线

`bldg` chunk 位于正式剧本数据偏移 `0x89F8E`，包含 200 项，每项 28 字节，共 5,600 字节。运行时据点 ID 使用记录序号 `0..199`。字段布局如下：

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| ---: | --- | --- | --- |
| `0x00` | `u32` | `soldiers` | 序列化据点士兵数；原始值必须保留，导入器校验不得超过全局上限 500,000 |
| `0x04` | `u16` | `serialized_id` | 原始序号槽位；正式样本等于记录序号，原程序读取后丢弃，运行时 ID 使用记录序号 |
| `0x06` | `u16` | `fixed_building_code` | 固定建筑/工作物代码；`0..16` 为有效引用，`0xFFFF` 为空 |
| `0x08` | `u16` | `name_resource_code` | 据点名称资源代码；参与显示名称构造，具体文本资源不在本规格定义 |
| `0x0A` | `u16` | `name_reading_resource_code` | 据点名称读音资源代码；参与读音构造，具体文本资源不在本规格定义 |
| `0x0C` | `u16` | `force_code` | 所属势力代码；`0..49` 为有效引用，`0xFFFF` 为空 |
| `0x0E` | `u16` | `city_code` | 所属城市代码；`0..49` 为有效引用，`0xFFFF` 为空 |
| `0x10` | `u16` | `durability` | 当前耐久；原样保留 |
| `0x12` | `u16` | `x` | X 坐标；`0..199` 有效，`0xFFFF` 为空坐标 |
| `0x14` | `u16` | `y` | Y 坐标；`0..199` 有效，`0xFFFF` 为空坐标 |
| `0x16..0x1B` | 6 字节 | `tactic_flags` | 小端 48 位兵法标志；bit `0..40` 对应同顺序 ID 的 41 条 `hiho` 记录，bit `41..47` 为当前程序不可查询的保留位 |

名称资源代码不是未使用字段。原作把名称代码打包为类型 `4`，再以 `message_id = 166 + 2 × code` 取得名称文本；读音代码使用同一类型和步长，以 `message_id = 167 + 2 × code` 取得读音文本。两类消息因此形成相邻的偶/奇数对。`tactic_flags` 经运行时据点对象 `+0x50..+0x55` 进入公共兵法位查询器；查询器只接受兵法 ID `0..40`，按 `byte=floor(id/8)`、`mask=1<<(id&7)` 读取。bit 39/40 因而分别对应 `hiho[39]` 落石与 `hiho[40]` 射台，而不是独立的据点特性编号。完整 48 位值仍须保存，不能清零当前程序不可查询的高 7 位。

## 重制行为

导入器必须生成 200 个按文件顺序排列的据点定义，并暴露全部原始字段。`FixedBuildingId`、`ForceId`、`CityId`、`XCoordinate` 和 `YCoordinate` 仅把目标程序确认的 `0xFFFF` 哨兵派生为空；原始代码保持不变。

`TacticFlags` 无损暴露完整 48 位原值；`HasTactic(id)` 只接受 `0..40`，并额外提供 `HasRockfall` 与 `HasArrowPlatform` 派生属性。bit `41..47` 不得暴露为有效兵法或命名为未经确认的玩法属性。`Soldiers`、`Durability`、名称资源代码和读音资源代码均不得被派生值覆盖。

`NameMessageId` 与 `NameReadingMessageId` 必须按上述公式从各自原始代码派生。文本解析属于内容层；导入器不得把当前本地化版本中读音消息为空这一事实改写成“无读音字段”，也不得内嵌 200 项原版名称文本。

原作运行时士兵容量只分两档：当前固定建筑类型为 `0`（都市）时为 `500,000`，其他类型以及无有效固定建筑时均为 `250,000`。所有载入、增加士兵、增加伤兵、部队并入、征兵资格和攻心倒戈写回路径共用 `get_region_building_soldier_capacity(0x4361C0)`；当前值写入器以 `min(请求值, 容量)` 饱和。导入记录据此派生 `SoldierCapacity` 和 `RuntimeSoldiers`，但不得覆盖原始 `Soldiers`。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整 `S9SC` 剧本流。
- 状态变化：读取 `bldg` chunk 后产生 200 条据点记录；导入过程不丢弃原始字段。
- 始终成立的不变量：chunk 大小为 `5,600` 字节；每项完整消费 28 字节；记录 `Id` 为 `0..199`；序列化兵法位集固定为 48 位，当前兵法查询域固定为 `0..40`。
- 输入校验：`serialized_id` 必须等于记录序号；士兵数不得超过 500,000；非哨兵的固定建筑、势力、城市代码必须分别小于 17、50、50；非哨兵坐标必须小于 200。
- 失败或无效输入行为：chunk 大小、记录边界、引用范围或坐标范围不合法时抛出 `InvalidDataException`。

## 示例与边界

`D_Sce002.S9` 第 0 条与 `据点.png` 的对照值为：士兵 `1000`、工作物代码 `1`、势力代码 `12`、城市代码 `0`、耐久 `300`、坐标 `(184, 26)`。第 24 条的兵法位集包含 bit 39，对应 `hiho[39]` 和截图中的“落石”。
