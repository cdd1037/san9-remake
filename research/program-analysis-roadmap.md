# 三国志 IX PK 核心程序分析路线

- 状态：执行中（R0–R7 已验收，当前执行 R8–R12）
- 适用样本：`SRC-SAN9PK-TC-101`
- 项目主数据库：`research/analysis/San9PK-TC-101.i64`
- 当前范围：`R8` 至 `R12`
- 更新日期：2026-08-25

本路线用于持续完成重制核心模拟所需的程序分析铺底。它是当前研究排期的唯一入口；研究结论仍以独立 `RE-*` 为载体，进入产品实现前仍须形成状态为“已确认”的 `BEH-*`。

## 目标与边界

R0–R3 已通过[第一轮独立验收](program-analysis-r0-r3-acceptance.md)，R4–R7 已通过[第二轮独立验收](program-analysis-r4-r7-acceptance.md)。最后一轮沿重制实现依赖闭合以下五项成果：

1. 事件引擎的触发、调度、一次性状态与效果写回边界；
2. 人物成长、伤病、寿命、死亡、登场及小兵培养的生命周期；
3. 战场命令、移动、建设、攻城、占领、撤退和战后清理；
4. 场景初始化、势力存续、胜负判定与结局路由；
5. 全来源、全候选和跨系统不变量的最终核心闭环验收。

本轮是核心逆向收口，不包括产品代码实现、玩法重设计、图形音频呈现、完整 UI 复刻、编辑器、联机、平台接口或逐条复刻历史事件文本。事件只研究可复用引擎机制和代表性事件族；已有公式、战术 AI、命令生命周期及资料结论只作为基线，不重复推导。异民族、界面和基础设施候选仅在会改变核心模拟状态、命令可用性或玩家可观察规则时进入本轮，其余必须获得明确的非核心处置而非静默遗漏。

## 来源与证据优先级

按以下顺序裁决冲突：

1. 当前精确样本的真实 IDA 函数体、交叉引用、数据流、类型、随机调用和最终写回；
2. 当前精确样本上的可重复黑盒实验、二进制差分或只读探针；
3. 与当前样本旧字节、地址、调用现场或记录布局直接吻合的第三方线索；
4. [`SanIX_程序分析.md`](docs/程序分析、设计公式、优化方法/SanIX_程序分析.md)、[`三国志9电子书.md`](docs/三国志9电子书.md)和 [`San9PKHard`](upsteam/San9PKHard/) 中尚未复验的主张。

低优先级来源不得覆盖高优先级证据。San9PKHard 的注入代码表示工具作者希望改变的行为，不自动等于原版规则；只有旧字节、宿主函数和原版控制流闭合后，才可把它用作定位或语义佐证。

## 状态模型

统一账本和批次使用以下状态：

| 状态 | 含义 |
| --- | --- |
| `planned` | 已进入队列，尚未开始只读调查 |
| `in-progress` | 当前唯一正在执行的原子批次 |
| `confirmed` | 当前样本事实链和独立佐证达到本批退出条件 |
| `inferred` | 解释与证据相容，但仍存在竞争性解释 |
| `conflict` | 来源主张、地址、旧字节或当前样本控制流不一致 |
| `experiment-required` | 静态证据无法唯一裁决，已有明确可执行实验 |
| `version-inapplicable` | 线索不适用于当前精确样本 |
| `blocked` | 所有安全、独立且依赖满足的路径均已耗尽，仍需外部条件 |
| `completed` | 原子批次的交付物、验证和提交均已完成 |

同一时间最多一个批次为 `in-progress`。事实、推断、待验证和冲突必须在 `RE-*` 正文中分节记录，不能只依赖账本状态。

## 每次唤醒的执行协议

每次 Goal 续行或定时唤醒只完成一个原子批次：

1. 阅读 `AGENTS.md`、本路线、Git 状态、最近提交及相关 `RE-*`；
2. 选择最靠前、依赖满足且未完成的批次，将其标为 `in-progress`；
3. 先写明领域对象、状态、输入、输出和不变量，再实际调用 IDA MCP 对项目主数据库做只读调查；
4. 闭合入口、调用者、过滤、算术顺序、随机调用、状态变化和最终写回；
5. 形成或更新 `RE-*`，并按实际结果修正文档、账本、索引和符号摘要；
6. 仅在证据充分时同步 IDA；完成保存、逐项回读和相关导出/健康检查；
7. 执行测试与一致性检查，将批次改为 `completed`；
8. 使用一个带 scope 的约定式提交交付本批，并报告下一批候选。

原则上每次唤醒只产生一个逻辑提交。若发现用户已有改动与本批重叠，停止修改重叠文件并报告；不得重置、覆盖或顺手整理无关变更。

## IDA MCP 使用与留痕门槛

- 当前样本机器事实必须来自对项目主数据库的实际 IDA MCP 调用。只阅读源码、历史 `RE-*`、导出文本或第三方地址表，不构成当前轮 IDA 调查；工作区中没有独立 PE 文件也不是跳过 IDA MCP 的理由。
- 涉及当前样本机器事实的批次开始时，必须用 IDA MCP 核对服务健康、当前输入样本和数据库身份；身份不符或无法确认时，不得继续确认地址、字节、函数或规则。
- 调查必须按问题调用相称的反编译、交叉引用、调用关系、数据流、字节或类型查询，不能用一次健康检查代替实质分析。
- 关联 `RE-*` 必须记录本批实际调用的 IDA MCP 能力类别、查询目标、关键返回和证据定位。没有调用时须明确写成“未执行 IDA 调查”，且不得把依赖当前样本事实的批次标为 `completed`。
- IDA MCP 不可用、项目主数据库未打开或样本身份不符时，应保留精确错误与恢复条件；不得以源码推断填补，也不得声称已完成当前样本验证。
- 纯来源编目或工具构建批次可以不查询机器事实，但必须明确其产物仅为候选或基础设施；一旦退出条件声称地址、旧字节、控制流或规则已在当前样本成立，仍须满足上述调用与留痕门槛。

## IDA 同步与回读门槛

每次实际写入项目主数据库必须满足：

1. 写入前完成只读调查和 dry-run 清单；
2. 名称、类型、注释和函数边界分别有证据与置信度；
3. 不覆盖无关人工标注，不用强制类型隐藏冲突；
4. 保存后逐项回读成功、失败、跳过和冲突；
5. 比较关键函数写入前后的反编译，确认表达改善且没有丢失机器关系；
6. 运行相称的健康基线及运行时类、虚表、消息映射或全局根导出；
7. 在关联 `RE-*` 中登记实际写入与回读结果；没有写入时不记录空变更。

IDA 数据库、私有样本、原版资源和生成物不得进入 Git 提交。
