地图资源由独立 `import-textures` 构建，`textures.json.map` 保存四季源图、遮罩、建筑组合、动画帧和云资源。`import-client` 只读取共享资源定义并编译剧本地图实例，`map.json` 保存方格、地形、对象位置与边界，不包含图片目录。小地图底图改为客户端按当前地图方格合成。资源覆盖不依赖190剧本的当前显示状态。

```powershell
dotnet run --project src/San9.Tools -- import-textures --source-exe "<已登记的San9PK.exe>" --data-dir "private/s9数据文件" --output "local/generated/content/textures-san9pk-tc101"
dotnet run --project src/San9.Tools -- import-client --source-exe "<已登记的San9PK.exe>" --data-dir "private/s9数据文件" --scenario "private/s9数据文件/D_Sce002.S9" --texture-package "local/generated/content/textures-san9pk-tc101" --output "local/generated/content/scenario-190-live"
dotnet run --project src/San9.Tools -- render-map --content-package local/generated/content/scenario-190-live --output local/generated/verification/map.png --terrain-only true
```

旧包重新转换，不读取旧 `map.json` 独立包。纹理复用、分类、透明边缘与预算见[纹理资源](texture-resources.md)。

### 当前多视图实现（2026-09-25）

`MapWorld` 负责主镜头、输入与装配；不可变 `MapScene` 从当前世界生成建筑显示状态及水面空间索引；`MapSceneView` 统一资源申请、完整帧切换和地形／水面／对象／标注绘制。详情预览只负责都市或地域定位及512×256裁剪，复用相同视图，不再自行合成地形或维护对象绘制循环。图片和地形块的租约、预算、过期取消与退役见[纹理资源文档](texture-resources.md#多地图视图的地形资源)。

动画共用显示时钟，按帧索引变化重绘；世界版本变化时重新生成场景，各视图依据自己的可见范围申请资源并提交。主地图保留外围一圈预取，预览只申请实际画面。换季准备期间保留旧画面，新季节按最新镜头请求提交，不改变用户随后输入的导航目标。建筑、旗帜、守兵与云沿既有绘制顺序；未来野外部队需接入共用对象排序，当前未新增部队外观或战斗特效。

多视图自动验证覆盖共享请求、远处资源与预算保护、季节代际隔离、取消、失败及独立视图提交。连续移动修复后的当前采样见下节，不沿用更早的历史测量作为当前实现的结果。

### 首次小地图跳转调度优化（2026-09-25）

非地形预算已调为256 MiB。本轮保持GPU预算和每帧2 ms上传目标：地形合成与图片解码各使用两个连续领取任务的后台线程，排队／执行／待上传结果各预留至多32 MiB（单个超大图片独占队列的例外保持不变）。任务采用显示优先和显式请求序号，不依赖字典删除后空位复用产生的枚举顺序；无消费者的排队项取消，已运行任务仍占并行名额直到结束。

主地图镜头外256像素的缓冲地形继续准备，但不再阻塞目标镜头提交。镜头内缺块先入队并必须全部就绪；外围块上传后补充绘制，移动进入前再次检查目标视野完整。此轮仅分离外围地形等待；后续对象纹理的等待分离见下节，实际画面完整性始终保持。此段更新上一节对完整准备区域的说明。

### 对象纹理按实际视野就绪（2026-09-25）

当前视野必需纹理与外围预取分开。必需集合从缓冲区域中按实际图片相交范围筛选，跨越屏幕边缘的图片不能遗漏；可见动画仍申请当前季节全部帧。镜头只有在自身所需地形及纹理完整时才能提交，外围对象加载慢或失败不再阻塞提交。移动进入尚未准备的对象区域时继续保持旧完整画面。多视图复用同一选择与就绪规则。

### 视野提交与性能验收（2026-09-06）

请求视野与已呈现视野分离，目标地形块和对象／动画纹理全部上传后同步提交位置、缩放及可见对象；等待时保持旧视野，小地图白框、拾取、建筑标注使用已呈现相机。换季先准备当前已呈现视野的完整新季内容，再继续处理最新导航请求；纹理创建失败时保留旧缓存。显示块在提交前固定保留，外围预取块可先逐出。

后台地形最多2路实际执行，按目标可见区优先连续处理，不再等待每帧主线程重新发出下一对任务。新请求取消未完成的非目标可见区任务；主线程按2ms软预算接收完成结果，单次纹理创建不可中断，预算不保证单次调用低于2ms。当前视野外一圈仍为预取范围，没有声称已实现移动速度预测。图片按需读取并解码，最多4路且不超过逻辑CPU数；保留PNG CRC、尺寸校验和确定的ID映射，包格式不变。地形中心扫描线直接复制连续RGB跨度，边缘混合保持原权重和顺序。

水面建立显示用空间分桶，仅在视野提交时更新可见实例；静态对象也只在视野提交时重新筛选。动画按实际帧索引变化重建命令，保持原图层顺序。建筑标注缓存当前不可变快照的文字与测量结果，随视野版本刷新。此索引不参与领域寻路或地形规则。

### 运行时图片加载简化（2026-09-06）

用户明确暂不转换Godot资源格式，以后再考虑。客户端取消启动时遍历所有图片的SHA-256检查，也取消单张图片解码前的SHA-256计算；保留转换时的指纹记录和离线校验。图片只在需要时读取并解码，PNG格式、CRC及尺寸仍检查。撤销已校验压缩字节的会话缓存方案，不增加常驻压缩数据副本。未使用季节的文件问题在切换到该季节时发现。

后续全项目检查还发现此前纯地图加载器隐式扫描四季图片，已移除；转换器也不再回读生成图片进行全量SHA-256核对，仅从编码时已有的字节记录指纹；需要审计时另行显式运行离线校验。普通地图加载不承担全包指纹审计。其余SHA-256用途：导入器识别原版EXE及记录输入/输出来源；研究脚本记录样本与实验差异；世界快照生成状态摘要；AI根据摘要和观察上下文生成确定性随机种子。后两项参与模拟确定性，并非资源扫描，本轮没有更改算法或声称它们存在性能瓶颈。清单中的哈希字段及长度检查只是元数据，不读取文件计算哈希。

PNG CRC改为256项查表，编码与解码使用相同标准CRC-32算法。测试以独立逐位参考检查RGB、RGBA、灰度PNG的全部块CRC，并覆盖运行时允许哈希变化、离线校验拒绝哈希变化、尺寸不符、损坏数据及取消。

214项自动测试通过，Godot实际运行的选择、缩放、拖动、边界、四季与连续导航自检通过。单次同机运行首屏图片读取解码85.35ms、首屏地图准备220ms、客户端就绪470.60ms；对比上一轮约202–210ms、338–351ms、660–669ms，仅作为少量运行观测。日志与GPU截图分别为 `local/generated/verification/map-history/runtime-images.log`、`runtime-images.png`。没有新增操作系统交互测试。

移除转换器全量哈希回读后，同配置连续启动三次复测（固定动画200ms，未清空系统文件缓存），日志为 `local/generated/verification/map-history/performance-repeat-1.log` 至 `performance-repeat-3.log`：首屏图片读取解码83.40–88.84ms；首屏地图准备211–224ms；客户端就绪464.30–476.62ms；每次前四次换季139–213ms；未缓存跳转28.52–45.51ms；缓存跳转0.85–0.86ms；移动120帧间隔P95为15.87–15.89ms。三次地图自检通过。这轮转换器改动不改变游戏加载路径，未测完整重新转换耗时；客户端就绪计时从Main._Ready开始，不包含进程启动。跳转计时不包含下一次屏幕呈现，移动间隔受60 FPS配置与调度影响。
