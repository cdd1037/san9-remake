## 调查范围

调查 `city` chunk 的 56 字节记录、目标程序反序列化路径和城市主要属性。用户提供的黑盒剧本编辑器城市页截图只作为界面与样本值对照，不登记或运行该程序，也不把界面标签单独提升为格式事实。

剧本样本来自私有目录 `private/s9数据文件/`，只读检查；私有内容不进入 Git。

## 目标程序证据

城市运行时表包含 50 项、步长 `0x1F0`。`deserialize_scenario_chunks` 对 `city` chunk 固定循环 50 次，通过城市 vtable `+0x13C` 调用 `0x43A8E0`。该入口经 dry-run 后命名为 `deserialize_city_record`。

函数每次完整消费 56 字节：先读取四个小端 `u32`，再读取十七个小端 `u16`，最后复制六个字节的兵法位集。关键运行时落点如下：

| 文件偏移 | 运行时处理 |
| --- | --- |
| `0x00` | 写入 City `+0x1E0` 标志 |
| `0x04` | 写入 `+0x1BC` 非兵役人口 |
| `0x08` | 写入 `+0x1C0` 兵役人口 |
| `0x0C` | 通过带 500,000 上限的士兵设置路径 |
| `0x10` | 读取但不作为运行时 ID；运行时 ID 使用记录序号 |
| `0x12`、`0x14` | 写入两个对象身份/资源辅助字段；正式数据等于记录序号 |
| `0x16` | 通过 15 项访问器转换为州域对象，保存到 `+0x1EC` |
| `0x18`、`0x1A` | 零扩展写入 `+0x1E4`、`+0x1E8`；本构建未发现业务读取，判定为剧本保留字段 |
| `0x1C` | 通过 50 项势力访问器转换为所属势力引用 |
| `0x1E` | 写入 `+0x1C4` 民心 |
| `0x20`、`0x22` | 写入 `+0x1D4`、`+0x1D8` 最大收益/收获 |
| `0x24`、`0x26` | 写入 `+0x1CC`、`+0x1D0` 当前收益/收获 |
| `0x28` | 写入城市设施子对象的当前耐久 |
| `0x2A` | 写入 `+0x1C8` 最大耐久 |
| `0x2C`、`0x2E` | 通过地图对象坐标设置函数写入横纵坐标 |
| `0x30` | 写入 `+0x1DC`；与黑盒界面“外观特征”及正式数据 0–2 对应 |
| `0x32..0x37` | 复制到城市兵法位集；正式数据只出现 bit 39、40 |

城市专用访问器进一步确认 `+0x1BC/+0x1C0` 分别为人口和兵役人口，`+0x1C4` 为民心，`+0x1CC/+0x1D0` 为当前收益/收获，`+0x1D4/+0x1D8` 为各自上限。`San9PKHard` 对运行时 `+0x1E0` bit 0 使用 `m_bCityTrader`，并把 `+0x54` 的 `0x80/0x100` 分别作为落石、射台，与目标位集布局一致。

## 黑盒界面对照

截图打开的是 `D_Sce002.S9` 城市页。选中的襄平显示：人口 58,000、兵役 7,000、士兵 8,000、民心 200、收益 240/600、收获 180/400、耐久 380/600、坐标 `(164, 17)`、外观特征 2。上述值逐项等于记录 0 的相应字段。

同一截图的城市列表中，邺显示“商”；前八条记录只有邺对应记录 5 的 `0x00` 为 1。晋阳、上党显示“落”；对应记录 6、7 只有 bit 39 置位。它们构成同屏对照样本，而不是仅依靠选中行的一次数值巧合。

黑盒观测到的城市“外观特征”下拉框显示 3 项：`0` 中原都市、`1` 南方都市、`2` 北方都市。它对应已有城市记录 `+0x30` 的 `TerrainCode` 字段，不是独立的新枚举；CSV 中按 `city_terrain` 记录为该字段的显示名。

## 正式样本复验

对 `D_Sce001.S9` 至 `D_Sce020.S9` 共 1,000 项城市记录逐项检查：

- 三个编号字段始终等于记录序号 0–49。
- 州域代码覆盖 0–14；势力代码为 `0xFFFF` 或 0–49。
- `0x18`、`0x1A` 始终为 0；仍原样保留，但不进入玩法逻辑。
- 商人标志只出现 0、1。
- 人口为 30,000–474,000，兵役人口为 1,000–20,000，士兵为 0–100,000。
- 民心为 100–540；收益、收获和耐久均未超过各自上限。
- 坐标均位于 200×200 地图内；城市外观特征代码只出现 0、1、2。
- 六字节兵法位集只出现 0、bit 39、bit 40 三种值。

## 事实、推断与保留项

- 事实：记录数量和大小、读取顺序、运行时落点、人口/兵役/士兵、州域与势力引用、民心、收益/收获、耐久、坐标、商人与 bit 39/40。
- 多来源支持：商人驻留、落石、射台、上限字段和 500,000 士兵限制。
- 事实：`0x30` 经 `sub_52E300` 映射到三个城市资源组：`2→0`、`0→1`、`1→2`；开发度资源偏移见 [RE-SAN9PK-0055](RE-SAN9PK-0055.md)。
- 已确认无活动用途：`0x18`、`0x1A` 在本构建中是剧本保留字段。城市对象构造将运行时 `+0x1E4/+0x1E8` 清零，剧本载入零扩展写入，复制操作原样复制；除此之外没有城市代码读取这两个成员。71 个直接调用 `get_city_record` 的函数均未访问它们，存档读写的城市 vtable 槽也不序列化它们。因此该结论只表示繁中 PK 1.0.1.0 不使用其值，不推断其他版本或编辑器私有扩展。
- 保留项：城市坐标与 `bldg`、`squa` 地图拓扑之间的引用关系；城市视觉资源的动态旗帜、士兵和动画帧仍按静态快照处理。

## IDA 标注

- `0x43A8E0` 的城市 vtable 槽、50 次调用、56 字节消费和运行时落点闭合后，先执行不覆盖现有名称的 dry-run，再命名为 `deserialize_city_record`。
- 为函数应用 `San9CityRecord *`、游标和 16 位记录序号签名，并加入本记录注释。
- 强制重新反编译后，四个 `u32`、十七个 `u16`、六字节尾部、引用范围和控制流均未改变。
- 未修改程序字节或函数边界；未给两个零字段强加名称。
- 后续只读追踪覆盖城市构造、剧本载入、对象复制、全部直接城市访问器调用者及存档读写路径；`+0x1E4/+0x1E8` 没有业务读取。IDA 仅在两个载入写点补充“scenario reserved”证据注释，没有改变符号、类型或函数边界。
- 2026-08-18 增量同步：在 `deserialize_city_record`（`0x43A8E0`）入口追加城市外观特征代码 `+0x30`、0–2 显示名及其与地图 17 项地形表区分的证据注释；未修改函数名、类型、边界或程序字节。回读反编译确认加载顺序未变。

## 独立实现

`San9ScenarioCityArchive` 依据已确认规格独立读取记录，保留未知字段和完整位集，并校验引用、范围、当前值/上限关系及地图边界。实现不复制反编译伪代码、第三方补丁代码或黑盒程序逻辑。
