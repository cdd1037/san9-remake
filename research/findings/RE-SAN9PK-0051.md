# RE-SAN9PK-0051：SQUARE 地貌过渡、桥方向与疆界类型

- 状态：部分确认（编辑器观测与运行时绘制链已交叉闭合；自动生成算法和少数字段仍待验证）
- 日期：2026-08-19
- 分析者：Codex
- 结论类型：IDA 事实、可信黑盒观测、冲突裁决和待验证项分开记录
- 置信度：高（文件/运行时映射、八方向位序、底图索引、桥方向资源、疆界方向）；中高（地貌融合、色调强度和疆界样式的产品语义）
- 关联来源：[`SQUARE研究`](../docs/SQUARE研究/SQUARE研究.md)、`SRC-SAN9PK-TC-101`
- 前置记录：[RE-SAN9PK-0019](RE-SAN9PK-0019.md)、[RE-SAN9PK-0024](RE-SAN9PK-0024.md)、[RE-SAN9PK-0032](RE-SAN9PK-0032.md)、[RE-SAN9PK-0034](RE-SAN9PK-0034.md)
- 关联规格：[BEH-IMPORT-0014](../../specs/behavior/BEH-IMPORT-0014-scenario-square-records.md)
- 后续收窄：[RE-SAN9PK-0052](RE-SAN9PK-0052.md) 证明 bit9 广泛存在于都市/港口 footprint，故不能整体命名为桥锚点；只有 terrain 11 绘制上下文使用该资格位。

## 1. 结论摘要

前人编辑器把相邻 byte 合并成 `0004/0006/0008` 三个 16 位显示值；这不改变文件记录仍为 3 个 `u16` 加 8 个 `byte` 的事实。把可信黑盒观测拆回文件字节后，可以与 IDA 绘制链逐项闭合：

| 编辑器项 | 文件字节 | 当前语义 |
| --- | --- | --- |
| `0004` | 低字节 `+0x06`、高字节 `+0x07` | 地形/高度融合；`+0x07` 是八方向过渡掩码，`+0x06` 是主要在水域类地形出现的辅助值，具体视觉作用未闭合 |
| `0006` | 低字节 `+0x0A`、高字节 `+0x0B` | 高差边缘与底图变体；`+0x0A` 是高差/边缘过渡掩码，`+0x0B` 选择底图纹理变体，黑盒观测表现为同地形的颜色浓度变化 |
| `0008` | 低字节 `+0x0C`、高字节 `+0x0D` | `+0x0C` 是桥覆盖方向码；`+0x0D` 的低/高半字节分别是地域线和都市线的四方向掩码 |

因此此前的 `tile_edge_geometry_mask`、`map_visual_variant` 和两个 `opaque` 字段可以进一步收窄为研究层语义：`terrain_transition_mask (+0x07)`、`elevation_transition_mask (+0x0A)`、`land_texture_variant (+0x0B)`、`bridge_orientation_code (+0x0C)`。导入器仍保留原始字段名和原值，不在本轮改动公开 API。

## 2. `0004`：地形融合与八方向位序

黑盒观测指出 `0004` 根据相邻地形优先级和偏移差生成，使低优先级或低偏移地块向相邻高优先级/高偏移地块融合。其高字节就是文件 `+0x07`；随附方向表与 `build_square_edge_overlays`（`0x519D30`）的八次位测试完全一致：

| `+0x07` 位 | 掩码 | 邻格 |
| ---: | ---: | --- |
| 7 | `0x80` | 北 `(0,-1)` |
| 6 | `0x40` | 南 `(0,+1)` |
| 5 | `0x20` | 西 `(-1,0)` |
| 4 | `0x10` | 东 `(+1,0)` |
| 3 | `0x08` | 西南 `(-1,+1)` |
| 2 | `0x04` | 东南 `(+1,+1)` |
| 1 | `0x02` | 东北 `(+1,-1)` |
| 0 | `0x01` | 西北 `(-1,-1)` |

`build_square_edge_overlays` 根据这些位选择邻格并建立八方向边缘覆盖记录；`adjust_square_visual_position` 也读取同一运行时字段修正瓦片边缘位置。因此 `+0x07` 不是通行方向，也不是图片编号，而是地形/高差融合的八方向几何掩码。

文件 `+0x06` 是 `0004` 的低字节。黑盒观测称除水、水贰、水参外通常为 `0xFF`，水域上的具体效果未能肉眼确认。IDA 只确认它加载到 `CSquareData +0x18` 并进入通用 getter/格式化接口；当前地图绘制链没有闭合出专用读取，故保留为 `terrain_transition_aux` 候选，不提升为正式玩法名。

## 3. `0006`：高差过渡与底图纹理变体

文件 `+0x0A` 是编辑器 `0006` 的低字节。黑盒单变量观测表明它按相邻更高偏移地块生成，用于补齐高差断层。IDA 与此相容并补足直接消费者：

- `calculate_square_edge_visual_position`（`0x519730`）把 `+0x0A` 与边方向掩码相与，命中时增加边缘锚点的垂直步进；
- `draw_square_mesh_overlays -> create_square_mesh_visual` 把它加到 MESH/COV 基础资源号；
- `build_square_boundary_segments` 也用它参与疆界片段变体选择；
- `calculate_land_tile_atlas_index`（原 `sub_5193A0`）对适用地形统计该值的置位数，并据此选择底图图集子变体。

所以 `elevation_transition_mask` 比此前较宽泛的 `map_visual_variant` 更贴近现有证据，但它仍是研究层名称；完整自动生成表尚未由代码恢复。

文件 `+0x0B` 是 `0006` 的高字节。黑盒观测显示值增大时同一地形的颜色更浓，并区分陆地与水域使用的显示值范围。IDA 新确认的 `calculate_square_land_tile_atlas_index`（原 `sub_51E1D0`）把 `terrain_code`、`offset_code`、`+0x0A` 和 `+0x0B` 一起传入底图索引计算；核心函数将 `offset_code × 272`、地形表基址、`+0x0A` 形状子变体和 `+0x0B` 纹理子变体合成最终索引。代码证明 `+0x0B` 会实际选择底图纹理，但没有证明数值是线性色彩参数，因此研究名采用 `land_texture_variant`，把“颜色浓度随值增强”保留为可信黑盒表现。

## 4. `0008`：桥方向与两类疆界线

### 4.1 桥方向

文件 `+0x0C` 是编辑器 `0008` 的低字节。`draw_visible_bridge_overlays`（原 `sub_5194D0`，`0x5194D0`）只收集 `terrain_code == 11` 且 `square_flags_02 bit9` 置位的可见方格，然后以 `10004 + runtime(+0x30)` 取得地图资源并绘制。`runtime +0x30` 正来自文件 `+0x0C`。

这与黑盒观测“`0` 为南北桥、`1` 为东西桥；每座桥只在锚点格表达方向”闭合。当前正式地图只观察到 `0/1`，故可称 `bridge_orientation_code`，但导入器仍须无损保留其他原始值。

### 4.2 疆界线

文件 `+0x0D` 是编辑器 `0008` 的高字节。IDA 已确认 `refresh_map_square_boundaries` 对低四位和高四位使用相同的北、东、南、西顺序；黑盒观测补足两组样式语义：

| `+0x0D` 位 | 掩码 | 方向 | 黑盒样式语义 |
| ---: | ---: | --- | --- |
| 0..3 | `0x01/02/04/08` | 北/东/南/西 | 淡黄白色地域线 |
| 4..7 | `0x10/20/40/80` | 北/东/南/西 | 红白色都市线；两者重合时画面优先显示都市线 |

代码中的最终绘制仍依赖邻格 Zone/城市对象、偏移、高差过渡和资源表，不能把每一位理解成无条件绘制一条线。

## 5. 都市、港口与地图对象 footprint

前人资料指出都市以中心坐标为锚点覆盖 5×5 方格，港口覆盖 3×3 方格；例如中心 `(89,64)` 的行优先方格号为 `12889`。这与原作运行时的地图对象几何模型相容，但两类证据需要分层：

- 可信黑盒/设定观测给出都市 5×5、港口 3×3 的具体尺寸；
- `get_map_object_rect -> quantize_map_rect_to_square_grid -> enumerate_map_object_squares` 证明运行时不会只看中心格或 `ZoneCode`：地图对象保存矩形，先把对象坐标按 5 个单位量化为 SQUARE 的半开矩形，再逐行枚举其中全部方格；
- `expand_map_objects_to_squares` 在出征覆盖层等流程中把一组 `CMapObjectData` 的实际矩形 footprint 展开为方格列表。

因此，都市/港口/工作物的 footprint 应作为地图对象几何关系建模，不能仅凭 `square_flags_02 bit0/bit14` 或中心格反推整个对象。5×5/3×3 可作为目标对象类型的可信原作基线；其他工作物尺寸、旋转后矩形和不规则占用仍需按对象类型闭合。

## 6. `square_flags_02` 的静态模板与运行时复用

前人观测为 `+0x02` 提供了重要的文件模板语义：bit0 表示建筑/工作物格；bit1..8 描述八方向阻塞形态；bit12/13 参与 3×1 关、土垒、栅栏方向；bit14 表示建筑中心格。IDA 另证实运行时会读写同一个 `CSquareData +0x34`，因此必须区分“文件初值”和“运行时复用”：

- `bit1..8 (0x01FE)`：在已确认的四邻格寻路中被整体折叠为硬阻塞；非零即不可进入。前人对逐方向含义没有严格完成测试，当前不能用于方向化移动规则；
- `bit9 (0x0200)`：桥覆盖绘制把它作为锚点资格位。资料正文称 `0` 表示桥部件，但其桥样例 `4993/1798` 都置有该位，且代码显式要求该位为 `1` 才绘制；本记录以“`1` 表示桥覆盖锚点资格”裁决这处冲突；
- `bit10 (0x0400)`：可信观测为“无所属/不画疆域线”，但当前尚未找到直接位测试；保留为待代码闭合的静态语义；
- `bit11 (0x0800)`：文件观测通常为 0；运行时代码会设置并整图清除，属于复用的临时位；
- `bit12/13 (0x1000/0x2000)`：可信观测参与 3×1 工作物方向；代码也有直接条件消费者，但尚未闭合完整对象类型表；
- `bit14 (0x4000)`：可信观测为建筑中心格，城市中心常见值 `0x4201` 同时含 bit14、bit9、bit0；当前没有独立代码 getter；
- `bit15 (0x8000)`：文件观测通常为 0；运行时城市路径/覆盖流程会批量设置。

这解释了此前“字段既像静态地图描述又像运行时标志”的现象：源文件提供初值，运行时对象在其上继续复用部分位。产品模型不应直接照搬这个可变复合字。

## 7. 事实、推断与待验证

### 事实

- 文件仍是 14 字节记录；编辑器的三个 16 位未知栏只是相邻 byte 的显示组合。
- `+0x07` 八方向位序由黑盒方向表和 IDA 邻格调用双重确认。
- `+0x0A/+0x0B` 同时进入底图图集索引；`+0x0A` 还进入边缘、MESH/COV 和疆界片段链。
- `+0x0C` 在桥地形覆盖链中选择 `10004/10005`；`+0x0D` 是两组北东南西疆界掩码。
- `+0x02 bit9=1` 是当前代码所要求的桥覆盖锚点资格；资料中的相反文字与代码及其样例冲突。

### 可信黑盒观测

- `+0x07` 的生成依赖相邻地形优先级和偏移差；桥边缘只在与陆地相邻处需要融合。
- `+0x0A` 可由相邻更高偏移格自动生成，错误或跨级偏移会造成可见断层。
- `+0x0B` 的不同值表现为同地形颜色浓度变化。
- `+0x0D` 低半字节为地域线、高半字节为都市线，重合时都市线视觉优先。
- `+0x02` 的 bit0、bit12/13、bit14 分别与工作物格、3×1 方向和中心格相关。
- 都市 footprint 为 5×5、港口 footprint 为 3×3；运行时代码按 `CMapObjectData` 矩形量化并枚举实际覆盖方格。

### 待验证

- 从原作代码完整恢复 `+0x07/+0x0A` 的自动生成算法、地形优先级表和桥例外。
- `+0x06` 在水、水贰、水参中的具体视觉效果。
- `+0x0B` 的 0..5 变体与资源图案/色调的精确对应，而非仅凭肉眼称为线性浓度。
- `+0x02 bit10` 的“无所属”直接消费者，以及 bit12/13 对各类 3×1 工作物的完整编码表。
- 其他寻路或移动模式是否逐方向解释 `bit1..8`；当前确认的方格图只把它们整体当作阻塞。
- 除都市和港口外各类工作物的矩形尺寸、旋转规则，以及是否存在不规则 footprint。
