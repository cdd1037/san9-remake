## 适用范围

适用于以部队为目标的伪报、扰乱、激励与救援，包括持续状态、士气、兵力和伤兵边界。公共提交与随机规则由 `BEH-STRATEGY-0001` 规定。

## 原作基线

伪报、扰乱、激励分别在成功时设置各自状态，并写入由对应公式产生的持续日数；每日模拟更新把正值持续日数减一。激励还把兵法间隔清零。

高昂仅在本次每日更新把正剩余日数减到 0，且部队当前命令事件类型属于 `38..52` 时，执行一次士气下降 30；正常正士气写回下限为 1，随后状态恢复为基准状态。此扣减对玩家和 AI 部队同样生效，消息显示另受所属势力对玩家可见性控制。不满足命令类型门槛，或进入更新前日数已不大于 0 时，只恢复基准状态，不扣士气。治疗在到期前清除高昂后，也不再触发这次下降。原版对扣减后非正士气另有部队终止分支，见关联研究；正常正士气不会由本次扣减进入该分支。

救援提交时从执行者所在来源据点立即扣除固定 3000 兵，保存来源当时的士气和判定骰，建立到目标的命令行程；到期后才复验并结算目标效果。成功请求补兵 3000，失败仍有缩减补兵，均按执行时目标带兵上限截断；已扣成本不返还，超额不回流来源，也不转成伤兵。两条分支均混合目标原兵力/士气与来源提交时士气/请求补兵量，不保证成功必升士气、失败必降；截断后士气权重仍使用请求补兵量。成功清除异常状态，但保留基准状态与激励状态。时序复核见[RE-0114](../../research/findings/RE-SAN9PK-0114.md#2026-09-13救援扣兵等待与超额复核)。

## 重制行为

保留三类状态的成功写入、按日递减、激励间隔清零、高昂到期士气惩罚。救援提交转出固定3000兵，失败仍有部分交付，目标伤兵不变，成功选择性清除异常状态。未交付兵力返还，士气按实际交付人数计算。

救援等待生效时序与原作对齐：提交时按来源与目标的领域细坐标中心计算整数欧氏距离 D = floor(sqrt(dx² + dy²))，初始倒计时 N = ceil(D / 30)，不按十天倍数取整。每日命令前将正倒计时饱和减一，到期后在当次每日命令阶段复验并结算。因此第 max(1, N) 次每日处理生效，对应下令日期偏移 max(0, N - 1)；零天也不能在提交调用中立即补兵。领域坐标与命令时序由 Core 保存，不依赖动画或原版内存字段。

提交从来源据点转出3000兵，由去程任务的`Reinforcements`唯一持有数量、来源士气及遣散城市。来源地域必须能解析到有效城市人口池。成功请求3000，失败仍使用原缩减请求公式；实际交付取请求量、在途兵数和目标空余容量的最小值。失败表示组织交付能力不足，本次不另设死亡或伤兵损失；全部未交付者随返程任务继续保存。

提交时拒绝满员目标；途中暂时满员不取消，到达当天才检查容量。目标消灭、改属或执行者失效等结构变化仍可中断任务。到达满员则取消目标效果，3000兵全部返程，不触发成功成长。

目标士气按目标结算前兵力与士气、实际交付兵力及来源士气作整数加权平均。返城同样只按实际入库人数混合驻军士气；零交付不改变士气。返城超过驻军容量的剩余兵员通过公共遣散服务转入该地域城市的预备兵役人口，不写成伤兵或静默丢失。

执行武将沿[现有人物返程规则](BEH-PERSON-0003-recall-movement-and-action-reservation.md#状态与不变量)返回。来源失守时选择有效己方据点，余兵随任务转移；返程目的地再次失守则继续重新安置。执行者被俘、改属、被取消执行资格，或没有有效己方归队据点时，余兵解除编制，进入任务记录的城市预备兵役人口，不跟随武将改属为敌军。势力消灭和会话终止清理同样先处理余兵再删除任务。

任务的遣散城市在提交时取来源地域城市；完成交付后更新为出发时保存的目标地域城市，若该地域没有城市映射则保留来源城市。它表达离散行程阶段的已知地域，不声称逐日追踪运输队位置。正常返城溢出优先使用到达据点的地域城市。人口池是地理状态，不要求仍归原势力。

去程与返程任务之间转移唯一的在途兵力，完整交付后清空载荷。快照、哈希、存档和录像保存该状态；恢复不得重复扣兵、提前入库或重复返还。仅由命令产生新状态，不改变原版导入范围、转换包定义、对象身份集合或显示资源。

### 已替代选择

2026-09-16用户要求修正救援兵力消失与士气权重问题，采用上述兵力守恒规则，替代此前“按原作请求兵数混合士气、未交付不返还”的重制行为。原作事实仍保留在原作基线和RE-0114；本节是有意的重制选择。

状态使用明确枚举和独立剩余日数字段，不继承原作数值编码。高昂到期沿用上述日数和命令类型门槛，正常正士气按固定 30 扣减并钳制到 1；救援成本与具体公式常量由相应公式规格提供；若调整固定 3000、到期惩罚或清除集合，须明确目标行为与验收，是否新增 DEC 按[文档规则](../README.md)判断。

## 状态与不变量

G08采用繁中PK 1.0.1.0的以下算术，依据 [RE-0113](../../research/findings/RE-SAN9PK-0113.md)、[RE-0114](../../research/findings/RE-SAN9PK-0114.md) 与 [RE-0067](../../research/findings/RE-SAN9PK-0067.md)。伪报、扰乱、激励和救援均已接公共命令与结算：

| 行为 | 公式与门槛 |
| --- | --- |
| 伪报 | `min(35, 3*max(0, 执行智力-目标最高智力+10)/4)`；方圆特性再除2 |
| 扰乱 | `min(30, 3*max(0, 执行智力-目标最高统率+10)/4)`；方圆特性再除2 |
| 激励 | `(执行智力-30)/2 + (会鼓舞 ? 20 : 0)`；保留负阈值及向零截断 |
| 救援 | `5*(执行统率-30)/4`；执行时已满员则无交付 |
| 救援失败请求 | `15*S(执行统率)`，实际补入受目标空余和在途兵数限制，未交付部分返还 |

对象状态、教论免疫与目标资格独立复验，不把纯算术函数替代资格查询。方圆特性通过内容语义表达，不能在Core按原版阵型编号判断。

- 输入与前置条件：来源据点与目标部队、双方领域细坐标中心、命令剩余倒计时、来源提交时士气、单名执行者、实时能力与阈值、来源兵力、目标容量、状态及持续日数；玩家目标属于来源城市或其直接邻接城市的地域范围。
- 状态变化：状态/日数、兵法间隔、来源和目标兵力、目标士气、执行者成功能力成长及策略熟练度。
- 始终成立的不变量：持续日数不低于零；目标兵力不超过容量；正常正士气的高昂到期恢复基准状态且士气写回不低于 1；救援不直接改变伤兵；提交成本只扣一次；失败不触发执行者基础能力成长。
- 失败或无效输入行为：来源不足固定成本时不得提交；目标失效或无容量时执行复验拒绝效果。

## 示例与边界

- 持续日数为 1 的状态在下一次每日更新后到 0。
- 救援成功时目标上限 10000、执行前有 9000 兵，只补 1000；来源已扣 3000，余下2000随任务返程。容量按到达时查询，士气权重使用实际交付1000。
- 救援失败请求 1500、目标只剩 500 容量时，只补 500，士气权重使用500；其余2500兵随任务返程。
- 救援失败仍走缩减补兵和士气失败分支，不能简化为无效果。
- 成功救援保留激励状态，不把所有非基准状态无差别清空。
- 士气 100 的部队被激励成功后，满足命令类型门槛的高昂到期将士气降至 70 并恢复基准状态，而不是回到激励前的数值。
- 高昂期间被治疗命中时保留高昂和剩余日数，清除到期惩罚标记；随后到期不扣士气。成功救援保留高昂、剩余日数与到期惩罚标记。
- 高昂到期的士气写回有下限，单次到期扣减本身不会把部队士气扣成 0。

## G07高昂生命周期与治疗的重制选择

2026-09-13用户确认：以部队独立布尔字段`HighSpiritsMoralePenaltyPending`表达待扣士气，不绑定某次激励的身份、不建立后台任务。导入正日数高昂时设置；后续G08激励成功或重新施加高昂须重新设置。治疗实际命中后清除此标记，保留高昂本身及原有剩余日数；高昂结束或被其他状态替换清标记。标记为true要求当前状态为高昂。

逐日1→0且有效命令类为Military、标记仍为true时扣30并钳制到1，随后恢复正常；初始已为0只归一。治疗免罚不单独增加治疗候选，健康高昂不会浪费治疗。该选择明确不同于原作治疗同时清除高昂及其到期扣减。字段进入初始态、快照、哈希与存档，不从剩余日数反推免罚状态。此生命周期已接入G07，激励命令本身仍留G08。
