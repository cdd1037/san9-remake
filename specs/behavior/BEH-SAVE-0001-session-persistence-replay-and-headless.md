# BEH-SAVE-0001：玩家存档、命令脚本与无界面运行

- 状态：已确认
- 最后更新：2026-11-02（完整阵位随命令和世界保存）
- 关联决策：[DEC-SIM-0001](../decisions/DEC-SIM-0001-determinism-and-saves.md)
- 前置行为：[BEH-SIMULATION-0001](BEH-SIMULATION-0001-time-progression-and-state-visibility.md)
- 继承方式：重制存档和调试协议，不导入原作存档，不声称复刻原作文件格式

## 重制行为

全局默认忠诚属于内容规则，不写入存档或确定性状态哈希。人物`ForceLoyalties`只保存差异条目；缺失条目在读档时采用当前内容包的`DefaultLoyalty`，显式0保留。不重新初始化忠诚；若当前规则默认值改变，未单独记录的忠诚随规则改变，已有差异值保持不变。运行时快照携带只读规则上下文用于查询与内部分支，该上下文不参与序列化。

Application提供新局、稳定边界保存恢复和操作水位。会话只维护当前状态，不保留完整操作／事件历史。局内编辑仍通过统一会话操作原子提交，结果进入普通存档。

2026-10-22按项目所有者决定撤下录像录制、导出、回放、专属协议和完整录像验收，替代此前显式调试录像的实现选择。不保留空接口、兼容读取或分块存储框架；旧录像不再有读取入口。存档和命令脚本结构未变化，不升级其格式或玩法规则，不要求重转内容包。

独立`San9.Headless`只依赖Application/Content/Core，读取公开夹具或转换剧本，执行显式JSONL命令脚本、推进、保存和验证，输出机器报告与失败码；不加载Godot、原版EXE或S9。`CommandLogService.CreateHeader`捕获脚本起始配置，`Write`只接受调用方显式提供的头和请求集合，不从会话追溯历史。脚本不包含完整起点状态或事件，不能替代存档。

## 常用出征编队（2026-11-01）

`SessionSnapshot.DeploymentPresets`保存本局按势力归属的编队方案，结构、引用和唯一身份在恢复时验证，当前成员忙碌、死亡、转属或技术失效留给套用时解释，不妨碍恢复。方案包含具体阵位和固定／最大兵力偏好，不包含缓存能力、主将或出征目标；完整行为见[常用出征编队](BEH-UI-0001-initial-strategy-screen.md#常用出征编队)。

新增或覆盖（含改名）使用`SaveDeploymentPresetOperation`，删除使用`DeleteDeploymentPresetOperation`；按当前行动势力授权，经公共会话提交更新水位、未保存标记和捕获缓存，世界状态与规则随机保持不变。显式命令脚本支持这两种操作。存档格式升为133、脚本格式升为155，旧格式拒绝且不补字段；玩法规则和内容包格式不变，无需重新转换内容。

## 零到多玩家控制（2026-10-20）

控制集合与当前行动水位是身份依据，不再保存`PerspectiveForceId`。`StrategicContexts`按势力保存战略提示与线索；零玩家存档合法，预览玩家数量可为0，使用无玩家摘要与中性旗帜。没有本方的阶段不把年表笔记挂到原玩家势力。格式变化不引入旧档转换或缺字段回填。

## 状态与不变量

- Core拥有日历、起始日期、领域集合、控制席位、下一命令序号、活动持续任务及命名随机。已完成命令ID集合不再保存；水位拒绝旧命令，活动任务保留自身ID和序号并验证身份/占用唯一性。
- Application持有当前内容定义、下一会话操作序号、最近128条自动内政记录和玩家主动填写的年表。记录超过上限按时间顺序淘汰最旧记录；手写年表保留，不自动累计逐旬事件。
- 自动检查点默认关闭，由Godot客户端显式启用；Headless默认既不生成自动检查点也不写自动档，`run`／`replay`仅显式`--save`写存档，`verify`按请求生成验证产物。旬开始自动存档使用Application在启用后的新局及新旬稳定发布后生成的独立检查点；领取后不重复生成，失败可归还当前旬检查点。待答完成前及终局不生成，玩家读档与精确恢复不生成；检查点和领取状态仅在内存存在，不改变存档协议。客户端在交还控制时提交检查点，主线程捕获、后台编码和原子写入，按经过旬数轮换十位置；完整规则见[存读档界面](BEH-UI-0007-save-load-browser.md)。
- 默认存档保存以上完整当前状态及格式／规则版本，不保存命令历史、事件历史、录像、UI缓存、对象指针或半执行事务；初始种子只存在于世界调度状态。存档大小随当前世界、任务及玩家记录变化，不随已执行操作数线性增长。
- 规范化UTF-8 JSON按Ordinal排序对象键，整数无浮点，枚举使用已定义整数，Guid使用标准小写字符串，null显式保留。身份/关系/无序兵法集合稳定排序；控制、熟练度下标、玩家记录和命令脚本操作保留顺序。
- 势力事件历史、全局事件消费键与命名随机流的加载校验要求键有效且唯一，不要求输入数组已排序；全局消费键与随机流在恢复时规范排序。玩家读档先校验保存的随机流，再清空流并更换运行种子，世界恢复校验只执行一次。
- 世界／会话状态比较由显式诊断API提供，覆盖权威状态、待答步骤、会话序号、记录、年表和AI记忆；排除本地提交次数。不提供快照哈希属性，不作为恢复前置，也不进入默认报告。规则版本由文件封套表达，不保存内容指纹。普通存档允许手工修改；结构、引用与状态合法即可载入。
- 恢复使用当前内容的规则与引用定义，存档保留实际世界状态。初始兵力、年龄、地图成本、规则参数和初始开关改变不作为拒绝门槛；已保存的开关不被内容初值覆盖。起始日期、控制权限、对象／任务／阵形引用和世界不变量仍按实际运行要求校验。
- 已成立的运行时势力加载时校验身份、来源引用及成立日期处于开局至存档当前日期之间，不重新要求起兵／自立开关开启或开局满30天；这两项仅控制事件触发。

运行中势力交接以`ForceControlOperation`记录；当前控制权读取世界席位，`PlayerForceController`仅保留开局控制配置供命令日志重建。恢复不要求控制权等于剧本初始配置，允许零到多个玩家席位，并校验有效势力完整席位集合及各势力战略提示归属。玩家年表保留记录当时的势力，不因接管改写旧记录。

## 命令、显示状态与配置

多人登庸命令使用`recruit-officers`及`OfficerIds`集合，旧单人命令脚本按结构版本拒绝。优化伴侣配置由客户端独立文件保存，不进入世界存档；宿主在恢复后提供当前配置，命令脚本头单独声明外部初始配置，见[优化伴侣设定与玩家自动内政](BEH-COMPANION-0001-settings-and-player-domestic.md)。建筑城防兵法保存在当前世界，五类局内编辑作为会话操作提交；见[局内编辑器](BEH-EDITOR-0001-world-editors.md)。部署命令的`Positions`和世界的`MemberPositions`保存完整列与前／中／后排行位；行位查询只从此位置派生，详情不重建列。缺失完整位置的旧格式明确拒绝，不从旧行位猜测迁移。存档保留部队实际朝向`Facing`和自主避战通知去重状态；朝向缺失或无效时拒绝，不从命令目标补算。事件保留计略、成长、登用、任免与战后结算的发生时身份和位置，区分单位终止原因及据点中立化。进行记录正文不写普通存档，年表独立保存；渠道约定见[统一消息](BEH-UI-0006-unified-messages.md)。

跨军团入驻、继任、据点失守与势力灭亡共用当前清理规则；战后补选君主也沿公共继任入口合并继任者子军团。旧格式明确拒绝；仅规则版本不同的记录按既有告警机制载入并按当前规则继续，不保证旧命令脚本结果一致，也不逆推旧档历史归属或补算已经发生的兵员回收。


势力`ForceState.ColorCode`属于权威状态：初值取内容，新建势力分配；快照和存档携带，恢复直接读取，不重新配色或维护平行颜色表。

## 本局部署与资料集

存档格式 141、命令脚本格式 171 记录资料集标识。开局额外部署的人物和必需的休眠亲代、血缘根只在部署引用中保留稳定 ID；新势力保存势力 ID 和创始人 ID。读取时从资料集解析姓名、字、列传、头像及旗字。剧本自带的人物使用该剧本生效的资料。修改显示资料后，同一存档再次载入可见新资料。

能力、兵法、逐势力忠诚、归属、位置、军团、钱粮及宝物持有人继续由存档世界持有。读档不再执行开局部署。当前资料中的双人联携规则用于之后的结算；精确复现需要相同的规则与输入。无关的库内人物不会增加存档记录。资料集标识不符、必需的部署人物缺失时报告所缺资料。

## 操作水位与原子性

每条请求包含从0开始的会话序号、关联ID、控制者及类型化载荷。本地请求直接绑定当前GameSession；外部JSONL在文件头核对格式、初始种子和会话配置，规则版本不同仅警告，不为每条操作另建流指纹。Core命令序号独立计数，会话序号另覆盖结束控制、推进和年表。

- 序号小于下一序号返回`AlreadyProcessed`，不执行、不返回旧结果或事件，也不声称核对过旧载荷。序号大于下一序号返回`OutOfOrder`。
- 下一序号按当前权限与业务规则终验；成功后水位加一。拒绝不占用序号、不改变世界/随机/会话。自动生成的ID直接编码身份类别、主体和序号，不经过SHA-256，只用于命令、任务和事件关联；旧请求改成新序号视为新请求，重新终验。
- 操作包括领域命令、势力控制交接、结束控制、推进旬和年表；推进显式结束剩余控制席位再前进，不能称为AI决策。操作在候选世界上执行，全部成功后发布世界、玩家记录与水位。
- JSONL输入按行提交，首个拒绝停止，接受前缀保持已提交进度，若停在待答交互则不能保存，须补齐答复完成结算。旧序号前缀可跳过；不是整个外部文件的跨行事务。CLI尝试诊断不进入权威状态。

## 保存与恢复

只从完整旬结算后的稳定下令边界或已完成终局捕获，允许跨日、跨旬的持续任务；执行中以及任何等待玩家答复的边界均拒绝保存。外交谈判、季度联盟邀请、季度修习报名、被俘君主日结处置、处决及单挑继任选择只在内存续行，任务队列游标、报价步骤和待答提案不进入存档契约。外交往返的货物、日期、已确定任务骰子、正式协议和已报名修习任务继续保存。未来可扩充完整日结算后的保存边界，当前不支持逐日存档，也不为任意中间阶段设计恢复协议。读档严格检查结构、格式版本、世界不变量、当前身份引用、记录和序号水位，再构造查询；缺字段、额外字段、重复键、未知类型/枚举、null集合元素、截断、未知任务规则均明确拒绝。

恢复创建新会话，不重跑新局准备。`SaveService.Load`是玩家读档：先完整验证，再生成新运行种子并清空运行流，保留本局种子、已保存任务骰子和其余当前状态。`SaveService.Read/Decode`及`GameSession.Restore`是精确恢复，保持运行种子和流游标，服务检查点、诊断与命令脚本复现。两个种子均属于世界调度状态，进入存档和显式世界诊断；完整分类见[随机约定](BEH-SIMULATION-0002-randomness.md)。未知文件格式拒绝；没有隐式迁移。规则版本不同仅警告，按当前规则继续载入，不因规则升级默认拒绝旧档案。文件使用同目录唯一临时文件，写完flush再原子替换；失败保留旧文件并清理本次临时文件，不承诺超出操作系统的断电保证。

宝物的存在和位置由存档中的世界状态决定，剧本初始配置用于新局。恢复检查存档中宝物的身份唯一性、规则定义、位置及相关引用。武将的地域引用按完整人物地点表校验，允许在野武将位于休眠据点所在地域。宝物掉落在已知据点时，即使该处没有独立地域名称也可恢复。缺少所需的宝物定义时，载入失败并报告宝物 ID。

内容指纹的生成、文件字段和匹配门槛已删除；存档、命令日志、槽位及默认报告也不保存哈希版本。哈希用途与边界见[约定](../../docs/development/state-diagnostics.md)。

会话另持有不进入存档或显式状态诊断的未保存修改标记。新局置真，恢复／玩家载入置假；统一操作提交成功后置真。成功保存按捕获操作序号清除，失败或保存完成前已有更新时不清除。只读查询、拒绝或重复请求不影响该标记。客户端据此决定载入前是否确认放弃进度，见[存读档界面](BEH-UI-0007-save-load-browser.md)。

## 命令脚本与验证

`run`执行调用方提供的命令文件，可用`--load PATH`玩家读档或`--restore PATH`精确恢复，二者互斥；可用`--save PATH`保存已接受前缀。从不同运行状态执行同一文件可能得到不同结果。中途脚本需要匹配的精确起点；初始种子和配置检查不等于拥有完整起点。脚本头声明本局新增定义；涉及新增人物或势力时必须提供起点存档，精确复现用`--restore`，另起随机运行可用`--load`。不从人物库重建起点，也不把完整世界重复嵌入脚本头。

`verify`显式构造请求并在连续会话和恢复会话上执行，逐步比较状态与事件；通过磁盘检查点验证恢复，再用导出的命令脚本校验执行及重复水位语义。请求集合属于验证宿主的输入，不属于GameSession；不新增运行时历史缓存。产物包括存档、命令脚本、事件诊断、检查点说明和报告，不生成录像。

CLI仅支持`run`和`verify`。原`replay`模式及`--record`／`--recording`参数明确返回用法错误；不静默忽略，不保留旧录像兼容入口。

`prepare-advance`、`advance-day`及玩家答复仍是会话操作。后台是否完成、转场计时和静止不进入领域状态。保存边界不变：待答或旬内推进阶段不保存，完整旬结算后的稳定下令边界及完成终局可保存。

## 面向玩家交付前的后续要求

录像整体延期，不再作为日常开发、规则修改或阶段收口的维护与验收要求。以后有明确需求时，从起点状态、随机状态及有序操作重新设计；全程回看、时间跳转、接手分支和长期存储范围届时确认。现在不预建接口、检查点索引、分支容器或存储框架。确定性模拟、统一操作、精确恢复和普通存档继续独立维护。

## 验收标准

- [x] 公开夹具CLI下令推进，报告含种子、日志路径、旬数、结束原因、首个失败、耗时及失败码。
- [x] 36旬连续与首次命令后、任务跨旬、跨年前精确恢复结果一致；待执行任务、已消耗随机流、控制、最近记录、年表、水位完整往返。
- [x] 玩家读档更换运行种子并保持已确定任务骰子；同档不同加载可建立不同运行，精确恢复保持种子和任务状态。固定条件骰不受运行种子、命令ID及其他提交顺序影响。
- [x] 默认模式不保存历史命令ID、操作和事件；短流程覆盖保存／恢复，自动记录越过128条上限后验证精确淘汰顺序，玩家年表保留。
- [x] 旧序号跳过且无事件，外部日志格式、种子或会话配置不匹配、未来序号和未知操作拒绝；水位和拒绝语义跨存档保持。
- [x] 存档截断、未知格式、损坏及异常引用拒绝；注入写入失败保留旧文件。
- [x] 集合/键顺序和文化设置不改变诊断语义；保留有序语义；全解决方案和本地190年集成通过。

实际证据与命令见[G02验收](../../docs/history/stages/g02-verification.md)。

## 未决问题

G02范围无阻塞问题。后续阶段已接入人事、战争及外交等生产任务，经济、人物生命周期与终局均可经公开会话推进、保存恢复和验证重放；当前仍不把脚本运行等同于完整战略AI自主对局。录像延期范围见上文。

- [x] 外交报价／接受、联盟邀请、修习报名及处决继任待答时拒绝保存；显式答复继续结算，稳定后可保存。

## 协议与采用边界

未知结构版本拒绝；仅规则版本不同则告警并使用当前规则，当前内容初值变化不覆盖保存的实际状态。规则版本差异的警告显示于客户端或Headless报告（`rulesVersionWarnings`与标准错误），自身不改变成功退出码；警告不进入存档、权威状态、诊断或未保存修改标记。重新保存使用当前规则版本；缺失规则版本仍拒绝。版本常量由[SessionProtocol](../../src/San9.Application/SessionProtocol.cs)维护，本规格不累计逐次格式号。取舍和替代关系见[DEC-SIM-0001](../decisions/DEC-SIM-0001-determinism-and-saves.md)。

玩家读档换运行种子、精确恢复保留两个种子及流状态，详见[随机BEH](BEH-SIMULATION-0002-randomness.md#保存玩家读档与精确恢复)。自动策略状态按当前采用的[AI边界](../original-ai/behavior.md#b30)保存，不保留退出原型的控制配置、录像或回退入口。

### 身份与条件存储

Core的派生任务身份分配水位继续随世界事务提交、回滚和恢复，独立于命令顺序，不由JSON哈希推导。既有命令发起的首个任务仍使用命令ID；派生身份类别由Core保留，命令入口拒绝占用，恢复检查现存派生任务序号非负且小于水位。

存档、命令脚本与槽位不保存内容指纹或整文件完整性哈希；结构、版本、引用、序号与操作接受检查继续有效。逐事件及终态内容比较属于显式诊断。
