## 适用范围

适用于势力与军团的直接玩家控制、委任方针、自动工作批次、自动军团管理计划、资源预算、共享命令复验，以及控制权或目标关系变化后的状态清理。不规定每旬登用、调动和外交权限。

## 原作基线

每条军团记录都有直接控制状态；玩家势力的根军团进入交互任务，普通委任军团和电脑势力根军团进入自动任务。势力级玩家归属从普通军团归一到根势力查询。交给电脑控制会清除直接控制、写入无玩家顺序并清除当前地图选择和交互上下文。

委任方针为一般、内政、打倒目标势力和攻略目标设施。后两者分别持有类型化目标；目标因关系、联盟、删除或归属变化而失效时，方针与目标一同回退到一般委任、无目标。

自动任务顺序消费工作表，并在每个实际产生的子任务完成后继续。二级工作表由独立运行时类型选择，不由委任方针选择。自动军团管理按直属城市和在职人物形成都督/城市组，按人物比例分配资金，按兵力比例分配兵粮；总兵力为零时兵粮改按城市比例。自动命令与交互军团命令共享最终校验和执行边界。

## 重制行为

重制版使用显式 `ControlMode`、`DelegationPolicy`、`DelegationTarget`、`AutomaticWorkProfile` 和 `CommandPlan`，不复刻原作的位字段存储。直接控制和势力归属是两个查询：前者决定当前军团由交互还是自动任务驱动，后者决定其所属玩家势力。

委任目标使用带类型的联合值，禁止把势力 ID 当作设施 ID 解释。自动规划只能产生候选命令；提交时必须重新读取当前状态并经过与交互命令相同的验证器。预算修饰因素采用领域命名和配置表达，不把尚未确认的原作字段名写入产品模型。

## 状态与不变量

- 输入与前置条件：有效势力根、活动军团、控制模式、委任方针、匹配方针的可选目标，以及可用的人物、城市和资源快照。
- 状态变化：切换直接控制；更新委任方针/目标；按有序工作表产生并执行自动命令；失效时清除目标；交出玩家控制时清除交互选择和上下文。
- 始终成立的不变量：每个普通军团仍属于唯一根势力；直接控制与势力归属不混用；定向方针的目标类型匹配；无效目标不得进入后续计划；自动与交互命令执行前使用同一领域验证；失败命令不写回。
- 失败或无效输入行为：目标类型错误、目标已失效、都督/辖区/容量不再有效或资源快照过期时拒绝命令；定向目标失效时回退一般委任；切换控制权后旧交互上下文不可继续提交。

## 调度与预算规则

- 工作表按配置顺序尝试；没有候选的工作项可以跳过，产生子任务的工作项必须完成或失败后才进入下一项。
- 工作表配置与委任方针分离；一个方针不直接等价于一张完整工作码表。
- 自动军团规划只有在根直属城市达到阈值时建立新分组，目标军团数受显式上限约束；既有无效/多余子军团可以先产生解散计划。
- 资金预算按分组在职人物占比取整；兵粮按兵力占比取整，总兵力为零时按城市占比取整。
- 取整后的命令仍须满足资源守恒、根军团保留和 `BEH-GOVERNANCE-0001` 的所有对象归属不变量。

## 示例与边界

- 玩家势力有一个根军团和两个普通军团：根军团进入交互任务，两个普通军团进入自动任务；三者的势力级玩家归属均为真。
- 把当前势力交给电脑：根军团改为自动控制，旧地图选择和命令上下文失效；随后从旧界面提交命令必须失败。
- “打倒敌势”的目标与本势力结盟：该军团立即回退一般委任并清除目标，不在下一批自动工作中继续攻击该势力。
- 自动规划后、执行前都督被调走：共享验证器拒绝该候选，不创建半完成军团，也不扣减资源。
- 根军团没有兵力：新军团兵粮按所选城市数占比预算，随后由共享执行器平衡实际资源差额。

## 验收标准

- [ ] 根军团、玩家委任军团和电脑根军团的交互/自动分流分别有测试。
- [ ] 直接控制查询与势力级玩家归属查询在普通军团上返回不同但一致的语义。
- [ ] 四种委任方针及两种目标类型由强类型模型和序列化测试覆盖。
- [ ] 关系、联盟、设施删除和对象 ID 失效均原子清除方针与目标。
- [ ] 有序工作表保证单个子任务完成后再推进，空候选可以跳过。
- [ ] 自动军团分组的人物、城市阈值、数量上限和都督有效性有确定性夹具。
- [ ] 资金人物占比、兵粮兵力占比和零兵力城市占比三条预算路径均有取整测试。
- [ ] 自动计划与交互请求经过同一验证器；计划后状态变化可使提交失败且零写回。
- [ ] 控制权切换后地图选择、当前势力和命令上下文均失效。
- [ ] 测试夹具不依赖原版文件、地址或内部工作码。
