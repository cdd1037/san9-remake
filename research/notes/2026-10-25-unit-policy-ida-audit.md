## 输入与共同量

**原作事实。** `460E50/70/90/B0` 分别查询 `0x1000/0x2000/0x4000/0x8000`；`45EAB0/D0/F0/45EB10` 对应写入敌接近攻击、自主撤退许可、追击许可、事后攻击。`4EB0D0` 维护四组互斥选中状态。当前 Importer 的四位解析、`UnitPolicies` 构造参数次序、界面字段及公开命令接线一致，没有开关反接。

`A` 是主将性格：0 莽撞、1 刚胆、2 冷静、3 慎重，不是野心。`R` 为双方总评估战力的整数百分比。`4355A0` 的连续指令与 `463B90 → 41D3C0` 确认总评估值为 `max(1, 基础战力×现兵/100)`，响应入口采用攻击程度 1；不能依据 Hex-Rays 初始栈参数恢复把算式反过来。当前 `CombatMath.PolicyStrength` 和性格裁决公式对应此含义。规则不抽取服从概率，也没有自主撤退冷却。

## 每日调度：更正旧旬级结论

**原作事实。** `50A760` 每个模拟日串行建立子任务：

1. `50A170` 先经 `453B20` 扫描全体自主撤退，再经 `453B50` 扫描全体追击，随后逐队执行军事任务及移动。
2. 每日预处理 `50E8F0` 中，`50BD00` 维护活动单位标志，再经 `50AB70 → 453AF0 → 464910` 执行敌接近响应。
3. 后续每日单位命令阶段处理普通攻击；最后 `50A340` 推进日期。非旬首继续下一日的同类任务。

因此敌接近也是每日处理。旧 RE-0087 将 `610B20` 错归为前一逐旬任务虚表的长表项，得出“旬级迎击”的结论，本轮以独立构造器／虚表／父状态机纠正。当前 `ResolutionPipeline.XunUpdate → ApproachXun` 每旬一次，与原作频率不符。

**更正上轮核对结论。** 原作追击取消只清当前目标和辅助字段，不记录“本日禁止再迎击该目标”；随后的每日迎击可以再次选中它。上轮公开推进诊断中同日出现 `pursuit-resume → enemy-approach`，只证明与现行 [G07](../../specs/behavior/BEH-WAR-0001-movement-and-command-lifecycle.md#g07-出征方针)“当日不重新迎击”句子的冲突，不能认定为偏离原作的缺陷，也不能据此添加原作没有的屏蔽状态。

## 敌接近

**原作事实。** 入口 `464910` 要求事件 38／39、状态 1／8、非建设／输送、未主动或被动交战；已有当前目标或主目标已在候选表时不重新改指。普通返回 39 可响应，持续自主返回 52 不可响应。候选经过活动标志、方向／视野感知及外交／原目标同根资格，按战力键降序取首，而非最近距离。`0x800000` 维护避战通知的重新出现／抑制状态。

| 方针 | 攻击条件 | 未满足时 |
| --- | --- | --- |
| 攻击 | `A<2` 或 `R+(A==2?25:0)>100` | 违令避战 |
| 无视 | `A<2` 且 `R-(A==1?25:0)>=100` | 依令避战；满足条件则违令攻击 |

当前公式、普通／自主返回身份及交战门已有对应实现。当前统一矩形半径、最近距离与 ID 顺序代替原作感知／战力候选，G07曾将它们声明为重制选择；本轮后续追溯未找到用户明确确认依据，不能据此豁免原作差异，详见文末确认来源更正。它们与误判每日频率分别登记。

**额外入口／记忆差异。** 原作候选使用每日设置的活动 `mask8`，不直接要求出发等待为零，也没有当前 `MilitaryCombat.ValidTarget` 的当日阵型攻击资格过滤。当前只要 `EngagementTargetId` 非空就跳过；原作仅在当前目标仍处于基础感知异属表时跳过，离开感知后可改指别人。避战提示的缺敌标记在原作行动入口判断前更新，当前则在多个活动／命令门之后更新。后三类条件不能仅以“距离与同距选择”概括为已采用差异。

## 自主撤退

**原作事实。** `464E00 → 464E08` 要求有效军事事件 38..52，但排除 52；状态为 1／8，返回对象和主将有效。事件 39／51 还要求有效当前目标 `45F0C0()!=-1`。因此原作并非允许所有普通返回再次撤退：纯返回被排除，普通返回临时迎击的子集仍可转为自主返回。

记 `M` 为士气、`T` 为本队现兵、`E` 为威胁来源现兵和，士气条件先判：

| 许可 | 条件 | 结果 |
| --- | --- | --- |
| 是 | `M<4A+25` | 依令低士气撤退 |
| 是 | 上项未中，`T<300A+2000 && E>T` | 依令兵少撤退 |
| 否 | `A>=2 && M<4(A-2)+25` | 违令低士气撤退 |
| 否 | `A>=2`、上项未中，`T<500(A+1) && E>T` | 违令兵少撤退 |

`E` 经 `474CD0/474560` 枚举通用单位域，包含合格驻军。排除相同根势力后，还要求**来源能用其普通攻击射程触及本队**；这条链不按关系、联盟或攻击请求排除非同根来源，也不要求出发等待为零。当前 `NearbyEnemies` 只统计自动敌对野战部队，以统一 `PolicyRadius` 代替来源射程：驻军与外交域差异没有找到独立采用说明，不能统称几何或同距选择。

当前数值公式一致，但所有 `Return` 都被排除，遗漏原作有当前目标的普通返回子集。原作先发布反馈，再尝试 `4642B0`；当前只有返回成功才发布。后者及失败保留原任务／次日重试是 G07 已记载的当前行为，但尚未找到用户明确确认这一差异的依据。不将原作提前提示视为已成功转换，也不因现行文档如此便认定用户已批准改变反馈时机。

## 追击：持续返回身份与一次性触发不同

**原作事实。** `465160` 要求本队事件 38／39、状态 1／8、当前对象是事件 52，并带 `0x40000`。事件 52 表示持续自主返回；`0x40000` 是新转换后的短暂响应标志，`50BD00` 在当日追击扫描后、敌接近前清除。两者不能合并为同一个持久布尔值。

| 许可 | 当前目标与原目标 | 性格／近邻条件 | 结果 |
| --- | --- | --- | --- |
| 是 | 相同 | 任意 A | 继续追击 |
| 是 | 临时目标 | A=0 | 继续追击 |
| 是 | 临时目标 | A!=0 | 清临时目标，恢复原任务 |
| 否 | 相同 | A=0 且近邻候选表为空 | 违令继续追击 |
| 否 | 相同 | 其余 | 自主返回 |
| 否 | 临时目标 | 任意 A | 清临时目标，恢复原任务 |

**近邻表不排除正在撤退的目标。** `461CA0` 只移除本队，随后按已出发与公共敌对等资格筛选。目标刚转自主返回仍保留活动标志；它在范围内时本身就能使表非空。当前两处 `Any(u => u.Id != targetId)` 将其剔除，导致莽撞部队在原作应返回时擅自追击。

当前 `AutonomousReturn` 保留事件 52 的持续身份，但没有表达短暂响应标志；后续日仍会重新裁决已经处理过的自主返回目标。当前仅用同批改令事件限制“继续追击”消息，不能同时保证规则只裁决一次。应在后续实现中分别表达持续返回状态和一次响应资格，不用事件列表推断领域状态。

追击近邻表原作使用公共自动敌对和活动 `mask8`，没有迎击感知或当日阵型攻击门；当前复用 `Nearby`，额外允许与明确目标同势力的非自动敌对对象，并加当日攻击资格及等待为零条件，候选口径也不同。

## 事后命令

**原作事实。** 目标变化通知 `4687B0/468570` 进入 `467190`，另有批处理入口。首先经 `461A90` 将普通／高昂以外状态恢复普通并清时长，然后处理保存的军事命令。原攻击仍合法则保留；原目标成为己方可驻人建筑则普通返回进入该建筑。建设／输送／返回目标失效分别走任务收尾，不一律开启事后找敌。

原攻击目标失效后，`461D50` 只填充部队候选：本队矩形外扩50相交、非自身、已出发、非排除势力、公共自动敌对，并且 `461490 → 44A680` 按本队陆／水机动力求得 **ETA≤8**。按距离选最近一个后才裁决，不因最近者拒战继续尝试次近者。建筑表只构造未填充，不能将比较代码解释为实际会新选建筑。

| 结果 | 条件 | 动作 |
| --- | --- | --- |
| 0 | 无候选 | 返回 |
| 1 | 攻击许可且满足敌接近同式攻击门 | 依令设置新的主攻击 |
| 2 | 攻击许可但不满足 | 违令拒战，返回 |
| 3 | 选择撤退且不满足违令攻击门 | 依令返回 |
| 4 | 选择撤退但满足违令攻击门 | 违令设置新的主攻击 |

当前公式和只新选部队一致，但没有候选 ETA／可达过滤；保留异常状态并延后事后处理，也不同于原作入口恢复状态。当前缺少有候选依令／违令、无候选的结果语义，全部折为通用攻击或返回。

原作事后候选的 `mask8` 表示已进入每日军事处理，不等同于等待天数为零。当前 `Nearby` 只检查 `DepartureDaysRemaining==0`，未消费已有 `HasEnteredDailyCycle`；此差异与 ETA 门分别存在。

原作 `467FA0` 是转属接收后的独立动作重选，不读取四项方针，而且填充建筑候选。当前事后反馈却与它共用 `10080..10082` 等消息，混淆了两个入口；这不能用“已有反馈”判定对齐。
