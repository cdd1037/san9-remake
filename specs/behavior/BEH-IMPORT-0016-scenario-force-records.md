# BEH-IMPORT-0016：剧本势力（`forc`）记录解析

- 状态：已确认（记录边界、主要字段、引用派生、势力兵法标志和外交数组；旗标逐位标签仍待验证）
- 负责人：项目开发者

- 关联证据：[RE-SAN9PK-0021](../../research/findings/RE-SAN9PK-0021.md)
- 关联决策：[DEC-DATA-0001](../decisions/DEC-DATA-0001-content-pipeline.md)

## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `forc` chunk 的记录边界、运行时引用、旗标查询、外交数组和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不把旗标位直接翻译成未经验证的中文界面标签，也不把 48 位势力兵法标志的每一位擅自命名为具体兵法或其他业务字段。

## 原作基线

`forc` chunk 位于正式剧本数据偏移 `0x8C06E`，包含 50 项，每项 86 字节，共 4,300 字节。运行时势力 ID 使用记录序号 `0..49`。文件按小端顺序包含三个 `u32`、九个 `u16`、6 个字节和 50 个字节：

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| ---: | --- | --- | --- |
| `0x00` | `u32` | `money` | 势力金钱；原样保留 |
| `0x04` | `u32` | `food` | 势力粮食；原样保留 |
| `0x08` | `u32` | `flags` | 状态/分类原始旗标；提供原始位查询和已确认的运行时类别码 |
| `0x0C` | `u16` | `serialized_id` | 原始序号槽位；原程序读取后丢弃，运行时 ID 使用记录序号 |
| `0x0E` | `u16` | `owning_force_code` | 所属势力代码；`0..49` 为引用，其他值的运行时所属势力回退为当前记录自身 |
| `0x10` | `u16` | `country_title_code` | 国号代码；`0..19` 为引用，其他值为空引用 |
| `0x12` | `u16` | `leader_code` | 军团长/领袖武将代码；`0..849` 为引用，其他值为空引用 |
| `0x14` | `u16` | `base_trust` | 基础信望；原样保留 |
| `0x16` | `u16` | `trust` | 当前信望；原样保留 |
| `0x18` | `u16` | `related_force_code` | 关联势力代码；`0..49` 为引用，其他值为空引用；具体业务名称未确认 |
| `0x1A` | `u16` | `rank_group_code` | 官爵组代码；`0..8` 为官爵组引用，其他值为空引用 |
| `0x1C` | `u16` | `color_code` | 势力颜色代码；原样保留 |
| `0x1E..0x23` | 6 字节 | `force_tactic_flags` | 48 位势力级兵法可用标志；运行时会与武将自身习得兵法合并；逐位映射及高 7 位用途仍待确认 |
| `0x24..0x55` | 50 字节 | `diplomatic_relations` | 按势力索引的 50 项关系值数组；外交好感度。 |

已确认的 `RuntimeTypeCode` 派生优先级为：含 bit 6 时为 `1`，否则含 bit 5 时为 `3`，否则含 bit 4 时为 `2`，否则为 `0`。该数值是运行时分类结果，不等于截图中的中文类型标签。

注:只有当军团为主军团时，国号、颜色、官爵、信望、基础信望、外交及兵法等数据才有意义，此时这些数据表示的是势力数据。

## 重制行为

导入器必须生成 50 个按文件顺序排列的势力定义，并保留所有原始字段。提供以下不覆盖原始代码的派生视图：

- `OwningForceId`、`CountryTitleId`、`LeaderId`、`RelatedForceId` 和 `RankGroupId` 按目标范围返回有效引用或空值；`RuntimeOwningForceId` 在所属势力无效时回退到记录自身 `Id`。
- `RuntimeTypeCode` 按已确认的 bit 6/5/4 优先级计算。
- `HasFlagBit(0..31)` 查询原始 32 位 `flags`；不得为未确认的位赋予业务名称。
- `ForceTacticFlags` 必须完整保留为 48 位值，并提供 `0..47` 的原始位查询；不能按当前样本默认值清零高位。
- `DiplomaticRelations` 必须完整保留，不能按当前样本默认值压缩或丢弃。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整 `S9SC` 剧本流。
- 状态变化：读取 `forc` chunk 后产生 50 条势力记录；派生引用不修改原始代码。
- 始终成立的不变量：chunk 大小为 `4,300` 字节；每项完整消费 86 字节；记录 `Id` 为 `0..49`；尾部数组长度固定为 6 和 50。
- 引用派生边界：势力 `<50`、国号 `<20`、武将 `<850`、官爵组 `<9` 才视为有效；无效代码保留原值并提供空视图。
- 失败或无效输入行为：chunk 大小或记录边界异常时抛出 `InvalidDataException`；`HasFlagBit` 的参数不在 `0..31` 时抛出 `ArgumentOutOfRangeException`。

## 示例与边界

`D_Sce002.S9` 第 0 条对照值包括金钱 `3100`、粮食 `30800`、旗标 `0x10`、基础信望 `150`、当前信望 `156`；外交数组以 `100, 60, 60, 60, 50, ...` 开始。`0x10` 同截图“盟友”勾选相符，但这仍是待单变量验证的推断，不是 bit 4 的正式中文命名。`force_tactic_flags` 的 48 位宽度由记录边界、编辑器势力兵法复选区和运行时合并路径共同支持。
