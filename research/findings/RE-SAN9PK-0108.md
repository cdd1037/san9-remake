- 样本：`SRC-SAN9PK-TC-101`
- 关联：[兵法最小间隔](RE-SAN9PK-0102.md)、[单挑战后写回](RE-SAN9PK-0105.md)、[单挑规格候选](RE-SAN9PK-0107.md)

## 边界与方法

本轮在项目主数据库 `research/analysis/San9PK-TC-101.i64` 对正在运行的 `San9PK.exe` 设置执行断点，只读取当前进程寄存器、对象字段和已加载代码字节。目标是闭合 `set_duel_participant_tactic_intervals(0x4FF0A0)` 的虚调用输入，并核对 `resolve_duel_combat(0x503AC0)` 末段成长分支的对象身份。未修改程序字节、游戏状态或工作区外样本。

## 事实：单挑间隔输入是部队士气

断点 `0x4FF0EA` 位于人物关联对象虚表 `+0x84` 调用处。当前进程实际目标为 `get_record_morale(0x45E410)`；该函数直接返回关联对象 `+0x38`。暂停样本中返回值为 `80`，而当前人物的当前有效武力、基础武力和统率分别为 `103/98/83`，排除了人物基础能力解释。关联对象 `+0x38` 又与既有士气读取、调整和 `100` 上限链一致，因此该输入可稳定命名为当前部队士气。

令 `M` 为人物当前所属部队士气，`T` 为 `compute_nonlinear_ability_score(0x41D2A0)`：

```text
T(x) = max(0, 3*max(x-90,0) + 2*min(x,90) - 160)
     + max(0, min(x,80)-60)
     + max(1, trunc0(min(x,60)/2))

interval = min(10, trunc0((100-T(M))/10) + 5)
```

暂停样本 `M=80` 时 `T(M)=50`、间隔为 `10`；`M=100` 时 `T(M)=100`、间隔为 `5`。双方全部参战人物都在阵亡、俘虏和伤势分区前按各自所属部队士气写回；被俘者随后再清零间隔。

## 事实与缺陷裁决：成长分支检查错对象

当前进程在 `0x5049E2` 命中连续有效代码，排除了 IDA 把数据误定义为指令的可能。该循环中 `ESI` 是逐组胜者，`EDI` 是对应败者：

```text
if winner.status == dead
   and winner.saved_martial < loser.saved_martial:
    increase_base_martial(winner, 1)
```

机器指令在 `0x5049E2` 检查 `[ESI+0x84] == 8`，`0x504A1A` 比较胜者与败者保存的低 16 位武力，`0x504A24` 又以 `ESI` 为成长对象调用强制基础武力增长。暂停样本中胜者状态为 `3`，败者已被俘且状态为 `4`，实际控制流按预期跳过该段。

这与同函数已闭合的不变量直接冲突：阵亡候选来自失败侧/配对败者，胜者不会由本链写成死亡状态；赢过前一组者还会因临时 `0x10000` 位被阵亡谓词排除。项目据此将该段明确裁决为原版错对象 bug，而不再保留为一般“可达性待验证”。

此前曾推测原始意图是检查 `loser.status == dead` 后奖励低武力胜者；该解释已被后续跨版本证据取代，不再作为当前设计意图结论。繁中非 PK 版在同一位置没有该状态检查，直接执行“单挑开始时当前有效武力较低的分组胜者基础武力 +1”，第三方资料也只以武力高低为条件、不要求败者阵亡。重制版不复制 PK 样本的错对象门，也不采用“必须阵亡”的额外推断；产品规则、备选方案与验收见 `RE-SAN9PK-0165`、`DEC-DUEL-0001` 和 `BEH-DUEL-0003`。

## IDA 同步与回读

- 已有动态命名 `get_record_morale(0x45E410)` 回读成功。
- `0x4FF0A0/0x4FF0EA` 注明间隔公式及虚表 `+0x84` 在运行时解析为士气 getter。
- `0x5049C0/0x5049E2/0x504A24` 注明胜败对象身份、错误的胜者死亡检查及其成长后果。
- 原位保存后回读名称和五处注释；程序字节修改为 0。

## 结论

- 事实：单挑参战者兵法间隔由其所属部队当前士气经非线性分值派生，不是人物武力、统率或其他基础能力。
- 事实：现有机器码只会尝试给“已经死亡的低武力胜者”增加基础武力。
- 缺陷：死亡门检查胜者而非败者，与本函数的胜负/阵亡状态机不一致，明确登记为原版错对象 bug。
- 规格：间隔公式与低武力胜者成长进入 `BEH-DUEL-0003`；PK 样本的错对象分支不得成为实现依据。
