# BEH-ECONOMY-0001：经营命令与周期经济

- 状态：已确认
- 最后更新：2026-10-24
- 关联决策：[DEC-PROJECT-0002](../decisions/DEC-PROJECT-0002-selective-inheritance.md)
- 范围：G03普通剧本经营、兵员与账户闭环；包含城市商人和粮食买卖补齐；战争补给和人事命令另见各自规格。
- 证据：[RE-0095](../../research/findings/RE-SAN9PK-0095.md)、[RE-0096](../../research/findings/RE-SAN9PK-0096.md)、[RE-0098](../../research/findings/RE-SAN9PK-0098.md)。基础内政计算沿用[BEH-DOMESTIC-0001](BEH-DOMESTIC-0001-base-development-effect.md)。

## 状态与不变量

只读人口与钱粮预测采用实际结算的参与范围：排除休眠人物、休眠／已毁据点，承运兵员沿当前归属账户统计。巡查预览与城市目录共用Core人口查询，允许替换目标城市民心作预览，但不改写总民心或世界状态。钱粮预测跳过距剧本起始不足30天的收入边界；异族拥有城市的账户预测采用资金30000及全势力现役＋伤兵粮食目标覆盖库存，没有城市的账户不获得该补给。覆盖型预测的`Income`表示扣除预测开支后的余额到补给目标的变化，可以为负数。预测保持静态当前状态假设，不模拟未来作战、人口变化或随机。

据点所属军团有独立金库时使用该账户，否则使用所属势力账户。军团引用必须存在且归属一致；据点没有资源副本。所有收支经过同一账户服务，事件包含账户、资源、原因、关联对象、请求变化、实际变化、短缺与饱和损失。普通存档只保存当前状态，事件仍由显式录像持有。

四项内政、征兵和训练即时提交。出发据点混乱或处于近距交战时禁止执行；准备资格和最终提交均从当前世界复验，不以客户端菜单禁用代替领域校验。依据见[RE-0095](../../research/findings/RE-SAN9PK-0095.md)与[RE-0096](../../research/findings/RE-SAN9PK-0096.md)。参与者为1至5个不同身份的当前同势力驻留在职人物，均未行动且无持续任务占用；城市限定巡查、商业、开垦、征兵，修筑与训练允许设施。每个项目每旬一次，旬恢复清除全部使用状态；拒绝不改变任何状态、序号、事件或随机。所有计算读取提交时当前能力、资金和容量，外部不提供费用、效果或能力。

## 重制行为

四项内政每人费用50；巡查上限1000，其余使用据点定义上限。多人组合由转换器输出运行时人物身份有序对、资格要求；领域不识别列传码。**重制选择**：参与者按对应当前能力降序、同能力按人物ID升序（2026-09-19统一人物顺序选择），君主独立优先；身份仅用于破平，不参与能力分数，取消原作打包排序键隐含的编号范围及君主200能力分界。按此顺序枚举参与者有序对，匹配后先掷10%，再检查身份资格与至少一人距君主相性不超过5；未成功再按`5*(最大同相性人数+1)`掷骰。单人或基础效果已满不消费组合随机。相性环长150。修筑给类别5、6各基础熟练度1；训练给0至4各1，精通乘3，饱和1000。

征兵以当前统率和S、人数n计算`Q=3*(100*S/(n+4))/2`，按兵役人口、`10*账户资金`和兵力剩余容量共同夹取D。D为0拒绝，费用`(D+9)/10`，兵役减少D、现役增加D。士气按原兵力和新兵基准`floor(sqrt(信望))+40`加权。**重制选择**：消除原作创建与提交间少付款、满编损失兵役的竞争窗口，兵员严格守恒。

训练使用执行统率`max(1,2*(min(A,60)/3))+max(0,min(A,80)-60)+max(0,2*A-160)`。令S为执行统率和，G为新兵基准士气，R为`floor(sqrt(士兵+10000))`，K为`10*(11-n)*(G-当前士气+100)/100`，基础增量`min(100-当前士气,n+(S*K/R)/10)`；随后按训练组合规则加倍并饱和100。无兵或士气满拒绝，不扣钱粮、不增加兵数。

## 钱粮容量

**重制选择（2026-10-24）：** 为扩大可保留的钱粮储备，每个军团账户的资金、兵粮常规入账上限分别提高到1000万，下限为0；替代原作及此前重制的100万上限。Core的`TreasuryRules`统一定义容量、可接收数量和余额投影，实际收支、只读预测、买卖资格、开局倍率／增量封顶和编辑范围共同使用，不在各消费者重复定义。

普通入账只接收剩余容量，差额报告为饱和损失；军团无损合并仍可超过常规上限，超过`uint`可表示范围时原子拒绝。已有超额库存不因普通入账或预测而削减，支出正常扣除；降至上限以下后恢复接收。各账户独立封顶，势力合计不再另封顶。存档沿用现有数值字段并完整保留余额。

外交单次赠与／赔偿金额限制、异族季度资金和年度补粮规模、人口上限属于独立规则，不随库存容量放大。

## 周期与边界

新局选择特殊势力时，创建世界必须清除所选势力的`IsBarbarian`，随后按普通势力规则计算收入与收获；未选势力保留内容定义的身份。该归一化只发生在新局创建，不修改内容包，不在读档、委任或经济结算时重新推导。依据为[RE-0021的开局选择链](../../research/findings/RE-SAN9PK-0021.md#2026-09-12新局选择异民族势力的标记清除)。验收须覆盖双方选择对照、普通收入和特殊补给、跨七月及保存重放。

每旬前置更新支付在职非君主俸禄，按俸禄降序、身份升序；官职目录提供金额，无官职为1。按驻留据点解析账户。足额支付，否则保留资金并报告整笔短缺。恢复原作双向忠诚关系：欠薪以`5*(16-义理)`百分比减1；足额支付以`(信望/10-人物与君主相性距离+50)/20`百分比加1，整数逐步截断，相性距离封顶50，缺少君主取50。每名符合俸禄资格者固定消费一次命名运行流`personnel-salary-loyalty`，概率为0、忠诚已到0/255仍抽样；只在实际变化时发布忠诚事件。忠诚饱和0至255，不形成隐含债务。本项替代此前欠薪必减1、支付不增加的未经平衡验证选择；依据见RE-0098本次补证。

每日命令前扣粮，驻兵每据点`ceil((现役+伤兵)/500)`、野战兵每部队`floor(3*(现役+伤兵+333)/1000)`，按实际归属账户汇总扣除。排除的设施由规范化规则字段明确标识。钱粮收支遵循上述统一容量规则。**2026-09-22按已采用规则修正旧文**：启用军事规则的会话，仅当本日粮食需求未足额支付时进入断粮分支；恰好足额支付后余额为0仍算本日有粮，不产生断粮损耗。合格野战单位或耗粮守军士气减3、现役损失向上取整1%，并按有效阵型／守军比例转伤兵；溃败部队有粮也进入同一分支，两者不重复。地利及异民族不豁免。账户统一承担，不能因单位遍历顺序抢粮；零兵／零士气部队复用无胜者终止与人员安置，驻军不凭缺粮直接换属。此规则替代旧`ceil(10*缺粮/需求)`强度选择；证据和恢复规则见[WAR-0004](BEH-WAR-0004-normal-combat.md#周期士气与地利)。

季度首日且距剧本起始至少30天，先更新人口，再发资金；七月同条件另发收获。整数运算逐步截断并使用宽中间量。总非兵役人口a、城市民心总和b、军事人口c（兵役、驻兵及野战兵）：新增兵役总量`f=(max(0,a-c+99999)/100000)*(a/100)/10`；每城按民心比例分配。民心总和为0时分配0，非兵役增量仅保留最低人口恢复；其他城市非兵役增量`max(30000-人口,民心*(a/20)/b-人口/20)`。人口上限100万，兵役自然增长上限50万。2026-09-13重制选择：兵员回收允许兵役人口超过50万，存档完整保留；自然增长在超限时为0，不削减既有存量。兵役自然新增不从非兵役扣除，与原作两个独立人口池一致。

普通势力每城令R为`floor(sqrt(人口+兵役))`：季度收入为`((R+600)*商业*6/1000)*(2500-商业)/2500`；年收获为`((R+300)*开垦/10)*(4000-开垦)/4000`。超出公式适用范围的内容拒绝加载。异族身份读取当前势力`IsBarbarian`，不判断势力或城市编号；恢复原作特殊经济：有城市的账户季度资金设为30000，七月粮食设为`min(1000000,max(100000,所属整个势力的驻兵与野战兵总数))`。这是赋值，不是每城叠加，也不与普通收入同时发放；同账户只结算一次，超过目标的库存亦下降并以独立原因报告实际变化。仍遵守季度/七月和开局至少30日门，独立军团使用自己的账户。G07已将伤兵并入日粮耗、异族年度补给和兵役人口核算。本项替代此前统一普通经济的未经平衡验证选择；依据见RE-0098本次补证。

巡查后按基础信望、城市贡献、玉玺及拥立贡献重新计算信望并饱和1000；每城贡献`((人口+兵役)*max(0,民心-300)/1000)/5000`。基础信望与相关规则身份必须由内容保留，不能从当前信望倒推。周期人口更新后同样重算。新局前置只执行一次，恢复不重复支付或增长。

### 信望派生值的统一维护

总信望由当前基础信望、活动城市人口／兵役／民心、君主持有的已发现玉玺及皇帝所在城市归属派生。运行态保留`Trust`作为便宜的读取字段，由共同状态写入入口在依赖改变后同步维护；业务规则不得单独写总值或手工要求重算。城市转属更新双方，皇帝继任／废立／移动及旅行任务变化、君主更替、玉玺转移／发现／持有人启用状态也纳入依赖；无关属性和日期推进不触发重算。后续同日／同旬判定必须立即读取新值，不能等旬后置清理补算。

新局在首次规则执行前重建总信望；稳定恢复在资格校验前按当前规则和输入重建，不信任序列化的派生总值，也不新增操作序号、世界修订或重复经济结算。界面及保存仍可携带总值作为快照投影。信望变化通知在统一阶段／命令收尾发布，合并该段内同势力的中间写入；查询不产生事件。拒绝事务中的派生更新与通知一并丢弃，不影响已提交状态。

验收包括出兵请求到期后的实际俸禄忠诚、攻城损失后的即时查询与后续旬判定、征兵／兵员回收、转属／玉玺／皇帝全部依赖、旧对象副本写回、拒绝与保存恢复；以普通190年及多部队战斗测量实际重算次数、分配和整旬耗时。

## 验收标准

- [x] 重复身份、跨城、敌属、占用、资金不足、满值均拒绝且零副作用；五人、精通、组合概率和恢复后的随机连续性有独立预期。
- [x] 钱粮均允许超过旧100万边界，1000万附近的接收／饱和损失正确；满库及超额库存预测与实际结算一致，势力汇总不额外封顶。
- [x] 独立军团与势力账户不串账；征兵容量和费用守恒；训练不增兵；资源事件能够解释实际变化、短缺与饱和。
- [x] 开局、普通旬、季度、七月、跨年、29/30天门分别验证；原作竞争窗口和本规格重制选择明确区分。
- [x] 俸禄双向概率及忠诚0/100/255、异族赋值与多城账户、固定驻军十年补给，以及超大ID和高能力下的组合排序有独立边界验证。
- [x] 公开场景与190年内容经正式命令经营一年，确定性简单策略实际经营补员；连续、磁盘恢复、日志及录像重放结果一致。

## 在途救援的军事人口

季度军事人口包含城市兵役人口以及全世界据点、部队、救援去程／返程任务持有的全部现役和伤兵。无主据点驻兵仍参与全局人口核算；势力年度补给只统计本势力持有的兵员。任务中的现役在交付、归队或遣散前始终是活兵，不能因离开据点而从人口核算消失，也不能同时计入来源据点和任务。

季度人口与异民族七月补给复用共同兵员统计入口，伤兵计入这两项；外交／事件等既有现役资格继续排除伤兵。去程3000及未交付返程剩余者均纳入。仅转移载体不能改变同一时点人口公式的输入；测试覆盖跨十万阈值的季度增长和包含伤兵／在途现役的年度粮食赋值。

救援去返程按共同军团账户参与日粮耗和断粮结算，现役与伤兵随任务保存并移交，见[救援后勤](BEH-STRATEGY-0002-unit-status-and-reinforcement.md#在途补给与兵员损耗)。

## 未决问题

俸禄忠诚与异族周期补给恢复上述原作关系；内政排序采用显式语义。完整战略AI与额外地理补给线尚未实现，不将零粮可运行作为经济可持续验收。

巡察界面已接入一次即时命令提交及完整消息编排。领域结果保存加倍类型、发言参与者及组合伙伴；表现层依据结果生成普通回应、组合双方对白或相性加倍／百姓回复，然后报告民心与派生增兵役变化，最多追加一条共用提示。显示随机独立于规则随机，翻页不重算或重复执行命令。巡察「我们的英雄」仍只是相性成功后三选一的候选，证据见[RE-0095](../../research/findings/RE-SAN9PK-0095.md#2026-09-12巡察我们的英雄回复时机)，操作、声音及验证边界见[巡察界面](../../docs/ui/patrol-presentation.md)。商业等其他经营界面不随本次扩大接入。

输送载荷沿既有承运规则保存，只有实际抵达指定己方据点才能卸入目标账户；载荷不算作出发势力已可用粮食，也不自动供给沿途部队。每日命令前先耗粮，日地图阶段再卸货，故补给到达只阻止后续日的缺粮损失，不追溯恢复当天士气。目的地失效沿既有返城/待命规则保留载荷，不向新所有者卸货。当前补给覆盖由势力/军团账户决定；不将未实现的地理封锁、补给线截断或围城断粮作为既有行为。

## 当前粮价

当前粮价表示每1资金对应的兵粮数，是世界持久状态；初值由内容指定且必须为正。可选市场定义提供12个月各自的有序正整数候选池，重复值保留其权重，每旬世界更新以独立`food-market`稳定随机流选一次；初始下令前准备亦更新，恢复稳定存档不重新更新。未配置市场时保留固定初值。原作TC101重置值1、月表与旬刷新证据见[RE-0097](../../research/findings/RE-SAN9PK-0097.md)及[商人专项](../../research/findings/RE-SAN9PK-0130.md#2026-09-20商人投资专项)。市场规则读取当前内容定义，当前值与随机状态进入保存和状态哈希；商人粮食回报读取当前值，不自行重抽市价。

## 城市商人与粮食买卖（2026-09-20补齐）

城市定义维护每旬商人在场概率，0表示不出现、100表示常驻，其余概率每旬以独立命名随机流按城市身份顺序各抽一次；TC101常驻标志转换为100，其他城市为20。设施不配置商人。当前在场状态与本旬交易已用状态属于城市运行时，旬准备清除使用状态并刷新在场，新局同样准备，稳定恢复不重抽。地图与悬浮信息卡沿原作仅在商人常驻（概率100）时显示商人图标，并优先于修行图标；临时驻在不显示商人图标，不遮挡修行图标，皇帝图标可共存。交易资格仍读取当前在场状态，不以显示图标驱动。

买进／卖出同样禁止在混乱或近距交战城市执行，报价与提交共用此限制（[RE-0097](../../research/findings/RE-SAN9PK-0097.md)）。买进／卖出由明确方向、城市、1至5名不同参与者和正整数粮食量组成；只允许己方城市、同城在职且未行动／未出任务／未在部队的人物，必须商人在场且本旬未交易。军团权限沿公共命令，钱粮使用该城市实际军团账户。令P为当前全局粮价，S为各参与者有效政治经既有执行能力函数T转换后之和（60→40、80→60、100→100），买进上限为min(100S,P×资金,剩余粮食容量)，卖出上限为min(100S,粮食,P×剩余资金容量)。卖出资格还要求当前库存至少值1资金，但选择量仍可小于P而收入为零。买进成本ceil(数量/P)，卖出收入floor(数量/P)。沿原作取整；没有随机收益、成长或组合加倍。成功原子扣付与返还，并将所有参与者标记已行动、该城本旬交易已用，买卖共用一次机会。

重制选择：只读报价不保留资源，提交时对当前资格、政治、粮价与库存重新计算上限，超限完整拒绝，不继承原作创建与执行间饱和扣款造成少付款／丢收益的竞争漏洞。非法或失败命令不改变账户、行动、随机及序号。查询提供不可交易原因、当前价格、账户与数量上限；命令和结构化结果进入保存／录像协议。原作事实见RE-0097和RE-0098，执行能力纠正见本次RE-0097补充。

验收覆盖常驻／流动／无商人、无主城市与设施、严格概率边界、买卖整数取整、多人与执行能力、独立军团、资金／粮食／容量上限、共享旬次数、人物占用、当前状态复验及失败零副作用、仅常驻商人图标与修行图标互斥、内容契约与真实源数据、稳定恢复和完整录像。AI策略是否主动选择交易独立于公共命令可用性，当前不新增自动经营策略。
