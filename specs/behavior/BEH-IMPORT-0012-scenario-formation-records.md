## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `jnki` chunk 的记录边界、记录身份、已确认字段和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不把阵位代码、视角范围代码或 `+0x18` 的资源相关代码擅自转换为重制版战斗规则，也不定义未观察阵位代码的几何位置。

## 原作基线

`jnki` chunk 位于正式剧本数据偏移 `0x107E`，包含 28 项，每项 32 字节，共 896 字节。运行时阵型 ID 使用记录序号 `0..27`，不使用文件中的序列化编号。文件按小端顺序包含 13 个 `u16`、5 个阵位字节和 1 个尾部字节：

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| ---: | --- | --- | --- |
| `0x00` | `u16` | `serialized_id` | 原始序号槽位；原程序读取后丢弃，运行时 ID 使用记录序号 |
| `0x02` | `u16` | `opaque_field_02` | 写入运行时对象并可由编辑器数据访问器读取；业务名称未确认 |
| `0x04` | `u16` | `opaque_field_04` | 写入运行时对象并可由编辑器数据访问器读取；业务名称未确认 |
| `0x06` | `u16` | `opaque_field_06` | 写入运行时对象并可由编辑器数据访问器读取；业务名称未确认 |
| `0x08` | `u16` | `against_units` | 对部队效果；编辑器字段已对照 |
| `0x0A` | `u16` | `against_soldiers` | 对守兵效果；编辑器字段已对照 |
| `0x0C` | `u16` | `against_walls` | 对城壁效果；编辑器字段已对照 |
| `0x0E` | `u16` | `defense_power` | 守备力；编辑器字段已对照 |
| `0x10` | `u16` | `mobility` | 机动力；编辑器字段已对照 |
| `0x12` | `u16` | `vision_radius` | 视野半径；编辑器字段已对照 |
| `0x14` | `u16` | `vision_angle_code` | 视角范围代码；截图显示并附带 `x45°`，高疑似代码到角度的映射 |
| `0x16` | `u16` | `deployment_cost` | 出征费用；编辑器字段已对照 |
| `0x18` | `u16` | `opaque_field_18` | 非零值进入 `0..14` 的资源表访问路径；业务名称未确认，导入层保留原值 |
| `0x1A..0x1E` | 5 字节 | `deployment_slot_codes` | 五个出征阵位代码；仅对已观察代码建立临时位置对照，其他代码保持原始字节 |
| `0x1F` | `byte` | `ignored_byte` | 当前记录加载器跳过但仍属于文件布局的字节；必须保留 |

已观察到的阵位代码对照为 `1=前中`、`3=中左`、`4=中中`、`5=中右`、`7=后中`。这只是当前截图和样本支持的部分映射，不是完整阵位枚举。

## 重制行为

导入器必须生成 28 个按文件顺序排列的阵型定义，并暴露所有原始字段。`Id` 使用记录序号；`SerializedId`、三个不透明字段、13 个数值字段、5 个阵位字节和 `IgnoredByte` 均不得因当前样本值而丢弃或重命名为未经证实的规则字段。

对 `OpaqueField18` 只提供范围派生的 `ResourceCode` 视图：原始值不大于 14 时返回该值，否则为空。该视图不代表已确认的玩法名称。阵位代码、视角范围代码和资源代码不得在导入层转换为新的战斗规则。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整 `S9SC` 剧本流。
- 状态变化：读取 `jnki` chunk 后产生 28 条阵型记录；导入过程不修改原始字节含义。
- 始终成立的不变量：chunk 大小为 `896` 字节；每项完整消费 32 字节；记录 `Id` 为 `0..27`；`deployment_slot_codes` 始终为 5 字节。
- 失败或无效输入行为：chunk 大小异常、记录截断或游标不能恰好填满 chunk 时抛出 `InvalidDataException`。

## 示例与边界

正式样本第 0 条的已观察数值为：13 个 `u16` 为 `0, 0, 0, 0, 15, 10, 10, 10, 12, 3, 4, 0, 1`，阵位字节为 `01 03 04 05 07`，尾部字节为 `39`。这支持可见效果字段和部分阵位映射，但不支持为三个不透明字段或 `+0x18` 赋予额外业务名称。

## 验收标准

- [x] 28×32 字节边界、记录顺序和全部原始字段由自动测试证明。
- [x] 5 个阵位字节与被目标加载器跳过的尾部字节均可逐项回读。
- [x] `OpaqueField18` 的原始值与 `ResourceCode` 派生视图不会互相覆盖。
