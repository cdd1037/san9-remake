# 表现层后续接入规划

状态：P1 操作闭环及此前自动化验证完成；2026-10-10补充的音效、对白、音乐与插图已接线，仅编译及内容转换校验，未运行测试。实际画面由用户验收；P2—P6 为后续实施规划。具体交互与原作时序在对应阶段核对后写入相关 BEH。
最后更新：2026-10-10。

目标是在已有核心玩法与客户端接线基础上，补齐玩家操作、消息、战场与剧情演出，使玩家不依赖调试入口完成一局。推进顺序为补操作闭环、补信息反馈与演出、收口整局体验。外交会谈及劝降灭亡插图音乐已接线，其余BGM和视频保持占位，音效随具体场景接入。

## 范围与两条开发线的关系

表现层与[电脑 AI](ai-implementation-plan.md)可并行推进，不再以完整 AI 和十年自动对局完成作为所有界面工作的统一前置。这是对[整体路线图](roadmap.md)中先完成 G12 再返回表现层排期的细化调整，不改变 G11、G12 的 AI 与长期对局验收要求；G13 所需查询和表现契约随实际场景逐步补齐。

AI 线负责规划、委任执行和长期对局行为；表现层负责委任输入、权限说明、状态与结果可见性。最终联合验收多势力行动下的消息数量、演出顺序和资源开销。界面不实现另一套 AI，也不直接修改领域状态。

人才提拔培养、游戏内编辑器、玩家录像回看与接手、跨平台最终打包另行安排，不作为本轮前置。正式新局先服务于已支持内容包，不扩大教学、挑战或剧本导入范围。外交及灭亡插图音乐由场景播放器临时持有，尚无完整地图音乐后端；其余媒体沿用现有 `ISceneMedia`／`SilentSceneMedia` 边界，占位不能阻塞事件续行或结局结束。

P1 按计略、主动外交、委任三个独立交付推进。P2 的消息排序与播放基础供 P3—P5 使用，具体消息随对应阶段接入，不要求先穷举全游戏才能交付第一批。P4 复用 P3 已明确的暂停、跳过和演出完成协议。P6 的独立入口或设置可提前完成，整局收口须等待前述链路闭合。

P1 当前覆盖八类计略、四类主动外交及军团新设／变更／解散、直接控制／委任和四种方针。正式菜单、目录选人选目标、赠与资源、原作意见与出发／结果消息、确认提交和失效提示均已接线；准备查询不占用人物、不扣资源、不推进规则随机。窗口内容矩形和关键锚点按 IDA 回读对齐，控制与方针扩展沿用原作组件。自动化覆盖及内容包检查见操作说明；用户画面验收尚未完成，不将此状态记为逐帧复刻验收。

## 计略对白的显示渠道与后续归属

当前P1接线区分台词内容、显示渠道和实际验收。已绑定的计略行动／回应使用公共人物对话框（立绘、姓名及正文），同时写入执行记录；这不等于原版地图喊话已实现。外交会谈使用同一人物叙述组件，原版专用外交场景仍待对齐；委任成功则为结果提示，关闭后留在地图。

原版已核对的伪报特殊失败回应定位到目标部队，是地图上的人物喊话；另有独立的成败结果地图消息。证据见[RE-0182第14节](../research/findings/RE-SAN9PK-0182.md#14-外交计略与委任的音效对白和音乐2026-10-10)。不能用进行面左下的记录行或普通人物对话框，声称已经对齐原版喊话位置。

| 后续项 | 阶段与状态 | 接入要求 |
| --- | --- | --- |
| 计略结论及损失／送达等事实记录 | P2，已有部分接线，待完整覆盖与记录交互 | 对齐消息分类、顺序、去重和对象定位；记录与地图喊话分别消费同一结算事实 |
| 计略行动及目标回应的地图人物喊话 | P3，待实施 | 保存本次执行的来源／目标、人物及位置上下文，按原作入口核对显示时机、可见性和播放顺序；不回查最终世界猜测已消失对象 |
| 团结免疫、识破计谋、伪报遇方圆阵等特殊失败对白 | P3，待实施 | 从规则结算保留真实失败原因，定向闭合原版条件；按原因选择消息，继续求值性格、性别和随机措辞分支，不按台词反推玩法 |
| 夺取宝物的原持有人回应 | P3，待实施 | 在结算事实中保留实际旧持有人及相关位置；没有持有人时按对应分支处理，不编造人物；当前仅显示取得宝物摘要 |

验收须分别确认地图锚点、喊话顺序、进行面记录和特殊分支；重复绘制、暂停／续行、跳过及资源加载重试不能重新选句或重复显示。P1操作闭环完成不能替代这些P3演出验收。本轮仅补充说明与排期，不实施地图喊话。

## P1 后续整理：命令界面文本

待整理。当前内政、人事、任免与 P1 命令混用代码内中文和 `TextCatalog`：例如各类草稿的 `Title`、`CommandFailureText` 对 `CommandRejection` 的描述，以及确认、失效提示和部分结果摘要。已有写法是当前实现基线，不作为继续新增硬编码文字的长期约定。

后续应统一命令标题、属性标签、选择／确认提示、拒绝原因和结果摘要的文本管理，复用现有文本目录与消息绑定机制。草稿保留命令种类及输入状态，领域层保留类型化拒绝原因，由表现层解析显示文本；整理覆盖已有同类命令，避免只迁移 `MissionDraft` 而留下两套做法。优先以语义键组织文本，不让原版消息编号或中文措辞成为业务标识。

原作措辞应通过 IDA 与源文本核对，并记录对应证据；重制新增的权限解释、失效原因和事件事实摘要单独标明来源。迁移时同步内容契约、转换器、校验与消费者，避免硬编码中文回退掩盖缺失文本。验收关注文本键覆盖、参数绑定、拒绝原因映射和既有命令行为不变；实际画面仍由用户验收。本项为后续整理规划，本次不执行文本迁移。

## 进入战略阶段时的情境发言

玩家所说的“回合开始，有时武将跳出来发言”属于 P2 的显式范围，不能遗漏，也不能混同于下令时的军师意见、执行中的战报或事件答复。

原作集中情境提示流程已有以下证据：敌军逼近报告及现场武将迎击／防守反应、季度钱粮不足提醒、人物和宝物地点线索。发言受局势、人物资格及概率等条件影响；不将其概括为每旬固定出现。依据见[RE-0171](../research/findings/RE-SAN9PK-0171.md#2026-09-13补充非战斗情境发言的反查可行性抽查)。

实施时沿原作入口核对新局、正常旬切换、读档和界面重入的触发边界，并明确候选发言者、情境优先级、互斥或连续播放、已显示标记及信息可见性。研究发现的提示不自动全部成为产品要求；与现有规则不一致的部分须先区分原作事实与重制选择。

验收至少覆盖有提示、无提示、多候选竞争、说话人物或目标失效、退出再进入、保存恢复。界面重绘不能重新选句、抽取提示或重复播放；提示若披露隐藏地点等玩法信息，其产生与保留语义须由领域／会话规则明确，不能归为纯视觉随机。

## IDA 核对与资源接入

2026-10-10 已使用 TC101 项目主库静态回读公共发言、集中情境提示及其调用点、兵法发动／连携战报、逐人喊话和地图演出转发入口，与既有 [RE-0171](../research/findings/RE-SAN9PK-0171.md) 和 [RE-0101](../research/findings/RE-SAN9PK-0101.md) 的入口结论一致。此次核对未闭合全部显示时序、可见性和资源播放状态机，不作为完整演出验收。

兵法战报、逐人喊话与地图演出分别有入口，P3 必须沿同一场景核对参与者、来源、目标、结果分支及播放顺序，不能只给兵法配一段动画。单挑规则和逐刀结果已有证据，动作资源、镜头、台词及播放节奏仍需专门核对，见 [RE-0103](../research/findings/RE-SAN9PK-0103.md)、[RE-0104](../research/findings/RE-SAN9PK-0104.md)、[RE-0105](../research/findings/RE-SAN9PK-0105.md)。

每批从既有 BEH／RE 和实际消费者出发，定向检查原作展示入口、调用者、消息及子消息、发言者、图像、音效和分支。按[逆向规范](reverse-engineering.md)记录新结论，并将有证据的标注同步到项目主库、保存和回读；地址及反编译细节留在 RE，不进入产品规格或运行时。

每项接入维护最少覆盖信息：情境与触发、可见范围、人物和对象绑定、选择及结果分支、资源角色、消费者、验证状态。事件族沿用[G10 覆盖清单](../docs/g10-event-coverage.md)，不再建立一套重复的玩法目录。资源已导出不等于已正确播放；契约变化同步 Importer、包校验、消费者与相关规格，按[内容管线](../docs/client-content.md#接入前的数据核对)核对数据链。

## 状态所有权与演出约束

Core 保留确定性行为事实，Application 组织用例、只读查询和必要的表现上下文，Rendering 处理引擎无关的动画与坐标，Godot 负责输入与播放。缺少上下文时在事实产生处补充，不能根据最终世界反猜已经消失的人物、部队、目标或中间结果。

复用现有逐日播放、消息和模态流程，按实际场景扩展，不先建设覆盖全游戏的通用演出框架。同一已提交操作只生成一次表现计划；资源重试、暂停、翻页和跳过不能重新提交命令或重新结算。台词措辞等纯表现随机与玩法随机隔离，演出速度不影响模拟结果。等待玩家选择时保持明确暂停边界，遵循既有保存协议，不为了表现接入另造可变世界副本。

## 验证与交付

每个子项完成原作证据或重制选择核对、必要数据与资源转换、正式交互、结果展示和相关验证后交付；同时更新受影响的当前文档，不附带全仓历史清理。

- 局部 C# 逻辑验证受影响项目；共享契约或跨层行为运行 `dotnet test San9Remake.slnx`。涉及持久化、录像、CLI 或跨进程接线时另运行 `dotnet test tests/San9.Headless.Tests/San9.Headless.Tests.csproj`。
- 纯视觉变更按[测试覆盖取舍](../tests/README.md#覆盖取舍)验证。实际画面由用户验收，不自动启动游戏，不默认复跑历史 Godot 脚本。
- 交付区分数据覆盖、查询／命令接线、自动化验证和实际画面验收，不以编译成功代替交互完成。已通过且输入未变的检查不重复运行。

最终代表性流程包括：新局、经营与人事、计略和外交、出征与战斗、兵法与单挑、事件选择、存读档继续及终局。低频事件可使用已有受控场景分别验收，不要求在一次自然对局中随机触发全部内容。长期 AI 对局另验证大量事件和资源使用下的表现稳定性。
