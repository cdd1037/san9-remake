# 原版界面坐标对齐

用于依据原版截图调整重制布局。目标是统一坐标参照后还原布局，不靠逐个控件反复目测挪动。此流程不要求启动游戏；用户负责画面验收时，仍只做必要编译／测试，并明确画面待验收。

## 坐标与资源边界

- 区分截图像素、游戏客户区、1024×768逻辑视口及控件局部坐标。窗口标题栏、边框、裁剪偏移、系统缩放、截图二次缩放均不能计入逻辑布局。
- 并排截图的两侧分别标定，不能假定客户区起点或缩放相同。客户区逻辑位置按 `logical = (screenshot - clientOrigin) / scale` 换算；有留黑或额外裁剪时先扣除对应偏移。
- 贴图矩形起点不等于可见装饰起点。核对原生尺寸、透明留白、帧切分和三段贴图端帽；不要把透明边距算成控件偏移，也不要拉伸端帽来掩盖定位问题。
- 背景、外框、装饰底框、按钮有不同边界。选择同一个明确的窗口锚点，相关元素按该锚点派生；不要分别猜测位置。
- 相似界面不保证布局相同。目录、地图、详情及各类别之间，只复用已经确认相同的尺寸与偏移。

## 调整步骤

1. 优先使用完整原始截图，确认客户区起点、逻辑尺寸和缩放；局部裁剪只作补充。参照不足时保留不确定性，不报未经确认的精确偏移。
2. 确认使用的原版资源与帧，先排除错误贴图、尺寸或透明留白问题。
3. 用外框、角饰等稳定特征标定窗口；必要时匹配已转换贴图的边缘，避开字体差异及透明区。
4. 建立窗口边界和共同锚点，再布置按钮、装饰及文字。核对关联元素间距，不能只看单个元素的绝对位置。
5. 记录截图坐标、换算参数、逻辑坐标及证据来源。截图量测不写成IDA常量结论；编译通过也不代表视觉已验收。

## 已遇到的实例

情报地图的关闭按钮与装饰底框曾分别偏右、偏左16逻辑像素，原因是混用了布局参照并独立估测位置，而非引擎统一缩放故障。按完整截图和源端帽匹配后，一览为(612,680)、关闭为(808,696)、关闭底框为(732,680)。这些是该页面的量测结果，不是所有窗口通用常量。证据见[RE-0161：地图页底部按钮定位复核](../../research/findings/RE-SAN9PK-0161.md#地图页底部按钮定位复核)。
