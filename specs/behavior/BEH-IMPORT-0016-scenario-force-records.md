# BEH-IMPORT-0016：剧本势力（`forc`）记录解析

- 状态：已确认
- 负责人：项目开发者
- 最后更新：2026-09-25
- 关联证据：[RE-SAN9PK-0021](../../research/findings/RE-SAN9PK-0021.md)
- 关联决策：[DEC-DATA-0001](../decisions/DEC-DATA-0001-content-pipeline.md)

## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `forc` chunk 的记录边界、运行时引用、旗标查询、外交数组和无损读取。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格区分复合原始旗标、可确认的派生视图和内容层名称。48 位势力兵法标志的低 41 位绑定 `hiho` 顺序 ID，高 7 位只保留，不伪造兵法。

## 新局消费边界

共享势力定义与运行时的 `IsBarbarian` 表示是否适用异民族规则。玩家选择和休眠激活处理完成后，玩家势力清除此标记；Application 创建新世界时由 Core 对有效电脑异民族一次性增加 200000 士兵。优先君主所在的有效所属城市，否则按城市 ID 稳定顺序选取首个所属城市，无城市则不发放；追加受城市兵力容量限制，不扣兵役人口，不改变士气。稳定回退顺序为重制选择。休眠或已毁据点不参与，后续事件激活不补发；保存恢复不执行此步骤。转换包保留基础驻兵，不预先叠加依赖玩家选择的奖励。证据见 [RE-0174](../../research/findings/RE-SAN9PK-0174.md#新局初始化补充核对2026-09-25)。验收覆盖玩家与电脑、休眠、君主驻地及回退、容量和读档不重复。

## 原作基线

`forc` chunk 位于正式剧本数据偏移 `0x8C06E`，包含 50 项，每项 86 字节，共 4,300 字节。运行时势力 ID 使用记录序号 `0..49`。文件按小端顺序包含三个 `u32`、九个 `u16`、6 个字节和 50 个字节：

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| ---: | --- | --- | --- |
| `0x00` | `u32` | `money` | 势力金钱；原样保留 |
| `0x04` | `u32` | `food` | 势力粮食；原样保留 |
| `0x08` | `u32` | `flags` | 状态/分类原始旗标；提供原始位查询和已确认的运行时类别码 |
| `0x0C` | `u16` | `serialized_id` | 原始序号槽位；原程序读取后丢弃，运行时 ID 使用记录序号 |
| `0x0E` | `u16` | `owning_force_code` | 所属势力代码；`0..49` 为引用，其他值的运行时所属势力回退为当前记录自身 |
| `0x10` | `u16` | `country_title_code` | 根势力国号代码；`0..19` 为引用，其他值为空引用；子军团通过根势力共享 |
| `0x12` | `u16` | `leader_code` | 军团长/领袖武将代码；`0..849` 为引用，其他值为空引用 |
| `0x14` | `u16` | `base_trust` | 基础信望；原样保留 |
| `0x16` | `u16` | `trust` | 当前信望；原样保留 |
| `0x18` | `u16` | `rival_force_code` | 剧本宿敌/主要敌手代码；`0..49` 为引用，其他值为空引用；当前 EXE 不据此改变外交或联盟 |
| `0x1A` | `u16` | `rank_group_code` | 官爵组代码；`0..8` 为官爵组引用，其他值为空引用 |
| `0x1C` | `u16` | `color_code` | 势力颜色代码；原样保留 |
| `0x1E..0x23` | 6 字节 | `tactic_flags` | 48 位势力级兵法标志；bit0..40 对应 `hiho[0..40]`，bit41..47 为当前 EXE 不可查询的保留位 |
| `0x24..0x55` | 50 字节 | `diplomatic_relations` | 按势力索引的 50 项关系值数组；外交好感度。 |

联盟角色派生优先级为：bit6 `Target`，否则 bit5 `Leader`，否则 bit4 `Member`，否则 `None`。盟主同时是联盟参与者，但派生视图按更具体的 `Leader` 返回。

注:只有当军团为主军团时，国号、颜色、官爵、信望、基础信望、外交及兵法等数据才有意义，此时这些数据表示的是势力数据。

国号定义和名称资源由 [BEH-IMPORT-0011](BEH-IMPORT-0011-scenario-country-title-records.md) 约束。运行时根势力持有唯一可空国号 ID，子军团不得复制出独立可写状态；势力记录重置清除该关联，授予流程防止普通国号被多个有效根势力重复占用。

## 重制行为

导入器必须生成 50 个按文件顺序排列的势力定义，并保留所有原始字段。提供以下不覆盖原始代码的派生视图：

- `OwningForceId`、`CountryTitleId`、`LeaderId`、`RivalForceId` 和 `RankGroupId` 按目标范围返回有效引用或空值；`RuntimeOwningForceId` 在所属势力无效时回退到记录自身 `Id`。
- `IsPlayerControlled`、`IsBarbarian` 和三个联盟位直接读取已确认的单个位；`AllianceRole` 按目标、盟主、成员优先级派生。
- `ControlOrderCode` 读取 bit8..11；代码 15 的 `ControlOrder` 为空，其余 `0..14` 原样返回。
- `HasPersistentMarker(0..4)` 映射 bit13..17，`HasEventHistoryMarker(0..14)` 映射 bit16..30。两者在 bit16/17 有意重叠，不能拆成独立可写位集。
- `HasFlagBit(0..31)` 继续查询完整原始字；bit3/7/31 没有专用名称。
- `TacticFlags` 必须完整保留 48 位；`HasTactic` 只接受 `0..40`，不能按当前样本默认值清零或暴露高 7 位。
- `DiplomaticRelations` 必须完整保留，不能按当前样本默认值压缩或丢弃。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整 `S9SC` 剧本流。
- 状态变化：读取 `forc` chunk 后产生 50 条势力记录；派生引用不修改原始代码。
- 始终成立的不变量：chunk 大小为 `4,300` 字节；每项完整消费 86 字节；记录 `Id` 为 `0..49`；尾部数组长度固定为 6 和 50。
- 引用派生边界：势力 `<50`、国号 `<20`、武将 `<850`、官爵组 `<9` 才视为有效；无效代码保留原值并提供空视图。
- 失败或无效输入行为：chunk 大小或记录边界异常时抛出 `InvalidDataException`；所有位/标记查询在参数越界时抛出 `ArgumentOutOfRangeException`。

## 示例与边界

`D_Sce002.S9` 第 0 条对照值包括金钱 `3100`、粮食 `30800`、旗标 `0x10`、基础信望 `150`、当前信望 `156`；外交数组以 `100, 60, 60, 60, 50, ...` 开始。bit4 的联盟成员语义由联盟形成与清理状态机确认，不再只依赖截图。

正式剧本共有 51 个有效宿敌引用，其指向关系值全部为 `0..60`；该内容映射不能替代外交数组，也不能成为导入时修改关系值的理由。复合旗标 bit16/17 同时被两个公共查询域覆盖，测试必须保留这一重叠。
