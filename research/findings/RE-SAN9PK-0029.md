# RE-SAN9PK-0029：`unit_status` 与运行时 `+0x20` 旗标分层

- 状态：`unit_status` 的加载、派生、生产、持续与解除链已确认；`+0x20` 的部分旗标已确认，部分高位仍待验证
- 日期：2026-08-30（2026-09-11补证状态8到期分支；2026-09-13补证交战标记生命周期）
- 结论类型：IDA 直接证据、编辑器用词表、upstream 研究代码交叉分析
- 置信度：高（状态字段位置、`0..8` 域、状态 0..2 与 4..8 的生产/派生/解除、状态 3 的全程序负面生产者审计、bit 2/22 的访问器、bit 3、bit 12–15）；中高（bit 0/1、bit 19–22 的 upstream 语义）；中或待验证（bit 16–18、bit 23–24）
- 关联记录：[RE-SAN9PK-0022](RE-SAN9PK-0022.md)
- 关联规格：[BEH-IMPORT-0017](../../specs/behavior/BEH-IMPORT-0017-scenario-unit-records.md)

## 1. 结论

编辑器的 `unit_status` 不是 `unit +0x0C` 中的某一个 bit，也不应与四项方针位混写。当前证据闭合为：

```text
unit +0x12
  -> deserialize_unit_record 0x460FF0
  -> set_unit_status_code 0x45EBB0
  -> CUnitData +0x24
  -> get_unit_status_code 0x45EBF0
  -> get_unit_status_text 0x45EC10
  -> get_status_text_resource_by_code 0x568240
```

`0x568240` 的状态文本资源表接受 `0..8`，超过 8 报错；这与用词表中的 `unit_status` 域完全相符：

| 值 | 用词表名称 | 当前说明 |
| ---: | --- | --- |
| 0 | 无效 | 重置无效对象和专用清理路径写入；也可从剧本/存档载入 |
| 1 | 正常(一般) | 新建有效部队、异常解除、治疗和救援等路径写入的原始正常态 |
| 2 | 正常(交战) | `get_unit_status_code` 仅在原始值为 1 且 `is_unit_engaged` 为真时派生；不写回 `+0x24`，存档写出器也直接保存原始槽而非派生值 |
| 3 | 陷阱 | 编辑器用词表名称；当前 EXE 的 setter、公共状态写入器和直接 `+0x24` 写入全程序审计均未发现内生生产者，只能由剧本/存档等外部序列化值进入 |
| 4 | 伪装 | 伪报命令成功写入 `5+rnd(3)` 日；清当前接战目标与寻路前瞻，保留原指令及玩家中继点；持续期临时返城，见[字段纠错](RE-SAN9PK-0113.md#2026-09-16-伪报持续返城补证) |
| 5 | 无阵 | 扰乱、攻心等已确认路径写入计算日数；公共写入器刷新部队 |
| 6 | 混乱 | 混乱/幻术兵法、攻击特定工作物后的概率分支及事件辅助路径写入计算或固定日数 |
| 7 | 溃败 | 普通攻击后满足围攻兵力比、士气与保护兵法门时写入 `5+rnd(5)` 日；与状态4共用临时返城覆盖，保留原指令及玩家中继点，清接战目标和自动前瞻 |
| 8 | 高昂 | 激励成功写入计算日数；到期时每日链先处理士气/击破边界，再恢复原始状态 1 |

因此，“正常(交战)”不是可与其它异常态并列写入的原始状态。`get_unit_status_code(0x45EBF0)` 只在原始 `+0x24 == 1` 时调用 `is_unit_engaged(0x461730)`：普通外部部队以 bit 2 或 bit 22 任一置位为交战，bit 0 内嵌部队只采用 bit 22。条件成立便返回 2，否则仍返回 1；原始槽不变。存档序列化器在 `0x45E6BB` 直接写出 `CUnitData +0x24` 的字节，也不会把派生 2 固化。

全程序交叉引用审计给出了状态生命周期的完整边界：`set_unit_status_code` 的 23 个直接调用点和嵌入对象 wrapper 的 3 个调用点只产生常量 0、1、4、5、6、7、8 或传入序列化值；对非栈对象的 `+0x24` 立即数写入扫描没有发现绕过 setter 的部队状态生产者。公共写入器 `apply_unit_status_with_duration(0x463C80)` 只接受 4..8；状态 3 不在其分派中。故状态 3 的结论不是“尚未找到”，而是“当前 EXE 不内生生产，只允许外部原始值进入”。

持续状态统一保存于 `+0x28`。每日更新用 `decrement_unit_status_duration(0x45EC20)` 饱和递减；4..7 归零后调用 `clear_expired_unit_status(0x461A90)` 恢复原始状态 1，并对4/7额外清理自动寻路前瞻`+0x7C`，不清玩家中继点`+0x80`或原指令。状态 8 使用单独的到期分支，处理士气下降和可能击破后恢复为 1。治疗会无条件把非 1 状态恢复为 1 并清零日数；救援清除除 1/8 以外的状态，保留高昂。2026-10-21按精确写入偏移纠正此前把自动前瞻称为中继点的解释，详见[同类扩查](RE-SAN9PK-0113.md#同类状态与命令扩查2026-10-21)。

## 2. 状态字段与相邻序列化字段

`0x460FF0` 的加载顺序还直接证明：

| 文件字段 | 运行时去向 | 判断 |
| --- | --- | --- |
| `unit +0x12` | `CUnitData +0x24` | `unit_status` 状态码 |
| `unit +0x14` | `CUnitData +0x28` | 异常状态剩余日数；公共状态写入器取当前/新值较大者，每日更新递减，救援清除时归零 |
| `unit +0x16` | `CUnitData +0x38` | 士气字段，样本值 `100` 与编辑器闭合 |

这会修正旧记录中把 `+0x12` 写成 `CommandCode`、把 `+0x14` 写成 `TargetTypeCode` 的表述。`unit_command` 和 `unit_target_type` 用词表本身仍有效；运行时目标类型 `3=部队`、`4=据点/Zone`、`5=都市` 已由 `0x4537C0` 闭合。命令字段已由 `RE-SAN9PK-0022` 确认为 `unit +0x18 → CUnitData +0x58`，取值域为 `-1..70`；逐命令玩法条件不再计作本字段未决。

`RE-SAN9PK-0113/0114/0116` 后续闭合了 `+0x14` 的生产和消费：伪报、扰乱、激励成功时写入按公式计算的持续日数，公共写入器保留当前值与新值的较大者，每日更新对正值饱和减一，成功救援在清除适用异常状态时同时清零。故该字段正式命名为 `status_duration_days`。

## 3. `+0x20` 已有证据的旗标

| bit | 掩码 | 当前语义 | 证据等级 |
| ---: | ---: | --- | --- |
| 0 | `0x00000001` | 都市内嵌/内部部队分类；会影响距离起点、战法间隔、伤兵上限和俘虏处理等特殊路径 | 中高；这是类别旗标，不是状态码 |
| 1 | `0x00000002` | 单人部队分类；会被普通目标、护卫/援护和外部部队筛选排除 | 中高；这是类别旗标，不等于士兵数为 1 |
| 2 | `0x00000004` | 主动交战位；CUnitData 虚函数 `0x45EA60/0x45EA70` 明确读写该位 | 高；“主动”来自 upstream 语义注释 |
| 3 | `0x00000008` | 沿用“已出征位”称呼；普通新建出阵部队初始为0，每日预命令阶段对非bit1、事件类型38–52的单位置1，不要求出发等待归零或已物理离城，见[RE-0174](RE-SAN9PK-0174.md#当旬新出兵的反应时机2026-09-30补证) | 高；名称不能代替置位时机 |
| 12 | `0x00001000` | 敌接近时攻击 | 高 |
| 13 | `0x00002000` | 自主撤退许可 | 高 |
| 14 | `0x00004000` | 追击许可 | 高 |
| 15 | `0x00008000` | 事后攻击 | 高 |
| 16 | `0x00010000` | 在行动辅助函数中有设置/清除；独立业务语义尚未闭合 | 待验证 |
| 17 | `0x00020000` | 转移/目标区域处理门控之一；在若干行动后被清除 | 中；暂不命名 |
| 18 | `0x00040000` | 目标状态位之一；追击路径要求目标具备该位，行动辅助函数也会设置 | 中；暂不命名 |
| 19 | `0x00080000` | 建设部队上下文中的“正在建设”标志；upstream 会据此跳过中继点设置，并在撤退/清除建设设施时清除 | 中高；当前二进制中其它通用门控路径的完整对象语义仍待闭合 |
| 20 | `0x00100000` | 建设图标标志 | 中高；upstream 直接测试 `unit +0x22` 的 `0x10` |
| 21 | `0x00200000` | 运输标志 | 中高；upstream 直接设置/测试 `unit +0x22` 的 `0x20` |
| 22 | `0x00400000` | 被动交战位；CUnitData 虚函数 `0x45EA80/0x45EA90` 明确读写该位 | 高；“被动”来自 upstream 语义注释 |
| 23 | `0x00800000` | 敌军接近／避战提示的缺敌记忆位：无候选敌军时置位，遇敌清除；避战报告读取进入本次检查前的值。随部队标志字存读档，详见[RE-0084补证](RE-SAN9PK-0084.md#敌军接近提示标记的存档边界复核2026-10-20) | 高；替代早期“瞬时处理／重入保护位”误判，并非处理结束后恢复旧值 |
| 24 | `0x01000000` | 状态/行动转换中被设置，但当前未找到同一对象的直接读取 | 待验证 |

其中 bit 2 与 bit 22 的关系由当前二进制和 upstream 同时支持：upstream 使用 `0x400004` 作为“主动/被动交战”组合；当前 IDA 中两个 bit 各自有虚访问器，`is_unit_engaged` 又明确组合它们来派生查询/显示状态 2。它们是两个独立运行时位，不是原始 `unit_status=2` 的编码。

对 bit 4–11、25–31，目前没有足够的当前二进制直接消费者证据，不能据此宣布“未使用”。bit 16–18 也只能确认存在写入、清除或门控读取，不能把这些操作本身当作语义确认。bit 19–22 虽已有 upstream 的上下文语义，但 bit 19 在当前二进制的其它通用路径中仍可能承担更窄的门控作用，不能把“建设中”无条件推广到所有部队。

## 4. upstream 的补充行为证据

upstream 对同一运行时部队对象的直接访问还给出了以下组合和行为。`unit +0x22` 是 `CUnitData +0x20` 旗标字的高字节别名，因此这里的字节掩码对应整体 `u32` 的 bit 16–23；但源码中也存在其它显示对象使用相同偏移的情况，只有带有部队循环/部队对象上下文的代码才纳入本结论。

| 证据 | 观察 | 语义边界 |
| --- | --- | --- |
| `InsertAsmSrc2.h:1444–1448` 的 `test eax, 700006h` | 同时筛掉 bit 1、bit 2、bit 20、bit 21、bit 22 | upstream 注释依次对应单人部队、主动交战、建设图标、运输标志、被动交战 |
| `InsertAsmSrc2.h:1680–1684` 的 `test byte ptr[edi+20h], 0Bh` | 只有 bit 0、bit 1、bit 3 全为 0 的部队进入“未出征部队”统计 | 这是“非内嵌、非单人、未出征”的筛选条件，不是 bit0/1/3 的组合状态枚举 |
| `InsertAsmSrc.h:919–924` | 先测 bit 3，再测 bit 20 和 bit 22，处理已出征且有建设图标、处于交战的建设部队 | 支持 bit 3、bit 20、bit 22 的组合使用 |
| `InsertAsmSrc.h:941–944` | 清除建设设施后清除 `unit +0x22` 的 `0x08` | 在该路径中 bit 19 是“正在建设”标志 |
| `InsertAsmSrc2.h:6002–6009` | 建设命令范围内，若 `unit +0x22` 的 `0x08` 已置位，则不设置中继点并保留出征日期为 0 | 进一步支持 bit 19 的建设中语义，但仅限建设部队路径 |

bit 0 的其它 upstream 行为包括把所属都市作为距离计算起点、调整针对内嵌部队的战法效果/间隔、限制伤兵和俘虏相关数值；bit 1 则用于排除单人部队的普通目标、护卫和外部部队选择。这些行为支持“分类旗标”的解释，但尚不足以要求重制版建立同名内部对象或复刻所有数值规则。

## 6. 2026-09-13补证：交战标记的置位、解除与每日清理

- 作者：Codex；样本及工具环境沿用[SRC-SAN9PK-TC-101](../sources/SRC-SAN9PK-TC-101.md)，项目主库`research/analysis/San9PK-TC-101.i64`，映像基址`0x400000`。
- 方法：读取部队和建筑虚表；扫描`.text`中虚调用`+0x9C/+0xA4`，按对象类型剔除窗口、绘制对象的同槽调用；对命中函数反编译，回查置位/清零调用附近指令，再追踪普通攻击及目标清理的调用者。
- 结论类型：以下时机为当前样本静态事实，置信度高；未做新的原版运行黑盒实验，不宣称穷尽所有旗标字整体写入或间接调用。

| 行为 | 当前样本证据 |
| --- | --- |
| 普通攻击开始时写入主动、被动交战 | `advance_normal_attack_resolution`的状态1002在`0x49B642`调用`0x49A710`；后者`0x49ADAC`对攻击者调用虚槽`+0x9C`传1，`0x49AE45`对防守者调用`+0xA4`传1。这发生在后续伤害计算、兵法机会与兵损阶段之前；空守军直接占领等分支可跳过该调用。 |
| 两个状态有独立存储 | 部队虚表`0x606490`的`+0x9C/+0xA4`分别为`0x45EA70/0x45EA90`，写入bit2/bit22。建筑虚表`0x605298/0x605938`对应槽为`0x435500/0x435520`，转发至对象`+0x58`内嵌守军。 |
| 解除一个攻击者不能直接清除目标的被动交战 | `0x459950`读取旧目标，经`0x435C30 → 0x466900`或直接`0x466900`检查除本来源ID以外是否还有合格攻击者；没有其他攻击者才清目标被动位，随后清来源主动位。内嵌来源通过`0x4559D0`执行相同边界。`0x466900`检查有效对象、指向该目标及攻击资格，找到一个即可返回。 |
| 目标清理由多种生命周期共用 | `0x459950`的调用者包括异常状态写入、战败`0x466FBC`、失效目标命令处理、归城吸收`0x468FDF`、归属军团转移以及自动撤退命令`0x49EE41`。不能仅在移动函数中维护交战位。 |
| 每日任务清理失效标记 | `0x509AF0`状态1002中，`0x509C44/0x509C5F`在目标无效或`0x508F50`判定该对对象不可攻击时清主动位；对被动对象经`0x470C10`枚举攻击者，没有任何一对通过`0x508F50`才在`0x509D4A`清被动位。它不是每日无条件清空再等待下次攻击。 |
| 汇总交战设置也保留对象区别 | `0x461770`对外部部队同时调用两个setter，内嵌守军只调用被动setter；与`0x461730`读取规则互证。 |

**推断与实现边界**：原作采用“开战置位、目标生命周期解除、每日复核”的状态维护，消费熟练度/士气等交战布尔条件时不需要重新枚举全场。原作在维护和攻击程度计算时仍会扫描攻击者，不能据此声称其所有关系查询均为常数开销。重制采用当前有效攻击关系的统一派生视图，不复制原作固定槽位和任务时间片；原作的历史交战位可能在开战前后与即时资格短暂不同，这不是重制必须保留的调度行为。产品规则见[BEH-WAR-0004](../../specs/behavior/BEH-WAR-0004-normal-combat.md#交战关系的统一维护)。

**IDA同步**：在`0x49A710`、`0x459950`、`0x509AF0`追加引用本节的函数注释，保留已有注释，未改函数名、类型或机器码。已保存主库，并用函数注释读取逐项确认三处写入成功。

## 7. 状态 8 到期分支补证（2026-09-11）

激励成功写入的高昂没有独立结算函数；到期动作全部发生在每日预命令遍历 `process_daily_unit_events(0x50BD00)` 的状态处理分支内，且只有本次更新把 `+0x28` 从正数递减到 0 的状态 8 才进入。

- 满足门槛时先取所属势力；若该势力对玩家可见（势力虚表槽 `+0x3C`）则显示消息 `10006`，随后调用 `adjust_object_morale(0x508030)(force, unit, -30, 1)`。

- 扣减后读取部队虚表槽 `+0x84`（`get_record_morale(0x45E410)`，即 `+0x38` 士气）：大于 0 时把状态写回 1；不大于 0 时进入 `update_mainmap_tactic_record(0x5084A0)` 与 `resolve_unit_defeat(0x4669A0)` 终止链。由于上一条的钳制，该终止边界只在单位进入本分支前士气就已经不为正时才会命中。
- 状态为 8 但 `+0x28` 在进入本次遍历前已不大于 0 的单位跳过以上分支，只把状态归一为 1 且不扣士气。
