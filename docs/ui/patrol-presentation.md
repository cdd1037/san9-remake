# 巡察命令：消息与音效流程

客户端已接入“设施 → 巡察”的准备、选人、执行、对白及结果流程。本页同时保留消息调用索引，不复制正文、不去重。依据 TC101 原作静态调用链和当前转换包，证据见 [RE-0095](../../research/findings/RE-SAN9PK-0095.md#2026-09-27巡察消息序列与音效)。没有进行原作动态播放或音频试听。

## 从确认命令到结果

确认参与武将后，原作验证命令并即时执行，不等到旬末。先计算基础增量；只有基础增量还不能把民心补到 1000，才检查加倍。下面三条回应路径互斥，且只在原作玩家可见势力条件成立时生成显示：

| 路径 | 触发条件 | 消息顺序 | 新触发的音效 |
| --- | --- | --- | --- |
| 普通巡察 | 没有成功加倍，包括基础效果已足以达到上限 | 武将回应 5592 | 无 |
| 特定组合加倍 | 匹配有序人物组合、概率与资格检查均成功 | 武将甲 5861 → 武将乙 5862 | 两句均无 |
| 相性加倍 | 特定组合没有成功，后备相性概率成功 | 武将回应 5826 → 百姓回复 5832 | 百姓回复触发 SE 8 |

随后，增量大于 0 时显示结果 5598，触发 SE 18；再进入内政共用提示选择，最多追加一条 5873–5877，也可能没有提示。三条回应路径都汇合于这个结果与提示阶段，不会在特殊对白后再补播普通回应。

这里记录的是调用／入队顺序。原作主地图可把消息加入队列，执行器随后写回民心、行动状态、费用、信望和本期使用标志；不能据此断言必须点击关闭所有消息才发生状态写回。

音效目录索引与文件名后缀不是同一个编号域，尤其不能把 SE 18 找成 `SE_G018.WAV`。这里确认的是调用用途与资源映射，没有把试听尚未确认的声音命名为某种人声或乐器。“不触发新音效”也不表示停止已经在播放的声音。

主地图队列保存音效参数，取出消息时再进入对话框播放路径。BGM 哨兵表示这些消息不请求切曲，不保证整个命令期间其他系统不会切换音乐。通用按钮按下／确认声属于控件输入链，本次未追踪，不混入巡察事件音效。

## 当前接入与验收

### 共用武将显示组件

巡察准备页现由 `OfficerRosterPanel` 组合名单和 `OfficerCard`，页面只传入已选武将与“武将／智力”两列。组件采用局部坐标，保留上文已核对的贴图和锚点。

- `OfficerCard`：200×120的人物卡片，`Officer`为null时自动显示灰色空底图；更新数据会同时更新姓名、头像、能力图。
- `OfficerRosterPanel`：`VisibleRows`可设为1、5、10或其他正整数；`Columns`配置列名、宽度和文字颜色，`SetEntries`传入全部条目。超出一页自动提供翻页按钮，卡片显示当前页第一人；刷新条目回到第一页。显示行数不参与选人上限和命令规则。
- `OfficerPropertyList`：通过`SetProperties`传入当前命令关心的属性，例如政治、忠诚、势力；每项可设置数值区域宽度和文字颜色。可以放在独立卡片旁，目标人物和执行人物各用一组；值由页面提供，组件不计算玩法数值。

调用方需像巡察入口一样预加载`deployment-`和`detail-`纹理前缀，并提供`TextureService`；头像由人物卡片按需加载。单人详情直接组合卡片与属性栏，不必套用名单。当前实际接入为巡察五行名单；一行、十行分页及独立属性栏已提供接口，尚无对应命令页面接入或画面验收。本次仅编译客户端，按用户要求不新增或运行测试，不启动游戏，不重转资源和提升版本。
