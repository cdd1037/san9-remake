# 逆向工程规范

状态：已确认

## 分析基线

- 项目必须从合法持有且可明确识别的样本创建自己的 IDA 数据库。
- 前人旧版 IDA 数据库移入被 Git 忽略的归档目录，只能用于寻找调查方向，不得作为项目事实来源，也不得继续承载项目标注。日常记录和交付无需声明归档库未被修改。
- 开始分析时必须记录样本 SHA-256、文件大小、版本/地区、架构、映像基址、IDA 与反编译器版本。
- 不同样本版本必须使用不同记录和数据库，地址不得跨版本直接套用。
- 每个样本版本应指定一个项目主数据库。新研究先完成只读调查；当证据足以支持命名、类型、结构体、枚举或注释时，按需同步到对应项目主数据库，避免结论只停留在会话或临时导出中。

## IDA 操作分级

1. **只读调查**：二进制概览、字符串、交叉引用、调用图、反编译与数据流查询。新目标必须先执行这一阶段。
2. **解释性标注**：函数/变量命名、注释、类型、结构体和枚举。每项必须能追溯到 `RE-*` 证据与置信度。
3. **批量整理**：批量重命名或应用类型。执行前必须审阅 dry-run 或等价清单，执行后抽查反编译差异与失败项。

只读调查不要求产生“未修改 IDB”的记录。发生解释性标注或批量整理时，关联 `RE-*` 必须列出实际变更、证据、置信度和回读验证；不为形式完整而写入证据不足的名称或类型。

工具自动分析结果和反编译伪代码都不是事实。地址相同也不能证明语义相同。

## 命名与类型

- IDA 是研究工作台，不是最终规格。当第三方源码、文档、旧 IDB 或黑盒观察与目标样本的字节、交叉引用或调用结构相符时，可以采用清晰的来源支持型业务名称，不要求统一添加 `candidate_*`。
- 来源支持型名称必须在注释或关联 `RE-*` 中标明依据和剩余不确定性。名称用于组织调查，不自动把语义提升为已确认行为。
- 只有缺少可对应来源、不同来源冲突或目标样本结构不吻合时，才使用 `candidate_*`、`unknown_*` 等中性名称。
- 高置信度：多种独立证据一致；中置信度：可重复观察支持但边界未完整；低置信度：单一线索或类比。
- 类型和结构体成员必须注明大小、偏移、读写位置、适用版本与推断依据。
- 更名或类型调整后必须比较修改前后反编译结果，确认只是提高表达准确性，没有遮蔽类型冲突。
- IDA 注释应引用 `RE-*`，完整论证保存在仓库记录中；IDB 不是唯一知识载体。来源支持型工作名称可以先于黑盒复验，正式行为规格仍必须满足研究与证据规范。

## 输出边界

- 可以提交自行撰写的符号表、结构说明、调用关系摘要和行为结论。
- 不得提交 IDB、原版二进制、大段反编译文本、汇编转写或可直接重建原版实现的代码摘录。
- 面向实现的规格不得出现硬编码原版虚拟地址；地址只留在 `RE-*` 记录中。
- 产品代码必须独立实现规格，不能链接、注入或补丁原版程序作为重制运行路径。

逆向记录使用[逆向结论模板](templates/reverse-finding.md)。
