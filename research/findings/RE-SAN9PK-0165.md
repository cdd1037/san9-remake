## 只读证据

### PK 基线：成长门检查错对象，正常不变量下不可达

`resolve_duel_combat(0x503AC0)` 的配对清账循环遍历至多五对（分组胜者，配对败者）。分组胜者来自表 `esp+ebp+6Ch`，配对败者来自 `esp+ebp+58h`；两者都先做对象有效性检查，再去重表过滤，随后写入去重表。

成长门在对象检查之后：`0x5049E2` 读取 `[esi+84h]` 并要求等于 `8`，`esi` 是分组胜者；`0x504A1A` 比较 `[esi+8]` 与 `[edi+8]` 的低 16 位（单挑开始时保存的当前有效武力）；`0x504A24` 以 `esi` 为对象、参数 `(1,1)` 调用 `try_increase_person_base_ability`，即强制给分组胜者加 1 点基础武力并饱和到 100。

阵亡与俘虏只从失败侧和配对败者产生，胜者不会由本链写成状态 `8`；赢过前一组者又会被临时 `0x10000` 位排除出阵亡链。因此 `[esi+84h] == 8` 永不成立，PK 版实际不执行任何成长。`RE-SAN9PK-0108` 的运行时断点已确认状态检查、武力比较和成长对象三处的 `ESI` 都是分组胜者；本函数的不变量与同记录一致，缺陷裁决见 `RE-SAN9PK-0105/0108`。

### 非 PK 版：同一位置没有该门

两文件的 `.text` 段布局不同（PK `VA 0x1000 / raw 0x400`，非 PK `VA 0x1000 / raw 0x1000`），比对前先按各自段表换算成文件偏移，没有跨版本直接套用地址。

PK 循环尾段为 `test eax,eax / jz +0x4F / cmp dword ptr [esi+84h],8 / jnz +0x3E / push esi ...`；`San9.exe` 在同一结构的对应位置是 `test eax,eax / jz +0x46 / push esi ...`，即缺少合计 9 字节的 `cmp dword ptr [esi+84h],8 / jnz +0x3E`，两条 `jz` 的相对位移相应各少 9 字节。

从分组胜者加载点（PK `0x5049C0`、非 PK `0x4E42F3`）起逐字节比较，两段除栈帧 `lea` 位移、rel32 调用目标和一处版本特有的临时字节初始化外，结构完全一致：两次对象有效性检查、去重表查询与追加、`[esi+8]` 与 `[edi+8]` 低 16 位比较、严格小于分支、`push 1 / push 1 / mov ecx,esi` 调用，以及 `add ebp,4 / cmp ebp,14h / jl` 循环控制。

两侧末尾调用同一语义的基础能力成长函数：PK 目标 `0x4505D0`（`try_increase_person_base_ability`，320 字节），非 PK 对应 `0x43C860`；两者函数体除异常处理地址、导入 thunk 和 rel32 外逐字节一致，都含 `kakuritsu(3,11,1)` 的强制旁路。因此非 PK 版执行的是“低武力分组胜者基础武力 +1”，没有死亡前置。

### 第三方资料

- 电子书 3-9《三国志IX 能力上升法》在武力一栏列出行动「单挑胜利」，备注「单挑时「武力」较低武将胜利﹐武力才会上升」。
- 同书后文引用玩家经历：车轮战中马超、赵云等单挑失败后由低武力军师接手取胜「附带武力上升」，并称「PK版好象单条不加武力了」。
- 两处都只以武力高低为条件，不要求败者阵亡；第二处还独立指出 PK 版行为与正文不同，与 PK 门不可达的事实一致。

### 状态门极性假设（推断）

另一种读法：该 PK 门本意是「要加武力的角色若已死亡则跳过」，但分支极性写反。核对结果支持这一读法，且它比「检查了错误对象」更能解释代码为何长成这样。

- 字段语义：`0x84` 是 `San9PersonRecord.status`；`kill_person` 以 `sub_44D540(this, 8, ...)` 把死亡写成状态 8。同一二进制用 `cmp [x+84h],8 / jz`（等于 8 则跳过）表达「跳过已死」，例如 `get_current_emperor_person`（`0x45856D`）与 `process_pending_training_events`（`0x40A42D`）。
- 对照形式：PK 此处是 `cmp [esi+84h],8 / jnz`，即「不等于 8 则跳过」，与上述惯用极性相反；改成 `jz` 后行为即与攻略书和非 PK 版一致，只需改动一处分支。
- 对象一致：状态检查、武力比较和成长目标都是同一个分组胜者 `esi`，「给成长目标加存活守卫」在结构上自洽；没有任何版本在此处检查败者。
- 现实效果：胜者先在 `0x503F42`（`esi`）与 `0x504035`（`edi`）被置 `0x10000` 免疫位，`roll_duel_death` 对该位返回 0，`kill_person` 只作用于进入死亡名单的败者，所以胜者在该点不可能是状态 8。极性正确时这个守卫是冗余的防御性检查，写反后则让成长分支永久失效。

因此「写反极性」是目前最能解释 PK 无成长、又不需要发明新规则的假设（推断，置信度中高）。它不改变 PK 基线的机器行为结论，也不改变产品口径。

## 结论与限制

- 事实：PK 基线的战后成长分支在正常不变量下不可达，其状态检查、武力比较和成长对象都是分组胜者。
- 事实：非 PK 版在同一逻辑位置没有该状态门，其余循环结构与 PK 基线一致，并调用同一语义的基础能力成长。
- 事实：电子书 3-9 及同书转载都只以武力高低为条件，不要求败者阵亡，其中转载还指出 PK 版与此不同。
- 推断：原始设计意图是“单挑开始时当前有效武力较低的分组胜者获得基础武力成长”，PK 版因错对象门而没有实际效果。该推断只用于说明取舍理由，不冒充 PK 样本行为。
- 推断：PK 门更可能是「成长目标已死则跳过」的存活守卫把分支极性写反（应为 `jz`），而不是刻意要求败者阵亡；该假设不改变 PK 基线不可达的结论。
- 规格：`BEH-DUEL-0003` 采用该规则；选择理由、备选方案与回退方式见 `DEC-DUEL-0001`。
- 限制：非 PK 版未按项目样本流程登记或建立 IDB，其构建身份来自 PE 版本资源和字节结构一致性，置信度中；本轮没有在非 PK 版上做动态验证。
