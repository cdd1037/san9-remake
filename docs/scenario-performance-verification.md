# 实际剧本结算压力验收

本页保存2026-09-13早期行军方案的实际剧本基线（当时临时标记为v7，与最终统一的规则v7实现不同），当前分段计划方案的100队对照与结论见[寻路优化验收](pathfinding-verification.md)。本次通过公开GameSession执行完整旬结算，不启动Godot，不计渲染和动画播放耗时。

## 数据与构造

输入为本地转换的190年剧本，保留真实地图、地形、设施、势力关系、原有武将能力和规则。原始开局无野外部队，在职武将195人；自然开局与人工构造压力版本分别统计，不能把后者称为自然演化出的历史局面。

压力版本每队5000兵、一名原有武将、阵型0、士气90。优先使用在职武将，再启用剧本内非死亡/非特殊身份的其他武将；300队启用105人，500队启用305人。新增野外兵力不扣除城池驻军，不调整原始势力粮钱。原有武将从驻地转入部队，指挥和成员关系通过正常会话校验与维护。

行军场景在所属城池周边放置不重叠且可站立的部队，命令为进攻就近敌对城池；因此也会产生实际战斗。近战场景改为放在目标城池附近。两者都执行完整经济、人员、军事、AI及收尾流程，保留动态阻挡；不是仅调用寻路器。

## 复现

```powershell
dotnet run --project tools/scenario-benchmark/ScenarioBenchmark.csproj -c Release -- local/generated/content/scenario-190-live/scenario.json 500 3 march local/generated/verification/scenario-500-march.txt verify
```

依次参数为剧本路径、初始队伍数、旬数、`march`或`combat`、报告路径，末尾可选`verify`。队伍数0使用未经修改的开局。启用验证时，在第一旬后恢复独立会话，逐旬核对后续最终状态；恢复和重复推进不计入主会话的旬耗时。报告直接追加到文件，可在长时间运行中读取进度。

每项为一次连续运行，首次旬包含冷缓存和JIT成本；报告中的分配量是当前线程累计分配，不是峰值内存。移动数为实际位置变化事件数，阻路数为不可达移动事件数，伤害数为战斗伤害事件数，均不是独立部队数量。

## 实测结果

| 初始场景 | 第一旬 s | 第二旬 s | 第三旬 s | 第三旬末队伍 |
| --- | ---: | ---: | ---: | ---: |
| 原始开局，0队 | 1.44 | 0.12 | 0.05 | 4 |
| 100队行军 | 8.20 | 4.64 | 3.41 | 97 |
| 300队行军 | 23.63 | 19.13 | 18.44 | 284 |
| 500队行军 | 41.40 | 42.72 | 35.71 | 463 |
| 500队近战 | 13.74 | 4.00 | 4.58 | 219 |

原始开局继续运行到第六旬，第四至六旬约0.023、0.014、0.015秒；此时只有1队，不构成高负载证明。

500队行军的三旬分别发生3933/3419/3189次位置变化、802/1049/1063次不可达事件、721/997/1224次伤害事件。每旬累计分配约1143/1733/2134MiB。高负载并非只存在于首次距离场构建，且后续仍有接近500队活动。

近战场景首旬有2733次伤害事件，队伍立即降到265，随后为239、219；不能将后两旬的4秒解释为持续500队交战只需4秒。

100队与500队行军均在第一旬后恢复独立会话，后续逐旬最终状态一致。所有场景正常完成，没有跳过不可达部队或关闭战斗规则。原始输出保留在 `local/generated/verification/scenario-*.txt`。

## 结论

当前完整结算仍不足以流畅处理这个数百队压力局面。独立寻路微基准的明显收益不能等同于整旬交互响应。

在忽略目录的源码副本中插入分段计时，重新执行500队行军首旬：42.51秒，位置变化、阻路、伤害和总事件数均与未插桩运行一致。

| 分段 | 耗时 s |
| --- | ---: |
| 行军阶段 | 40.03 |
| 其中：寻路总计 | 39.77 |
| 其中：静态距离场构建 | 23.28 |
| 战斗阶段 | 1.06 |
| 军事策略与命令收尾 | 0.65 |
| 兵法支援 | 0.13 |

上表包含嵌套计时，不可相加：距离场构建包含在寻路内，寻路包含在行军内。本旬4989次寻路触发1304次距离场构建。百万节点地图的每份距离数组约7.63MiB，64MiB预算只能保存8份，而压力版本初始进攻目标有16个，后续AI与目标变化还会引入其他查询。

**事实：**主要开销仍在行军，尤其是重复距离场构建；战斗不是这一样本的主要瓶颈。**推断与下一步：**当前逐目标全图距离场及LRU预算在多目标场景下复用不足，需要优化派生数据的粒度和共享方式；剩余搜索耗时还需区分正常绕行与动态无路。不能只扩大缓存或依据阻路计数直接归因。
