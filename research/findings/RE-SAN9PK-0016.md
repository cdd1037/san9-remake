# RE-SAN9PK-0016：剧本国号（kkgu）记录与运行时字段

- 状态：已确认记录边界、加载顺序、类身份、君主/州域字段、国号到州域的运行时链接和两个保留槽位的读取位置；保留槽位与名称资源不阻塞运行时身份模型
- 日期：2026-08-16
- 结论类型：逆向事实、黑盒/样本推断和非核心保留项分开记录
- 相关记录：`RE-SAN9PK-0005`（剧本 chunk 布局）、`RE-SAN9PK-0010`（官爵记录）
- 相关规格：`BEH-IMPORT-0011`

## 1. 范围与证据边界

本记录分析繁中 PK 1.0.1.0 正式剧本和同布局教程剧本中的 `kkgu` chunk，以及原程序载入该块的 `deserialize_kkgu_record`。本轮调查完成后，已将下述已确认的表边界、访问器和链接关系同步到当前 `San9PK-TC-101.i64`；未修改旧版 `San9PK.exe.idb`。

证据来源如下：

- `SRC-IDA-006`：`deserialize_scenario_chunks`（`0x453F60`）、`deserialize_kkgu_record`（`0x4499F0`）、`CKokugouData` 类识别（`0x449780`）和字段归一化分支。
- `SRC-BIN-004`：`private/s9数据文件/D_Sce001.S9`–`D_Sce020.S9`、`D_Ttrl00.S9`–`D_Ttrl05.S9`。
- `SRC-BLACKBOX-007`：`private/剧本编辑器截图/国号.png`。

## 2. 黑盒与样本观察

国号编辑器显示国号表，选中“魏”时基本区为君主“曹操”、州1/州2为空；未知区显示 `0000=0、0002=0、0004=0`。正式样本的 0 号 `kkgu` 记录为：

```text
0, 0, 0, 326, 65535, 65535
```

因此 `+0x06=326` 与曹操的记录代码相符，`+0x08/+0x0A=65535` 表示没有州域关联。`kkgu` 有 20 条、每条 12 字节；50 条势力记录属于后续的 `forc` chunk，不能将两者数量混淆。

## 3. 记录边界与加载事实

`kkgu` 从剧本文件偏移 `0xF86` 开始，长度为 `240` 字节：

```text
240 = 20 × 0x0C
```

`deserialize_scenario_chunks` 以顺序 `0..19` 调用国号加载函数。加载顺序为：读出并丢弃 `+0x00`，将 `+0x02`、`+0x04` 写入运行时对象，再将 `+0x06` 归一化为 `<1050` 的人物代码，`+0x08`、`+0x0A` 归一化为 `<15` 的州域代码。名称由 `CKokugouData` 的运行时 ID 和资源系统生成。

| 剧本偏移 | 类型 | 当前字段 | 证据与状态 |
|---:|---|---|---|
| `+0x00` | `u16` | `serialized_id` | 读出后丢弃；运行时 ID 使用外层序号 |
| `+0x02` | `u16` | `opaque_field_02` | 写入运行时对象；截图未知栏显示 |
| `+0x04` | `u16` | `opaque_field_04` | 写入运行时对象；截图未知栏显示 |
| `+0x06` | `u16` | `ruler_person_code` | `<1050` 时保留为有效人物代码；否则运行时为空 |
| `+0x08` | `u16` | `area_1_code` | `<15` 时保留为州域 ID；否则运行时为空 |
| `+0x0A` | `u16` | `area_2_code` | `<15` 时保留为州域 ID；否则运行时为空 |

`+0x06` 的 1050 上限是原程序加载分支的事实，不应直接等同于当前正式剧本 `prsn` chunk 的 800 条记录；导入器保留代码原值并只提供按原分支范围的派生空值。`+0x08/+0x0A` 的 15 上限与 `area` 的 15 条记录闭合。

## 4. 运行时访问与链接（IDA 事实）

- `sub_453850` 以 `n < 20` 为边界，返回 `0x15007B0 + 0x30*n`，因此 `kkgu` 不是只在加载阶段存在的临时表，而有独立的按 ID 访问器。
- `sub_4499B0` 只接受槽位 `j=0..1`，读取当前 `kkgu` 对象 `+0x28 + 4*j`；`sub_4499D0` 再将该值通过 `sub_452EF0` 映射为 `area` 记录指针（代码 `0..14` 有效）。这确认 `+0x08/+0x0A` 是两个州域关联代码，而不只是未使用的保存槽位。
- `sub_456100` 遍历 20 条 `kkgu`，对两个州域槽位执行映射；若州域记录有效，则写入 `area_record +0x24 = kkgu_record`。该写入是州域到国号的运行时反向链接，目标不是覆盖 `kkgu +0x24` 的君主代码。
- `+0x02/+0x04` 在当前 IDB 中仍只有加载和对象保存证据，没有已确认的业务消费者；保持不透明命名。

## 5. 结论分级

### 已确认

- `kkgu` 是 20 条固定长度记录，每条 12 字节。
- `+0x00` 不建立运行时身份，外层循环序号建立 `Id`。
- `+0x06` 是国号的君主人物代码；`+0x08/+0x0A` 是两个州域代码。
- 原程序将人物代码限制为 `<1050`，将州域代码限制为 `<15`；越界值在运行时变为空关联。
- `kkgu` 有按 ID 的直接访问器；两个州域代码会参与州域记录解析，并建立州域记录到国号记录的反向链接。
- `+0x02`、`+0x04` 会写入运行时对象，不能在导入时丢弃。

### 可选格式深挖

- `+0x02/+0x04` 是否是编辑器遗留槽位、排序数据或其他国号属性。
- 20 条国号记录与 50 条势力记录在游戏逻辑中的完整关系。
- 国号名称资源的具体索引表及编辑器单变量修改后的保存差分。
- 非正式布局 `D_Trst01.S9`–`D_Trst28.S9` 的不同 `head` 布局适用性。

在未知槽位语义闭合前，产品层保留全部原始值，不将它们命名为势力、颜色、官爵或排序属性。

> **SCN-02 收口（2026-08-26）**：`kkgu +0x06` 是场景定义的君主人物引用，但不承担运行时势力继任，也不决定当前皇帝；根势力君主、势力官爵与皇帝解析的独立状态见 [RE-SAN9PK-0141](RE-SAN9PK-0141.md)。上述保留槽位和名称资源属于可选内容/编辑器深挖，不再作为核心路线缺口。
