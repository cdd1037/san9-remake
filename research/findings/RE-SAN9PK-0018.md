## 1. 记录结构与运行时类型

`skrk` 位于正式布局剧本偏移 `0xF38`，大小 70 字节，即 7 条固定的 10 字节记录。`deserialize_sakuryaku_record(0x452C70)` 固定执行 7 次，并把记录载入 `g_scenario_sakuryaku_records(0x14FD9F0)`；运行时记录步长为 `0x20`。

RTTI 名称 `CSakuryakuData` 直接确认该表是原程序的“策略（Sakuryaku）”数据，运行时打包类型码为 14。每条记录的加载行为如下：

| 偏移 | 大小 | 产品字段 | 目标程序行为与结论 |
| ---: | ---: | --- | --- |
| `+0x00` | `u16` | `SerializedId` | 读取后丢弃；运行时编号使用外层循环序号 |
| `+0x02` | `u16` | `SerializedIdCopy02` | 写入运行时 `+0x10`；182 条库存记录均等于顺序 ID，无业务读取 |
| `+0x04` | `u16` | `OpaqueField04` | 写入运行时 `+0x14`；稳定分组但无业务读取 |
| `+0x06` | `u16` | `OpaqueField06` | 写入运行时 `+0x18`；稳定分组但无业务读取 |
| `+0x08` | `u16` | `OpaqueField08` | 写入运行时 `+0x1C`；库存恒为 3，但无业务读取 |

## 2. 全库存观察

20 个正式剧本和 6 个同布局教程剧本共 182 条记录完全一致，每个文件的 7 条记录均为：

```text
0: 0, 0, 1, 1, 3
1: 1, 1, 1, 1, 3
2: 2, 2, 1, 1, 3
3: 3, 3, 1, 1, 3
4: 4, 4, 2, 4, 3
5: 5, 5, 2, 4, 3
6: 6, 6, 2, 4, 3
```

因此 `+0x02` 可闭合为第二份序号。`+0x04/+0x06/+0x08` 的稳定模式只证明它们不是随机填充；没有读取方时，不能把 `1/2`、`1/4` 或常量 3 推定为伤害、距离、设施、地形或目标类别。

## 3. 策略到兵法的显示关系

原 IDB 曾把 `0x452D90..0x452E2A` 误识别为数据。按虚表入口、完整指令、返回指令和对齐边界恢复代码后，`get_sakuryaku_tactic_name(0x452D90)` 明确执行：

```text
related_tactic_id = strategy_id + 35
```

随后经 `get_killer_record` 取得兵法运行时记录并返回它的名称。兵法访问器只接受 `0..40`，因此映射为：

| 策略 ID | 关联兵法 ID | 显示名 |
| ---: | ---: | --- |
| `0` | `35` | 穴陷 |
| `1` | `36` | 火陷 |
| `2` | `37` | 水陷 |
| `3` | `38` | 岩陷 |
| `4` | `39` | 落石 |
| `5` | `40` | 射台 |
| `6` | 无 | 越出兵法表，回退为空/错误文本 |

`format_sakuryaku_property(0x452DE0)` 又形成独立交叉验证：通用属性 0/1 输出策略顺序 ID，属性 2 输出上述关联兵法名称。`RE-SAN9PK-0026` 的本地消息资源枚举没有实际使用策略对象选择器，因此当前确认的是对象自身具备通用格式化能力，而不是存在已命中的消息脚本消费者。

## 4. 消费者边界

不能说整个 `skrk` 表是死数据：原程序会构造 `CSakuryakuData`，验证类型 14，并可通过虚函数输出 ID 与关联兵法名称。能关闭的是四个序列化运行时槽的业务读取问题：

- 全局表基址的直接引用只落在初始化/加载路径；7×4 个精确字段地址均无交叉引用；
- `runtime_class_CSakuryakuData` 没有业务下转型引用；
- 恢复出的类专用虚函数只读取对象身份，不读取运行时 `+0x10..+0x1C`；
- 本地消息资源没有策略选择器命中。

因此 `+0x02` 是无业务消费者的冗余序号副本，`+0x04/+0x06/+0x08` 是当前 EXE 无业务消费者但必须无损保留的原始槽。结论仅适用于繁中 PK 1.0.1.0；其它版本和库存外文件不在覆盖范围内。

## 5. 产品实现

- 导入领域模型使用 `Strategy`，存储层仍按原始 FourCC `skrk` 定位。
- 记录 `Id` 使用文件顺序；`+0x02` 暴露为 `SerializedIdCopy02`。
- `RelatedTacticId` 对 ID `0..5` 返回 `35..40`，ID 6 返回空；非法策略 ID 被拒绝。
- 三个无消费者字段继续按原始偏移无损保留，不参与玩法派生。
