# 统一文字样式

界面通过 `GameTextStyles` 选择用途和状态，通过 `GameTextPresenter` 或 `GameRichTextLabel.Present` 应用。字体统一来自 `assets/GameFont.tres`。不在各个界面重新实现描边、不从原作调色板号直接构造业务样式。消息编写见[消息约定](messages.md)；解码、繁简转换及姓名用字见唯一权威[文字与翻译规范](../../specs/text-and-translation.md)。

## 绘制约定与实现状态

原作是颜色、信息层次和状态组合的依据。按 [DEC-UI-0002](../../specs/decisions/DEC-UI-0002-modern-text-effects.md)，重制使用现代字体及 Godot 原生效果：描边参数 `outline_size = 4`、效果色 alpha 乘 `0.57`（8-bit 取 `91`）；阴影偏移 `(1,1)`、保留效果色覆盖度；无效果角色关闭两者。

这里的参数 4 在当前 Godot 4.7.2 普通字体 FreeType 路径下约对应 1 个逻辑像素的几何扩张半径，不表示向外扩展 4 像素。参数 1 约对应 0.25 像素，不能再称作“1 像素描边”。MSDF、字体后端或版本变化后须重新校准。

实现状态（2026-09-27）：`TextOutlineStyle` 集中定义参数 4、alpha 0.57，并生成 8-bit alpha `91`；`GameTextEffects` 与 `MessageStyleMarkup` 共享此配置，覆盖普通标签、富文本基线、行内预设和地图入口。实际游戏画面尚未按新参数验收。

- `Label`：缓存共享的不可变 `LabelSettings`，使用 `OutlineSize/OutlineColor` 和 `ShadowOffset/ShadowColor`。
- `RichTextLabel`：使用对应原生主题属性。图标由原生 `[img]` 参与排版，不对图标复制文字效果。
- 地图：`DrawStringOutline` 加主体绘制，或一次偏移阴影加主体绘制。

阴影保持 `ShadowOffset = (1,1)`、效果色 alpha 不额外衰减，`LabelSettings.ShadowSize = 0`、富文本 `shadow_outline_size = 0`。这里的偏移直接对应逻辑坐标，不套用描边参数的半径换算；扩张为 0 只关闭额外轮廓，不会关闭阴影。现有三个入口已在 264 字、16／24 号字、两底色与两主体色的对照中验证为与单次偏移参考完全相同，详见 [RE-0167 阴影复核](../../research/findings/RE-SAN9PK-0167.md#阴影路径复核与现代入口对照2026-09-27)。此结论针对无行内预设的阴影，含预设时仍按下文宿主转换策略处理。

Godot 的堆叠轮廓、堆叠阴影不需要用于这批已确认的单一效果组合；原作同时打开两个标志时，实际阴影优先，并不是双层效果。当前不使用八邻域文字副本，不引入 TextServer 排版。原生轮廓的粗细与原作位图不同属于明确的重制选择。

## 多行排版

普通标签和富文本统一由 `GameTextMetrics` 计算额外行距：`字号 - ceil(font.GetHeight(字号))`，以字号作为默认基线步长，避免现代字体的上升部、下降部高度和控件默认行距叠加。当前字体按度量估算，16 号字约补偿 −3，24 号字约补偿 −5；实际值取运行时字体度量，不在页面写死。

文字布局入口区分字格锚点与控件区域，调用方按坐标语义选择：

- 原作坐标表示名义字格顶部时，普通标签使用 `GameTextPresenter.ApplyAtGlyphCell`、富文本使用 `GameRichTextLabel.PresentAtGlyphCell`，直接绘制使用 `GameTextPresenter.DrawAtGlyphCell`。三者共享 `GameTextMetrics.GlyphCellPosition`，将现代字体行框居中放入名义字格：`floor((字号 - font.GetHeight(字号)) / 2)`；直接绘制入口再转换为字体基线。每次调用按当前字体计算，不累计移动已有位置。应在控件加入主题所在树后调用。
- 容器、按钮和给定区域内居中的文字继续使用 `Apply`／`Present`，位置与大小交由布局和对齐属性管理；已提供基线的直接绘制继续使用 `Draw`。容器子节点不使用绝对字格定位入口。

地图喊话已接入公共字格入口，调用处保留原作锚点姓名(106,23)、正文(92,41)。当前 16／12 号字行高分别为 19／15，均上移 2 个逻辑像素。这是现代字体的行框适配，不校正每个字形的内部留白；换字体后仍需检查画面。其他既有界面按其坐标语义逐处接入，不能全局统一上移。

`GameTextPresenter`、`GameRichTextLabel` 和 `GameDialog` 共用此规则，覆盖人物对话、命令结果、通知正文和详情说明。保留末行完整字形高度；确认弹窗仍将超出字号的末行高度计入正文区域。手动定位的列表行、地图文字和表格行距由各自布局控制。富文本内较大的字号或图标仍参与原生行高计算，不强行压缩。

此次统一未运行测试或游戏，实际画面待用户验收。

## 消息内样式

消息只引用八个有限预设，不保存调色板号、前景／效果通道或任意BBCode开闭片段。字号和布局仍由所在界面决定。

| 预设 | 主体色 | 描边色 |
| --- | --- | --- |
| `blue-outline` | 沿用外层字色 | 98B0F8 |
| `green-outline` | 沿用外层字色 | 88F880 |
| `peach-outline` | 沿用外层字色 | F0B080 |
| `yellow-outline` | 沿用外层字色 | F8F8B0 |
| `blue` | 7EBAC2 | 000000 |
| `green` | A4D168 | 000000 |
| `peach` | F0B080 | 000000 |
| `yellow` | F8F8B0 | 000000 |

前四项只指定描边，字色沿用外层样式（没有外层主体强调时沿用控件默认字色）；人物对白和无头像结果框因此保持黑字，预设结束后恢复外层效果。后四项用于帮助／教学规范化后的主体强调，`yellow`也用于已确认的容貌帮助。轮廓统一采用参数 4、效果色 alpha 为 `91`。

静态范围保存为`[preset=名称]正文[/preset]`并与相邻文本合并；包含动态参数、分支或引用时使用`MessageStyled(Preset, Body)`。嵌套、引用和提前返回均闭合自身范围，恢复外层样式；正文默认样式由控件提供。Importer独自处理源控制码及跨调用状态传播，发布后不需要原作状态机。未登记组合明确拒绝，不将32种调色板值任意组合。

带预设的富文本使用描边组合：若宿主原本为整段阴影，将该段正文基线转换为同效果色描边，再应用行内预设，避免原生富文本不能局部关闭阴影的问题。无预设文字仍使用原有宿主样式。源复位恢复正文基线而非强制关闭宿主描边，这两点属于本次重制选择，画面待验收。

帮助／教学调用方使用Importer的`OriginalMessagePresentation.Help`，将已确认的`b/s`及颜色1→28、4→27归并为上述主体强调预设。默认消息目录按普通消息用途转换；专用用途需明确选择，不全局改写普通消息，也不代表帮助页面已经接入。标准BBCode自由颜色、字号等创作功能留待Mod扩展。

左下进行记录同样采用主体强调，原作发布前的规范化证据见[RE-0183](../../research/findings/RE-SAN9PK-0183.md#记录与喊话的行内强调复核2026-10-10)。其富文本入口选择 `MessageEmphasisMode.Foreground`，将四种轮廓预设按显示用途转换为同名主体预设，不修改已产生的消息；范围结束恢复外层样式。喊话和普通对话继续使用默认 `Outline` 模式。

帮助、教学的游戏接入优先级较低，按用户2026-10-10决定延后对齐。后续接入时必须覆盖教学正文、帮助页、帮助内容和帮助主题四个已确认入口，选择上述主体强调转换，并核对黑描边、预设结束后的样式恢复及12／16号现代字体排版；不能直接套用普通对话的轮廓强调。现有Importer转换能力和测试保留，尚未完成游戏画面验收。

## 覆盖与复核入口

已对共享设置／布局函数的全程序直接引用建立清单：883 个调用点、209 个函数、853 条反编译观察；归并得到 47 种实际引用的单通道状态表。它们不等于 47 种已确认完整组合。另有 102 条动态／上下文观察和 47 个未匹配调用点，均保留定位，不能据此宣称全游戏样式已经闭合。研究见 [RE-0167](../../research/findings/RE-SAN9PK-0167.md)。

在对应 IDA 主库执行 `research/scripts/ida/export_text_style_usage.py`，再运行：

```powershell
python research/scripts/summarize_text_style_usage.py local/generated/research/text-styles/usage.json
```

得到 `catalog.json` 与 `catalog.md`，包括去重状态表、每个实际调用的证据及未闭合项。生成物只写入 `local/generated/`。以后优先查该目录和研究记录，未闭合的对象生命周期仍需要研究，不能直接交叉组合调色板值。

历史验收入口 `--text-smoke` 会生成 12／16／24 字号、99 个角色／状态样本的三入口比较页 `local/generated/verification/text/styles-*.png`，并检查普通标签与富文本效果参数一致。后续开发默认不运行，只有当前任务明确要求复现文字场景时单独执行，见[Godot历史画面验收](client-verification.md)。实际截图还须检查可读性、图标、裁切；自检通过不代替画面检查。
