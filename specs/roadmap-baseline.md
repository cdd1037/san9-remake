## 使用 IDA MCP 定位原版行为

当当前阶段缺少可执行规则输入、已有证据矛盾，或行为时机与写回边界不清时，可直接使用 IDA Pro 与本地 MCP 定向调查。执行遵循[逆向规范](reverse-engineering.md)和[研究规范](research-method.md)；常规只读调查及有证据的解释性标注已有授权，无需逐项确认。

1. 先把问题限定为当前阶段所需的行为，例如“持续任务何时释放人物占用”或“某笔费用从哪个军团账户扣除”。查对应 BEH、RE 和符号记录，优先复用已有结论；将事实、推断与待验证项分开。
2. 发现并连接当前可用的 IDA MCP 工具，核对连接的样本与项目主库身份；默认使用 `San9PK-TC-101.i64`，引用已有样本登记。只有问题涉及 DLL 内部契约时才进入对应 DLL 数据库，不能跨版本套用地址。
3. 从已有符号、字符串或交叉引用定位入口，沿调用者、被调用者和字段读写追踪前置校验、输入生产、调度条件、随机消费、最终写回及清理分支。反编译用于导航，关键整数截断、符号性、条件跳转及调用顺序须结合实际指令和数据流核对。
4. 对静态证据无法判定的分支，记录最小动态实验的初态、操作、观察量与预期区别；实际运行前遵守当前任务的不启动游戏约定。MCP不可用或证据不足时明确记录缺口，继续不依赖它的工作；需要重制选择时在BEH/DEC中明确采用的行为，不把猜测写成原作事实。
5. 将结论、来源、适用范围及限制写回对应RE。需要更名、注释或类型修正时，先完成只读查证，再同步样本主库并记录实际变更与回读验证；批量操作先审阅dry-run。原版地址与存储偏移留在RE，产品只消费规范化语义。
6. 依据证据更新对应BEH的输入、效果、不变量与验收，再独立实现规则。原作动态实验与重制测试分别报告；不将反编译代码、汇编转写或第三方补丁实现复制到产品代码。

近期定位入口：G01从[RE-0145](../research/findings/RE-SAN9PK-0145.md)、[RE-0123](../research/findings/RE-SAN9PK-0123.md)及[RE-0098](../research/findings/RE-SAN9PK-0098.md)核对前置更新、命令时机与周期清理；G03从RE-0095/0098/0067追踪组合、账户和经济输入。G05之后按上表的缺口进入对应战争、人物或治理证据，不预先安排全库扫描。

## G01 具体实施与验收输入

依据 [BEH-SIMULATION-0001](behavior/BEH-SIMULATION-0001-time-progression-and-state-visibility.md)和 [DEC-SIM-0001](decisions/DEC-SIM-0001-determinism-and-saves.md)细化，先修改该 BEH，再实现以下边界：

1. 用唯一日历表示日级时间，明确当前内容每月30日与1/11/21日稳定边界。旬/月/季/年由日期派生，不保留第二套可写时钟。新局入口执行本旬前置更新一次，稳定恢复入口跳过已提交更新；场景起始日期须独立保留，供 G03 的经过天数门使用。
2. 按已有 BEH 串行组织终局检查、旬事件、普通旬更新、月事件、登场/独立、季度前置/主事件、季度更新、年度登场清理；日循环为命令前更新→命令事件→日期加一→日地图更新→后续部队/建筑事件。未接入的领域不声称有实际效果；测试可记录阶段调用以验证顺序。
3. 即时与耗时命令共用类型化终验，权限上下文不能仅凭客户端传入的 ForceId 认定合法。Core 保存可恢复的活动控制边界，Application 将玩家/AI控制配置转成请求；G04再扩充治理变更。即时内政保留即时生效及旧有拒绝行为。
4. 持续任务保存身份、发起方、执行者、目标、开始/到期、进度及占用；提交只产生开始效果，到期重新验证后提交完成效果，失败释放占用且不发成功事件。旬行动恢复不能擦掉持续占用。用明确的测试任务验证内核，不把测试任务暴露为已完成的人事或战争命令。
5. 为实际执行顺序、随机流名称及状态、稳定/执行中/终局边界确定可恢复表示；事件在成功提交后发布。终局判定可用测试夹具驱动短路，G06负责实际征服/灭亡规则。G01不假称已完成磁盘存档。

自制夹具设计：两个势力各一城，各有君主和两名普通驻留人物；四项能力刻意不同；第一城商业300/500、开垦200/500、资金1000。人物和军团引用闭合，日期参数化为190-01-01、190-03-21、190-12-21，固定种子190，命令使用显式固定ID。复用现有测试构造方法，避免私有内容依赖。

| 终局和原子失败 | 前置终局后后续更新不执行；候选事务失败不发布事件；对外不能取得可保存的半提交状态 |

验证使用受影响测试；时钟、命令及快照跨层变化运行整个解决方案。G01完成后再进入G02，不借测试夹具替代后续真实任务实现。

## G02 具体实施与验收输入

复用G01夹具和权威状态，Application新增明确的新局、保存、恢复用例，CLI只依赖Application/Content/Core。现有San9.Tools含导入用途，不能仅以已有工具命令证明独立headless runner存在。

- 存档清单覆盖日历/起始日期、全部领域集合、控制边界、命令序列/去重信息、命名随机及未完成任务。区分权威状态和可派生缓存；自定义年表需要明确作为会话持久数据保存，不能无声丢失。UI投影从恢复状态重建。
- 内容指纹覆盖影响规则的规范化定义与规则版本；不能直接把当前WorldSnapshot.StateHash当内容指纹。定义集合排序、数值/枚举编码、空值及摘要版本；事件比较也使用结构化字段，不以显示文本判断确定性。
- 建议重放采用稳定执行序号和命令ID：相同记录重复导入不再次执行，相同ID不同载荷明确拒绝；准确行为在G02规格中采用后实现。拒绝记录与接受记录分开，不能由当前每旬清空的去重集合承担跨存档去重。
- 保存仅接受稳定边界；读取时先校验格式、内容身份、结构及世界不变量，再发布会话。未知版本明确拒绝，未来迁移只能显式实现；失败不改变现有会话。明确磁盘写入失败保护策略。

验收夹具：固定日志运行36旬，分别在首次即时命令后、持续任务跨旬后、跨年之前保存再恢复；与连续运行比较最终权威哈希及恢复点之后完整事件序列。覆盖截断文件、篡改引用、缺少任务执行者、内容不符、未知版本、重复ID及相同ID不同载荷。CLI自制场景下令并推进，机器报告包含指纹、种子、命令日志、旬数/终止原因、哈希、首个失败和耗时，失败类别具有明确非零退出码。该36旬验收是时序与重放验证，不代表G03一年经济完成。

G03a完成多人四项内政与征兵训练；G03b完成周期经济。两项共同通过一年实际经营与恢复验收后才完成G03。
