# BEH-IMPORT-0006：剧本官职记录解析

- 状态：已确认
- 负责人：项目开发者
- 最后更新：2026-08-16
- 关联证据：[RE-SAN9PK-0011](../../research/findings/RE-SAN9PK-0011.md)
- 关联决策：[DEC-DATA-0001](../decisions/DEC-DATA-0001-content-pipeline.md)

## 适用范围

本规格约束繁中 PK 1.0.1.0 正式剧本 `shak` chunk 的记录边界、官职字段、官爵组引用、能力加成和当前运行时无效字段。输入必须先通过 [BEH-IMPORT-0001](BEH-IMPORT-0001-source-container-validation.md)。

本规格不定义官职名称资源、编辑器控件布局或其他原版构建可能对三个保留槽位的解释。

## 原作基线

`shak` chunk 位于剧本数据 `0x9C6`，包含 77 条记录，每条 18 字节，共 1,386 字节。运行时官职 ID 使用记录序号 `0..76`，其中 76 是“无官职”哨兵，正常可任命官职为 `0..75`。

| 偏移 | 类型 | 规格字段 | 已确认语义 |
| --- | --- | --- | --- |
| `0x00` | `u32` | `command_capacity` | 官职提供的指挥/带兵上限；界面显示为“指挥” |
| `0x04` | `u16` | `serialized_id_ignored` | 库存剧本中等于记录序号；加载后丢弃，当前运行时无效 |
| `0x06` | `u16` | `opaque_unused_1` | 加载后写入对象槽位，但当前官职 getter 和业务路径不消费 |
| `0x08` | `u16` | `opaque_unused_2` | 加载后写入对象槽位，但当前官职 getter 和业务路径不消费 |
| `0x0A` | `u16` | `rank_group_id` | 对应 `kans` 官爵记录的组 ID；`0..8` 有效，`>=9` 运行时视为空关联 |
| `0x0C` | `u16` | `salary` | 官职俸禄；不是忠诚字段 |
| `0x0E` | `u16` | `ability_mask` | 四项能力加成掩码；bit 0..3 分别为统率、武力、智力、政治 |
| `0x10` | `u16` | `ability_bonus` | 四项被选能力共用的增加值；界面显示为“能力增加数” |

`+0x04/+0x06/+0x08` 是当前运行时无效或遗留的原始槽位，不得进入官职玩法领域模型。它们仍属于输入记录的原始字节，导入器必须保留，以支持无损内容源和编辑器往返。

`salary` 与官职忠诚必须分开建模。原版可由俸禄派生官职忠诚影响值；San9PKHard 的 `official_loyalty` 是按官职 ID 替换该派生结果的表，不是 `shak +0x0C` 的字段名。

编辑器下方的 `0002/0004/0006/0008` 是原始记录的 2 字节偏移显示，不是四个额外业务字段：`0002` 是 `+0x00` 的高 16 位，后三项分别对应 `+0x04/+0x06/+0x08`。

## 重制行为

导入器必须生成 77 个按序排列的官职定义，并至少暴露以下领域字段：

- `id`：记录序号 `0..76`；
- `is_assignable`：`id < 76` 为 true，`id == 76` 为 false；
- `command_capacity`：`+0x00` 原始 `u32`；
- `rank_group_id`：原始值 `0..8` 转换为对应官爵 ID，原始值 `>=9` 转换为空关联，同时保留原始 `u16`；
- `salary`：`+0x0C` 原始 `u16`，不得命名或转换成忠诚值；
- `ability_mask`：至少使用低 4 位；bit 0..3 依次代表统率、武力、智力、政治；高位原始值必须保留但不得解释为已确认能力；
- `ability_bonus`：`+0x10` 原始 `u16`，对 `ability_mask` 选中的能力统一生效。

官职 76 必须作为“无官职”记录保留，但不得被分配给正常武将。运行时内部空关联可以表示为 `null` 或等价空值，不得把 `-1` 重新当作有效官职 ID。

导入器还必须保留 `serialized_id_ignored`、`opaque_unused_1` 和 `opaque_unused_2` 的原始值，但不得根据它们改变官职 ID、任用资格、指挥上限、官爵组、俸禄、能力掩码或能力增加。不得把这些字段命名为排序权重、地域、能力类型或其他未被证据支持的业务属性。

本规格不对 `salary`、`ability_bonus` 或能力掩码高位施加库存样本之外的平衡范围，不得静默钳制或截断；若产品需要额外设计范围，必须另行建立决策记录。

## 状态与不变量

- 输入与前置条件：已通过 `BEH-IMPORT-0001` 的完整剧本流，读取位置为 `0x9C6`。
- 状态变化：无；只生成 77 个只读官职定义。
- 始终成立的不变量：记录顺序等于 `id`；每项完整消费 18 字节；`command_capacity` 按 `u32` 读取，其余字段按 `u16` 读取。
- 官职不变量：只有 `0..75` 可任命；76 始终表示无官职；`rank_group_id` 的领域值只能是 `0..8` 或空值。
- 能力不变量：`ability_mask` 的 bit 0..3 独立选择四项能力，所有被选能力读取同一个 `ability_bonus`。
- 业务不变量：三个无效/遗留槽位不得影响领域字段或运行时行为。
- 失败行为：容器、chunk 位置或记录边界不成立时抛出格式错误；不得用相邻 chunk 字节补齐记录。

## 示例与边界

- 官职 75“武卫校尉”：`command_capacity = 15000`、`rank_group_id = 8`、`salary = 4`、`ability_mask = 0`、`ability_bonus = 0`。
- 官职 75 的原始 18 字节为 `98 3A 00 00 4B 00 4B 00 4B 00 08 00 04 00 00 00 00 00`；编辑器偏移行 `0002/0004/0006/0008` 对应 `0/75/75/75`。
- 官职 64..67 的 `ability_mask` 为 `0x000C` 时，表示智力和政治加成；能力增加数由同一条记录的 `+0x10` 提供。
- 官职 76：`is_assignable = false`，领域引用解析为空。
- 修改任一 `+0x04/+0x06/+0x08` 原始值不得改变导入后的领域字段。

## 验收标准

- [ ] 77×18 字节边界和字段宽度由自制夹具测试证明。
- [ ] 指挥、官爵组、俸禄、能力掩码和能力增加值的字段映射由自制夹具测试证明。
- [ ] 0..75/76 的任用边界和 `rank_group_id` 空值转换由自制夹具测试证明。
- [ ] 三个无效/遗留槽位能无损保留，且不会进入玩法领域模型。
- [ ] 测试夹具不依赖原版文件、编辑器或 IDA 数据库。
