# 哈希与指纹用途

哈希用于比较内容或记录证据，不替代领域不变量、版本语义或身份字段。当前没有防作弊、对抗性存档验证或跨机器身份认证需求，不把SHA-256当作所有对象的默认身份。

| 用途 | 保留方式 | 实际消费者 |
| --- | --- | --- |
| 原版程序识别 | 对已登记EXE计算SHA-256 | Importer选择正确版本，防止以错误布局解码 |
| 导入来源与文本证据 | 记录源文件SHA-256，证据与源样本匹配 | 离线溯源、文本位置核对与研究复现；客户端不重新读取原文件 |
| 内容指纹 | 对规则所需规范化初始数据计算一次并复用 | 存档、日志、录像检查内容匹配；规则版本差异单独警告 |
| 世界/会话摘要 | 访问`StateHash`时计算，不写入普通快照 | 测试、headless报告、录像最终一致性比对 |
| 录像文件完整性 | 每文件一个封套校验值 | 检测意外损坏；不代表签名或防篡改认证 |
| 命名随机 | 稳定非密码学混合后使用SplitMix64 | 隔离规则/AI分析随机用途；不承担完整性校验 |
| 研究目录、队列和字体产物摘要 | 保留离线来源/快照摘要 | 确認样本、记录处理输入、定位旧证据；不进入游戏运行时 |

普通存档允许手工修改，摘要头和正文均不保存或检查完整性哈希；仍检查结构、版本、内容身份和状态合法性。`hashVersion`标识内容指纹的规范化版本，不代表存在正文哈希。

默认运行和录像录制/重放均不为每条操作计算世界SHA-256；当前验证录像在导出时计算最终会话摘要，在重放结束时核对。录像格式4移除逐操作世界摘要，旧录像格式明确拒绝，普通存档和日志格式不变。默认运行不为每个快照计算SHA-256，也不为内存恢复重复核对世界摘要和会话摘要。录像使用直接恢复入口，不先把快照转成带校验的存档再读回。内容加载不重复构建同一份定义指纹。

本地命令绑定当前会话，序号决定处理顺序；自动ID直接编码初始种子和操作序号。JSONL只在头部比较内容和种子，规则版本不同仅警告，不给每条操作附加派生流指纹。AI分析由初始种子、势力、日期和用途派生，不依赖全世界哈希。

Importer组合流程复用已读源字节和来源摘要，地图编译不再自行重复读取、哈希同一份EXE/剧本。版本识别与研究导出仍可独立运行，保留各自必需的样本核验。纹理增量更新继续使用已有转换版本、文件大小和时间戳，没有新增全资源指纹链。

世界引用、数值范围、稳定边界、任务占用及未知格式／哈希版本仍按各自契约校验；这些是保证状态有效的规则，不因移除重复哈希而省略。具体存档和录像入口见[G02使用与验收](g02-verification.md)。

本次验证：既有全解决方案460项行为测试通过；公开和190年剧本各36旬的连续/恢复、日志与录像重放通过。Importer组合读取调整通过编译及既有183项导入测试，本次未重新转换完整原始资源包。

玩家录像的正式交付目标包括全程回放、跳转和接手新分支。以上事件／摘要核对描述当前验证模式，正常播放不必强制逐事件比较；玩家模式的一致性检查与差异处理在交付前明确，见[后续要求](../specs/behavior/BEH-SAVE-0001-session-persistence-replay-and-headless.md#面向玩家交付前的后续要求)。
