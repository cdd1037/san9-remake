## 适用范围

适用于普通场景从玩家确认结束战略阶段，到旬结算、逐日推进、下一旬地图日历可见的完整时间边界。具体事件内容、消息演出、存档容器字节布局和第三方补丁扩展不在本规格内。

## 原作基线

确认结束战略阶段只提交阶段切换，不直接推进日期。旬结算按单一活动子任务串行执行：旬世界结算、两个中间/演出阶段、部队模拟、逐日日期模拟。旬世界结算先设置月、季、年边界标志并检查终局，再依次执行旬事件选择、普通旬更新、可选月事件选择、登场/独立处理、可选季度前置与主事件选择、季度世界更新、可选年度登场和清理；终局成立时跳过不应继续的后续世界更新。

逐日模拟在每一天串行处理命令前更新、部队命令事件、权威日期加一、日级地图更新及后续部队/建筑事件，直到到达下一旬的第一日。日循环完成后才把权威日期同步为大地图日历缓存并刷新显示。存档保存权威场景日期、世界标志和领域记录，不保存活动任务阶段或大地图日期缓存；载入先恢复权威日期，UI 状态随后派生。

## 重制行为

重制版以 `SimulationClock` 持有唯一权威日期，以 `PeriodBoundary` 表示旬、月、季、年边界，以显式的 `ResolutionPipeline` 串行阶段替代隐式任务状态码。周期系统只能读取权威日期和边界快照，不能各自维护可分叉的日期。`CalendarViewModel` 始终由已提交的权威日期派生；存档不持久化它，也不恢复执行到一半的旬结算。

保存只允许发生在稳定交互边界。若将来需要中途保存，必须另立决策定义事务快照、随机状态和任务恢复协议，不能把现有 UI 缓存或内部阶段号当作兼容格式。

## 状态与不变量

- 输入与前置条件：已确认结束战略阶段、当前权威日期、场景世界状态、有效领域对象引用、周期事件表和确定的随机源。
- 状态变化：旬级世界更新按固定顺序提交；随后逐日推进到下一旬第一日；最终发布新的日期视图模型。
- 始终成立的不变量：权威日期唯一；同一时刻最多一个活动结算子阶段；月/季/年是旬边界上的派生条件；显示日期不可反向修改模拟日期；存档不包含 UI 缓存和未完成任务阶段；失效对象引用在消费前校验并清除或拒绝。
- 失败或无效输入行为：阶段输入缺失、对象引用失效或日期不合法时拒绝开始或中止尚未提交的阶段，不用旧引用、默认对象或显示缓存继续结算。

## 示例与边界

- 3 月下旬结束后，逐日推进到 4 月 1 日；该旬同时产生月和季边界，不产生年边界。
- 12 月下旬结束后推进到 1 月 1 日；该旬同时产生月、季和年边界，年度步骤位于季度世界更新之后。
- 普通月份的 11 日或 21 日只产生旬边界；当前样本的月事件表为空也不能省略月边界语义。
- 载入后以存档中的权威日期重建日历显示，不接受存档外的旧 UI 日期缓存。
- 年表中的零年份是原作无效条目标记；负年份显示属于第三方扩展，不是本规格的原作基线。

## 验收标准

- [ ] 旬、月、季、年四类边界及 1 月 1 日组合边界均有顺序测试。
- [ ] 测试证明每个结算阶段仅在前一阶段完成后开始，终局短路不会执行被禁止的后续更新。
- [ ] 逐日推进覆盖 1、11、21 日边界，并证明 UI 日期只在提交后更新。
- [ ] 保存/载入往返只持久化权威状态，重建后的显示日期一致，且无任务阶段或 UI 缓存字段。
- [ ] 失效人物、势力、建筑或部队引用在消费点被拒绝或清除，不会复用旧对象。
- [ ] 测试夹具不依赖原版文件、IDA 数据库、第三方补丁或研究工具。
