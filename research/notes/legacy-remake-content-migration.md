# 旧版重制内容包迁移核对

核对日期：2026-11-09。输入为本机 `E:/San9R/content`，仅检查元数据，不复制或提交游戏资源。记录旧版迁移的证据、实现和验证范围。

- 根目录 `catalog.json` 为版本4，当前契约为版本6。旧根目录没有独立的 `shared/definitions.json`、`shared/officer-defaults.json` 和 `shared/officer-flags.json`。
- 历史剧本4的组合包为版本243，内嵌剧本状态为版本151；当前组合包和状态分别为254、158。旧剧本状态包含武将、势力、军事及情报数据，可作为拆分共享资料与剧本差异的输入，但不能直接改版本号通过校验。
- 新增状态迁移原型：从旧文本恢复官爵、官职、兵法和阵形的名称与说明，核对旧阵位行与目录格位后构建完整位置，忠诚缺项保留旧运行时的零值语义，熟练度上限采用当前默认1000。使用旧包共享消息库及0号剧本为共享基准，20个剧本均通过状态校验及拆分后重新组合的一致性检查，每个保留700名武将。探测显式指定显示年龄，旧包能否还原此剧本开关仍待核实；已有野战部队及实际发布尚未验证。
- 状态准备已封装为 `LegacyScenarioDataUpgrade.PrepareAsync`，从旧目录和共享消息库读取全部剧本，要求调用方逐剧本明确指定年龄显示选项，并复用共享数据组合一致性校验。`PublishWorldsAsync` 将准备结果写入独立的暂存内容目录；本机旧包的20剧本与700条共享人物资料已通过发布、重新读取和状态一致性检查。暂存目录仅含世界数据与入口清单，尚不是完整可运行内容包。
- 旧纹理包为schema 5、转换版本62，图片引用内嵌物理文件路径、尺寸与通道。当前schema 8通过文件表引用物理图片；转换必须核对同一路径的尺寸和通道一致，并保留每个逻辑图片的裁切区域。
- 已实现图片文件表转换组件，并以本机旧纹理清单进行只读探测，得到5295个唯一物理文件引用。组件深拷贝清单，校验图片区域与同路径元数据；此步骤保留旧schema，后续版本迁移及完整资源校验仍未完成。
- 旧纹理来源记录为名称、长度和修改时间，当前来源记录要求SHA-256。原始文件不在旧包中时不能从这些字段计算或伪造原文件哈希；迁移必须明确表达来源不可验证，并避免把迁移结果声称为已核验源文件的转换结果。
- 迁移原型将旧头像锚点拆为半身与面部锚点，并将不可验证的来源列表留空。导入器已明确把空来源视为不匹配，避免误判为源数据未变化。实际旧包已通过这两步反序列化，随后因皮肤schema 62与当前64不一致而停止；当前皮肤新增`icon-commanded`、地图对象选择框和列表行角色，尚须核对旧素材是否能提供这些角色。
- 已核对本机旧纹理库：`g_common` 的475～486号、调色板65的图片，以及 `g_marker` 的33号、调色板4的图片均存在。当前导入器分别用它们生成地图对象选择框／四帧行和`icon-commanded`。迁移原型从旧纹理库裁出22张独立图片并准备对应角色，避免与库中完整图片区域重叠；实际包探测中，临时设置当前纹理schema后33578个逻辑图片通过纹理结构校验。图像观感、迁移产物发布与完整内容包仍待验证。
- 新增 `upgrade-legacy-textures --source PATH --output PATH` 入口，以独立新目录暂存并校验全部图片后发布。使用本机旧纹理包生成 `local/generated/legacy-texture-validation`，再调用 `verify-textures`，33578个逻辑图片通过；该入口仅升级纹理，无法独立构成可运行内容包。旧包缺失的可选阵形外观预设保持空集合，原版资源指纹不予伪造。
- 旧武将条目包含姓名键、姓氏和旗帜编号。旗帜目录可从旧数据重建候选映射，但须检查重复姓氏、旗帜资源完整性，以及与各剧本身份的关系；不可假定从单个剧本得到完整原版目录。
- 开局迁移原型使用旧包消息与纹理库补充新势力页面所需配置，并从显式指定的共享基准人物生成旗帜目录。本机0号剧本的700个人物产生179项姓氏映射与186个旗帜编号，所有旗帜方向引用通过校验；与20个旧剧本预览组合后，开局菜单和剧本选择配置也通过现有结构及资源引用校验。该验证未检查实际画面。
- 在 `local/generated/legacy-full-probe` 组合迁移纹理、开局、共享资料及20个剧本；以旧插画引用恢复人物头像身份，补齐当前重制自有命令文字与缺失的表现绑定后，`verify-content` 对20个剧本的世界、查询和资源校验全部通过。该副本尚未接入新兵种内容，年龄显示暂按全部开启试验，完整升级入口和新规则对局仍未验证。
- 可复用 `SharedScenarioData.From`、`ScenarioDocument.From` 和现有资源校验器，在版本映射完成后分别检查共享地理、定义、人物和各剧本组合结果。输出必须先写入独立目录，通过完整校验后才发布，输入目录不得原位修改。

上述观察不能证明所有旧版本或数据均可无损恢复；当前仅支持已识别的版本和无初始野战部队的输入。

## 完整升级入口（进行中）

`dotnet run --project src/San9.Tools -- upgrade-legacy-content --source <旧内容目录> --output <新目录> --show-officer-ages true` 将目录复制到独立暂存区，升级纹理、开局和剧本，核验通过后发布。`--show-officer-ages` 必填且作用于全部剧本；旧包没有保存原始年龄显示开关，调用者需要自行选择。输出根目录的 `legacy-equipment-upgrade-report.json` 按剧本列出无法识别类别的宝物 ID 和原类别；这些物品保留，有名马效果时归坐骑槽，其余归宝物槽。仅支持根清单 4、剧本清单 243、状态 151 与纹理 5 等本次已识别的版本，不覆盖源目录或既有输出。升级输出包含玩家的原有资源，不应提交仓库或公开分发。

迁移同时加入新版兵种、研究与阵形预设。本机完整升级结果通过全部20个剧本和33578个逻辑图片的内容校验；另逐剧本启用新规则创建会话通过。该检查不构成实际画面验收或完整对局验证。
