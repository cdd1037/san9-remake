# 运行时状态与资源目录

## 当前结构

G10已完成核心玩法验收（2026-09-21），搜索38项对象、支持历史与周期事件均已闭合，190年完整包及独立CLI36旬通过；专用表现继续按路线图交接。普通场景终局和八类结局已接入。`TerminalDefinition`／`EndingDefinition`是内容输入，`TerminalEvaluation`在旬前置检查，`EndingSnapshotFactory`从终局世界产生只读汇总。`GameSession.GetEndingPrompt`提供责任者候选，`EndingOperation`提交选择，`Ending`查询结果；Application保存选择并进入会话状态，世界状态和日期不变。普通探索通过`GetSearchRecruitmentPrompt`查询发现人物后的实时选择，复用逐日任务响应继续推进；待答期间禁止保存，回答后回到稳定边界即可保存，实际回答通过会话操作提交。主动求官由`GetOfficeRequestPrompt`查询、`RespondOfficeRequestCommand`回答，与联盟共用日历拥有的`EventSession`；人物及资源效果只在提交时写回，候选游标续行不重跑旬更新。特殊探索已接入华佗疗伤：内容人物引用与概率参数驱动当前世界伤员查询，包含原属己方的俘虏，原子治疗后停止搜索；`SearchHealingResolvedEvent`提供治疗名单。初始事件消费键由内容复制到世界并纳入保存恢复。神兽通过`GetBeastSearchPrompt`查询战斗／逃走选择，复用逐日任务响应；奖励、伤势、寿命和地点消费原子提交，完成后结束搜索。季度历史入口`QuarterHistoricalEvents`先尝试联盟，资格失败才检查二乔；`QiaoMarriageEvent`记录当前人物寿命与信望奖励、外交目标，成功消费与效果同事务进入保存恢复，无额外确认命令。二乔失败才检查`SunMarriage`，完成转属、旧任务／部队／军团清理、关系与玩家兵法奖励，`SunMarriageEvent`和消费同事务提交；资格失败不消费，二乔先成功则留到下季。其后汉中王、五虎将、出师表依次检查，首个成功停止季度主表；晋爵复用`PoliticalEvents.GrantRank`，人物奖励按原属俘虏／在职范围分别处理，政治收尾仍读取已提交的爵位与信望。新定义进入内容，消费状态纳入存档，无新增命令。其余进度见[G10验证](g10-verification.md)。

内容包提供支持范围内的完整定义、资源和初始状态，不按首屏或初始可见性删减对象。`GameSession.Start`复制初始记录，创建独立的`WorldState`；Core持有势力、据点、人物、宝物等当前状态。两个会话互不影响，改变导入对象也不会改变已启动会话。Core不依赖内容包、Godot或原版格式。

状态只能通过规则提交，成功事务更新世界版本。`WorldSnapshot`保留按ID排序的只读记录；旧快照不随新事务变化。武将已学兵法使用不可变有序集合，只表达成员关系，不记录学习顺序；学习和编辑自动去重，枚举及JSON存储均按兵法ID升序，快照直接共享该集合。状态摘要包含日级日期、起始日期、控制席位/当前位置、命令序号水位、持续任务、命名随机状态及全部当前领域记录，仅在测试或诊断主动请求时计算，用于确定性对比。世界摘要不包含显示文本、图像或会话内容身份；会话诊断摘要覆盖当前世界、年表、最近记录与操作水位，二者均不写入普通快照；磁盘文件仅保留封套完整性校验和独立内容指纹。

`SimulationEngine`统一组织规则执行及事务提交：类型化命令经控制权限与业务终验后即时提交或建立持续任务；全部控制席位结束后逐日推进到下一旬，再完成前置更新。`DomesticDevelopmentHandler`检查业务前提并准备变更，`XunRecovery`负责旬行动恢复；二者都只修改候选事务，不自行发布世界。`GameSession`通过运行引擎执行用例，从成功提交返回的领域事件生成会话记录，再通知界面。

`WorldState`负责状态保存与发布。初始化显式拒绝全部七类集合的重复身份，包括同ID同内容的重复记录；初始化和领域事务提交共用`WorldInvariants`，校验现有领域数值、日期及对象关联约束。事务允许中间状态暂时不一致，在最终候选状态上统一校验，便于跨对象归属变更。校验失败不改变世界、随机状态、版本或缓存快照；成功只增加一次版本。此处保证单线程执行中的原子发布，不提供并发写入同步。新增规则须把公共状态不变量放入统一校验，业务可执行条件留在对应处理器。

`WorldMutation`按需建立事务内成员、任务和宝物派生索引，供规则查询使用；当前实现与后续优先级见[运行时查询优化](#运行时查询优化)。索引不进入快照、摘要或存档，不发布事务中间状态。

Application把当前世界与复制后的名称/显示定义组合成`StrategySnapshot`，按世界版本缓存。HUD、标注、设施可用性和小地图读取同一视图。Rendering根据耐久、开发度、驻兵、归属选择组合和动画；客户端不再把初始精灵实例作为建筑真值。

当前700名内置人物保存在世界中，只有可见身份进入人物视图；宝物状态保留出土状态、持有人和发现地域，情报查询再筛选已出土且由可见人物持有的宝物。没有进入初始情报的对象仍有定义和资源。数据核对方法见[内容管线](client-content.md#接入前的数据核对)。

## Core代码目录

`src/San9.Core`保留`Domain`（领域状态与基础规则）和`Simulation`（规则执行与世界变更）两层，层内按业务职责分组。子目录用于导航，命名空间仍为`San9.Core.Domain`和`San9.Core.Simulation`；目录本身不新增依赖层或公共接口。

剧情按业务含义归档，不按调用入口机械分类；例如官渡由登用触发，仍归历史剧情。皇帝解析、人员转属、势力生命周期、日常人事与联盟规则继续由各领域目录维护，不因会产生领域事件就全部迁入`Events`。目录整理不改变命名空间、内容／保存契约或调用关系；通用事件插槽和内容模型仍按[后续重构计划](../specs/roadmap.md#原作事件解析后的系统重构后续计划)统一评估。

依据[BEH-ECONOMY-0001](../specs/behavior/BEH-ECONOMY-0001-domestic-and-economic-cycle.md)，六项经营命令支持1至5名不同参与者。公共处理器验证当前归属、驻地、行动占用、项目次数与资源，原子提交属性、账户、兵员、熟练度和使用状态；拒绝不改变世界与随机。征兵按实际剩余容量和资金计算，兵役与驻军严格守恒。

`EconomyRulebook`由Application从内容的官职和人物组合定义构建，不保存第二份可写世界。`ResourceAccounts`解析势力/军团账户并报告请求、实际、短缺和饱和；`EconomicCycle`在旬前支付俸禄、每日命令前扣粮、季度更新人口与收入、七月收获。普通存档包含当前状态；资源事件由执行结果返回，调用方按需消费，不进入会话永久历史。

F3面板对选中玩家城市选择可用武将中当前政治最高者执行，展示成功增量或拒绝原因。它是实际用例的调试入口；正式内政菜单尚未制作。

## 时间、命令与任务内核

G06的`MilitaryOrder`分别引用部队或据点，失效目标在战后事务中清除；`UnitState.MemberRanks`保存出征时的实际阵位，`Wounded`独立于健康兵。`ForceState.IsEliminated`与`SettlementState.IsDestroyed`保留内容身份，清理活动引用，当前查询公开相应状态；毁坏对象不再占用领域地图。战败清理先解决人员和账户，再修复治理，初步终局停止后续日历推进。完整说明见[G06验收](g06-verification.md)。

`SimulationState`保存场景起始日期、本局种子、运行种子、稳定/终局边界、控制席位与当前位置、单调命令序号水位、任务和命名随机。固定条件骰使用本局种子和日期/身份，运行流使用运行种子；玩家加载换运行种子，精确恢复保持原状态，见[随机约定](randomness.md)。执行中标记由`WorldState`独占持有，不序列化；同一世界的多个引擎入口也不能重入。`GameClock`只有年月日可构造，旬与周期标志均派生。

`GameSession.Start`将玩家势力置于首席，其他势力按ID配置自动席位；请求携带由Application指定的控制者上下文。`Execute`和`Validate`共用类型化终验，`Develop`只是现有客户端内政调用的转换方法。`EndControl`由WorldState执行专用的控制游标状态转换：只校验稳定边界、剩余席位和控制者身份，成功后增加游标与世界版本；领域集合保持不变，已有快照复用这些只读集合，不重新全量校验、排序或复制武将等记录。拒绝不改变状态，旧快照保持有效；领域命令和旬结算仍使用完整事务校验。现有会话`AdvanceXun`显式结束剩余席位后推进，CLI可调用`DomesticPlanner`选择真实经营命令，尚无完整战略AI。命令拒绝不消耗序号、资金或随机，不发布事件。

人事任务记录是旅行占用的来源，名单和建筑可用人数读取任务及人物当前据点/部队位置；旬恢复清行动位时不清任务，也不把出征成员变回驻城者。内部编译规则决定人事任务时长、资格及完成效果，存档不能携带执行代码；未知任务规则恢复时拒绝。正式任务已接入搜索人物、普通登用与多人调动，驻地与出行目的地分别保存，到期重验并由统一人事转换清理引用。军师任命与褒美使用即时公共命令；实际边界见[G04推进记录](g04-verification.md)。军事命令由`UnitState.Order`持有，日地图阶段重寻路，不使用固定到期日的人事任务表达行军。

`CaptureStableState`拒绝执行中取存档；`WorldState.Restore`验证稳定边界与不变量，保留版本且不执行首轮更新。`SaveEnvelope.Session.World`包含权威世界，初始种子只保存于`SimulationState`。Application的`SaveService`实现严格校验、同目录原子替换和新会话恢复；`CommandLogService`按会话序号重放，旧序号返回已处理且不产生事件、不验证旧载荷。`GameSession.Apply`在候选世界上执行，世界、最近128条内政记录和水位一起发布；玩家年表保留，不保留完整操作与事件历史。协议、独立CLI和实际验收见[G02验收](g02-verification.md)。

情报扩展使用不可变目录投影和独立模态导航；所有军团（含君主军团）均独立持有必填CorpsTreasury，以IsRoot标识君主军团；ForceState不保存金钱／兵粮。每个未灭亡势力恰有一个根军团，军团ID独立于势力ID。HUD读取玩家根军团账户，势力情报仅汇总所有所属军团一次。人物可具有据点位置或独立地域位置，具有据点或部队位置的可见在职人物才进入右侧行动名单；官爵、人口、宝物及关系值纳入内容校验。详见[情报界面](ui/information-browser.md)。

## 人物有效能力

`OfficerAbilityRules`统一计算四项有效能力：基础能力先按伤势折算并至少取1，再加当前持有宝物的逐项最大加成和现职加成。人物、初始态及存档不保存宝物加成、官职加成或有效能力副本。

事务内单人规则复用当前持有人对应的宝物效果汇总，批量能力查询使用同一入口；快照上的批量排序和情报查询一次聚合宝物后计算人物集合。同一事务内授予、没收、任免和能力成长立即影响后续计算，旧快照仍按自己的状态计算。查询结果可包含有效能力，但不回写领域状态，也不跨事务缓存。

内容加载与存档恢复保留基础值范围、官职及宝物引用等源数据校验；删除加成缓存相等检查和人物有效性检查中的试算。公式及整数运算规则保持不变。

兵役人口`DraftPopulation`的500,000是自然增长上限，遣返／解散回收可超过该值，季度增长不降低已有超限人口。兵员回收使用受检加法完整保留，并进入资源事件、快照和存档。当前军事规则为G07 v13，存档与日志版本均为18；剧本／组合内容版本为36／37，旧包须重新转换。

## 运行时查询优化

优化目标是让局部战斗查询的成本取决于相关成员与对象数量，减少反复扫描全部人物、任务和宝物。优先级依据调用路径、扫描规模和维护成本安排；尚未进行性能基准测量，不把结构优化或测试通过解释为已测得的耗时收益。

### 已完成：优先级1～4

| 优先级 | 优化项 | 当前实现与覆盖 |
| --- | --- | --- |
| 1 | 部队／驻地成员索引 | `UnitMembers`、`SettlementMembers`按位置取得当前参与对象，保留俘虏等非在职成员供战后处理；在职战斗查询再通过公共成员入口筛选。统率、计略防守者、单挑、学习、治疗、救援与战后人员处理已接入。 |
| 2 | 人物任务索引 | `TasksFor`按人物保留任务顺序，`IsBusy`查询任务占用，`IsTraveling`查询存在行程的任务。战斗及相关命令资格查询复用索引，区分忙碌与在途。 |
| 3 | 宝物持有索引及效果汇总 | `HolderId`仍是唯一归属事实。按持有人取得宝物，按宝物规则集分别缓存四项最大加成、免俘虏马与宝物兵法来源；能力、兵法资格和战败／单挑免俘虏查询复用汇总。 |
| 4 | 统一战斗成员查询 | `ServingUnitMembers`筛选在职成员，`ServingSettlementMembers`额外排除在途人员；归属、阵位、伤势等用例条件继续由相应规则筛选，保留各调用路径的排序与随机消费顺序。 |

实现集中在[WorldMutation.Queries.cs](../src/San9.Core/Simulation/WorldMutation.Queries.cs)，由`WorldMutation`的状态变更入口维护，生命周期为一次事务。首次相关查询建立索引；部队／驻军有效统率随后只遍历当地符合条件的成员并取最大值，无符合条件者为0。部队统率沿用原规则排除在途人员，不直接读取主将统率。

| 派生数据 | 输入依赖 | 更新／失效方式 |
| --- | --- | --- |
| 成员索引 | 当前参与人物记录，尤其是部队、驻地与启用状态 | 人物替换更新旧、新位置中的记录；参与对象启停导致活动记录重建时，成员索引按需重建。身份、归属、伤势变化后查询读取新记录。 |
| 人物任务与在途集合 | 当前`Simulation.Tasks`，包括人物引用、行程和任务内容 | 任务集合改变后失效，下次查询重新建立；仅日期、随机状态等其他模拟字段改变不使索引失效。 |
| 宝物持有索引 | 宝物状态、持有人引用及持有人的启用状态 | 宝物替换更新持有集合；活动记录重建时按需重建。 |
| 宝物效果汇总 | 持有集合、宝物发现状态、对应不可变规则集 | 易主使旧、新持有人汇总失效，发现状态改变使当前持有人汇总失效；活动记录重建时清空汇总。发现地域单独改变不影响效果汇总。 |

能力加成与免俘虏马沿用“未禁用”的宝物条件；宝物授予兵法要求“已出土”。不统一这两种条件。个人最终能力、部队最终统率和伤害结果不缓存，伤势、治疗、任免、能力成长、死亡与成员离队即时影响后续查询。官职按ID读取规则，无需额外汇总缓存。

[WorldQueryTests](../tests/San9.Core.Tests/WorldQueryTests.cs)覆盖同一事务内成员移动、身份筛选与启用变化、伤势与官职改变、任务替换与结束、宝物易主及发现状态变化，并核对查询不发布世界变更。默认解决方案测试已通过，包含现有战斗、选任、保存恢复与回放覆盖。本次未改变内容契约或保存协议，不需要重转内容包。

## 交战关系查询

`WorldMutation`拥有当前事务的`EngagementRelations`派生视图，记录来源到目标及目标的攻击者数量，消费者不各自扫描世界。位置、目标、归属、资格、设施形态和外交等相关状态通过统一写入口使视图失效，按需重建；普通兵损/士气/耐久变动未跨有效门槛时可复用。视图保存对象引用的身份而非对象状态副本，设施选敌返回事务中的最新单位状态。定义引用变化也会重建；不跨事务共享、不持久化、不计算输入哈希。具体行为与验收见[战斗规格](../specs/behavior/BEH-WAR-0004-normal-combat.md#交战关系的统一维护)。

## G08任务与结算契约

`PersonnelJourney.Route`必填，保存出发、目的坐标与野战目的标记。新任务读取当前设施坐标，恢复与计时使用历史快照。`PersonnelReturnLeg`显式保存野战返还语义和外交使者身份，返程重定向保留身份；已结算谈判载荷不随返程重复携带。

人事、八类计略与四类外交使用互斥的类型化任务载荷。外交去程按整旬取整、旬边界谈判，正常返程使用普通距离天数。待决状态的`Phase`区分日内与旬边界续行；谈判报价和阶段持久化，恢复或重复回答不得重复结算。具体公式见[人事行程](../specs/behavior/BEH-PERSON-0003-recall-movement-and-action-reservation.md#行程位置与返还不变量)。

`GiftResolvedEvent`区分`Received`、`Refunded`、`Spent`，资金／兵粮预扣量等于三者之和。拒收结算时退回来源主账户，容量溢出计入损耗，返程不再退款。外交业务规则见[外交规格](../specs/behavior/BEH-DIPLOMACY-0002-command-negotiation-and-resolution.md)。当前协议版本见[内容契约](client-content.md#领域契约导航)。
